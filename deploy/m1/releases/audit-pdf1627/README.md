## 发布条件和操作

用户本轮明确要求部署 #1627。上一批 #1611 的限定门禁例外仅覆盖 #1591/#1605/#1610，已经结束，不扩展到本次。当前缺少本发布版本完整募集书真实模型金样及独立人工复核，`full_quality_gate_passed=false`，用户实际操作验收尚未记录。本候选需要本批明确限定例外或满足完整门禁后才能激活；prepare 不提供激活授权。

激活入口 `activate.py` 沿用两端现有 config/deploy/migration 锁、pending、精确配置 CAS、前像备份和只读 overlay。先更新并自然排空旧 parser，再启用 confirmation/API producer，最后 web。不得强杀在途任务，不重启编制/复核、PG 或网络服务。当前镜像、环境、资源限制、挂载、安全设置全部通过 create-only 配置比对；parser 的 /opt/venv/bin PATH 保持。调用状态未知时先核对 pending 与实际进程，禁止盲重试。

准备时主站约 9.3GiB、Azure 约 2.55GiB 可用；Azure 只略高于 2.5GiB 下限，激活前重新核对。配置及原文件前像保留在两端 `/var/lib/bondbuddy/audit-pdf1627-20261118/private`，本次不操作业务数据库备份/还原。

激活后必须跑真实公网 HTTPS 上传 → 私有 Blob → 独立确认 → parser 的专用合成账号验收，验证普通低 DPI 可继续、严重模糊仍阻断及旧 v3 回执重检；页面桌面/手机核验；核对 10 个实际文件 hash、运行健康及没有新增生成/扣费。通过后才完成共享台账并清 pending。

回滚与发布使用相同锁，仅在本批仍为当前版本时恢复各组件保存的 before.compose.json。先回退 producer/API/web，保持 v4 parser 到 v4 任务排空；检查 v4 queued/running 任务清零后才回退 parser。不得回滚数据库/客户材料，也不得覆盖后续其他发布。回滚过程需重新记录实际容器和台账，不能直接复制旧容器 ID。
