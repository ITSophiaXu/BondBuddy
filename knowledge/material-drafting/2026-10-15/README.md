# 材料案例版式模板

版本：`case-templates-20261015-v1`。本批按用户 2026-10-15 提供的“材料生成模板”目录及随后补充的上交所核查意见 DOCX 整理，11 份案例全部可读取，形成 11 套可编辑模板，覆盖六种市场/品种/材料组合。原件不进入仓库，模板仅保留结构、通用标题和版式；源文件及 OOXML 部件 SHA-256 记录在配套 JSON 中。

## 可调用范围

| 材料 | 市场及品种 | 版式数量 | 默认模板 |
| --- | --- | ---: | --- |
| 申请书 | 上交所普通私募公司债 | 1 | `sse-private-application` |
| 申请书 | 深交所普通私募公司债 | 2 | `szse-private-application` |
| 主承销商核查意见 | 上交所普通私募公司债 | 1 | `sse-private-underwriter` |
| 主承销商核查意见 | 深交所普通私募公司债 | 2 | `szse-private-underwriter` |
| 推荐函 | 交易商协会 PPN | 3 | `nafmii-ppn-recommendation` |
| 推荐函 | 交易商协会 MTN | 2 | `nafmii-mtn-recommendation` |

非默认版保留各自章节和字体差异，不混合成一套。PPN 第三版保留原 Letter 页面尺寸；其余保持各自原页设置。页面中按“材料 → 市场 → 品种 → 案例版式”选择，默认自动采用基础版，切换市场或品种会清空不再适用的版式选择。

## 固化的内容与使用边界

- 保留原 styles、numbering、fontTable、theme，以及段落/字符格式、分节、页边距、页码位置、表格网格和合并结构。正文通过带名称的槽位扩展；数据表通常保留前 3 行作为格式样本，实际编制需补全表头期间、数据和行数。上交所核查意见的发行人信息表、签署角色表保留全部行，历史沿革表保留两行表头和两行数据样式。
- 保留通用章节及其原文位置；案例企业特有的数字编号小节转为事项标题槽位。标题和正文槽位的位置记录在每份 JSON 中，不将案例业务、风险或符合性判断当作新项目结论。
- 移除案例机构及人员名称、金额、事实正文、签章图片、批注、嵌入对象和文档元数据。正文连续段落折叠为可扩展槽位，目录按新正文重建。原空白/窄表格格保留空白，避免占位符撑高；上交所申请书图像签署页替换为签署占位。上述版式差异记入 `deviations`。
- 用户明确选定的私有模板或准确续改成果优先。知识模板控制版式，募集书及本任务材料提供事实依据。缺失事实与未完成核查标待核，不生成虚假的尽调、内核、批准或签章。
- 案例含有历史法规名称和核查事项，不能证明法规现行有效、发行人符合条件或机构已签认。具体适用章节仍由本次材料和适用规则决定。

## 加载与不可变输入

`apps/api/src/m4-knowledge.ts` 只从服务端目录按材料/市场/品种匹配模板，校验路径和模板 hash；将知识正文、模板 ID/版次/hash 和完整 DOCX 字节固定进任务输入。旧任务继续使用原快照，不因知识库更新而换版。浏览器不能上传知识快照来替换服务端模板。

Worker 在独立任务工作区写入只读 `knowledge/case-template.docx`，编制时从它复制并填充。`python/bondbuddy_m4_render_template.py` 可在保留未编辑 OOXML 部件的前提下填充文字及段落数组；表格按资料扩展。收集成果时继续检查源文件和模板未改动。输出为正文 Word 和独立编制说明。

## 仍需用户提供

| 优先级 | 缺失模板 | 建议提供内容 |
| --- | --- | --- |
| 当前范围 | 各券商立项报告 | 每家拟使用券商的现行空白模板或完整脱敏案例，含附件表、签批页；已有私有模板可继续使用。 |
| 当前范围 | 沪深法律意见书 | 两个交易所各一份普通私募完整 DOCX；如律所格式不同，请按律所分别提供。 |
| 当前范围 | 沪深募集说明书摘要 | 两个交易所各一份实际使用的普通私募摘要 DOCX，并注明属于申报、内部还是其他用途。本批未提供案例版式，现有指引继续保留。 |
| 扩展范围时 | 公募公司债材料 | 按交易所和大/小公募分别提供申请书、核查意见、法律意见书、摘要等所需材料。不能拿本批私募案例代替。 |
| 扩展范围时 | 协会 CP、SCP、DFI 推荐函及其他申请材料 | 按品种分别提供完整可编辑 DOCX，并注明推荐/申请事项。当前仅启用 PPN、MTN 推荐函。 |

每份模板建议注明：材料类型、交易所/协会、品种、适用机构、版本日期、是否现行使用、必须保留的附件和可选章节。仅提供 PDF/扫描件时可以参考排版，但准确字体和可编辑结构优先以 DOCX 为准。

## 复建与验证

```powershell
python scripts/build_material_case_templates.py --source-dir '<获授权的材料生成模板目录>'
$env:PYTHONPATH='python'
python -m unittest python.tests.test_m4_case_templates -v
```

复建只读取原件，生成固定 ZIP 时间戳的模板、配套 JSON、目录和公共版式列表。发布包须包含本目录的 catalog 与 templates；Dockerfile 已增加对应 COPY。没有新增依赖。

本机使用 Word 只读导出 PDF，再用文档技能 `render_docx.py` 的 rasterize 生成 PNG，检查模板各页。Windows 运行时未提供 LibreOffice，因此未调用桌面 LibreOffice。模板字体/分页在不同客户端仍可能有差异；实际生成的篇幅取决于本项目数据。

上交所补充来源 SHA-256：`4daf531228b7fc65aa3bd7877ef738d5b7ddcca5957895ba420841a5ab068236`。已逐页检查其 Word 导出的 94 页；模板保留 7 个分节、1 个横向分节、22 张表格、8 个自动编号标题及 30 项发行条款名称。标题补充同页约束，签署页独立分页；正文压缩为槽位后的页数不代表最终生成篇幅。

API/worker 测试覆盖六种默认范围的真实 PostgreSQL/API/任务/模板填充/双 Word/4500 积分结算及归属隔离，模型输出为 synthetic，私有 Blob 为内存适配器。浏览器测试使用模拟 API，不能据此声称真实模型或用户验收通过。迁移 `0106_m4_case_templates.sql` 仅在独立测试数据库验证，未部署。
