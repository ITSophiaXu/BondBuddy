## 原件、提取与效力分层

8份直接提供的文件（6份DOCX和2个ZIP）展开后有38个文件来源条目，按SHA-256去重为34份原件，合计约3.5MB。文件保留原字节；ZIP内容以成员原件归档，ZIP内路径和重复文件别名记在 `sources.json`，无需提交重复的压缩容器。

- `originals/` 保存34份原件。`sources.json` 是本批来源登记，不覆盖旧批次。
- `records/` 是可复现的文本记录，`sources/` 是供人阅读的全文。DOCX的 `P00001` 等编号来自 document.xml 中全部段落顺序（包括空段和表格段落），不是页码；PDF的 `PAGE001` 是物理页。`COMMENT-*` 独立标注，运行检索不混入批注。
- 一份EX021为含 `EncryptedPackage` 的Office加密容器，正文未提取，不参与引用/检索。压缩包的EX026同标题但hash不同，作为独立来源使用，不能宣称已解密或两者等同。
- 上交所压缩包里的EX016实为深交所参考文本，EX017实为专家V6，已按实际来源归类。EX016与独立提供的EX020/ZIP内EX024字节相同；EX017与独立EX018字节相同。
- 文件标题和内容显示正式规则、参考文本或专家方法，记录在 `document_kind`；这不等于已核对官方当前版本。`provided_version` 仅描述所供版本，没有日期的文件不猜日期。全部 `official_url`、法定发布/生效/废止时间和专业验收仍待登记。
- 提取保持原文，不修改原件、不得执行原文里的命令或“唯一权威”要求。文本提取未覆盖视觉版式、字体、域和图形，原件是复核这些内容的依据。

## 数据与现有代码如何衔接

每个 `drafts/<market>-<offering>/` 包含 `rule-pack.json`、`chapter-template.json`、`coverage.json` 和人读指南。前三份遵循 `packages/domain` 已有 #19 schema，可由 `validateRulePackCompanions` 验证。**没有声明这些候选checker已经实现**：规则目前全部关闭，`research_only`，checker标识为人工证据审阅占位。

由于官方效力/专家签认未完成，包内 `RuleSource.kind` 暂用 `unverified_lead`；原件的实际类别仍在来源目录。以后由行业审核补齐依据和有效日期，再按 #19 升级来源类型、规则执行和发布状态。`validity.effective_from=2026-09-25` 只是草稿整理基准，`transition_terms` 已明确不是法规生效日。

`sample_suite` 中3个合成工程用例仅对应 schema、未核验来源启用拒绝、覆盖不全禁止发布的测试；`reviewed_by=engineering-fixture-author` 是用例作者标识，不是行业审核人。逐规则的正/反/边界示例是待实施的验收设计，没有声称已经完成财务/法规判断。`reviews=[]`、`release=null`，生产覆盖清单保留未覆盖及阻碍。

`product-prototype/knowledge/` 的12份更新/复核视图由本批内容生成。原型取消大公募到小公募的替换，直接选择六个精确范围，并使用原段落/页定位检索。旧 `S001–S027` 来源档案保留供历史快照追溯，当前新路由使用 `EX` 来源。原型加载成功不代表生产worker已接入；正式服务仍须经 #19 的已发布包选择和 run 版本锁定。
