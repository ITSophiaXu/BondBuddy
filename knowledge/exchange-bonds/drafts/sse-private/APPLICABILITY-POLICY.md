# #20 → #19 上交所普通私募适用性业务交接

版本：2026-09-26.1。对应 #20、#19、#31；基于 develop `4785dc3` 的接口核对。

这是可供业务审核和工程实现的具体判定方案，**不是 Maxy 已签认记录，也没有使规则生效**。已有用户确认只覆盖四组样本的目标市场、发行方式、财务期间及单列日期处理。规则仍为 draft / research_only；本文件不修改公共契约或数据库。

## 1. 交付边界

首先覆盖有历史原稿、同市场同方式的 `sse` / `private` / `ordinary-company-bond`。国内公司不因为具有城建、房地产或集团属性就被当成非普通公司债；这些属性需要叠加审核重点。专项债券、可转/可交换/可续期、特殊主体及优化审核的增量能力未经验证时，不能按普通路径声明已覆盖。

本次不要求前台增加“是否重大重组”“是否设置保护条款”“注册模式”问卷。后台先从材料识别，存在影响选包的歧义时通过既有补充对话追问；普通条款或财务披露的局部缺口按 UPD-GAP-01 标记待确认并继续有依据的工作稿处理。

## 2. 逐字段定义及来源优先级

字段名称区分 producer 与 selector。当前 #19 强制候选名为 `documentPurpose`，不是 `documentStage`；由审核后的前者映射到后者，不能同时存两份不一致事实。

| producer 候选 fieldKey | selector 字段 | 本范围值及业务含义 | 可以批准的证据；缺失处理 |
| --- | --- | --- | --- |
| market | market | sse | 锁定版本的用户目标；与项目目标一致。历史市场单独识别，不能覆盖目标。目标陈述本身可以证明写作意图，不证明历史事实 |
| offering | offering | private | 同上。小公募/大公募不得映射为 private；源方式不同转 #32，不悄悄改用同方式分支 |
| instrument | instrument | ordinary-company-bond | 历史有效原文发行条款与本期方案/补充消息共同核对；若仅有历史材料，当前是否变化保留待确认。不能从文件名或“公司债”关键词排除特殊结构 |
| documentPurpose | documentStage | registration / issuance | 前者在私募指挂牌条件确认申报稿，后者指具体一期发行稿。本期任务意图或对应申报/发行文件是证据；历史标题“第二期”不证明目标也是发行稿。未确定为 null |
| issuerScope | issuerScope | domestic-company | 已核对的发行人实体绑定，加原稿主体信息、登记资料或审计附注中的组织形式/注册地。绑定了名字不等于已证明法律主体范围；政府机关、金融债等不得猜成普通公司 |
| investorScope | investorScope | professional | 私募法定适用对象与本期发行安排分别核对；此值不证明具体投资者资格、穿透或人数已经合规，人数核验仍是独立规则 |
| industry | industry | 经审核分类的行业代码；未确认 null | 保留分类标准及版本、业务原文和审核理由。城建/集团不是凭名称推断的行业。当前没有统一代码表，不能把自由文本、GB/T 行业代码与 #77 三业务代码混用 |
| specialFeatures | specialFeatures | 经审核的适用特征集合；未知 null | 按第3节逐项记录有/无/未知。当前未建立正式特征代码表，不先提交任意新字符串到生产 selector；空集合必须有完整排查与真实审核记录 |
| asOf | asOf | 本次目标文书的法规适用日，YYYY-MM-DD | 由本期申报/发行时点或明确测试任务设定证明；测试设定只证明本次测试的基准。不得用财务截止日、历史文件年份、上传日或系统当天自动代填 |

除 market/offering 外，用户陈述需要保留 `user_asserted`，不能改写为已从原件识别。目标意图可以由用户直接决定；外部事实则需要相应材料或保留未核验状态。审核采纳一个值不改写其原始来源类型。

`asOf` 和 `documentPurpose` 还必须与上下文顶层同名值一致。每个候选固定材料 ID/version/SHA、parse snapshot、record ID/SHA；消息来源固定消息版本及输入版本，不能只有一段无法追溯的摘要。

## 3. 特征与专项排查表

以下是业务排查维度，**不是新增公共枚举**。#19 的代码表应在与 Maxy/Xuefeng 对齐后定义一次；producer/selector 从同一来源导入。

| 维度 | 主要材料 | 核对后的处理 |
| --- | --- | --- |
| 城市建设、房地产、集团型经营等审核重点 | 业务章节、收入/资产结构、合并范围、子公司附注、资金用途 | 多项可以同时成立；分别列审核重点，不能用单一主行业排除其余触发项 |
| 专项品种或用途标签 | 本期品种、发行条款、资金用途和对应权证 | 专项增量未覆盖时记录能力缺口；不能去掉标签后当普通债已完成 |
| 可转/可交换/可续期等结构 | 发行条款、含权、利息递延、续期安排 | 与普通公司债能力范围核对，不能因标题写公司债就默认无特殊结构 |
| 优化审核或简明披露 | 本期申报方案、资格依据及适用日 | 2026-09-04后不能采用2023版旧资格；新版增量未经核验不予自动确认 |
| 重组、特殊主体及过渡安排 | 审计附注、交易资料、登记信息、历史受理/批复与协议 | 系统识别并列出证据，不增设用户必填重组开关；影响范围的未知不得当不存在 |

空集合的证据应说明审过哪些材料版本、哪些维度以及结论，不能仅写“未发现关键词”。当前 producer 明确拒绝 `specialFeatures=[]`，因此完整否定审核要通过 #19 新增的审核路径实现；不能用 `unknown` 或编造 `none` 标签绕过。

## 4. 字段审核与整体放行

### 字段审核

每个字段保存真实审核人及权限、审核时间、原候选版本/hash、采纳值、来源、理由、冲突处理和适用任务。允许业务结果为采纳、纠正、待补证或超出范围；这些是业务动作说明，不预设新的 API 状态名。

- 采纳：材料/目标足以支持当前字段，不等于整个项目或募集书合规。
- 纠正：保留旧候选，以新不可变审核版本记录；不得覆盖旧 run 的依据。
- 待补证：null/来源冲突/OCR存疑不能以置信度阈值批量批准。
- 超出范围：记录具体缺少的规则/能力，不生成“已合规”结论。

### 整体放行顺序

1. owner/project、完整材料集合、来源输入 hash 和 #206 发行人绑定真实且相互一致。
2. market/offering、instrument、文书阶段、主体和投资者范围、法规适用日均有审核依据；需要的行业/特征判断完整。
3. 所有影响选包的冲突已处理，实际使用的分类版本固定；未知不能被空值、默认值或最新版替换。
4. 选到同范围、同适用时点的 production 规则/模板/覆盖版本，来源及样本审核真实，未撤回；不把 test 发布用于真实任务。
5. 缺少普通披露材料仍可按 UPD-GAP-01 留待确认；缺少规则授权、关键身份或必需执行能力则按平台门禁暂停。两类缺口单列。
6. loader 返回审核后的完整 pin 和 `ProductionRulePackRequest`，#17 在事务中选择并锁定；恢复旧 run 使用已锁定版本，后续草稿编辑不更换旧任务依据。撤回/篡改仍应暂停。

**选包成功 ≠ 每条规则已执行 ≠ 财务事实已核验 ≠ 可申报 ≠ Word交付成功。** 每层必须分别保留状态与证据。

## 5. 本轮仍需 #19 实现的明确接口缺口

截至 develop `4785dc3`，`ReviewedRuleApplicabilityContextResult` 只有 `needs_review` 分支；loader 末尾始终返回 `rule_applicability_taxonomy_and_review_threshold_not_defined`。#217 虽已合并，仍不能自行产生已批准上下文。需要由 #19 负责人继续完成：

1. 同源分类字典及版本（重点是 industry 与多项 specialFeatures），与业务审核意见对齐。
2. 字段审核及整体审核的追加记录、审核人权限、完整否定特征证据；不得把 reviewDecision=null 改为固定通过。
3. 消息/目标意图来源的不可变定位；现有 parse evidence 不能伪装成消息证据。
4. 经批准 loader 分支、selector请求组装，以及与 #17 当前事务/恢复模式的实际接入。
5. 真实来源核验、规则包发布及撤回验证。规则中的 `unimplemented.1` checker 仍须实际实现/验收；仅启用规则不能补出执行能力。

这些属于依赖交接，不在 #20 中复制数据库、API 或公共枚举。若公共契约变化，按 AGENTS.md 由受影响负责人核对后实现。

## 6. 最小验收反例

| 输入 | 应有结果 |
| --- | --- |
| target=sse/private，历史=szse/private | 两者保留；不能误认成同市场更新，转 #32 能力检查 |
| documentPurpose 顶层为 issuance，候选为 registration | 拒绝不一致上下文 |
| 名称含“建设投资”，没有业务证据 | 不自动确认城建或非城建 |
| 已核对城建，同时存在集团经营 | 同时保留两项触发，不被单行业字段覆盖 |
| specialFeatures=[]，无否定审核 | needs_review，不视为普通范围已获准 |
| 用户称无担保，但材料存在保证合同 | 记录冲突；不静默优先用户或历史文件 |
| 财务截止2025-09-30，任务未给申报/发行日 | asOf未知；不能按财务日选旧法规 |
| 新版财务缺审计意见，其他依据完整 | 明确未经审计/意见缺失；不因局部缺口全篇停止，也不生成审计通过结论 |
| 已锁定run后编辑项目或后续批准新值 | 旧run仍用原pin；新输入另建版本；撤回旧审核则暂停 |
| 规则来源和上下文已审，但checker未实现 | capability_not_ready，不能宣称规则执行通过 |

反例是待接入测试设计，不是实际测试通过记录。真实样本按 [ACCEPTANCE.md](ACCEPTANCE.md) 执行；逐项业务意见可填写 [REVIEW-WORKSHEET.md](REVIEW-WORKSHEET.md)。
