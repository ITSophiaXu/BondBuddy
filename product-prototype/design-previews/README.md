# 更新募集书：连续项目工作区

2026-09-24 的可点击 UX 演示。开始前、运行中、待补充和已完成保持在同一个项目工作区；右侧对话与项目身份持续保留，左侧切换进度、补充要求和成果。

**这是独立交互演示，尚未接入真实项目、模型调用、积分或 Word 生成。** 当前应用的 `/#update` 仍会进入独立任务详情页；本次演示发布不代表该入口已改造，也不关闭相关开发 issue。

## 打开体验

- 已从这份代码启动 `product-prototype`：打开 `/previews/update-workspace.html`，默认地址为 `http://127.0.0.1:4320/previews/update-workspace.html`。使用其他端口时相应替换。
- 仅看演示：下载并用浏览器打开 [update-workspace.html](../public/previews/update-workspace.html)，不需要登录、模型配置或真实材料。GitHub 文件页只展示源码，需要下载或本地启动后查看。
- 同一电脑上旧目录的 4320 服务不会自动读取另一份 checkout 的页面；请确认启动的是含本提交的目录，或按 [HANDOFF](../HANDOFF.md) 使用其他端口。

页面顶部明确标记“交互演示 · 示例项目”。示例文件、章节数量、状态和对话由本地演示控制；下载按钮只提示预期动作，不生成文件。图标由固定版本的公共 CDN 加载，业务交互不向模型或业务 API 发请求。不要在演示中填写真实客户资料。

## 推荐体验顺序

1. 默认显示“更新中”。可以直接切换“开始前 / 更新中 / 待补充 / 已完成”，观察项目标题、材料入口和右侧对话的位置保持稳定。
2. 切换“开始前”，点击“开始更新”。左侧在原位置展示整理材料、核对目标、章节更新、全文检查和生成 Word；演示按固定时间推进，实际产品必须使用服务端进度事件。
3. 在“待补充”状态选择“补充示例材料并继续”，或将这个非关键授信缺口暂列待补后继续。关键材料或事实冲突不能通过“暂列待补”绕过交付检查。
4. 在“已完成”查看摘要和修订版、清洁版、更新说明的下载入口；右侧发送修改要求后，点击“继续修改”，观察 v2 的过程。示例版本号不代表后台已生成成果。
5. 运行中点击“停止更新”，再点击“继续更新”，体验同页保留上下文。正式取消、恢复和补新材料的运行语义须遵循下方规范。

## 实现时的约束

- 用户不需要跳到“全部项目”等待或查找成果。项目列表是主动离开后的返回入口，返回后恢复同一项目的运行进度、会话和最新成功成果。
- 进度显示业务阶段及可靠计数；尚无分母时只显示当前阶段。生成 Word 和检查可下载性也属于未完成阶段，不用假百分比或前端定时器冒充真实进度。
- 当前运行输入不可变。普通补充进入下一版草稿；同范围澄清可以继续原 run。新增材料或改变目标需新 input revision 和新执行，界面仍留在同一个项目。旧失败成本不转嫁，已完成的可靠解析可复用。
- “停止”映射明确取消时，终态任务不能作为暂停任务重新打开；用户后续明确执行创建新的关联运行。基础设施暂停和断线恢复按既有契约处理。演示中的界面状态不是公开 API 枚举。
- 成果经检查可获取后才显示完成。新版失败不得隐藏或覆盖旧成功成果；历史稿交付真实修订版和清洁版，无历史稿交付独立初稿。后台参考库和匹配过程不显示给用户。
- 示例对话只做本地收录，真实意图路由遵循第 13 章：用户明确发出执行指令时可以直接启动对应任务，不能一律要求再点击按钮。
- M1 平台试用记录真实 prompt/job/token/错误，M2 再接账务；前端不能因演示存在而宣称真实日志、收费、恢复或生成已经验收。

## 修改与校验

可编辑源为 [update-workspace.fragment.html](update-workspace.fragment.html)，独立页面为 [public/previews/update-workspace.html](../public/previews/update-workspace.html)。独立页面保留导出时的隔离容器和必要运行支持；更新源后，在 `product-prototype` 运行：

```sh
node scripts/build-update-workspace-preview.mjs
node scripts/build-update-workspace-preview.mjs --check
```

脚本使用 Node.js 内置库，将源片段同步到已提交独立页面的明确标记区域；不依赖原作者的本机目录或 Codex 插件。不要手动修改独立页面中的片段副本。
