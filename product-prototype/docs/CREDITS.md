# BondBuddy 1.9 积分钱包

实现版本：2026-09-22-v1.1。默认地址仍为 http://127.0.0.1:4320。

本版替换新售月度套餐：注册 / 迁移体验赠2,000积分，四档演示充值50 / 500 / 2,000 / 10,000元，分别到账5,000 / 52,500 / 220,000 / 1,150,000积分。注册绑定邀请、有效消费激活、付费14天观察期、北京时间每日活跃次日奖励均记入同一钱包。服务每分钟处理到期奖励，也会在钱包操作前补处理。

更新、复核在材料页点击开始，一次请求完成材料预检、内部计价、原子冻结和排队。没有报价页或第二次费用确认。问答与材料生成同样校验余额；赠分和购入积分可用于同一任务。余额不足不启动；充值后用户再次点击。问答中的明确文书编制指令路由至对应材料生成能力，必要资料缺失时提示补充，不冒充已执行任务。

## 计量与结算

- `lib/credit-rules.json` 保存完整方案参数及14×14迁移矩阵。`credit-pricing.mjs` 实现更新、复核、生成、问答与首次模型解析系数，区分实际新增报告期与附件中的重复年份。
- 本机当前解析DOCX / PDF / Excel使用本地程序，无模型成本，解析不额外收费。扫描OCR尚未开放；定价表列出格式不等于该格式已经可处理。
- 模型适配网关记录供应商请求ID及输入、缓存、输出token，作为唯一计费来源。CLI聚合usage只作显示后备，不与网关数据重复累计。缓存检查点复用、失败请求和被替换的重试不再次收费。纯澄清、拒答、空回复不收任务积分。
- 参考模型计量单价为每百万token输入10元、缓存1元、输出30元，明确标记为演示参考价。可在服务端 `runtime/settings.json` 中配置 `modelPrices: {"deepseek-chat":{"input":...,"cached":...,"output":...}}` 及 `modelPriceVersion`，钱包显示当前单价。上线真实收费前须按实际合同校准，不能将参考价宣传为供应商实价。
- 外部服务采购价由服务端 `externalPrices` 配置，键为 `web`、`registry` 或连接ID，单位为人民币/成功调用。没有价格配置的采购成本由平台承担，不猜测扣分。已计费的外部事件统一乘1.2，无单独用户付款步骤。
- 启动冻结 B = ceil(预计积分 × 1.2或1.5)。此预留因子不进入实际收费；最终 P = min(真实计量向上取整积分, B)，释放B−P，平台承担超额。算法估算仍需真实运行数据校准。
- 失败或取消释放全部冻结。用量无法验证时保持 `pending_metering` 待核对，不将估算直接扣成实耗。账单、批次、冻结、释放、消费和退款均记录不可覆盖的事件。
- 本机为单服务进程，通过队列串行修改账本及原子文件替换避免并发超扣；不支持多服务实例同时写同一JSON账本。多实例部署须迁移数据库事务及共享锁。

## 旧账户与价格条款

首次迁移先生成 `runtime/billing.json.pre-credits-backup.json`，保留原订单、订阅和旧已启动任务。旧有效权益按原单位及期限保留，适用的新任务优先使用剩余旧权益，用尽再走积分；旧点数没有1:1转换。旧待付套餐停止收款。充值积分整批按实际订单成本处理，按未用、未冻结余额比例演示退款。旧套餐退款不由本版积分退款接口擅自换算。

注册页、钱包和独立的 `/credit-terms.html` 提供价格条款，`/credit-rule-details.html` 提供完整系数表。任务前不要求逐项确认。当前手机号验证、充值、退款均为演示；没有接入真实短信、微信、支付宝或商业支付退款接口。支付模式为非sandbox时，新建支付和演示付款均关闭。
