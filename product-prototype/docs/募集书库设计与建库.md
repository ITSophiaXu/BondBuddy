# BondBuddy 募集书库：体验与建库设计

实现日期：2026-09-21。本版提供可运行的浏览、检索、人工收录、批量公共入库和项目蓝图选用。尚未接通三个官方平台的自动采集，也未预置未经核实的募集书。首次进入时，收录数量为零是正常状态。

## 用户从哪里进入

1. 左侧“工作空间 → 募集书库”：独立浏览和检索，默认未关联项目；不会暗中套用已保存草稿的条件。可明确选择当前待创建草稿作为推荐项目，不需要先购买套餐；需登录。
2. “更新募集书 → 没有历史稿，参考相似企业起草 → 上传材料 → 从募集书库选择”：带着当前项目条件进入推荐视图，顶部明确显示项目名称、发行人、市场、发行方式、最新报告期及“待创建 · 尚未提交”状态。
3. 库内查看募集书详情，点击“用作蓝图”，核对参考发行人与本次发行人，再返回项目。这里只选择材料，不立即发起付费编制任务。

```mermaid
flowchart LR
  A[本发行人是否有历史稿] -->|有| B[上传本企业 DOCX]
  A -->|没有| C[上传同业 DOCX / PDF 或打开募集书库]
  C --> D[浏览 / 匹配推荐]
  D --> E[核对来源、版本与适用性]
  E --> F[选用蓝图，返回项目]
  B --> G[添加本项目材料]
  F --> G
  G --> H[检查项目信息与材料]
  H --> I[生成修订稿或新编初稿]
```

推荐项目指创建募集书页面中尚未提交的草稿，不是“全部项目”中最近使用的任务。当前只有一份正在创建的募集书草稿；不支持从已提交项目中选择并原地更改底稿。项目名称、发行人或发行范围等身份条件变化后，需要重新关联；从侧栏重新进入或刷新页面也需明确选择。

项目名称、发行人全称、交易所、发行方式、最新报告期仍是五项必填信息。另增加行业、所在省市、企业性质、总资产规模四项选填匹配条件；其余已实现的33项仍为选填。匹配条件可以在库页修改，并保存到当前项目。选择参考企业不会覆盖本次发行人、发行金额、报告期或本项目材料。

## 库页如何组织

| 区域 | 内容及行为 |
|---|---|
| 收录概览 | 实际索引数、可用公司债蓝图数、发行企业数、公共收录数；不展示虚构规模 |
| 项目匹配 | 展示本项目市场与发行方式，展开后选填行业、地区、性质、资产规模 |
| 两种视图 | 全部募集书；为本项目推荐。推荐视图只列适用且有可解析正文的条目 |
| 检索 | 发行人、标题和已提取正文关键词；正文命中展示页码/段落定位与片段 |
| 常用分类 | 交易所/市场、债券类型、发行方式、发行企业 |
| 更多分类 | 行业、地区、企业性质、官方项目状态、公共/个人范围、蓝图可用性 |
| 结果卡片 | 名称、发行企业、分类、状态、版本、披露日期、核对人类别、正文情况；点击企业筛出该企业全部条目 |
| 详情 | 官方项目页与文件链接、版本与核对日期、原始文件浏览/下载、提取章节线索、解析缺口、与项目的匹配情况 |
| 官方来源 | 三个平台直达链接及本库相应收录数，明确本库不代表官方网站的全部项目 |
| 添加入口 | 添加官方募集书至个人索引；可先登记索引，再补充正文或新版本 |

结果每页12条。按披露时间排序，也支持按匹配排序。当前“地区”使用录入值精确匹配，例如“江苏”和“江苏省”不会被自动当作同一地点；维护公共库时应统一省级名称。企业名称采用法定全称；当前未实现统一信用代码实体归并。

## 推荐如何产生

首先检查能否用作蓝图：

- 人工确认已核对官方来源，登记官方文件链接、文件版本和披露日期。
- 项目状态为“审核通过”“注册生效”或“已发行”，并有能提取文字的 PDF / DOCX 正文。
- 当前支持交易所公司债，且与项目的交易所、发行方式一致。
- 条目没有被显式登记的新版本替代。无正文、扫描件、待核对、终止/撤回、已替代版本均可浏览，不进入蓝图推荐。

适用条目再按以下分值排序：交易所25、发行方式20、行业25、企业性质10、地区5、总资产规模5；近两年披露加10分，二至四年加5分。未知字段不加分，相同分数按披露日期和收录时间排序。页面解释真实匹配条件、差异和信息缺口，不把排序分数包装成合规评分或发行成功概率。

银行间 MTN、CP、SCP、PPN，以及其他债券类型可以建索引、分类、查正文和下载；当前不套用交易所公司债规则自动编制。历史项目通过不等于文件已定稿，更不代表其披露安排适用于本次项目。

## 两类收录范围

**公共库**由维护人员取得并核对官方公开文件后，通过批量入库工具发布。本机应用所有登录账号可见；客户页面不能伪造公共发布权限。

**个人索引**由用户在库页明确添加，只有当前账号可检索和下载。普通项目上传文件不会自动入库，更不会共享。个人勾选来源核对后显示“个人已核对官方来源”；公共条目显示“维护人员已核对官方来源”。这些是人工核对记录，不表示系统实时访问了官方平台。

索引和正文分别管理：未上传文件也能保存官方线索；扫描件或损坏文件收录后如实显示无法提取文字；未核对的条目不能被推荐。Word 内复杂对象、PDF 图片等解析警告保留在详情和编制说明中。

## 现在如何创建库

个人路径：打开官方平台，取得项目页面、募集说明书文件和相关披露信息；在“添加官方募集书”中登记分类、状态、版本与链接，上传正文；核对后勾选来源确认，保存。只保存索引时可稍后从详情“补充正文 / 收录新版本”。

公共路径：维护人员整理 JSON 数组或 JSONL 清单，用本地命令批量收录，每批最多500项。文件路径相对清单所在目录解析，不会通过网址自动下载文件。只有明确标记 `reviewed: true` 并使用 `--publish` 的条目才会发布。建议先在单独的测试运行目录中检查导入结果。

```text
node scripts/import-library.mjs <核对后的清单.json> --publish
```

清单字段：

| 字段 | 必填 / 含义 |
|---|---|
| title、issuer | 募集书名称与法定发行人全称 |
| market | sse / szse / nafmii |
| instrument | 公司债券、企业债券、中期票据（MTN）、短期融资券（CP）、超短期融资券（SCP）、定向债务融资工具（PPN）、资产支持证券 / 票据、其他 |
| offering | public / private / unknown；NAFMII 请据实际发行方式登记 |
| projectStatus | 未知 / 待核实、审核通过、注册生效、已发行、受理 / 审核中、终止 / 撤回 |
| sourceUrl | 官方项目详情页，尽量避免只登记平台首页 |
| documentUrl、publishedAt、version | 公共发布或确认来源时必填；官方文件链接、YYYY-MM-DD 披露日期、申报稿/注册稿/发行稿等实际版本 |
| sourceProjectId | 选填，官方项目编号 |
| industry、region、ownership、assetBand | 选填分类；行业/性质/规模使用页面提供的枚举值 |
| filePath | 选填，已取得的原始 PDF 或 DOCX；未提供则只建索引 |
| reviewed | 公共发布必填 true，由维护人员逐项核对后设置 |
| supersedes | 更新同一范围、发行人、市场下旧条目时，填原条目 ID；保留旧文件，停止推荐旧记录 |
| notes | 选填，记录口径和待补事项；最多1500字 |

文件上限40 MB。正文提取后保存定位、章节线索、解析警告和 SHA-256。相同范围、内容和元数据重复导入会去重；版本、文件或状态改变会产生新记录。更新旧记录时应填写 `supersedes`，不能仅导入一条无关联的新记录后假定旧版已自动失效。个人详情的补充入口会自动建立这个替代关系。

清单文件不是待执行指令；文档内容不会作为程序或系统提示执行。所有网址限制为对应平台配置的官方域名，本版没有任意网址抓取接口；域名限制用于链接安全，不替代来源内容核验。

## 自动扩库的后续接入方式

推荐建设“官方项目发现 → 附件识别 → 原件保存 → 分类抽取 → 人工核对 → 入库 → 版本跟踪”的流水线。三个平台应使用各自的适配器：独立记录原始项目状态、官方项目编号、募集书附件链接、披露日期、发行人和状态采集时间，再映射到库内分类。不能根据文件名猜测审核通过，也不能把三个平台的不同状态文字直接等同。

自动取得的候选必须先处于待核对区；自动分类与企业规模数据应带出处和置信信息，缺失保留未知。通过核对后使用本版同一入库模块发布。后续应增加请求限速、失败重试、增量游标、来源变更告警、内容变更检测、失效记录撤回、人工核对工作台及任务监控。大规模全文库再迁移至数据库和独立全文检索服务。

本版尚未实现上述在线适配器、调度器、OCR、语义向量检索、自动主体识别或工商补全。当前无法访问三个平台核实接口及下载规则，不能承诺自动覆盖数量或更新频率。线上发布前还应对来源访问条件、公共文件提供方式及运营审核流程作实际确认。

## 选用后如何隔离蓝图与事实

开始编制时，服务器重新检查账号权限、项目适用范围、版本是否被替代及文件哈希；通过后将文件复制到该项目的材料目录。项目保存蓝图ID、参考发行人、官方链接、版本、披露日期、人工核对时间与文件哈希。后续资料库变化不改写任务已有文件。

参考募集书用作结构检索，不能成为本项目事实引文。蓝图来源元数据也不进入“用户填写的项目信息”事实证据。来源快照写入编制说明，正文根据本项目材料起草；缺依据的内容留作待补。

## 本版验证范围

隔离测试覆盖元数据和网址校验、文字 PDF 检索、正文缺失与扫描件处理、版本替代、公共/个人权限、批量入库、排序解释、蓝图哈希校验、HTTP提交与文件快照、账号隔离、前端跳转及本项目信息保留，并以模拟模型检查来源不进入本项目事实、实际导出Word。

未进行官方站点自动采集验收、真实浏览器视觉验收及真实发债项目起草质量验收。测试中的募集书仅位于独立测试目录，不作为正式库数据。
