# M3 复核工作区交互设计

复核页预览：`http://127.0.0.1:4320/review-v2.html`。工作台预览：`http://127.0.0.1:4320/dashboard-v2.html`。原复核页保留在 `/#review`，可从新页面底部直接对照。

## 设计目标

复核页用于查看问题并处理，标准流程通过页面按钮完成。项目助手承接按钮无法表达的业务口径、补充背景、异议理由和跨问题要求；用户可以在同一项目中继续讨论，不必搬到独立问答页重新说明背景。

复核页仅保留“材料与要求”和“复核结果”两个标签。版本记录留在工作台，复核页显示当前输入与报告编号。2026-10-04 当前决定：宽度大于 900px 时，项目助手始终显示在右侧，与左侧复核内容并排，去掉重复的“项目助手”开关；宽度小于或等于 900px 时使用可开合抽屉。切换标签、开合窄屏助手和刷新都保留草稿及其问题、报告引用。

右侧使用同一条时间线呈现真实提交的用户消息、明确标识的合成助手回复、待确认范围提议和持久化任务卡。任务卡直接位于对话中，不另设任务面板。左侧快捷操作与对话入口使用相同的任务路径；点击按钮不会伪造一条用户消息，也不会把原始 CLI 日志或内部推理塞入对话。

2026-10-04 #547 补充：按[当前动作与助手执行摘要](../../docs/product-decisions/2026-10-04-review-agent-progress.md)在左侧两个标签上方持续显示紧凑当前动作；右侧同一任务记录突出当前真实动作和简短执行摘要，已完成动作默认折叠。轮询保留用户展开/阅读位置。运行反馈和助手消息不显示时间戳、心跳、耗时、预计时间或百分比。原型活动仅为 synthetic UX 演示，真实实现必须来自已校验的宿主/工具事件，不按客户端计时轮播动作。

## 已实现的交互

- **复核前**：材料与要求集中显示；可通过快捷按钮或对话提出执行意图，也可以先补充关注点和修订要求。完整复核确认展示完整输入与三项检查维度，明确开始后才创建任务；它不借用某份旧报告作为差异执行基线。
- **复核中**：左侧显示运行状态与已锁定的输入版本，右侧同一时间线内显示对应任务卡；新说明和附件进入下一版；同一项目不同时启动两个演示任务。仍可回看已有报告。
- **复核后**：每项发现提供原文、依据、解释、补证、异议与修订入口。“查看解释”使用弹窗，不生成聊天消息；“继续讨论此项”将问题及报告引用带入常驻助手，窄屏同时打开抽屉。
- **按问题补充**：F-002 提供“说明口径”，其他待补证问题提供“补充材料”。补充说明和异议带入问题引用；要求记录包含 `reference` 和 `report`。发送异议理由后才记录异议，原结论仍保留。
- **标准动作反馈**：加入修订等局部操作使用页面状态和 toast 提示。快捷执行入口与对话执行入口都在同一时间线创建类型明确的范围提议或任务卡，不追加假聊天或逐次点击日志。补证后显示确认弹窗，明确下一步重新核验的对象与范围。
- **修订计划**：可以勾选或取消有依据的修改；空计划不能执行；待确认事项保持待补。
- **差异复核**：说明或异议先保存为要求，再形成可编辑的范围提议。提议显示来源报告、当前输入、真实用户消息引用或快捷操作来源及所选问题；确认后才创建任务。后续切换聊天引用不会改变已经确认的执行基线；结果区区分本轮新核验结果与未重新核验的沿用记录，沿用记录不算本轮重新通过。
- **任务与结果互相定位**：任务卡显示状态、输入、执行来源、来源报告与选定范围，可定位到左侧对应运行状态或结果；左侧结果可定位回同一任务卡。停止或完成更新原任务卡，不新增重复任务。回看历史报告时，新任务完成保留当前查看对象，由用户明确切换查看新结果。
- **工作台版本记录**：集中查看复核、修订及已停止任务，保留输入、材料名称、要求、范围和任务状态的快照。已停止任务占用的输入版本不会被后续说明复用。
- **持续协作**：消息、要求、问题及报告引用、输入草稿、材料信息、范围提议、任务状态和时间线保存在当前浏览器，刷新可恢复真实消息与任务的关联。此次界面调整继续读取既有演示记录，不要求清空用户已有操作。

## 项目助手的使用场景

助手用于表达额外信息。筛选问题、查看解释、补充文件、加入修订、核对计划、执行和下载等常规动作不要求对话。

下表区分期望的 M3 行为与当前交互演示。当前原型可以记录说明和问题引用，按确定规则匹配演示输入并展示合成回复、范围提议；它没有通过模型理解自由输入。匹配到执行意图也只进入范围确认，不能自动执行或真实生成修订成果。

| 场景 | 用户输入示例 | M3 预期动作与边界 |
| --- | --- | --- |
| 说明业务口径 | “F-002 这段要求用母公司口径，集团偿债能力一节才用合并口径。” | 将说明关联到具体章节与问题，提议重新核验的范围并允许调整；不默认统一全稿口径，不直接认定原结论错误，明确确认才执行。 |
| 对结论提出异议 | “F-004 提到的旧名称属于 2023 年的历史沿革，不能全部替换成现名。” | 保存异议理由与真实消息引用，关联 F-004，保留原发现并提议待重核范围；异议本身不能使问题变为已通过。 |
| 解释补充材料 | “新上传的名称变更证明自 2025 年 8 月生效，请按这个日期区分前后表述。” | 将日期说明、文件和问题关联，列出待核验事项；上传与说明不会自动启动复核。 |
| 跨问题附加限制 | “F-001 的债务金额和摘要引用一起改；F-005 先不处理，保留模板样式。” | 提议包含 F-001 及关联引用、排除 F-005 的计划，并展示可核对的范围；只有确认执行才开始任务。原型目前仅记录这类要求，计划仍由勾选操作调整。 |
| 执行中补充情况 | “刚收到新版审计附注，当前任务先继续，这份用于下一轮。” | 将新材料和说明保存为下一轮输入并显示生效任务；当前任务的输入快照不变。 |

典型路径是“用户说明 F-002 的口径 → 保存说明与原报告引用 → 时间线出现待确认范围提议 → 调整并确认范围 → 同一时间线记录差异复核任务 → 左侧显示进行中状态 → 查看本轮新结果及未重核的沿用项”。补充说明、提出异议、确认执行是不同动作，不用说明记录替代复核判断。

## M3 交互规则

1. 常规复核处理流程可以完全不经过对话，助手不得成为查看依据、修订或下载的必经步骤。
2. 自然语言说明先作为要求或待核对的提议。不得因识别到“修订”“重新核验”等词语就悄悄启动任务、增减范围或改变既有结论。执行前显示任务类型、范围、输入版本及执行来源，由用户明确执行；差异复核同时锁定来源报告。完整复核锁定完整输入，不设置差异来源报告。本次 M3 不包含报价或收费流程。
3. 问题级说明保存问题编号和来源报告；项目级与跨问题要求明确标注适用范围。切换卡片不得偷偷改写尚未发送草稿的上下文。
4. 草稿与绑定的上下文一起保存；开合窄屏助手或刷新后可以继续。对话引用的报告用于说明讨论对象，执行基线由确认的任务类型和范围决定，不能因后续切换对话引用而改写。完成的任务保留不可变快照，后续说明进入下一版。
5. 用户消息、合成助手回复、范围提议和任务卡具有不同类型，统一保存在助手时间线。标准按钮反馈放在相应页面，其执行任务使用相同任务卡；不能伪造用户输入、用聊天日志代替任务状态，或展示隐藏推理与原始 CLI 日志。
6. 任务卡和左侧结果通过同一任务标识互相定位；显示运行中、新结果与沿用项的差别。历史报告是查看对象，新任务完成不强制替换它，也不能把新结果标识贴到旧报告上。

## 预览边界

这是独立交互原型：发行人、文件、发现、任务与助手回复均为合成示例。自由输入仅匹配确定的演示规则，任务进度通过演示按钮手工完成。没有后台或模型/API 调用、真实文件上传或解析、联网核验、Word 生成和扣费。选择本地文件只记录文件名及大小；示例下载是明确标识的 TXT 记录。它用于评审 UX，不代表后端功能或模型接入已经实现，也不提供真实业务验收结论。

源文件：`public/review-v2.html`、`public/review-v2.css`、`public/review-v2.js`、`public/review-demo-data.js` 及 `public/dashboard-v2.html`、`public/dashboard-v2.css`、`public/dashboard-v2.js`。两个新页面读取同一套演示项目记录，继续使用 `bondbuddy:m3-review-design:chuan-tech:v2` 与 `schema: 2`，与原页面数据分开。读取旧记录时补充消息标识和类型明确的时间线，保留已有材料、要求、草稿、消息与任务快照；不更换存储键、不清空记录。新范围提议与任务保存真实消息标识，刷新后恢复对应引用。

## 验证记录与本次验收重点

以下为 2026-10-02 版本的历史验证，描述当时按需开合助手的设计，不代表 2026-10-04 调整已通过：要求发送与刷新恢复、运行中的新增要求进入下一版、任务停止后版本递增、修订选项增减及空计划阻止、差异复核范围、旧补证动作的目标绑定、历史快照，以及桌面和窄屏操作。

此前检查尺寸为 1360 × 900、1154 × 800 及实际窄面板，JavaScript 语法检查通过，浏览器未记录脚本错误。上述结果不替代此次导航及助手交互调整的复验。

2026-10-04 本次原型验收要求：

- 大于 900px 的桌面助手始终可见且没有重复开关；小于或等于 900px 的抽屉可开合，键盘焦点及草稿正确保留。
- 快捷操作与真实对话使用同一时间线的提议和任务卡；普通解释和局部按钮操作不产生假用户消息、原始 CLI 日志或推理内容。
- F-002 口径说明、F-004 异议或补证先记录要求，再提议可编辑范围；只有明确确认才创建任务；空范围与并行任务不能执行。
- 任务卡包含输入、状态、执行来源、真实消息引用及差异来源报告和范围；左右定位指向同一任务与结果；停止及完成更新同一张卡。
- 完整复核使用锁定的完整输入且不带差异来源报告；对话所引用的旧报告不能覆盖任务执行基线。
- 左侧区分进行中、新核验结果与未重核的沿用项；查看历史报告时新任务完成不强制换页或给旧报告贴新结果标识。
- 使用原存储键与 schema 保留当前浏览器记录，刷新恢复真实消息引用、提议与任务关联；工作台仍能读取既有版本快照，收费入口均已移除。
