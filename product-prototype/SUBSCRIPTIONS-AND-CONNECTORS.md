# 订阅与外部数据连接

## 手机号注册 / 登录（演示）

首次进入展示手机号注册 / 登录页：填写 11 位中国大陆手机号，点击获取验证码，页面显示 6 位演示验证码；输入后新号码自动注册，已有号码直接登录。不发送短信，不要求姓名、邮箱或证件。

验证码有效 5 分钟，60 秒后可重发，最多尝试 5 次；成功后不可重用。会话通过 HttpOnly、SameSite=Strict Cookie 保存 30 天，退出登录立即撤销。演示验证码公开显示，因此不能证明手机号实际归属，也不能当作生产短信认证。

用户与会话数据在 `runtime/accounts.json`，只向页面返回脱敏手机号。首个手机号接管原本机 primary 工作空间，保留已有项目、订阅和额度。之后注册的手机号创建独立账号。项目、下载、订单、付款和额度以服务端会话身份为准；旧的席位请求头或下载 URL 参数不能切换账号。不同账号的表单草稿分别保存。

## 订阅与付款流程

“选择套餐 / 加购 → 确认演示支付 → 额度到账”已经贯通，不设姓名、邮箱、席位表单或额外勾选步骤。页面统一为“套餐与用量”：未订阅时先展示月度套餐，已订阅时先展示剩余用量与“¥299 / 4 点”加购。余额、套餐卡片和付款页均显示可完成的更新或复核次数；两种任务共用点数，不是两份独立额度。套餐按钮直接打开付款确认页，一个主按钮完成演示支付。订单记录默认折叠，待支付订单 30 分钟到期，可取消或继续支付。

| 套餐 | 每账号每月 | 问答 | 对话中上传文件 | 募集书额度 | 外部数据查询 |
|---|---:|---:|---:|---:|---|
| 个人版 | ¥499 | 1,000 次 | 40 份 | 4 点 | 不包含 |
| 专业版 | ¥999 | 2,000 次 | 80 份 | 12 点 | 企查查 / 工商、企业预警通、Wind 等 |

- 全文更新 4 点 / 次，独立 AI 复核 1 点 / 次。例如专业版可以做 2 次更新和 4 次复核。
- 加购 ¥299 / 4 点，可以增加1次更新或4次复核，也可组合使用。只增加当前账号的任务点数，不增加问答次数或对话附件份数，不延长套餐有效期，与其订阅周期同期到期。问答/附件不足时不会再提示用户通过加购点数解决。
- 单账号一个月，按首次付款日开始；月末日期夹到下月最后一天。到期手动续费，开启新周期，额度不结转，不自动扣款。
- 个人版升级专业版：按当前周期剩余时间补 ¥500 差价，精确到分向上取整。到期日不变，保留已用额度和加购点数。价格在服务器计算并锁定在订单内。
- 页面使用“在对话中上传文件”：对话每新增上传一个文件计一份，引用原有项目/对话材料不重复计量。募集书更新和复核附件包含在任务点数中。
- 个人版依据用户项目与材料回答；专业版增加平台提供的外部数据查询。删除没有对应产品功能的音频转写和商业 OCR 说明。套餐、升级确认与用量页均明确列出数据权益。
- 提交任务预占，成功扣除，失败 / 停止 / 待连接返还；继续任务重新检查额度，成功结果不会重复结算。重启按已落盘的任务状态恢复预占，不重复收费。
- 根据最新产品要求，不再使用实名席位、填写成员信息或切换席位的付款流程。每份新订单只作用于当前账号；保留旧版历史数据，不再收集姓名或邮箱。

### 当前支付边界

默认 `BILLING_MODE=sandbox`，付款页全程标识演示，**不收款、不输入支付凭据、不生成真实发票**。订单状态由独立 `sandbox-pay` 接口模拟。设置为 `disabled` 可阻止创建支付订单。没有可通过切换配置启用的生产付款接口。

正式收款仍需要支付商户接入、受验证的异步回调、支付订单对账、退款及可靠的账号登录；客户付款页无需实名资料表单。不能把当前的演示支付接口开放为生产收款接口。尚未调用任何真实支付服务。

本机数据：`runtime/billing.json`，单进程串行事务 + 原子写文件。不要让多个服务实例共用同一运行目录。金额单位为人民币分，禁止信任客户端金额。每份订单使用幂等键，重复提交和重复模拟支付不会叠加权益。成功任务的幂等结算以任务 UUID 为键。

## Wind、企业预警通及其他 MCP

客户不配置任何服务。模型和企查查 / 工商、Wind、企业预警通及其他 MCP 由平台统一接入。部署人员在服务端配置真实授权服务，或使用设置了 `BOND_BUDDY_ADMIN_TOKEN` 的管理 API（登录会话及 `X-BondBuddy-Admin` 管理请求头均必需）。管理令牌不写入前端，未设置时管理 API 默认关闭。普通账号无法读写配置或发现工具，专业版只能获取服务名称与用途，不返回地址、参数或凭证。

服务端根据当前有效套餐校验外部查询权限。个人版更新 / 复核继续处理用户材料，明确外部未核验；直接询问外部数据时先提示升级，不创建任务或占用额度。伪造 `web`、`registry`、`connectorIds` 或 `plan` 不能提升权限。专业版自动匹配已启用服务；升级后刷新服务目录，重试任务重新检查套餐。明确只依据材料时不会调用外部服务。

支持 **MCP Streamable HTTP** 的初始化、会话标识、JSON / SSE 响应、分页 `tools/list` 和 `tools/call`。服务 URL 必须是 HTTPS，或者本机回环 HTTP。仅调用服务声明为只读，或配置人明确确认为只读的工具；明确声明具有破坏性的工具始终拒绝。本机 stdio MCP 需另接 HTTP 网关。

应用没有内置或冒称 Wind / 企业预警通官方 endpoint，也没有商业数据账户。平台必须提供已获得商用授权的服务；这是部署前置条件，不交由客户配置。问答、更新、复核均支持把所选查询结果与材料共同传入 Codex；应用执行 MCP 查询，Codex 分析带来源的结果，不直接获得服务凭据。

参数模板按照实际工具 `inputSchema` 填写，可用 `{{query}}`、`{{issuer}}`、`{{cursor}}`。下例适用于遵循本应用数据契约的债券查询适配器，不代表供应商官方参数：

```json
{
  "query": "{{query}}",
  "issuer": "{{issuer}}",
  "includeMatured": true,
  "includeOutstanding": true,
  "cursor": "{{cursor}}"
}
```

工具结果应在 MCP `structuredContent` 或 JSON 文本 content 中返回以下形状。普通查询可以使用 `results` 或 `items` 数组；非 JSON 文本也会保留为来源，但不能确认债券全量覆盖。

```json
{
  "issuer": {"name": "发行人准确全称"},
  "scope": {"includeMatured": true, "includeOutstanding": true},
  "bonds": [{
    "bondCode": "实际债券代码",
    "bondName": "实际债券名称",
    "market": "上交所",
    "issueDate": "实际发行日期",
    "issueAmount": "带单位的发行金额",
    "balance": "带单位的余额",
    "maturityDate": "实际到期日",
    "status": "已到期 / 存续 / 提前兑付 / 展期 / 违约等实际状态",
    "payments": "有来源的历次兑本兑息记录",
    "creditEvents": "有来源的违约或展期情况，未知不可写无",
    "url": "https://可用的来源页"
  }],
  "total": 1,
  "nextCursor": null,
  "complete": true
}
```

后续页面带 `nextCursor`，每页均应确认主体和口径，最后一页显式 `complete:true`。应用核对累计条数与 total、精确主体和已到期 / 未到期全口径，最多 50 页、10,000 条、累计 12 MB；异常或超限均标为未完成，不将部分存续券当作全部历史发行。若工具结构不同，需要在授权适配服务转换为该契约，或使用 JSON 路径映射（如后续版本提供）。

查询条件应覆盖发行人发行过的全部公司债，包括已到期、未到期、回售、提前兑付、展期、违约及兑息兑本记录，不以当前存续筛选替代全历史。空结果不证明从未发债或无违约。Wind / 企业预警通的不同结果保留来源分别展示，由项目组判断冲突。

每次任务保存外部结果快照。更新和复核将它们作为可逐字验证的证据；对话按相关性选取摘录并注明覆盖缺口。获取全量记录不代表模型已逐条审核所有记录。结果提供 `外部查询记录.csv` 与 `查询覆盖说明.md`，包括原始字段、查询时间和完整性状态；无公开 URL 的授权数据保留服务 / 工具来源。重试复用快照，查询时点不会伪装为重试时的新查询。

全部 API 仅面向当前本机工作空间。除演示注册 / 登录接口与服务状态外，业务接口需要服务端会话；设置与数据连接是平台共享配置，由独立管理令牌保护；当前单机文件存储不适合直接开放成多租户服务。正式部署需要真实短信服务和生产账号系统。
