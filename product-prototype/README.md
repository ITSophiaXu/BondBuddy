## 启动

双击工作区根目录或本目录的 `Start-BondBuddy.cmd`，访问 **http://127.0.0.1:4320**。也可在本目录运行 `node server.mjs`。需要 Node.js 22+、Codex CLI、Python 及 `python-docx >= 1.2`、`openpyxl`、`pypdf`；本机已能自动发现 Codex 和捆绑 Python。

服务由平台预先配置，客户不填写 API Key、MCP 地址或凭证。部署人员在 `.env` 或 `runtime/settings.json` 配置模型与授权数据服务，前端不提供设置页面。管理 API 默认关闭；如需使用，平台设置 `BOND_BUDDY_ADMIN_TOKEN`，仅凭独立管理请求头 `X-BondBuddy-Admin` 访问。普通登录账号不能读写服务配置或发现工具；前端只读取当前套餐允许的数据服务名称和用途。凭证始终留在服务端。

首先用手机号和页面显示的演示验证码注册 / 登录，不发送短信。可以先免费创建项目、提供材料和评估点数；确认开始前需有有效套餐和足够点数。订阅时从顶部“开通套餐”选择套餐，点击“确认演示支付”。无需姓名、邮箱或实名席位。未订阅时优先展示套餐；已订阅后，顶部统一展示剩余点数、可用次数、套餐与用量入口及加购按钮；首页正文不再重复展示用量横条，侧栏不再重复展示套餐摘要。套餐详情页仍可加购。更新和复核共用点数，具体消耗由本次工作量评估确定，不再用固定点数换算次数。有效订阅下，没有模型密钥时仍可保存材料，任务显示“服务暂不可用”，额度返还；平台恢复服务后可继续。

## 工作流程

### 首页

首页保留一个直接对话区，可以输入问题、附材料、关联项目，发送后进入连续对话。首页移除“新建项目”按钮和最近项目空状态的重复创建按钮；保留具体任务入口。首页提供 6 个建议问题；对话开始页按材料起草、财务分析、项目查询提供 12 个建议。输入框在前，带明确标签、独立边框与聚焦状态；建议紧接输入框下方，以三列分类卡片排列，点击填入后可以修改再发送。窄屏改为纵向分类、双列按钮。底部保留添加材料、问答余量和发送；回答依据的常驻提示已删除，仅在需升级或查询不可用时显示提示。开始页按内容确定高度，不再强制撑满整屏；进入对话后保留滚动消息与底部输入框，只有一个新对话按钮，小屏也可访问历史。不再弹出数据源选择器；系统按任务需要使用已配置的服务，没有服务时仍可处理材料，并列明外部核验缺口。客户无需设置数据连接，外部数据查询由专业版提供。展示真实完成的募集书更新、复核和对话数量，最近项目、状态及成果下载入口。没有注入虚构项目或模拟业务成果。侧栏“对话与材料”直接进入对话；客户页面不展示知识库。侧栏导航在短屏滚动，底部工作空间保持完整可见。

### 更新募集书

1. 页面采用「编制方式与项目 → 上传材料 → 检查并开始」。首先主动选择「更新本企业历史募集书」或「参考相似企业募集书起草」，新项目不默认选择。本企业其他期次的原稿属于第一种。
2. 项目信息只有项目名称、发行人全称、交易所、发行方式、最新报告期五项必填。其余37项信息分七组折叠选填：蓝图匹配信息（行业、地区、企业性质、资产规模）、发行人补充资料、发行规模与债券品种、参与机构、评级与增信、资金用途、特殊事项与编制要求。区分本次申报总额和本期金额、两个债券品种及各自含权/专项属性。不默认把空白的评级、增信、城投、重组、保护条款等回答解释为“否”。不适用的隐藏从属信息不会随提交带入任务事实。
3. 报告期保留年份和“3月末、6月末、9月末、年末”。默认上一个已结束季度；即时展示私募两年一期、公募三年一期的完整窗口，年末不重复列一期。交易所仍为已配置规则的上交所、深交所，未把截图中的北交所作为已支持范围开放。
4. 本企业历史募集书 DOCX 与本项目材料分区上传；相似企业蓝图可上传 DOCX / 文字版 PDF，或从募集书库选用。30类支持材料按财务审计、发行与用途、工商信用评级、债务授信担保、经营治理行业分组；增加一期报表、科目明细、发行方案、使用计划、可研、前次资金使用、受托管理、决议、银行授信、存续债券、担保人、治理人员和行业资料等。每份支持材料可调整类型；一份审计报告含报表和附注时无需重复上传。文件开始任务时才上传，未承诺本地文件刷新后保留。
5. 切换方式保留本项目材料，两个主募集书槽位独立，不自动改用途，提交时只发送当前方式的底稿与支持材料。参考起草至少需要一份本项目材料，解析后仍无可用项目正文则停止。最终页面展示材料清单、项目、选填项、报告期及成果类型；此时只检查清单，不宣称完成内容、主体或期间核验。最后一次点击才提交任务并预留额度。
6. 本企业更新仍下载 `募集说明书_更新修订版.docx`、`更新说明.docx` 和 Markdown 清单，使用真实 `w:ins/w:del`，保留未改文字、表格及样式。
7. 参考起草按章节匹配本项目证据与同业写法，生成全新的 `募集说明书_初稿.docx`、`编制说明.docx`、`编制说明.md` 和 `资料缺口清单.md`，包含实际 Word 表格和待补标记，不直接复制参考稿未修改的原文。参考稿不能通过项目事实引文校验；不在当轮提供的来源、错误引文和列数不一致的表格不写入正文。没有通过引用检查的正文时任务失败并返还额度，不用全是占位符的文件冒充初稿。引用匹配不等于已完成实质性事实核验。

两种方式沿用现有更新任务点数，提供实际处理进度、停止和检查点继续。任务列表、详情和成果持续展示编制方式。旧接口未传方式时兼容为本企业更新；显式空白或非法方式拒绝。内部知识快照仍不列入客户成果。

升级后需重启后台服务并刷新页面。新页面在正式提交前检查后台的编制能力标志；旧服务未重启时保留填写与选材操作，但阻止任务提交，避免旧服务忽略新增字段或错误处理参考稿。

### 复核募集书

**仅待复核募集书 DOCX 必传**。历史募集书、财务报表、附注、审计、征信及其他支持材料均可选。未提供支持材料时继续进行文内复核，相关外部核验列为待补证/未覆盖。

按全文片段、来源反查、逐组规则三轮检查，输出 `复核结果报告.docx`、`募集说明书_复核批注.docx`、CSV 和 Markdown。报告保留未能写入批注的问题与原因。批注是原文真实 Word 批注，定位失败不转移到其他同名段落。

### 材料生成和问答

支持连续对话、附加材料、关联已有项目、项目说明书等轻量文档下载。关联项目包含已解析材料和用户填写的信息；当前对话先前上传的附件会继续参与检索。不同对话和项目互相隔离；切换项目需新建对话。

专业版可使用联网及授权外部查询，个人版基于项目和上传材料处理。平台侧联网查询支持 Tavily；工商查询支持平台统一接入的 HTTPS 适配服务。配置一次后，系统按任务意图自动选择已启用服务：债券兑付问题使用债券服务，工商问题使用工商服务，明确的联网/公告搜索使用搜索服务；普通材料整理不会自动调用无关服务。专业版更新和复核自动使用已配置的债券及工商服务，个人版不会调用外部数据。服务端校验当前套餐，伪造请求中的方案、连接选择或联网开关不能绕过权限，升级后和重试时重新判断权限。可以在任务中写“仅依据材料”或“不要联网”禁止本次外部查询。公司名称从关联项目带入，仅无关联项目且确需债券查询时补充全称。模型收到查询原文、来源 URL 和获取时间；未配置、失败或无结果时显式说明，不伪造查询结论。

工商适配接口：`POST REGISTRY_URL`，请求头 `Authorization: Bearer <REGISTRY_API_KEY>`，请求体 `{"query":"用户问题"}`，响应为 `{"results":[{"title":"主体名称","url":"https://来源页","content":"工商查询正文"}]}`。可在企业服务中连接有权限的企查查、天眼查等供应商；本项目不捆绑商业数据库账号，也未声称完成真实工商供应商联调。

## Codex 和 DeepSeek

手机号演示注册、简化结算、账号额度、MCP 接入协议与全部公司债查询规则见 [SUBSCRIPTIONS-AND-CONNECTORS.md](SUBSCRIPTIONS-AND-CONNECTORS.md)。新版首页、侧栏和订阅流程使用真实本机状态；付款为明确标识的演示，没有发生真实收款。

所有三个流程均通过 `lib/codex.mjs` 调用 **真实 Codex CLI**。Codex 使用 Responses 协议；应用为每段任务启动仅监听回环地址、带随机鉴权令牌的协议适配器，将文本请求转为 DeepSeek Chat Completions，并把输出还原为 Responses JSON / SSE。

模型凭证只由服务端适配器持有；Codex 子进程使用独立运行目录及临时适配令牌，不借用用户的 OpenAI 登录。CLI 处于只读沙箱且禁用 shell，模型接口不转发工具定义，也不产生工具调用响应。原始材料由本地文档组件解析，应用将任务提示、项目字段、匹配的知识全文、原文及相关材料片段传入 Codex；Word 写回由应用根据验证后的结构化修改执行。

输出会进行结构校验。更新需原文锚点和证据逐字匹配；复核校验来源、规则号和锚点，缺少有效证据的明确错误降为待判断。模型截断、错误、超时不会被计作完成。停止、服务重启和失败后可续跑；已完成调用按提示、模型和输出结构的哈希复用。

`deepseek-chat` 为默认模型，平台可在环境配置中改为 `deepseek-reasoner`。模型实际可用性和计费以 DeepSeek 账户为准；本次没有使用真实 API Key 进行付费测试。

## 使用边界

- 本版是本机应用，只在 `127.0.0.1` 监听，校验 Host/Origin，文件下载限于成果白名单。演示手机号账号的项目和额度互相隔离；不具备正式短信认证、团队权限、远程部署、云存储或企业身份认证。
- 文件支持 DOCX、可提取文本的 PDF、XLSX、CSV、TXT，最多60份、合计80 MB；不支持加密文件、旧 DOC 上传和扫描 OCR。XLSX 读取缓存值，不替代 Excel 重算。
- 更新支持普通段落和现有表格单元格内的精确文字修订。新增报表列、复杂表格重排、图形、内容控件、已有修订/批注的复杂范围等列为待人工处理，不会冒称已完成。该版不是任意 Word 版式的全自动排版系统。
- 模型按相关性取得材料片段，不能用未检索命中证明全文缺失。原材料解析缺口、未通过证据校验的修改、未能定位的批注和未覆盖规则均保留在结果中。
- 输出用于项目组审阅。财务测算暂由模型完成并提供计算依据，未增加独立的十进制财务引擎，也未开展业务准确率验收。
- 本环境的浏览器工具被自动审批错误阻止，未完成真实浏览器视觉验收。捆绑环境缺少 LibreOffice，Word XML 结构检查通过，但未完成分页渲染验收。

## 验证和维护

运行 `node --test qa/*.test.mjs` 进行隔离测试；不会调用付费模型，也不污染业务任务。运行 `node qa/smoke_codex.mjs` 通过真实 Codex CLI 与本地模拟 DeepSeek 响应验证协议衔接。`node qa/e2e_codex.mjs` 进一步验收三条流程的 HTTP 提交、真实 CLI、文档写回及下载闭环。

知识重建：用捆绑 Python 运行 `scripts/extract_knowledge.py <知识库目录>`，再运行 `node scripts/build_knowledge.mjs`。所有任务在开始模型处理时保存知识快照和哈希；重试继续使用原知识版本。

运行数据位于 `runtime/jobs`：原始上传、提取定位、知识快照、提示词、检查点、结果和文档。服务进程需持续运行，关闭网页不终止任务。详细验证记录见 `QA.md`。


## 募集书库（1.6.0）

左侧“募集书库”支持按市场、债券类型、发行企业、行业、地区、性质、状态筛选，以及元数据和已解析正文关键词检索；在参考起草的上传步骤可以进入库内推荐并选用蓝图。详情保留官方来源、文件版本、披露日期、人工核对记录与解析警告。

个人可明确添加官方材料至个人索引，仅当前账号可见；公共库由维护人员通过 `node scripts/import-library.mjs <清单.json> --publish` 批量导入核对后的文件。支持仅索引、补正文及显式版本替代，普通项目上传不会自动共享。服务重启后健康检查返回 `libraryVersion: 1`。

当前未接通三个平台的自动采集，也没有填充未经核实的示例条目。银行间等其他品种可浏览，自动编制暂限同市场、同发行方式的交易所公司债。详见[募集书库体验与建库设计](docs/募集书库设计与建库.md)。
