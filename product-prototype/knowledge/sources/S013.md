[S013:1] # 04 系统架构与核心数据模型
[S013:2] 
[S013:3] ## 1. 架构原则
[S013:4] 
[S013:5] 项目可按五层能力划分：
[S013:6] 
[S013:7] | 层级 | 内容 |
[S013:8] |---|---|
[S013:9] | L1 数据证据层 | 项目材料、历史募集说明书、财务报告、模板、公开数据和证据定位 |
[S013:10] | L2 知识规则层 | 章节本体、材料要求、规则卡、公式、阈值、来源优先级和模板版本 |
[S013:11] | L3 程序引擎层 | 文档解析、财务抽取、勾稽、披露检查、跨章节一致性和 Word 渲染 |
[S013:12] | L4 Agent 编排层 | 任务规划、材料选择、定性文字生成、缺口提问和人机协作编排 |
[S013:13] | L5 工作台层 | 项目、材料、正文、修改建议、复核、版本、权限和审计 |
[S013:14]

[S013:50] ## 3. 技术路线说明
[S013:51] 
[S013:52] 当前存在两套技术资产：
[S013:53] 
[S013:54] ### 3.1 当前主工作台 BondMvp
[S013:55] 
[S013:56] - Next.js 15；
[S013:57] - React 19；
[S013:58] - NestJS API；
[S013:59] - Worker；
[S013:60] - PostgreSQL；
[S013:61] - MinIO；
[S013:62] - pnpm/Turbo monorepo。
[S013:63] 
[S013:64] ### 3.2 后端目标架构设计
[S013:65] 
[S013:66] `architecture.md` 提出：
[S013:67] 
[S013:68] - .NET 控制面作为单一状态写入方；
[S013:69] - Python 无状态 Agent；
[S013:70] - Open XML 负责 Word；
[S013:71] - Azure Blob、PostgreSQL、AI Search 等基础设施。
[S013:72] 
[S013:73] ### 3.3 建议
[S013:74] 
[S013:75] 程序化财务引擎的设计不依赖特定语言。短期为了让开发尽快落地，建议继续在 BondMvp 当前技术栈中实现：
[S013:76] 
[S013:77] - NestJS 负责项目状态、事实、规则、建议、审批和版本；
[S013:78] - Worker 执行长时间解析、校验和 Word 任务；
[S013:79] - Python 仅在现有生态明显更适合解析时作为无状态计算服务；
[S013:80] - Word 写回可根据现有库能力选择 Node 或独立文档服务；
[S013:81] - 先完成业务闭环，再决定是否迁移到 .NET/Python 双平面。
[S013:82] 
[S013:83] 是否迁移技术栈应形成单独 ADR，不要与第一版财务引擎开发绑在一起。
[S013:84]

[S013:217] ## 6. 任务执行模型
[S013:218] 
[S013:219] 文档解析和财务更新属于长任务，不建议长期使用同步 HTTP。
[S013:220] 
[S013:221] 建议：
[S013:222] 
[S013:223] 1. API 创建任务；
[S013:224] 2. 任务写入数据库或队列；
[S013:225] 3. Worker 获取任务；
[S013:226] 4. 使用幂等键防止重复执行；
[S013:227] 5. 定期记录心跳和进度；
[S013:228] 6. 失败进入可重试或死信状态；
[S013:229] 7. 结果写回数据库；
[S013:230] 8. 前端通过轮询或事件订阅刷新状态。
[S013:231] 
[S013:232] 任务必须记录：
[S013:233] 
[S013:234] - 输入文档版本；
[S013:235] - 规则版本；
[S013:236] - 程序版本；
[S013:237] - 开始和结束时间；
[S013:238] - 重试次数；
[S013:239] - 错误信息；
[S013:240] - 输出版本。
[S013:241] 
[S013:242] ## 7. 状态权威和单写原则
[S013:243] 
[S013:244] 不论使用 NestJS 还是 .NET：
[S013:245] 
[S013:246] - 业务控制面是项目状态的唯一权威写入方；
[S013:247] - AI 服务无权直接更新项目权威状态；
[S013:248] - 程序引擎返回结果，由控制面保存；
[S013:249] - 只有控制面可以批准文档交付；
[S013:250] - 所有修改必须经过版本和审计日志。
[S013:251] 
[S013:252] ## 8. 历史募集说明书资料库
[S013:253] 
[S013:254] 资料库需要的不只是文件存储，而是可检索的数据结构：
[S013:255] 
[S013:256] - 文件；
[S013:257] - 发行人；
[S013:258] - 行业；
[S013:259] - 债券品类；
[S013:260] - 年份；
[S013:261] - 申报场所；
[S013:262] - 章节；
[S013:263] - 小节；
[S013:264] - 段落；
[S013:265] - 表格；
[S013:266] - 风险事项；
[S013:267] - 主营业务类型；
[S013:268] - 数据来源和权限。
[S013:269] 
[S013:270] 推荐：
[S013:271] 
[S013:272] - 对象存储保存原文件和派生文件；
[S013:273] - PostgreSQL 保存结构化元数据；
[S013:274] - 搜索索引支持关键词、语义和结构化条件混合检索；
[S013:275] - 检索结果必须保留来源文件和章节位置；
[S013:276] - 同业内容仅作表达和结构参考，不得直接成为当前发行人事实。
[S013:277] 
[S013:278] ## 9. 安全与权限
[S013:279] 
[S013:280] - 客户材料按租户和项目隔离；
[S013:281] - 对象存储使用受控下载地址；
[S013:282] - 敏感材料不进入公共代码仓库；
[S013:283] - 所有访问和导出记录审计日志；
[S013:284] - 角色权限至少区分项目负责人、撰写、财务复核、法律复核、发行人和只读；
[S013:285] - AI 仅接收当前任务必要材料；
[S013:286] - 不向第三方服务发送未经授权的客户材料。
