## 6.1 范围与输入体验

REV-01：复核一份已经写好的募集书，向用户明确展示三个范围：财务数据核对、合规与格式检查、公开信息核验。首发默认三类完整执行，不让用户填写一套新的发行方案。

必需材料：待复核募集书、相关审计报告/财务报表及附注。可选其他证据。项目名称可自动生成；发行人、市场、品种、披露截止日优先读取，只有无法可靠确定或相互矛盾时请用户校对。不强制资金用途、多品种、机构、评级等输入框；这些从募集书读取。

复核页只保留“材料与要求”和“复核结果”两个标签，并显示当前输入与来源报告编号。版本记录位于工作台的项目卡片内，包含复核、修订及已停止任务；从工作台继续处理时进入所选成果及其准确来源，不在复核页重复设置历史标签或历史列表。

宽度大于 900px 时项目助手始终在右侧，无重复打开按钮且不自动抢输入焦点；窄屏使用唯一入口的抽屉。它在同一项目的准备、运行和结果阶段保留上下文，承接业务口径、异议理由、材料解释及跨问题要求，例如“这段用母公司口径，偿债能力一节用合并口径”。用户可以完全通过页面按钮完成常规流程，不必输入聊天文本。真实消息、待确认范围提议和执行任务卡在同一时间线，快捷与对话确认共用既有任务入口。助手发送只保存说明、讨论或提出计划；不得自动执行、改变勾选范围或改写已有结论。详情见第 13 章。

已知差异、特别关注点和核验线索作为补充要求保存，用户补充不代表其他两类检查自动取消。明确要求只用本机材料时，先提出范围调整并展示其影响，经用户明确选择该范围并开始后执行；结果说明公开核验未执行，不将其命名为三维完整复核。

点击“开始复核”前，页面展示任务类型、检查范围、输入版本和来源材料／报告版本；点击后持久化任务并锁定不可变输入。商业数据接口未开通不阻断复核。实际规则或网页检索能力不可用时说明受影响范围；不得把未执行的检查写成已完成，或仅交一段摘要却标为完整复核。M3 不展示价格／报价，不检查余额，不要求充值，也不执行积分冻结、扣减或结算；任务锁定是输入一致性要求，与账务无关。

问题说明和异议先形成可编辑/取消的范围提议，明确采纳要求并纳入固定输入后才执行。完整复核固定完整输入，不设置差异来源报告或 finding 范围；对话报告引用另存。差异复核固定来源报告、材料、重核/关联/排除范围与 proposal/origin/input hash，范围不明先明确完整或差异方式，不从一句“重点看”静默缩小完整范围。

## 6.2 财务核对

REV-ENGINE-20261003：按[CLI 统一业务执行决定](../../docs/product-decisions/2026-10-03-m3-cli-runtime.md)，Codex CLI 阅读固定原文、选择检查步骤、比较来源并形成判断；固定 Skills 由运行时显式加载，知识 MD 按需读取，精确计算、真实属性和引用校验为定向工具。平台继续负责权限、队列、输入快照、恢复、用量、存储、通用成果校验及报告序列化，取消模型抽取后后台自动完整规则扫描。下面的检查组描述复核目标，不表示后台逐组自动扫描或保证全部已覆盖。页面联动按 2026-10-04 决定，明确执行与无收费边界继续有效；接线、测试及部署分别记录。

REV-FIN：以主体、期间、口径、币种、单位及版本为键，建立“募集书披露 ↔ 财务证据”映射。核对项目包括：

| 检查组 | 具体检查 | 结果依据 |
|---|---|---|
| 金额与期间 | 三表、附注、正文引用、报告期标题、上年同期 | 原材料锚点、原值、披露值、标准化差异 |
| 单位与符号 | 元/万元/亿元、外币、千分位、负数、比例 | 换算公式、源精度、符号 |
| 报表勾稽 | 合计、资产负债权益、现金流净额等 | 实际表结构及完整列示项 |
| 指标 | 资产负债率、毛利率、现金流、债务及保障指标 | 项目适用定义、输入证据、计算和舍入 |
| 变动分析 | 变动金额/幅度、百分点、比较基期、异常波动 | 复算值；变动原因需独立依据 |
| 披露口径 | 合并/母公司、重述、会计变化、审计意见 | 审计报告及附注，原文引用 |
| 多处一致 | 财务表、摘要、风险、经营、偿债相同事实 | 各处位置清单，不只改第一个命中 |

资料缺失、不确定 OCR、来源冲突分别呈现，不将数字“看起来合理”作为通过依据。会计余额时点与最新债券存续金额不同不必然是错误，先建立还本付息/新增发行/重分类等桥接。

2026-10-02 用户提供的[审计勾稽知识](../../knowledge/audit-reconciliation/README.md)保留 40 项原编号、原文与原件哈希，作为内部核对方法接入 M3-02。CLI 按需读取并选择适用关系，定向算术请求由精确计算工具复算；不自动遍历完整目录。有条件的简化式与定性关系必须保留明细、期间、符号、分配、汇率及现金等价物等适用边界。实际缺证项显示待补或人工判断，不用缺失值补零，也不将附件声称的法规出处冒充已核实法规。方法版本、知识内容哈希及实际工具数据参与运行恢复；旧抽取任务/旧提示不能静默升级为新方法。

## 6.3 合规与格式核对

REV-REG：按目标市场、品种、发行对象、申报阶段、规则生效日与过渡安排选规则包。大公募、沪深及银行间各有独立适用性矩阵。

CLI 按需读取对应知识 MD 并结合原材料判断实际适用条件与披露；服务端验证精确来源/版本和工具读取的实际属性。未获批准的研究参考不会因为能读取 MD 或模型肯定回答而升级为有效法规，定向属性检查也不代表完整合规规则集或视觉排版已通过。

每条规则包括 rule_id、来源原文/条款/版本、生效区间、适用条件、要求字段、检查方法、证据、例外与结论。规则未核实或未覆盖时结果为未覆盖/待人工判断，不能作为确定违反法规的结论。

检查维度：

- 文件组成、必需章节与应披露事项是否存在，披露是否充分需结合适用性与事实。
- 发行条件、资金用途、发行对象、条款、增信、投资者保护和机构职责是否自洽且符合有效要求。
- 重大风险、关联交易、诉讼处罚、重组、对外担保等有证据事项是否适当披露。
- DOCX 的字号、字体、层级、段落、表格、页码、目录和引用；用实际样式/继承链计算，不只查直接属性。
- 版式渲染、换页和复杂视觉效果若不能可靠验证，明确列人工检查；主题字体缺少实际字库时不伪造确定字号/字体结论。

字体格式有两类：有效规则明确要求，以及用户/机构模板要求。结果必须标识类别，不能把偏好字体写成监管强制要求。

### DFI 的合规核对

发行方式可选择 DFI · 储架发行，但不增加额外必填表单。通过上传募集书、注册文件和补充说明识别是统一注册文件还是具体一期文件。核对适用注册条件、通知与有效期、覆盖工具、额度（文件有约定时）、分期发行披露、承销商团及实际机构分工。阶段不明则列待核实，不能自行认定已注册；注册阶段尚未确定的本期条款不能一律判为遗漏。

具体一期按实际工具适用规则核验，全文财务和公开信息核验范围保持不变。未取得现行协会原文或注册文件的相关结论标为未覆盖/待补，不能套交易所格式要求，也不能宣称 DFI 合规已通过。

## 6.4 公开信息核验

REV-PUB：worker 直接复用 Codex／所配置模型实际可调用的 web search，围绕发行人及任务相关主体查四类信息；不新增专用搜索服务、爬虫或快照平台：

| 方向 | 要核对的事实 | 数据路径 |
|---|---|---|
| 工商与控制关系 | 名称、统一社会信用代码、股东、实控、登记变更、存续状态 | web search 查找官方登记、公告及可核实公开来源 |
| 债券与信用 | 存续债券、发行/兑付、债项评级、违约和重大信用事件 | web search 查找官方债券披露、发行人及评级公告 |
| 诉讼处罚与风险 | 案件、执行、处罚、失信及相关公告 | web search 查找官方公示、处罚与相关公告 |
| 重大事项 | 公告、资产交易、控制变动、重大经营事件 | web search 查找官方公告及其他公开证据 |

M3 不依赖启信宝、Wind、企业预警通接入。上述商业接口属于后续可选能力，届时按第 15 章另行验证。当前使用实际网页检索结果，不把模型已有知识或模型自述当作已联网核验。

公开核验分为上下文隔离的检索与比较：联网 CLI 仅获得允许的主体、日期及类别；材料比较由一次 CLI 执行使用只读材料工具按需阅读原文，结合已取得的真实来源形成结论。平台不按文本批次规划多个比较调用，也不将内部材料传入联网检索上下文。搜索事件、材料读取与引用均须能独立核对。

先解析主体唯一标识，不能仅凭同名命中。复用现有运行记录和复核报告，保留查询主体、实际工具、查询时间、事实时点、来源标题与 URL、可得的发布日期及支持结论的摘要／定位；不另建来源快照服务。媒体传闻与公司公告分层；转载不算独立第二来源。

“未检索到”只描述本次查询结果，不等于“无诉讼/无处罚/无违约”。材料截止日至查询日的新事项要区分报告期事实和期后信息；生成日不能取代所有法定时点。

## 6.5 结果模型

每个 finding 至少包含：

| 字段 | 内容 |
|---|---|
| 稳定引用 | project_id、run_id、report_id／report_version、finding_id；跨轮保留原发现及后继发现的关联 |
| 位置与原文 | 募集书文件版本、章节、段落/表格锚点、原句 |
| 维度 | financial / compliance / public |
| 结论状态 | 明确错误、来源冲突、待补证、待人工判断、未覆盖 |
| 严重级别 | P1 / P2 / P3，与结论状态独立 |
| 依据 | 财务证据、计算链、有效规则、公开记录及日期 |
| 差异与影响 | 实际不一致、影响章节和判断范围 |
| 建议 | 修正值/建议措辞/需补材料；无法确定时不强填 |
| 置信与限制 | OCR 不确定、来源局限、未执行检查 |

检查执行记录另含通过、不适用；每条“不适用”须有适用性依据。P1 设计定义为影响关键财务/发行条件/重大披露的高优先级，P2 为重要一致性或充分性问题，P3 为文字格式等一般问题。严重级别不能伪装为监管定性。

去重以同一事实及错误原因聚合，多位置保留列表；不同期间或不同规则不能机械合并。输出问题总数、检查覆盖数和未覆盖数，不以“没发现问题”显示 100 分或保证合规。

异议、说明、补证和修订计划都绑定原问题及来源报告。当前打开的聊天问题改变后，已经开始的补证操作仍归原问题；不得只凭屏幕当前选中项覆盖引用。用户提出异议仅形成待核对记录，不能直接将原发现改成通过。

## 6.6 执行覆盖与成功标准

一个外部查询失败后可以继续其他检查，以取得尽可能完整的证据；最终必须按请求范围判定能否成功：

- 核心三维流程实际完成，个别事实因公开来源没有披露而列待补证，可交付有效复核报告。
- 实际 web search 工具不可用、必要规则依据缺失、财务证据无法读取等导致整个关键维度未执行，不认定完整复核成功；保留诊断性中间结果、失败原因及可恢复的下一步。
- 商业接口未配置或不可用不构成 M3 失败或发布阻碍。worker 网页检索按实际取得的公开来源继续，报告如实记录范围与证据；个别来源不可达不静默取消其他检查。
- 用户主动选择较小范围后，是另一次明确执行的新任务；不能后台自动缩小已接受任务或据此伪报完整覆盖。

专业复核有问题并不意味着任务失败。任务成功是准确完成约定检查、清楚交付问题与覆盖情况，不是得出“全部通过”。

## 6.7 结果操作、修订与交付

必交付复核报告 DOCX，包含范围/版本/时点、摘要、问题明细、核验依据、未覆盖清单。DOCX 输入时另提供批注版募集书，批注锚定原位置并保留原正文；PDF 输入给报告和可回查页码，不假装产生原 Word 级批注。

应用内提供摘要、问题清单、原文、依据、覆盖限制和下载。用户可以直接筛选问题、查看解释、补充材料、勾选有依据的修订、核对计划、明确执行及下载；这些动作不要求对话，也不要求在线逐条接受／拒绝全文修改。专业解释使用问题内详情或弹窗，不伪造用户聊天消息。“继续讨论此项”“说明口径”“提出异议”等语义入口将问题与报告引用带入常驻助手，窄屏同时打开抽屉。

结果驱动修订先形成可核对的计划，展示选中问题、关联章节／引用、补充要求、保留事项与未决事项。用户可勾选或取消具备依据的修改；缺证问题仍待补，不通过猜测填入“正确值”。跨问题自然语言只能提议计划，不得默改用户现有勾选。计划为空时不创建修订任务。开始前展示任务类型、范围、输入与来源报告／文稿版本，由用户明确点击执行。

修订生成新文稿版本，保留原报告、原文稿和逐项变更来源，提供修订版与清洁版；不能只修改网页文本或交付假 Word。DOCX 结构、表格、样式、标题层级、目录／引用及真实修订标记按文稿交付规范检查，保留 Word／WPS 兼容性验证及未验证项说明，不将生成文件等同于交付检查通过。修订完成不自动代表复核通过，也不自动启动新一轮复核。平台引用／计算错误修复保留 `correction_of_run_id` 及更正原因，用于追溯。

修订业务在一次 CLI 文件工作区执行中完成：CLI 读取锁定原件、已采纳计划、证据和允许位置，写出局部修订提案，并显式调用提供的 Python Word 工具。宿主独立验证范围、原件/hash，并重放同一提案拒绝未申报的文件修改；不能由后台重新规划修订或由 CLI 顺手全稿改写。报告/原生批注的固定格式序列化仍由平台执行，不为固定渲染步骤增加无业务作用的模型调用。技能/方法版本改变时，旧运行不得静默切换新路径。

补证或修订后可以直接选择差异复核，执行前显示受影响问题及检查范围。新报告区分“本轮重新核验”和“沿用先前结果”，逐对象保存旧 finding 与本轮 finding/coverage 的明确关联，分别标注来源报告、输入版本和核验时间；被选但未完成的对象保留原因，未返回旧 finding 不自动解决。未触及问题不能被标为本轮已通过，局部复核不能冒充全稿重新通过。原报告保持可回查。

### 任务与版本规则

- 同一项目最多一个活跃的复核／修订任务；普通保存和讨论可以继续，但新的执行按钮说明当前任务并阻止并行冲突。相同 `execution_request_id` 重复点击／重试返回同一个 run，不重复执行。
- 运行时材料、要求、范围、规则及来源版本与 hash 固定。运行中新文件、说明或异议进入下一版输入并明确显示生效范围，不暗中改变当前 run。
- 停止任务保留已分配的 run 和输入版本，版本号不回收、不复用；下一次变更或执行按新版本规则推进。系统断线恢复沿用原 run，不伪装成用户重新执行。
- 工作台版本记录保存每轮输入、材料、要求、来源、范围、状态及成果的不可变快照。助手开合、页面切换和刷新恢复当前草稿及其问题／报告引用，不能串项或丢失未发送内容。
- 局部操作反馈在对应页面显示；快捷与对话执行任务在同一助手时间线更新同一张持久任务卡，状态来自真实宿主事件，只展示白名单安全摘要，不追加假消息/逐点击日志或暴露原始 CLI 日志、prompt、推理。
- 任务卡定位左侧准确运行状态/报告/成果，左侧问题和结果可返回对应卡片与提议；用户回看历史时新任务完成不强制换页，只提供准确新结果入口。断线、乱序重播、关闭重开及旧 schema 恢复不重复任务/卡片，不重发未知调用。

### 本次 M3 的计费边界

本次 M3 的复核、差异复核、结果修订和项目助手均不包含用户收费流程，不依赖 M2 的价格、报价、余额、充值、冻结、扣费、结算或收费验收。该范围调整不改变 M2／M4 的收费规则，也不作永久免费承诺。实际模型调用、用量及内部成本继续按真实数据记录，缺失用量记为 `unknown`；内部成本记录不转为用户账单。
