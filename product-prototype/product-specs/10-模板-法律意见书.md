# 10 模板规格：法律意见书

标识：TPL-LEGAL｜计价 G03｜首发必需｜交付性质：供律师审阅的法律意见书草稿

## 10.1 目标与必要输入

基于项目事实和有效法律依据形成可编辑的法律文书工作稿。软件不能签发法律意见、冒用律师或律所名义，不能把来自募集书的自述自动称为已独立核查。

必需：最新募集书或项目、发行人、目标市场和品种、对应适用模板。出具律所、承办律师、法律意见用途可由资料提取或在对话补充；未确定的签署信息明确待确认。

建议支持材料：主体登记/章程、股权控制资料、内部决议及授权、外部批准/注册文件、重大合同、担保与资产权属、项目许可、诉讼处罚、律师已完成程序记录。模板应告诉用户哪些事项尚缺资料，不要求一开始填写所有法律事项问卷。

## 10.2 章节映射

| 章节族 | 应处理的法律事项 | 来源及结论要求 |
|---|---|---|
| 标题、致送与释义 | 项目身份、用途、发行人、机构和关键定义 | 避免复制旧发行人/旧律师事务所 |
| 出具依据与声明 | 委托关系、审查范围、所获材料、法律依据 | 不虚构委托和独立核验；已有原文声明需与事实相符 |
| 主体资格及存续 | 设立、登记、存续、组织形式、资格 | 有效主体资料，名称变更与日期可追溯 |
| 股权与治理 | 股东控制、章程、治理机构及人员 | 登记/决议/章程相互核对，不仅靠财务附注推法律结论 |
| 批准与授权 | 内部决议、授权额度、有效期和外部程序 | 拟申请、受理、注册完成等阶段不能混用 |
| 发行条件及条款 | 按市场品种的适用条件、条款合法性 | 逐项规则和事实映射，缺证据保留判断 |
| 用途与相关项目 | 偿债、补流、建设、股权/基金用途法律事项 | 相应许可、合同、批准和用途限制 |
| 主要资产及债务 | 权属、担保、受限、重大合同及或有责任 | 区分资产账面值和法律权属证明 |
| 关联、重组及重大事项 | 关联关系、交易、重组、诉讼、仲裁、处罚 | 审计线索结合交易及官方/授权记录 |
| 信息披露核对 | 募集书涉及法律事项的陈述是否一致 | 明确核查范围，不对未核验全文作无条件保证 |
| 结论与条件 | 支持的意见、限制、待落实条件 | 不生成无事实基础的绝对肯定意见 |
| 签署与附件 | 日期、律师、机构、核查材料/法规清单 | 真实签署由机构完成，软件不填假章 |

## 10.3 法律判断数据模型

每项判断包括 issue、fact_evidence、legal_basis、applicability、procedure_evidence、analysis、conclusion、limitations。事实与法律依据分别引用；同一结论必须有可解释的推理连接，不能只列一个法规名称。

法条引用须核对名称、条号、原文、效力日期和适用范围。不得编造现行法、引用未生效草案作为生效规则，或把专家经验当强制法条。

同一法律事件要区分历史发生、持续影响、已解决和未知状态。例如诉讼撤诉、执行终结和债务清偿是不同事实，不能自动互相替代。

## 10.4 缺证与生成边界

无公司决议证据时不得写“已取得合法有效内部授权”；无权属证书时不得由资产负债表推断权属无瑕疵；未发现公开诉讼不能写“发行人不存在任何诉讼”。

专业草稿可包含清楚标注的待核事项，但主体/发行方案等核心事实缺失或关键篇幅仅有占位符时，不满足收费交付。必要时先追问材料而不是连续输出模板空壳。

用户要求“使用某律所的行文习惯”可以改变风格；用户未提供真实程序及签署授权，不能借该要求生成已签发状态。

DFI 项目须区分注册申报意见与具体一期发行意见的用途，分别核对注册适用条件、授权及决议、覆盖工具、有效期间和本期条款。尚未取得注册通知的不得写成已经注册；各阶段程序是否完成以文件证据判断，不能因 DFI 名称生成确定的合法合规结论。

## 10.5 验收

TPL-LEGAL-A01：审批文件只有受理通知，生成文本仍为受理阶段，不写注册已完成。

TPL-LEGAL-A02：审计报告有资产但无权证，不生成“合法拥有全部资产且无争议”的结论。

TPL-LEGAL-A03：规则版本已被替代，适用性检查触发重新核验，不静默沿用。

TPL-LEGAL-A04：公开查询无结果，正文保留检索范围与待补证，不绝对化不存在。

TPL-LEGAL-A05：法条名称/条号/引文不匹配，来源检查阻止该结论交付。

交付 Word 草稿与编制说明，说明集中列未取得的法律资料、尚未实施程序及需要律师确认的判断。
