# 02 注册登录与账号

> 2026-09-24 M1 决策：用户选择用户名密码注册/登录，短信供应商接入不需要。以下短信界面及验证码段落为历史原型，当前 M1 实现与验收以本段及 Issue #7 最新要求为准。用户名使用 3–32 位 ASCII 字母、数字或下划线，以字母开头，转小写后唯一；密码 12–128 字符，服务端仅存 Argon2id 哈希。注册记录当前协议版本和一次注册事件；登录失败统一提示，并按账号及账号/来源组合限制尝试。旧手机账号不会由同名新账号自动接管。人工找回按第 2.7 节定稿执行；旧手机账号不自动迁移，不开放无人核验的自助找回。


## 2.1 目标与范围

AUTH-01：个人券商用户通过真实手机验证码注册/登录，账户集中管理积分和充值订单。首发不要求用户自行开通模型账号，不要求为领取赠分上传身份证。手机号验证证明号码控制权，不能对外宣称已经完成自然人身份认证。

设计默认首发大陆 +86 手机号；其他地区号通过配置开放。若供应商不支持某地区，在发送前明确提示。

## 2.2 页面字段与状态

| 字段/操作 | 必填及校验 | 反馈 |
|---|---|---|
| 手机号 | 必填；区号与号码规范化；前后空格可清理 | 格式错误本地提示；服务端再次校验 |
| 获取验证码 | 合法手机号后可用 | 发送中、倒计时、失败可重试；不展示验证码本身 |
| 验证码 | 必填，按短信供应商定义的位数 | 过期/错误统一易理解提示 |
| 服务协议及隐私政策 | 必要同意独立展示，可打开全文 | 记录版本、时间；营销同意不能默认勾选 |
| 邀请码 | 可选，可从有效邀请链接带入 | 绑定前显示归因；首次有效归因后锁定 |
| 登录/注册 | 同一主按钮 | 号码不存在时创建，存在时登录 |

设计默认验证码有效 5 分钟、发送间隔 60 秒、连续错误 5 次使本挑战失效；具体供应商限制可更严格。账号、设备、IP 多维限流，同单位共用网络不得作为直接封禁依据。响应不泄露手机号是否已注册。

状态：待输入 → 发送中 → 待校验 → 校验中 → 已登录；发送失败、验证码失效、限流等保留手机号，不清空整个表单。生产环境禁止演示短信、万能验证码或页面回显。

## 2.3 注册成功与赠分

M1 原子创建 user 并保存注册幂等事件，不展示尚未真实入账的赠分。M2 启用 wallet、welcome_reward，按实际用户规则去重；同一验证码重复提交不重复赠分。欢迎积分 2,000，30 天有效，活动规则见第 14 章。M1 存量账号按 M2-08 的明确迁移规则处理，不能补写虚假历史账单。

首页展示“注册赠送 2,000 积分”和到期日，不承诺它足够完成某份募集书。赠分发放失败但账号已创建时，用户仍能登录，记录可恢复发放事件，显示“积分发放处理中”，不诱导重复注册。

邀请关系使用签名链接/规范化邀请码绑定；不得由客户端直接写 inviter_id。手机号、设备等风控标识最小化留存，注销后防重复领分的必要标识及期限应写入隐私规则。

## 2.4 会话与账号设置

AUTH-02：短期访问令牌 + 可撤销刷新会话，或同等安全的服务端会话。设计默认访问有效期 15 分钟、刷新会话最长 30 天；登出、手机号变更和高风险事件可撤销。Web 使用 Secure/HttpOnly/SameSite Cookie 和相应 CSRF 防护，不在 localStorage 持久化会话密钥；M5 令牌存入 Windows 安全存储。任何端都不把令牌写入日志。

设置页包含显示名称、绑定手机号掩码、当前版本、设备会话、数据服务说明、协议、联系客服和注销入口。Web 提供云端项目存储与删除说明；M5 增加本机项目位置和备份设置。券商名称在立项报告中按项目填写，不把其当作注册强制企业认证。

当前 M1 的账号找回和联系渠道变更以第 2.7 节为准；本节原有换号流程仅作为历史短信方案记录，不能仅凭新号码接管账号。一个账号跨设备使用钱包一致；Web 可访问该账号云项目，M5 本地项目仅存在创建或导入它的设备，除非用户显式迁移。

## 2.5 登出、注销及权益

Web 登出撤销当前会话，服务端任务继续且不能再用旧会话读取材料；登出前说明运行状态，可主动取消。M5 普通登出保留本机加密/隔离资料，下次登录恢复；运行任务需明确选择继续本机后台或取消。不因登出自动核销全部冻结。

注销前列出未完成任务、冻结余额、可退购买积分，以及云端项目和本机资料各自的处理选项。先处理任务与退款，再按留存策略删除云端正文与派生资料并关闭账号；法定订单/账务记录可按规定留存，其用途和期限须说明。活动积分不可提现；已购买未用积分按原订单比例退款。

账号注销不会自动删除用户自行导出到其他位置的 Word 或备份。删除本机目录时再次显示准确目录和涉及资料，避免误删用户源文件。

## 2.6 接口与验收

当前 M1 接口：POST /api/v1/auth/register、POST /api/v1/auth/login、POST /api/v1/auth/refresh、POST /api/v1/auth/logout、GET /api/v1/me。账号设置、改密、会话撤销和注销已接入 /api/v1/account 路由；人工找回按第 2.7 节定稿，恢复相关入口现已实现，按配置启用。请求/错误公共约定见第 16 章。

| ID | 场景 | 预期 |
|---|---|---|
| AUTH-A01 | 同一验证码重复提交 | 一个账号、一次欢迎赠分 |
| AUTH-A02 | 过期/错误验证码 | 不创建账号，不发积分 |
| AUTH-A03 | 修改邀请码后再次验证 | 已锁定关系不改变 |
| AUTH-A04 | 同单位多个真实用户同 IP | 不因共用网络一律封禁 |
| AUTH-A05 | 已登出令牌调用材料接口 | 被拒绝，返回安全错误 |
| AUTH-A06 | 注销时有冻结任务和余额 | 先完成状态与退款处理，账务可追溯 |
| AUTH-A07 | 协议更新或营销选项未勾选 | 必要协议版本可追溯，正常注册不绑定营销 |

## 2.7 M1 人工找回与身份核验（定稿 v1）

2026-09-26：按用户“自行定稿、简单一点”的要求，#9 采用以下流程。这里核验的是**原账号控制权**，不作自然人实名或券商资质认证。M1 由 Chris 或其指定的一名客服处理即可；复用现有客服渠道和受限工单，不建设多级审批或单独的客服系统。

### 三步处理

1. **提交申请。** 用户通过产品公布的客服入口（`BB_SUPPORT_CONTACT`）提供用户名、遇到的问题和回复渠道。客服建立一条工单；未核验前统一回复“已收到申请，需要核验原账号归属”，不透露账号是否存在、项目或材料信息。收到申请不锁号、不改密、不结束现有任务。
2. **核验原渠道。** 客服从申请前已经核验、且与该 `user_id` 绑定的联系记录发起确认，例如原邮箱或原客服会话。对方在该旧渠道确认本次工单后才可通过。临时新填的号码/邮箱、姓名、单位、身份证照片、项目名、文件截图和材料内容都不能单独证明归属；不要求用户提交身份证或客户材料。
3. **用户自行设新密码。** 核验通过后，客服通过上述旧渠道发送一次性重置链接；链接 30 分钟有效，仅用于该账号本次改密。用户自行设置符合现有规则的新密码，客服不询问、不代填密码。重置成功后撤销该账号全部旧会话及未使用的重置链接，通知原渠道，并让用户重新登录；`user_id`、项目、材料和运行任务保持不变。

### 没有旧记录时怎么办

**原渠道不可用，或从未绑定过可靠渠道，就不执行人工重置。** 客服说明无法确认归属，保留原账号和资料；用户可另行注册，但不转移原账号资料。客服认识申请人、申请人能描述项目，均不构成例外。旧手机号也不能仅凭一条新号码验证码迁移或合并成用户名账号；旧手机身份迁移不在本简版恢复能力内。

为使正常账号以后能够找回，首次绑定或变更恢复渠道需要用户**已登录且再次验证当前密码**，然后在新渠道完成一次确认；记录服务端确认的 `user_id`、渠道和核验时间。不得在忘记密码后补录一条“事前已绑定”记录。现有账号尚无这类记录时，明确提示暂不具备人工找回条件。

### 实现只保留必要约束

- 重置链接由服务端生成，使用足够长的密码学随机值，仅存 token 哈希；绑定账号/工单/用途，过期或用过即失效。重复申请沿用未结工单，重新签发作废旧链接；复用现有账号及来源限流，不因申请次数锁住正常登录。
- 发链接须有指定客服权限及已通过的工单；链接不提供读项目、下载材料或登录能力。只有用户提交有效链接和新密码时，才在同一事务更新 Argon2id 凭据、消耗授权、撤销会话并写审计/outbox；任一步失败全部回滚。
- 每次处理只留工单号、账号内部 ID、事前联系记录引用、核验结论、客服身份、时间和结果；按现有受限记录保存策略处理。密码、重置链接/token、Cookie 和客户材料不得进入普通日志、GitHub 或仓库。核验工单也不发到公开 Issue。

用户提示统一为：“忘记密码请联系客服；需通过事先绑定的联系方式核验。无法核验时不能重置，原账号资料仍保留。”客服未配置或恢复功能尚未部署时，不显示可用的找回入口。

### 最小验收与当前状态

| 场景 | 结果 |
|---|---|
| 旧绑定渠道确认本次工单 | 一名指定客服可签发链接，用户自行改密后重新登录 |
| 只有新号码、项目截图，或没有事前绑定 | 不重置、不迁移资料、不泄露账号信息 |
| 链接过期、重复使用、用于其他账号或客服无权限 | 拒绝；原账号不受影响 |
| 改密成功 / 事务失败 | 成功时旧会话全部失效、资料和任务保留；失败时凭据与授权一并回滚 |

**恢复渠道绑定、受限客服工具和用户重置页面/API 已实现。** 详见 [#9 运行与验收说明](../../docs/ACCOUNT-RECOVERY.md)。需配置客服入口并给指定账号授予专用客服权限才启用；确认码、链接与完成通知仍由客服通过原渠道人工发送。`self_service_recovery=unavailable` 保持兼容，不代表人工恢复不可用；不能以手工改数据库替代正式入口。旧手机身份不自动迁移。

技术依据：[OWASP Forgot Password Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html) 关于独立联系渠道、单次限时 token 和重置前不改变账号的建议；30 分钟及单客服处理是本项目的简化决定。
