# 16 数据模型、接口与状态机

本章为新版本目标契约，不表示现有 /api 路由已符合。客户端与平台均需版本化接口；现有代码迁移可用适配层，不能让旧 quote/confirm 成为新流程的用户前置步骤。

## 16.1 边界与通用约定

M1–M4 浏览器通过 HTTPS 调用 /platform/v1，项目、上传材料、事实、对话与成果保存在账号隔离的服务端工作区。M5 客户端 UI 通过受保护的本地 IPC/环回接口调用 /local/v1，本机处理能力使用相同业务契约。身份、钱包、用量、任务租约与供应商密钥始终由平台管理。

下表“本地”是 M5 的存储归属；在 Web 阶段对应对象统一由平台数据库/私有对象存储持久化。对象增加 storage_origin（cloud/local）和 workspace_id，M5 本地对象另有 device_id；跨端关联不能仅按 project_id 假设文件已存在。模板私人作用域无论存于云端还是本地都绑定 owner。

所有 ID 为不可推测标识，所有对象绑定 owner_user_id；每次读取/关联/导出重新校验。客户端提交的用户 ID、价格、系数、余额和 usage 不可信。路径只能用授权文件句柄/材料 ID，不能接受任意绝对路径交给模型。

时间存 UTC ISO-8601；活动日转换 Asia/Shanghai；金额人民币分，数值/成本定点十进制；空值、0、未知、不适用分开。修改使用 revision/If-Match 乐观锁，冲突返回 409 并保留用户输入。

分页使用 cursor；接口错误返回 code、message、retryable、field_errors、correlation_id。日志不得默认带材料正文或访问令牌。

### DFI 字段及兼容映射

| 字段 | 语义与约束 |
|---|---|
| market / offering | nafmii / dfi；前台选项名称为 DFI · 储架发行 |
| scope | 当前接口使用 nafmii-dfi；所有创建、上传、执行、恢复及关联接口接受并保留 |
| registrationMode | 当前兼容字段由服务端根据 nafmii-dfi 推导为 dfi；前台不填写独立注册模式 |
| arrangement（目标） | dfi；区别于 instrument，不能把 DFI 当 MTN 的别名 |
| document_stage（目标） | registration / issuance / unknown，带证据；按文档及明确说明识别，不增加强制问卷 |
| covered_instruments（目标） | 来自注册文件的覆盖工具及来源；未知为空，不等于无覆盖 |
| issuance_instrument（目标） | 本期已确定工具；注册阶段可空，不凭覆盖列表第一项推断 |
| notice / validity / amount（目标） | 通知、适用有效期及额度（如有）均保留来源、未知和待取得状态 |
| arrangementPricing | 当前计费快照 dfi-v1，与 source/target 及 pricingBasis 一同锁定，不由客户端传价 |

当前实现保存 nafmii-dfi、推导 registrationMode，并将原注册/分期输入与材料传入任务；结构化阶段、覆盖品种和注册事实的抽取及证据模型仍属于上线工作。旧项目若为 nafmii-mtn 且材料有 DFI 背景，不自动改写其具体中票品种。仅切换市场不能留下交易所+DFI 的无效组合。

### 历史稿识别与难度输入契约（M1-31）

HistoricalProspectusProfile 的 source_market/source_offering 是上传历史稿的识别值，与 Project.market/offering 的本次目标含义不同。reporting_periods 至少逐项保存 start/end、年度或中期标记、报表口径和来源，latest_reporting_cutoff 从有依据的期间集合推导；签署日、发行日另存，不能替代。无法判定小/大公募、源市场或报告期时，规范值可为 null，同时保存 raw_value 与 uncertainty，不能填一个默认品种。

识别状态为 queued → analyzing → ready / needs_confirmation / failed；ready 表示源信息具备依据，不表示整份募集书或财务数据已复核。每个候选值带 evidence_refs；用户校正标 user_asserted，保留前值、理由、操作者、时间和校正版本，不伪装为模型识别或审计确认。

上传持久化事件按 owner + material_version + extractor_version 去重，替换文件后迟到的旧识别结果不得覆盖新材料。更新草稿读取所选历史稿版本的 profile；本次目标不被源值自动改写。UpdateDifficultyInput 同时绑定 profile_version、目标修订、财务材料版本和适用规则版本，任一变化使未启动估计失效。执行时锁定该输入，actual_N 和实际分类以追加工作记录给出，不改写原估算证据。

M1 识别与差异比较不需要钱包，保存平台承担成本的预检事件；M2-02 消费同一契约生成 M/J/N 与计价快照。源字段待确认不能悄悄当成完整可信定价输入；估计和实际须分字段。

~~~json
{

  "project_id": "project_example",

  "input_hash": "sha256_example",
~~~

## 16.4 执行与账务状态

~~~mermaid
stateDiagram-v2
    [*] --> preparing
    preparing --> rejected: 缺材料/能力/授权或余额
    preparing --> queued: 试用授权或原子冻结成功
    queued --> running
    running --> awaiting_input: 原范围澄清
    awaiting_input --> running: 澄清答复
    running --> paused: 执行进程不可用或本机退出
    paused --> running: 对账后恢复
    running --> validating
    validating --> delivering
    delivering --> settlement_pending: 已交付但用量待对账
    delivering --> succeeded: 已交付并完成结算
    settlement_pending --> succeeded: 可验证结算或平台承担
    running --> failed
    validating --> failed
    delivering --> failed
    awaiting_input --> failed: 新材料不可缺少
    queued --> cancelled
    running --> cancelled
    awaiting_input --> cancelled
    paused --> cancelled
    failed --> [*]
    cancelled --> [*]
    rejected --> [*]
    succeeded --> [*]
~~~

图为主路径，所有未终结运行阶段均需处理取消、超时及不可恢复失败，包括 validating/delivering；实际转换表以服务端实现，不能只实现图上画出的边。Web 浏览器离线或关页不导致运行暂停；暂停指工作进程/必要服务不可用。M1 无账务冻结，成功只记录交付与平台成本；后续收费阶段才进入账务结算。

rejected 不产生有效冻结。failed/cancelled 全额释放。awaiting_input 仅在现有范围内澄清可继续原 run；新材料或范围修改生成新版本、新 execute。settlement_pending 保持成果可用，但不显示已扣分；对账超时政策见第 14 章。

账务状态独立为 reserved、settlement_pending、settled、released。成功可为零计量；失败不允许 settled。取消已经成功结算的任务返回 ALREADY_TERMINAL，后续走纠错/退分，而不是再次释放整笔。

派生项目状态使用最新运行记录，但最新成功成果永远独立保存；失败新版本不会把旧成功成果隐藏。

## 16.5 幂等、快照和租约

execution_request_id 按账号唯一，同一键同一内容返回同一 run；同一键不同 input_hash 返回 IDEMPOTENCY_CONFLICT。网络重发不能生成新 UUID；用户新的主动执行才创建新键。

输入文件列表、目标字段、需求消息版本、规则/模板/模型/费率均锁定。解析前尚不确定的历史状态或期间可以记录估计分类，用于 B；实际归类依据以同一规则版本的已完成工作记录追加，不能把保守高估当实际收费。实际扣分仍受 B 保护。

工作进程 lease_id、lease_expiry、last_event_seq 由平台控制；同一 run 不能有两个有效工作进程。恢复前核对 provider_request_id，避免把已完成但响应丢失的请求再次收费。

支付回调、用量、结算、退款、活动分别有独立幂等域。不能将“相同提示词”作为所有任务的去重依据，因为不同来源版本可能是不同任务。

## 16.6 事件与进度

事件结构：event_id、run_id、seq、type、occurred_at、stage、payload。按 run 有序，可用 last_seq 补拉。允许重复投递，消费者按 event_id 去重。

| 事件 | 主要内容 |
|---|---|
| material.upload_progress / material.import_progress | Web 已上传或 M5 已复制/总字节，以及服务端/本机保存状态 |
| material.parse_progress | 已处理页/总页、当前材料 |
| historical_profile.updated | material_version、profile_version、识别状态、源信息/来源或待确认项；免费预检与全文执行状态分别显示 |
| run.state_changed | 前后状态及业务原因 |
| run.progress | 当前阶段、已完成/总工作项，未知总量时不编百分比 |
| conversation.clarification | 问题、必要字段、来源片段引用 |
| artifact.ready | 成果哈希、版本、质量摘要、可获取状态 |
| wallet.reserved / settled / released | run 关联与实际变动 |
| payment.updated / reward.granted | 订单/活动状态，用户可见信息 |

不要返回模型隐藏推理链、内部匹配候选或原始密钥。进度中断后页面显示最后事件时间和实际等待状态。

## 16.7 错误约定

| 代码 | 含义/用户行为 | 收费处理 |
|---|---|---|
| INPUT_REQUIRED | 缺必要材料/字段，定位补充 | 未开始无冻结；执行后不可交付释放 |
| INPUT_REVISION_CONFLICT | 输入已变化，刷新并保留编辑 | 不用旧快照误启动 |
| MATERIAL_UNREADABLE | 加密/损坏/关键不可辨 | 不完成则释放 |
| FACT_CONFLICT | 核心事实冲突需确认 | 不生成虚假确定成果 |
| CAPABILITY_NOT_READY | 产品/规则/模板尚未验收 | 不启动 |
| DATA_NOT_ENTITLED | 无相应数据授权 | 不绕过权限 |
| DATA_UNAVAILABLE | 接口超时/故障 | 可等价替代，否则按覆盖标准处理 |
| CREDITS_INSUFFICIENT | 可用 < B，充值后再次执行 | 不启动不扣 |
| METERING_PENDING | usage 待核对 | 不用估算直接结算 |
| DELIVERY_FAILED | 导出损坏/无法取得关键成果 | 修复或失败释放 |
| IDEMPOTENCY_CONFLICT | 同键不同内容 | 拒绝，客户端修正请求 |
| RATE_LIMITED | 请求过多 | 说明可重试时间，不默默丢弃 |

状态、错误、账务三者必须一致；页面显示“已返还”前需收到平台释放凭证，否则显示“正在返还”并可重查。

## 16.8 字段限制及可配置项

以下为初始工程默认，统一从版本化配置读取，前后端不得分别维护不同限制。

| 字段 | 初始约束 |
|---|---|
| 项目名称 | 1–120 个字符；草稿可暂空，执行前自动建议或补齐 |
| 发行人/机构全称 | 最多 200 字符，保留法定括号等字符；不能自动缩成简称 |
| 单条对话 | 最多 12,000 字符，超限保留内容并提示拆分 |
| 债券安排/机构分工/用途补充 | 每项最多 6,000 字符；可引用附件替代重复粘贴全文 |
| 金额 | 十进制字符串，非负、最多 6 位小数；单位独立枚举，未知使用 null |
