# BondBuddy 产品开发说明书

> 2026-09-30 [最新产品范围](../../docs/product-decisions/2026-09-30-m1-simplification.md)：M1 两类自带稿＋手填原市场/品类/报告期＋末尾补充要求；M2 仅增加相关付费且无余额退款/用户消费记录页；库推荐/维护归 M3。旧聊天、自动源识别及库依赖须迁移，正文工程历史不代表新范围已实现。进度/成果展示方案待布局确认。

版本：1.3｜范围修订：2026-09-30｜对象：产品、设计、客户端、服务端、AI 工程、行业专家、测试及运营

本说明书面向“当前 BondBuddy + 补齐商业上线能力”。它定义目标产品，不代表这些功能已经实现或通过行业验收。当前工作区为 1.9.0 本地产品，包含 DFI 储架发行选项及积分原型，版本差异见第 18 章；另一个文档编辑原型仅作为技术参考。

本次修订将交付顺序调整为“先 Web，最后 Windows”，同步材料存储、会话、任务运行与分阶段验收要求；[开发任务清单](delivery-plan/README.md)整理了 5 个里程碑和 74 个可认领子任务。M1-31 改为用户手填原稿信息，M1-13 改为补充要求；M1 两类自带稿直接交 worker 更新，M1-32/33 参考库与持续维护移入 M3。M1-34 为 P0 统一使用日志，记录用户 prompt、job、模型 token 及结果/error，必须先于首个用户更新任务开放；第 16.9 节给出完整记录规范。第 3 阶段已确认是募集书付费复核，在积分付费之后上线。DFI、大公募、个人私有模板与积分方案保持原已确认要求。

## Git 仓库中的维护方式

本目录是开发说明书的统一入口。先修改对应的 00–18 分模块，再在本目录运行 `node build-spec.mjs`，重新生成合订版、文件指纹和校验记录。此脚本只依赖 Node.js 内置库及仓库内文件，无需原作者的本机目录。

本文记录本地产品与已确认的目标需求；第 18 章的 DFI 实现和回归结果来自本地编写快照，不代表这次文档提交同时修改了本分支应用代码。原始来源及其指纹保存在[本地规格来源指纹](references/本地规格来源指纹-v1.1.json)，未随规格提交的研究资料已明确标识。

## 使用方法

先读产品边界，再读所负责的功能模块，最后对照公共接口与验收表。模块中的“必须”是目标版本的验收要求；“设计默认”是为完成实现而提出的可调整方案；“接入待落实”是需要真实供应商、规则原文或运行数据才能关闭的交付条件。

需要连续阅读或转交时使用[完整合订版](BondBuddy产品开发说明书.md)。需要按模块开发时使用下方目录。参数快照、文件指纹与文档检查结果随本版本一并保存。

用户已经确认：个人券商用户、Web 先上线及 Windows 最后上线、桌面版本机为主保存材料、Codex 执行框架调用 DeepSeek、更新/复核覆盖大公募与 DFI、支持启信宝/Wind/企业预警通、上传券商模板默认个人私有、真正多轮项目对话、结果摘要和 Word 下载。Web 需要服务端工作副本，不能沿用桌面版的存储说明。

## 分阶段交付判断

页面存在、模拟接口返回成功、模型生成了一份 Word，都不等于可商用。M1 需要真实账号、Web 材料安全、更新规则与质量验收；M2 增加真实支付和积分账本；复核需要三家数据源及三维专业验证；M4 验收五类模板与独立 QA；M5 验收安装、本地文件及恢复。各阶段门槛和缺口见第 17、18 章及任务清单。

当前没有承诺上线日期、真实准确率或固定任务耗时。本文中的性能及测试数量是工程建议目标，需要在指定环境和授权样本上实测。
