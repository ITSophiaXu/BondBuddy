## 3.1 导航与首页

HOME-01：主导航依次提供首页、更新募集书、复核募集书、材料生成、QA 问答；全部项目入口与账号/积分/设置保持稳定。普通用户端不出现募集书库、蓝图推荐、内部业务匹配结果。

以上是完整产品导航。M1 仅开放已验收的更新入口和补充要求，M2 增加钱包/充值，复核及材料/独立 QA 分别按后续里程碑开放。M3 项目助手随复核工作区交付，不以前置独立 QA 为条件；本次 M3 不包含收费。未上线入口隐藏或明确不可执行，不显示虚假余额、成果或演示数据。

首页先展示用户的项目和可继续的工作，提供四个核心功能入口。推荐结构：

1. 顶部简短欢迎信息；钱包已上线时按 M2 规则展示可用积分和充值入口，不作为 M3 操作门槛。
2. 四张任务入口卡，描述分别为全文更新、三维复核、五类文书、债券专业问答。
3. 运行中/待补材料的工作，可恢复至正确位置。
4. 最近项目与最近成果，展示类型、发行人、更新时间、状态。

不以宣传横幅、充值套餐或内部资源库占据主要首屏。统计区按 update、review、generation、qa 独立计数，不把 QA 和材料生成归为一个“生成”数。

## 3.2 项目列表与详情

| 项目属性 | 展示/规则 |
|---|---|
| 名称 | 可编辑；为空可由发行人+任务类型生成 |
| 类型 | 更新、复核、材料生成；QA 会话单独管理，可关联项目 |
| 发行人 | 已填/已识别全称，主体冲突需标记 |
| 市场与品种 | 识别或用户选择的当前值，不显示未经确认的猜测 |
| 状态 | 草稿、待补材料、处理中、等待恢复、已完成、失败、已取消 |
| 最近成果 | 最新成功版本、生成时间、下载 |
| 存储位置 | Web 云端工作区；M5 本机项目标明所在设备，不在本机的文件不可伪装可下载 |

列表支持名称/发行人搜索、类型及状态筛选、最近修改排序；空状态提供创建入口。工作进程与平台状态短暂不同步时显示“正在同步”，不以刷新将进行中任务变成新草稿。

项目详情遵循对应任务的已确认原型。M3 复核页面只有“材料与要求／复核结果”两个 tab，常规操作在结果中直接完成；宽度大于 900px 时项目助手在右侧始终可见，无重复打开开关，宽度小于或等于 900px 时使用唯一可开合抽屉。结果页展示当前报告、问题、依据、材料补充、修订选择、执行和下载，没有版本历史 tab、版本目录或收费入口；不要求应用内逐条 Word 接受/拒绝 UI。

PRJ-TIMELINE-01：M3 无需输入对话文本即可通过按钮闭环。快捷和对话执行复用同一任务入口，实际用户消息、助手回复、待确认提议和稳定任务卡在同一时间线按类型区分。任务卡投影同一持久 run 的输入、来源、确认范围、真实状态和成果，与左侧结果双向定位；不为每次点击、轮询或阶段变化创建重复任务卡或假用户消息。任务摘要只使用服务端可展示的安全字段，不直接渲染原始 CLI 日志、prompt 或隐藏推理。

PRJ-HISTORY-01：M3 历次执行和成果统一在工作台项目卡中查看，显示复核／修订类型、版本、源报告或基线、输入版本、执行时间、真实状态、成果及下载。项目“继续处理”进入明确的最新可用成果；从历史条目进入则打开所选版本，不暗换成另一份报告。回看历史报告时新任务完成不强制替换当前查看对象，提供准确的“本轮有新结果”入口，不给旧结果改贴新版本标识。较新失败或停止记录仍保留，不能遮蔽旧成功成果；原报告、修订版、清洁版及各自来源保持关联。此处不新增用户消费记录页。

## 3.3 项目、版本、任务关系

PRJ-01：一次项目可以多次执行。每次执行锁定项目字段、材料文件哈希、对话需求版本、规则/模板版本及输出目标。编辑不改变已运行任务的输入。

运行时允许查看与编辑“下一版草稿”；明确提示“修改将在下一次执行时生效”。M3 同一项目的复核、差异复核与修订执行互斥，由服务端原子校验，连点、重试及跨标签页不能创建竞争任务。讨论、保存要求或上传下一版材料不改变正在运行的快照；跨项目已启用收费的任务仍按既有钱包规则保护并发。

用户在 Word 中自行修改后，如需继续处理，应导入该文件为新的输入基线，系统显示其与上次成果不同。不能认为本地导出文件被编辑后项目事实已经自动更新。

成功版本具有 v1、v2 等可读名称，并保存不可变 artifact_id、哈希及来源快照。M3 在执行创建时保留版本编号，停止或失败后不复用；无成果的执行不显示下载成功。旧版本不覆盖。下载失败可重试，重新导出同样内容不创建新执行；改变内容属于新任务或平台纠错，本次 M3 均不产生用户收费。

PRJ-CONTEXT-01：M3 已提交说明和未发送草稿分别持久化，至少绑定账号、项目、来源报告和问题（项目级要求明确标记为项目级）。切换 tab、问题、报告、收起窄屏抽屉或刷新后恢复原上下文；附材料始终关联发起动作的原问题，不跟随当前聊天焦点改变。保存要求／助手计划提议与已选修订清单分别维护；提议可调整，用户明确采纳才固定范围，明确执行才创建 run；“确认并开始”可在一次操作中完成采纳和提交。执行前直接展示任务类型、范围、源报告／基线和输入版本，将已采纳提议及来源绑定到不可变执行输入；来源或材料变化须重新核对，不静默换源。完整复核的讨论报告引用与执行基线分开，不能因正在讨论某项而缩成差异复核。空修订范围给出可操作提示且不创建任务。

## 3.4 项目操作

| 操作 | 规则 |
|---|---|
| 创建/重命名/修改字段 | 免费，自动保存；Web 提示服务端保存状态，M5 提示本机保存状态 |
| 复制项目 | 新项目 ID，可复用同账号材料解析；不复制冻结或消费记录 |
| 归档 | 隐藏默认列表，仍可恢复、下载 |
| 删除 | 先处理运行任务；分别显示云端或本机材料/成果影响范围，保留法定云账本 |
| 关联材料生成 | 锁定所选成果版本，不随原项目后续变化漂移 |
| 关联 QA | 显示项目范围，可切换；不自动把所有项目全文放入上下文 |
| 从失败恢复 | 区分系统重试同任务与用户新需求重新执行 |

材料与模板有共享引用时采用引用计数/依赖清单；删除一个项目不应破坏其他项目已锁定的材料和成果。已成功版本至少保留可重建的来源快照，用户主动清理时告知后果。

## 3.5 结果摘要规范

更新摘要：处理范围、实际新增/替换期间、章节变化、多品种联动、材料冲突与待核实项、成果文件。

复核摘要：三类已执行范围、问题数量与级别、未覆盖项、资料截止日/查询时间、报告和批注文档。

生成摘要：文种、来源募集书版本、模板/券商、完成章节、待确认项、成果文件。

M2、M4 等已启用收费的任务按其规则提供最终积分消耗和可用余额；结算对账中时显示“成果已生成，积分结算处理中”，禁止显示猜测的扣分。M1 受控试用和本次 M3 不展示伪造账务，M3 结果不显示价格、消费或结算提示。差异复核摘要分别列出本次重新核验、沿用旧报告及仍未覆盖项，不把沿用当成已重核。摘要不披露内部参考库条目或他人文件名。

## 3.6 验收

HOME-A01：新账号空状态能直接进入当前已开放任务；已存在项目的账号首先能找到项目。

HOME-A02：筛选、刷新、应用重启后状态一致，四种业务计数不混淆。

PRJ-A01：修改运行任务的草稿后，当前成果仍对应启动快照；下次执行才采用新值。

PRJ-A02：复制、归档、删除、恢复不会重新收费或破坏其他项目。

PRJ-A03：Web 同账号跨设备可访问云项目与云账务；M5 不得显示不存在于该设备且未显式迁移的本地文件为可下载。

PRJ-A04：工作台可打开准确历史版本；复核页无版本目录，桌面助手常驻／窄屏唯一抽屉。无需输入对话文本即可完成解释、补材料、范围选择、执行和下载；实际执行进入同一时间线任务卡，浏览操作不产生假用户消息或逐点击日志。

PRJ-A05：对 F001／报告 R1 留下未发送草稿，转到另一问题或报告再刷新，原草稿、附件目标和已选范围均保持原绑定；保存或讨论不执行，运行中补充只进入下一版。

PRJ-A06：M3 同项目跨标签页并发执行只接受一个有效 run，重复同键返回原 run，空修订不执行；停止后的下一次执行使用新编号，旧成功成果仍可下载。

PRJ-A07：M3 快捷与对话任务的卡片、左侧结果和工作台历史指向同一 run／input／report；任务卡与结果可双向定位，刷新恢复不重复卡片，历史回看时完成不强制换页。回复引用须由服务端保存并验证的结构化元数据定位，安全任务摘要不得透传原始日志、内部提示或推理。#537／#538 与 #47 联调，由 #56 按 2026-10-04 决定逐项验收，不借用旧工程通过计数。

## 3.7 通用交互规范

布局以相应任务已确认原型为准。M3 在大于 900px 的窗口中保持右侧助手并排可见；小于或等于 900px 使用唯一可关闭抽屉，主操作始终可用。收起窄屏抽屉、缩放和布局切换保留输入、上下文、任务卡和范围选择；恢复桌面时自动恢复并排，不自动抢输入焦点。M1 补充要求区不据此改成聊天栏。

所有输入有可见标签，示例使用 placeholder 且不作为真实默认值提交。必填、可选、金额单位、时点、错误文字直接可见；不只依赖颜色、悬停或小问号。输入错误定位到字段，保留其他内容。

支持键盘焦点、清晰聚焦状态、合理 Tab 顺序及 Windows 显示缩放；错误/进度变化向辅助技术提示。对话 Enter 发送、Shift+Enter 换行可作为默认，中文输入法候选确认不得误发送。

长任务按钮防重复点击，但不锁死全应用；用户仍可查看其他项目、取消任务及保存下一版需求。删除资料、注销、真实支付等有实质影响的操作需清楚展示对象；普通保存、导航和生成前不添加无意义确认。
