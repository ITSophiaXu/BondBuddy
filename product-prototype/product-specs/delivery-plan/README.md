## Web 与 Windows 的边界

Web 阶段无需安装本地服务：材料必须经明确上传才能由服务端处理，按账号隔离、权限控制、加密与保留/删除策略保存工作副本。关闭浏览器不取消服务端任务；恢复登录可查看。具体保存期限与服务商保留条款在 M1-01 交付设计中落实。

M5 原文件、解析、缓存和任务检查点主要保存在本机，必要内容经平台网关发模型。Web 项目迁移为用户显式操作，不默认全量同步或删除云端副本。平台账号、钱包和账务一直作为统一权威。

每条 issue 包含目标、范围、依赖、建议角色、可验证验收、交付物和规格链接。所有任务默认未指派；成员自行设置 assignee，权限不足可评论认领并由维护者分配。没有虚构工期和到期日。规则包按 11 个市场/品种或 DFI 安排分别拆分，方便行业专家与工程师并行；工程规则包的拆分不对应额外的用户入口。

`build-plan.mjs` 及 scope-20260930.mjs、scope-20261001.mjs 是历史快照，包含已被当前 M1／M2 决定及本次 M3 范围取代的内容。`node build-plan.mjs` 现于写入前明确报错并退出，禁止全量重生成 plan.json、issues/ 或索引；当前需求按对应决定定向维护，不能通过删除保护恢复旧生成路径。

`node publish-issues.mjs --check` 仅执行本地引用／依赖／M3 六项范围校验，不等于远端已发布或已核验。包含 M3 的 `--apply`（含默认全阶段）在任何网络调用之前拒绝；M3 通过逐项核对现有 Issue 的定向更新维护，保留已有 assignee、状态及历史。其他阶段的发布规则未因此重新确认；使用旧发布器前仍须先核对它们各自的当前决定，不要据此批量覆盖。

历史 GitHub 发布使用官方 gh 已登录账号，按稳定隐藏标识识别任务并保存 published.json。该文件的旧 bodyHash、verified 和 verifiedAt 只描述当时发布快照，不证明本次范围已远端同步；新增 M3-11 只记录已保存的 #145 身份，不伪造新正文 hash。定向发布后另外核对实际正文、里程碑、依赖和父子关系。不自动指派、不发额外邀请、不覆盖已有人工内容。网络/权限/审批失败时停止；不盲重试创建，重新发现远端标识后继续。

本清单按 2026-10-01 用户决定修订；旧发版历史不等于当前任务已完成。它补充并优先于 v1.1 的 Windows 首发安排；产品业务约束、大公募与 DFI、私有券商模板以及指定积分方案保持。
