# [M4-11] 通过 Codex CLI 交付首批两文种、真实 Word 与准确底稿的全文迭代

里程碑：M4 · 建议角色：AI 工程师 · 优先级：P0

前置任务：{{M4-01}}、{{M4-02}}、{{M4-03}}、{{M4-07}}、{{M4-09}}、{{M4-10}}、{{M1-29}}。依赖是交付验收前提；资料研究、方案和单元开发可先并行。M4-09／M4-10 先提供意图、输入、任务事件和成果关系契约；本 issue 产出真实执行与成果，不让契约消费者倒依赖本流水线完成。M4-04／05／06 已整体转 M5，不作为本期依赖。

## 本期范围与后续范围

M4 只交付**立项报告、交易所普通私募募集说明书摘要**，每次一个文种；均支持准确底稿的全文新版本、真实可编辑正文 Word、独立编制说明、执行过程和恢复。主承销商核查意见、法律意见书、推荐函整体移至原编号 issue 的 M5；组合及精准范围改稿由 [M5-08](M5-08.md)接续，公募／银行间／DFI／多机构和模板扩展由 [M5-12](M5-12.md)接续。阶段范围以[2026-10-06 M4/M5 优先级拆分](../../../../docs/product-decisions/2026-10-06-m4-m5-priority-split.md)为准；不把移出要求写成已支持或取消需求。

## 目标与范围

本地实施：受信技能／方法 pin、只读输入、单文书双 Word、准确底稿全文新稿、崩溃与费用待核恢复已接入；证据见[实施验收记录](../../../../docs/acceptance/m4-implementation-2026-10-06.md)。最终统一验收待办：真实完整文书、专业内容、Word／WPS、生产沙箱与吞吐；两个真实文书 smoke 的超时证据保留，远端 issue 尚未修改。

- M4 后端继续使用 Codex CLI 作为任务理解、业务编排、事实／模板选择和文书编制入口；独立 worker 复用持久队列、租约、幂等、项目互斥、调用检查点、真实 usage 与恢复。确定性解析、计算、Word 写入／文件交付验证仍由有界工具实现；不新建模型 API／SDK agent runtime，不另造一套运行引擎。
- 执行前锁定完整输入：已开放的单文种、发行主体、目标与期间、来源募集书和采用资料准确版本／hash、模板准确版本、已采纳要求及其消息版本、编辑底稿及全文范围。CLI prompt、受信技能和工具／协议版本参与逻辑调用身份；资料及模板内指令是数据，不能扩大执行权限。
- 同一来源事实可按准确版本复用，建立事实／证据／规则／用户要求映射，输出首发文种各自完整正文、表格、引用与编制说明。普通私募摘要不得误用小公募／大公募章节或银行间背景；尚未开放的市场／品种在执行准入阶段明确反馈，不静默套模板。
- 模板按 M4-02 首发范围使用平台或本用户的精确版次，记录结构／样式处理和来源授权。旧参考企业名称、金额、签章、个人信息不能残留；不可用模板或匹配冲突按缺项规则处理，不静默换模板。模板库／市场和机构扩展由 M5-12 完成，不作为本期流水线前提。
- 补充／讨论只保存；明确生成或全文改稿才执行。制作中上传资料、改期间／品种、增加写作要求进入下一任务草稿，当前固定输入不变。“准备新任务”和同版本重复“继续改稿”保留草稿；术语澄清只追加原范围 clarification 事件，不改输入 hash。
- 显式继续改稿选择的 artifact 准确版本是编辑底稿，原募集书是生成事实来源，两者分别保存并沿连续版本追溯。全文新版本按底稿及完整要求执行，不能拿旧讨论引用覆盖新底稿。准确引用仍可用于讨论；精准章节／段落执行在 M4 未开放，收到该请求保留意图并说明 M5 范围，不创建 run、不擅自全篇重写。
- 新版本保留旧正文和旧编制说明；正文与编制说明独立登记，任务／成果／源稿／模板／要求／编辑底稿关系可回查。以真实可编辑 DOCX 和实际内容预览交付，不用聊天文本或合成预览冒充正式 Word。
- 宿主持久化实际执行阶段和安全工具摘要到同一 run，工作区显示“正在制作”及固定输入，助手显示执行过程。没有实际事件的工作不伪造执行；停止、失败、待处理、完成和实际可交付成果一致。读旧版本不抢切，制作页完成原位成为成果本体。
- 单文书正文／编制说明失败按已固定输入复用可靠成果，仅重试失败分支；系统恢复沿用原逻辑调用、任务和冻结。状态未知先核对，不能把页面刷新／部署升级当新生成或重复收费。平台错误免费修复，记录 correction_of_run_id；新材料／新要求的明确新任务按既有执行契约计量。
- 未开放文种、组合和局部改稿执行不进入生成队列、不预留积分、不用已有单文书冻结完成额外工作。用户显式选择另一首发文种作为独立任务才按独立输入执行，遵守项目互斥；不通过两个隐藏任务提前实现组合。
- 关键主体、发行方案、核心数据或必要模板无法确定时追问；执行后仍不可交付则失败释放，不把全篇待补充当成功成果。非关键缺项在可交付草稿中标待确认并列位置，不伪造核查程序、批准、签名或确定法律结论。

## 输入、输出和恢复责任

- 公共契约在 packages/contracts/ 唯一定义。worker 校验已开放范围、准确采用清单、输入 hash、模板 pin、要求采纳依据、底稿和授权目标；不能靠会话摘要或“最新文档”字符串定位执行文件。
- worker 显式载入受信的固定助手／首发文种技能并固定原字节 hash，不依赖用户个人目录或 CLI 自动发现。技能、模板、规则、prompt 及协议升级不能静默应用到旧调用；恢复验证原版配置，缺失或不匹配时保留待处理原因。
- 原件／模板只读，本轮可写工作目录隔离；CLI 仅使用允许工具和授权材料。Word 工具的输入／输出、实际文件 hash 与成果登记留证；未经申报的文件修改、越权材料或引用不得交付。只开放全文范围不削弱文件、授权或准确版次验证。
- 原始字节、固定输入／prompt 和成果存私有对象存储；版本、run、call／usage、事件、澄清及账务关系持久化。恢复先复用已完成调用及可靠解析／文件，不重发未知调用、不复用停止／失败任务的输入版本。
- 任务执行不以 M4-10 浏览器状态为权威；页面关闭后后台继续，重开从真实任务和成果恢复。已有有效技术交付与专业机构签发分别表述，不将“生成成功”写成“专业审核通过”。

## 验收标准

- [ ] 立项报告、普通私募募集说明书摘要均由真实 Codex CLI／工具路径生成完整可编辑正文 DOCX 和独立编制说明；正确文种、市场、目标、主体、模板／来源状态和本轮消费可追溯，不只替换标题。
- [ ] 对小公募／大公募／银行间／DFI、多机构、其他三文种和组合请求明确计划 M5，不进入生成或收费；不将交易所普通私募模板冒充其他完整结果。
- [ ] 采用带修订募集书的有效正文，不使用已删除旧数字；原参考企业名称、金额、签章和个人信息不残留。使用准确来源与模板版本，不能用模糊“最近”覆盖显式旧版选择。
- [ ] “请把偿债能力作为重点，保留财务表格，不要新增风险承诺。”三项出现在固定输入并实际影响内容；制作中新增一年内到期债务分析仅用于下一任务，原任务和 hash 不变（U2/U3）。
- [ ] 续改先补禁止新增风险承诺，再要求“精简全文，保留财务表格，生成新版本”，新版本同时遵守限制、全文范围和准确底稿；重复选同底稿不清空草稿。连续版本可追溯原募集书，底稿和事实来源分别展示（U3/U4）。
- [ ] 保留 v1 讨论引用后显式选 v2 做全文改稿，实际使用 v2；v4 底稿与 v3 段落引用同时存在时明确区分讨论引用和编辑底稿，不暗中改源（U4）。
- [ ] 第三章 section3-p1 引用可准确讨论；请求“压缩这段，保留数字并生成新版本”或“只改第二章”得到 M5 未开放反馈，不创建任务、不擅自全篇重写。用户另行明确全文新版本后才以全文快照执行；精准范围文件差异验收留在 M5-08（U5 的阶段边界）。
- [ ] “请生成立项报告，保留待核事项，不要新增风险承诺。”一次明确发送启动且正文遵守限制；“补充资料已经上传了，请开始生成立项报告。”一次启动。方法询问、暂缓／禁止整个任务不执行（U6）。
- [ ] 同项目不同话题／标签并发不能创建两个冲突 run；草稿保留，无自动排队。连点、断流、进程重启、丢 ACK 和部署升级恢复同一任务／调用／成果／预留，不重新收费，未知 usage 保持 unknown（U7）。
- [ ] 单文书正文失败时已完成说明保留且明确未完成；停止／失败旧有效版本可读。正在看制作页时真实完成原位转成果，正在读旧版时保持旧版，两侧绑定同一 run／input。
- [ ] 关键依据不足、模板不可用、无可交付 Word 或无法授权下载不收费交付全篇占位稿；非关键待核项定位到编制说明。未实施现场核查、函证、外部查询不得声称已经实施。
- [ ] 文件内命令不扩大工具权限；跨用户、项目、话题和私有模板读写／恢复／下载均验证授权。固定技能／prompt／协议版本恢复可核对，原始 CLI 日志和隐藏推理不透传到助手。
