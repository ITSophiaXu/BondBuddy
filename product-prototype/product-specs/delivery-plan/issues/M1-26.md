# [M1-26] 基于本发行人历史原文更新全文并形成可追溯修订

里程碑：M1 · 建议角色：AI 工程师 · 优先级：P0

前置任务：{{M1-10}}、{{M1-12}}、{{M1-14}}、{{M1-31}}。依赖是交付验收前提；资料研究、方案和单元开发可先并行。

## 目标与范围

- 有历史募集书时锁定用户原稿及有效正文为修订基线，在原文上修改；不能改走其他发行人参考稿重新起草，也不能只重写全文后把文件命名为修订版
- 读取 M1-31 的用户源市场、品类、期间声明和实际材料完整性结果，建立全文章节和数字引用关系；每处新增、删除、替换记录原文锚点、前后内容、来源和原因，交给 M1-29 生成真实 Word 修订
- 更新三表、附注、财务分析及全篇金额/期间引用，确定性计算指标；跨市场/品种允许必要的章节增删重组，保留原文对应关系
- 保留未受影响文字、有效旧事实、非标准审计意见和风险；保留原文件及已有修订，生成独立有效基线，缺新证据不只替换日期
- PDF/扫描历史稿先形成有原页锚点的可编辑重建基线，再基于基线修订；无法可靠重建的关键内容先补清晰材料，不能悄悄改成无历史稿模式
- SCOPE-10：原始材料直接交 worker（Codex + DeepSeek）；不依赖预先结构化财务数据或独立财务提取服务，财务读取/核对在任务内部完成

## 验收标准

- [ ] 新增一期、重述、合并/母公司、单位转换及旧年保留案例通过，未改动正文不会全部被删后重插
- [ ] 封面、表格、正文引用和财务指标同步一致，关键数字及条款修改可回到原稿位置和新证据
- [ ] 缺依据的变动原因和否定结论不编造，上传原件及旧成果哈希不变
- [ ] 已有修订删除的旧数不进入有效基线，本次修订与原文件历史修订分别可追溯；PDF 重建限制明确
- [ ] 有历史稿用例无需依赖相似募集书库，不能因库无匹配而阻止基于本企业原文更新

## 交付物与验证

- 对应实现或规则/模板版本，以及能复现上述边界用例的测试/样本记录。
- PR 关联本 issue；标明当前原型复用项、新增能力、配置迁移与尚未关闭的阻碍。
- 涉及生产短信、模型、支付、供应商或专业规则时，提供真实接入/审核证据；模拟通过不能替代上线验收。
