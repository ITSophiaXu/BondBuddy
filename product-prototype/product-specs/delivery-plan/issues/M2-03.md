# [M2-03] 将 M1 真实调用日志接入计费归因与外部服务成本计量

里程碑：M2 · 建议角色：服务端/支付工程师（财务参与验收） · 优先级：P0

前置任务：{{M1-11}}、{{M1-34}}、{{M2-02}}。依赖是交付验收前提；资料研究、方案和单元开发可先并行。

## 目标与范围

- 复用 M1-34 已上线的供应商请求、token、job/调用和 usage 证据，依据版本化费率生成成本事件；M2 增加计费归因与账务关联，不把采集推迟到收费上线
- 正确拆分缓存输入/推理输出；保留失败、重试、无效循环的真实消耗日志，按计费规则排除用户不应承担的费用，区分运营总成本、可计费成本与用户实际扣分
- 外购 OCR/数据费用只计一次，未知 usage 进入待对账；预检/试用/复用等 billable=false 事件不能补收

## 验收标准

- [ ] 重复事件、重复网关/CLI 聚合 usage 不重复计费，失败重试真实消费仍在运营报表可见
- [ ] 全任务高精度汇总后只取整一次，原始 token、归因成本与账本扣分可串联追溯
- [ ] 缺失用量不能以估算扣成实耗，演示费率不进入生产账单，历史 M1 试用不追溯扣费

## 交付物与验证

- 对应实现或规则/模板版本，以及能复现上述边界用例的测试/样本记录。
- PR 关联本 issue；标明当前原型复用项、新增能力、配置迁移与尚未关闭的阻碍。
- 涉及生产短信、模型、支付、供应商或专业规则时，提供真实接入/审核证据；模拟通过不能替代上线验收。
