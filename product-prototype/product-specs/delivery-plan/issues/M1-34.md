# [M1-34] 上线前交付统一用户行为、Prompt、Job、Token 与错误日志

里程碑：M1 · 建议角色：服务端工程师 · 优先级：P0

前置任务：{{M1-01}}、{{M1-04}}、{{M1-11}}、{{M1-12}}。依赖是交付验收前提；资料研究、方案和单元开发可先并行。

## 目标与范围

- M1 首个募集书更新任务向用户开放前必须 ready，受控试用也不豁免；第一批先定字段与埋点契约，随模型网关、队列、材料和已保存补充要求同步接入，不等 M2 收费上线才采集
- 建立统一 operation/request/trace/span、user/project/conversation/message、job/run/work_item/call/attempt 关联；记录已提交的登录/项目/材料/对话/执行/取消/恢复/下载行为、服务端结果与浏览器异常，不采未提交键盘输入
- 保存用户实际提交 prompt 及编辑版本、结构化输入/附件版本、实际发模型请求的受控内容快照或可还原清单、模板/规则/模型参数版本；正文加密限权，常规检索日志仅存引用和摘要，密钥/验证码/Cookie 不落日志
- 按逻辑 job 记录 update/review/generation/qa/preflight/parse 等类型与子类型、来源及父任务、时间/耗时、阶段、输入/成果版本、业务成功/失败/取消/拒绝和错误关联；成功按质量检查与可获取成果判定
- 按每次实际模型调用及重试记录供应商请求 ID、输入/输出/缓存/推理 token、usage 原始计数依据与状态、费用/费率引用、billable 与承担方；供应商包含关系按适配器归一，缺用量为 unknown/pending，失败消费仍入运营汇总
- 设计结构化 error_code/category、阶段、脱敏消息/堆栈、供应商状态、重试次数、根因指纹和恢复结果；HTTP 成功、模型结束、Word 导出失败及用户取消不得混为任务成功
- 采用持久化 outbox/缓冲、幂等事件和调用归属去重，关键事件全量记录；补写、乱序、进程崩溃及日志服务不可用均可恢复，无法持久化执行证据时暂停新外部调用并报警
- 提供后台按用户/项目/job/trace/时间/模型/状态/error 筛选、任务时间线、限权 prompt 查看、token 与成功率/失败率/耗时看板；日志查阅/导出留审计记录，配置保存期限及删除流程，不把 prompt 用于公共库或训练

## 验收标准

- [ ] 首个真实更新任务上线前，按 job_id 能查到用户 prompt、目标/材料版本、阶段、全部模型尝试、分项 token、成果或错误；有稿修订/无稿新编、免费预检及已保存补充要求均覆盖
- [ ] 成功、解析失败、模型超时/重试、用户取消、导出损坏、预检拒绝及浏览器关闭后继续运行有样本；未创建 run 的拒绝仍可检索，终态不双计
- [ ] 重试失败消耗与最终成功消耗均保留；同一供应商调用的网关/执行框架重复 usage 只算一次，缓存输入/推理输出不重复相加，断流缺 usage 不记 0 或估成实耗
- [ ] 提示词正文可在受控权限下回查和追溯版本，普通日志/指标/客服默认看不到明文；跨账号越权、凭证泄漏、日志注入及到期/用户删除后的内容回收通过
- [ ] 日志转发中断/数据库事务失败/进程崩溃演练不静默漏掉 job、调用或终态，积压可重放且不重复统计；原始日志追加更正不覆盖历史
- [ ] 提供字段字典、事件目录、真实匿名联调记录、后台检索与指标口径、日志保存配置及告警/恢复手册；M1 不产生用户账务扣分，M2-03 消费同一记录作计费归因

## 交付物与验证

- 对应实现或规则/模板版本，以及能复现上述边界用例的测试/样本记录。
- PR 关联本 issue；标明当前原型复用项、新增能力、配置迁移与尚未关闭的阻碍。
- 涉及生产短信、模型、支付、供应商或专业规则时，提供真实接入/审核证据；模拟通过不能替代上线验收。
