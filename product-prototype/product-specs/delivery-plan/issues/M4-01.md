# [M4-01] 交付首批材料生成与问答合并工作区、按文种构建输入及成果联动

里程碑：M4 · 建议角色：前端工程师 · 优先级：P0

前置任务：{{M1-04}}、{{M1-07}}、{{M4-10}}。依赖是交付验收前提；资料研究、方案和单元开发可先并行。M4-10 提供共享话题、草稿、助手与成果标签契约；本 issue 消费契约完成左侧任务输入和文种表单。M1-13 不再作为已交付多轮助手的前提。

## 本期范围与后续范围

本地实施：已接入合并入口、按文种表单、讨论按钮及真实成果 tabs。自动化和跨业务交接证据见[实施验收记录](../../../../docs/acceptance/m4-implementation-2026-10-06.md)。最终统一验收待办：真实 API 逐屏、同尺寸原型对照及发布环境回归；远端 issue 尚未修改。

M4 首批只开放**立项报告、交易所普通私募募集说明书摘要**的单文种生成及全文新版本；入口、资料、草稿、执行、真实 Word 与编制说明、成果阅读和恢复必须形成完整闭环。阶段范围以[2026-10-06 M4/M5 优先级拆分](../../../../docs/product-decisions/2026-10-06-m4-m5-priority-split.md)为准，覆盖上一版 M4 的广度要求，已确认 UX 继续有效。

主承销商核查意见、法律意见书、推荐函及摘要的其他市场／品种在 M5 开放；组合生成和精准章节／段落执行改稿归 [M5-08](M5-08.md)，跨业务自然语言创建／执行及高级 QA 成果管理归 [M5-10](M5-10.md)。未开放项明确显示“计划 M5”，不进入可执行表单，不虚构已完成任务；不将请求偷偷改为首发文种或全文改稿。

## 目标与范围

- 沿用 BondBuddy 的业务导航和左右布局，将材料生成与项目问答合并为“材料生成与问答”入口。右侧助手始终可用，负责理解、澄清、执行反馈和讨论；取消收起／全屏助手选择，不另建独立 QA 页面。
- 左侧工作区组织材料、目标、范围和要求，构成同一 Agent 任务输入；同时通过成果标签阅读 artifact 本体。纯问答直接在右侧完成，不创建“问答任务输入”表单或标签。
- 先选择立项报告或普通私募募集说明书摘要，再仅展开该文种需要的来源、模板、补充资料和业务字段；各文种草稿分别保存。不一次罗列所有文种材料，不把组合请求拆成自动执行的两份任务。
- 新材料任务默认提供“上传最新版募集书”，第二选项为关联本账号项目的准确文件版本；已有明确选择的草稿保持原选择。关联列表优先展示已完成更新稿，显示发行人、市场／品种、报告期、版本、更新时间及完成状态；选择未完成稿时如实显示实际来源。
- 工作区上传、助手附件和显式关联进入同一话题可用资料库；每项任务另有准确采用清单。来源、模板和专属证据标明用途、准确版本和状态，不能因进入话题库就全部用于当前文种。
- 删除左侧“补充意见／补充要求”文本框。经助手采纳的写作重点和限制回填当前草稿，左侧只读显示“助手已采纳要求”；预置内容标“系统默认规则”。字段澄清回填对应字段，不能重复记为写作要求。
- 执行按钮旁提供“与助手讨论”：带入当前任务、来源、期间、范围、模板或编辑底稿的准确上下文并聚焦消息框；保留已有未发送文字和准确段落引用，不发送、不执行、不覆盖原引用。
- 点击“开始生成”或在 M4 助手明确请求已开放的单文种生成时调用同一真实任务入口；沿用有效报价、授权和预留契约。工作区提供“正在制作”标签及固定输入，右侧显示同一 run 的实际执行过程；阅读旧成果时提交或完成任务都不抢切，正在查看制作标签时完成原位成为成果本体。
- “准备新任务”打开已有的下一任务草稿；“继续改稿”选择明确 artifact 版本作为全文新版本的底稿，同版本重复操作保留已有要求。编辑底稿与原募集书生成来源分别展示，旧版本和编制说明独立保留。
- 准确引用仍可用于讨论、解释和核对来源。收到“只改第二章／这段并生成新版本”等局部执行请求时，说明精准范围改稿计划 M5，不创建 run、不扩大范围；用户随后明确改为全文新版本，才按重新核对的完整输入执行。
- 从当前入口提出更新／复核需求时，保留讨论意图并给出到现有目标工作区的显式入口；用户跳转后核对目标、来源、范围和有效报价，再明确执行，不在当前话题自动创建其他业务任务。前端不执行模型业务；助手与首批生成仍由服务端受控 worker 的 Codex CLI 完成。

## 验收标准

- [ ] 首次进入合并入口，纯 QA 无左侧任务输入；选择首发文种后仅有该文种资料区。其他文种和组合明确未开放。取消补充意见、收起和全屏选择；桌面与窄屏沿用现有框架，不增加新导航或重复助手。
- [ ] 工作区上传募集书后，助手能看到同话题已授权资料。发送“计算这份募集书的资产负债率，告诉我数据来源。”采用准确募集书；随后“再用这份募集书生成立项报告。”只追问真实缺项，不重新索要已有募集书（U1）。
- [ ] 上传稿后明确采用项目 v5，再选另一首发文种，来源仍为 v5；关联 v5 后再明确采用新上传稿，后续目标任务采用该新稿。多个候选无明确指代时澄清，不静默取旧附件、其他话题或其他项目（U1）。
- [ ] 发送“请把偿债能力作为重点，保留财务表格，不要新增风险承诺。”后，三项显示在对应草稿的已采纳区及随后固定输入；回答目标发行人、报告期或立项目的后回填对应字段，仅追问剩余项，不执行；问“是否应该保留财务表格？”只讨论，不冒称采纳（U2）。
- [ ] 制作中补“增加对一年内到期债务的分析”，再点准备新任务，该要求仍在下一任务草稿，当前 run 固定输入不含该项。切首发文种再返回恢复各自草稿及要求，专属证据不串用（U3）。
- [ ] 继续改稿补“禁止新增风险承诺”，再要求“精简全文，保留财务表格，生成新版本”，固定输入同时保存限制、全文范围、准确底稿与来源；重复点同版本继续改稿不清空草稿。明确准备新任务／改稿更新讨论目标，未绑定要求不重复消费（U3）。
- [ ] 保留 v1 引用后打开 v2 点继续改稿，明确全文改稿采用 v2；旧引用不覆盖底稿。v4 底稿与 v3 引用并存时要求解释“这段”，明确引用对象；局部执行不启动，也不悄悄改成全文（U4/U5）。
- [ ] 引用第三章 section3-p1 讨论时显示准确 artifact／version／anchor／引用原文；发“压缩这段，保留数字，并生成新版本”，说明精准范围改稿计划 M5，保留引用／要求且不创建 run。另行明确全文新版本后按全文范围执行（U5 的阶段边界）。
- [ ] 与助手讨论通过点击和键盘触发均保留未发送文字及引用，仅带上下文、聚焦；320px 无横向溢出，主要执行和讨论操作可达。已有不同引用上下文显示准确绑定，不静默覆盖。
- [ ] 左侧正在制作和右侧执行卡对应同一 run／输入；观看制作页时完成原位呈现真实正文，观看旧版本时保持原阅读对象，有准确新成果入口。正文、编制说明及历史版本独立可查。
- [ ] 同一项目另一话题有活动任务时，生成请求被互斥阻断并可查看该任务；当前草稿保留，无自动排队，任务结束后旧请求不自动执行。
- [ ] 要求“再用这份募集书生成法律意见书”，说明文种计划 M5，不重新索要已有稿，也不执行替代文种；要求复核该稿时给显式业务跳转，只有进入目标工作区重新核对并明确执行后才创建目标业务 run。
