# [M1-13] 实现更新项目右侧多轮讨论与补材料继续

里程碑：M1 · 建议角色：AI 工程师 · 优先级：P0

前置任务：{{M1-06}}、{{M1-10}}、{{M1-12}}。依赖是交付验收前提；资料研究、方案和单元开发可先并行。

## 目标与范围

- 真实回答、追问缺口、保存额外信息，并区分拟定安排与证据事实
- 明确执行要求触发全文更新，普通补充或方法提问不自动执行
- 补材料、改报告期/品种产生新输入版本；同范围澄清可继续原任务
- 每次已提交用户 prompt 保存版本化受控快照并关联 message/operation/job，记录用户意图与实际路由；未执行全文的问答、追问和补充同样接入 M1-34

## 验收标准

- [ ] 授信日期/单位缺失会追问，冲突不被最后一句话静默覆盖
- [ ] 对话中的重点不缩小默认全文更新范围
- [ ] 清楚显示保存、继续和生成新版的差别，旧成果保留
- [ ] 编辑 prompt 不覆盖旧快照，一条消息触发多个模型调用可逐次追溯，普通日志/指标不输出 prompt 明文

## 交付物与验证

- 对应实现或规则/模板版本，以及能复现上述边界用例的测试/样本记录。
- PR 关联本 issue；标明当前原型复用项、新增能力、配置迁移与尚未关闭的阻碍。
- 涉及生产短信、模型、支付、供应商或专业规则时，提供真实接入/审核证据；模拟通过不能替代上线验收。
