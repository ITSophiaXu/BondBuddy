# [M1-13] 以表单末尾补充要求替代更新项目多轮聊天

里程碑：M1 · 建议角色：前端工程师 · 优先级：P0

前置任务：{{M1-04}}、{{M1-06}}、{{M1-12}}。依赖是交付验收前提；资料研究、方案和单元开发可先并行。

## 目标与范围

- 项目表单最后一行选填“本次更新的补充要求”；服务端保存确认、刷新/重登恢复，失败保留输入
- 移除 M1 聊天/发送/助手回复与追问；唯一“开始更新”锁定输入，输入文字本身不执行
- 旧用户消息保留版本、来源及顺序；待执行要求迁入字段，不把助手回复当用户事实，不默默覆盖冲突
- 运行中改动只影响后继输入；完成后回到同一项目改资料/要求并明确开始，旧成果保留

## 验收标准

- [ ] SCOPE-05：字段末尾可保存/恢复，无聊天入口，保存失败可重试且不丢原文
- [ ] SCOPE-06：写“开始/继续”不创建 run，重复明确提交幂等，当前 run 不被编辑污染
- [ ] 旧项目、消息来源、冲突处理、账号隔离、新旧输入和成果分别验证；真实任务日志不丢要求版本

## 交付物与验证

- 对应实现或规则/模板版本，以及能复现上述边界用例的测试/样本记录。
- PR 关联本 issue；标明当前原型复用项、新增能力、配置迁移与尚未关闭的阻碍。
- 涉及生产短信、模型、支付、供应商或专业规则时，提供真实接入/审核证据；模拟通过不能替代上线验收。
