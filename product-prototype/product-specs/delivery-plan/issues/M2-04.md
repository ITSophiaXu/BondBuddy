# [M2-04] 将更新任务接入一键冻结、结算与失败释放

里程碑：M2 · 建议角色：服务端/支付工程师（财务参与验收） · 优先级：P0

前置任务：{{M1-12}}、{{M1-29}}、{{M2-01}}、{{M2-02}}、{{M2-03}}。依赖是交付验收前提；资料研究、方案和单元开发可先并行。

## 目标与范围

- 开始执行时原子检查余额并冻结，成功交付后扣 min(A,B)
- 失败/取消全额释放，超出 B 由平台承担，系统恢复复用原 run
- 处理余额不足、取消/交付竞争、待对账和免费纠错
- 有任一关系原稿及无原稿都接入同一付费闭环，按批准方案计费，不依赖参考库

## 验收标准

- [ ] 余额等于 B 可开始，小于 B 不启动且保留材料
- [ ] A<B、A>B、重启、超时、取消及重复点击用例通过
- [ ] 充值后不自动重放原任务；资料补充、上传和旧成果下载免费

## 交付物与验证

- 对应实现或规则/模板版本，以及能复现上述边界用例的测试/样本记录。
- PR 关联本 issue；标明当前原型复用项、新增能力、配置迁移与尚未关闭的阻碍。
- 涉及生产短信、模型、支付、供应商或专业规则时，提供真实接入/审核证据；模拟通过不能替代上线验收。
