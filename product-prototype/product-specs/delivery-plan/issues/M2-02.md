# [M2-02] 实现按真实工作量的分类、系数与冻结估算

里程碑：M2 · 建议角色：服务端/支付工程师（财务参与验收） · 优先级：P0

前置任务：{{M1-31}}。依赖是交付验收前提；资料研究、方案和单元开发可先并行。

## 目标与范围

- 按指定积分方案实现更新/复核/生成/QA/首次付费解析分类
- 读取 M1-31 用户声明的原市场/品类/报告期、材料完整性与源目标差异结果；据此确定源目标产品代码、迁移方向 M、目标结构 J 和待更新期间估计 N，不从文件名或目标下拉框猜原稿
- 识别 N=0、新期间、重述和模板/证据工作量，不按附件年份粗算；最终实际 N 按执行中真正完成的不同截止期核定
- 内部 E/B 估算、价格及源信息快照锁定；原稿/目标/校正变化使旧估算失效，DFI 不重复收费
- 上传后既有免费预检由平台承担的 OCR/模型事件标记 billable=false，任务复用结果不得倒补收费
- 同时消费原企业关系和明确无原稿状态；非同企业源期间不能抵减目标期间；关系定价映射缺失由 M2 明确，本次不新设系数

## 验收标准

- [ ] 原稿上交所私募转深交所公募与同市场同方式更新使用各自有依据的迁移系数，计价可追溯到用户声明、实际材料处理证据和目标版本
- [ ] N=0/1/多期、重述、无历史稿及 DFI 组合有参数化用例；原稿含三年但只新增一年不得按四期收费
- [ ] 多品种及特殊事项只作用于实际相关工作项，报告期和迁移是难度因素而非固定整单价格，最终结算仍结合实际用量
- [ ] 关键源字段待确认时不能猜定高系数并收费；材料/目标变化重算且不覆盖已执行快照
- [ ] 估算与价格只由平台生成，无用户报价确认页；源信息填写/保存不扣分，预留 B 与成功实际结算 min(A,B) 可逐项回查

## 交付物与验证

- 对应实现或规则/模板版本，以及能复现上述边界用例的测试/样本记录。
- PR 关联本 issue；标明当前原型复用项、新增能力、配置迁移与尚未关闭的阻碍。
- 涉及生产短信、模型、支付、供应商或专业规则时，提供真实接入/审核证据；模拟通过不能替代上线验收。
