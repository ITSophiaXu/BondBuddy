# [M2-06] 交付钱包、充值、流水、余额不足和费用结果页面

里程碑：M2 · 建议角色：前端工程师 · 优先级：P1

前置任务：{{M2-01}}、{{M2-04}}、{{M2-05}}。依赖是交付验收前提；资料研究、方案和单元开发可先并行。

## 目标与范围

- 展示可用/冻结、批次与到期、充值档位、订单和任务流水
- 提供支付中/过期/到账/失败反馈及余额不足后的充值入口
- 规则说明清楚解释实际结算与冻结上限，无月费门槛

## 验收标准

- [ ] 赠分和购入积分可用于同一已授权能力，不强制付费积分
- [ ] 重复点击支付不会产生重复充值，到账后用户再发起任务
- [ ] 页面消费与账本一致，活动到期提醒按批次去重

## 交付物与验证

- 对应实现或规则/模板版本，以及能复现上述边界用例的测试/样本记录。
- PR 关联本 issue；标明当前原型复用项、新增能力、配置迁移与尚未关闭的阻碍。
- 涉及生产短信、模型、支付、供应商或专业规则时，提供真实接入/审核证据；模拟通过不能替代上线验收。

## 规格与认领

- [14-积分充值与结算](https://github.com/ITSophiaXu/BondBuddy/blob/feat/review-classification-optimization/product-prototype/product-specs/14-%E7%A7%AF%E5%88%86%E5%85%85%E5%80%BC%E4%B8%8E%E7%BB%93%E7%AE%97.md)
- 认领时设置 assignee（权限不足请评论认领并请维护者分配），写明方案及依赖；完成后附 PR 与验收证据。
- 本 issue 不预设个人负责人或截止日期；多个成员可按组件协作，避免重复实现。
