# [M2-06] 交付余额、充值、支付状态和余额不足提示

里程碑：M2 · 建议角色：前端工程师 · 优先级：P1

前置任务：{{M2-01}}、{{M2-04}}、{{M2-05}}。依赖是交付验收前提；资料研究、方案和单元开发可先并行。

## 目标与范围

- 保留可用余额、必要冻结/到期提示和充值入口，不建设用户消费记录/任务流水页
- 提供支付中、过期、到账、失败及余额不足反馈，资料保留
- 本次任务收费反馈可与后台账本核对；不要求累计消费面板或余额退款入口

## 验收标准

- [ ] 支付到账与后台一致，重复回调不重复发分
- [ ] 余额不足不启动且不丢材料，充值后需用户再次明确开始
- [ ] 失败/取消释放可正确反馈，无消费记录和余额现金退款入口

## 交付物与验证

- 对应实现或规则/模板版本，以及能复现上述边界用例的测试/样本记录。
- PR 关联本 issue；标明当前原型复用项、新增能力、配置迁移与尚未关闭的阻碍。
- 涉及生产短信、模型、支付、供应商或专业规则时，提供真实接入/审核证据；模拟通过不能替代上线验收。

## 规格与认领

- [14-积分充值与结算](https://github.com/ITSophiaXu/BondBuddy/blob/develop/product-prototype/product-specs/14-%E7%A7%AF%E5%88%86%E5%85%85%E5%80%BC%E4%B8%8E%E7%BB%93%E7%AE%97.md)
- 认领时设置 assignee（权限不足请评论认领并请维护者分配），写明方案及依赖；完成后附 PR 与验收证据。
- 本 issue 不预设个人负责人或截止日期；多个成员可按组件协作，避免重复实现。
