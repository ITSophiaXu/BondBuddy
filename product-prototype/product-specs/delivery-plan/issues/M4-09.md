# [M4-09] 实现首批助手意图路由、任务草稿回填与既有按轮计费

里程碑：M4 · 建议角色：AI 工程师 · 优先级：P0

前置任务：{{M4-08}}、{{M2-02}}、{{M2-04}}。依赖是交付验收前提；资料研究、方案和单元开发可先并行。先交付版本化意图／草稿／执行来源契约，M4-01、M4-10、M4-11 消费，不能等待这些消费者完成而形成倒依赖。

## 本期范围与后续范围

M4 支持基础专业 QA，以及立项报告、普通私募募集说明书摘要的单文种生成和全文新版本；保留完整执行保护、准确输入、恢复和原价格契约。组合生成、精准章节／段落执行改稿移至 [M5-08](M5-08.md)，跨业务自然语言创建／执行和高级 QA 成果管理移至 [M5-10](M5-10.md)。范围以[2026-10-06 M4/M5 优先级拆分](../../../../docs/product-decisions/2026-10-06-m4-m5-priority-split.md)为准。

## 目标与范围

本地实施：免费澄清、准确草稿回填、有效报价下单任务自然执行、实际钱包按量封顶及 unknown 用量恢复已接入；证据见[实施验收记录](../../../../docs/acceptance/m4-implementation-2026-10-06.md)。最终统一验收待办：正式价格配置、真实费用／支付核对及发布环境回归；远端 issue 尚未修改。

- Codex CLI 理解完整消息与上下文，分别识别问答、字段答复、事实补充、写作要求、停止意图和明确执行动作。平台验证结构化意图、开放范围及归属，持久化草稿及执行输入，不采用“补充／生成／不要生成”等单关键词优先级执行。
- 纯 QA 直接在右侧完成；补充和缺项答复默认保存／澄清、不自动执行。已开放单文种的明确材料生成请求在同次发送启动正确任务，不要求特殊口令或新建“问答任务”。已具备有效执行条件和明确授权时，不增加形式确认或独立报价页；未具备的资料、有效报价／授权及账务准入按对应公共执行契约如实处理。
- 整句同时含生成动作和局部禁止项时，局部约束进入固定输入；“先别生成／暂时不要生成”等停止整个任务的指令不得启动。“如果缺资料请告诉我”不撤销前面的执行请求；确有关键缺项时保存原请求并只追问剩余项，答复缺项本身不启动，齐备后等待明确执行。
- 最近明确来源优先；未指定来源且当前话题候选唯一时可继承，候选不唯一或指代冲突时澄清。共享资料库与任务采用清单分开，模板与专属证据不能随新文种全量采用，不读取未选择的云项目或其他话题资料。
- 自然写作重点、篇幅和禁止项保存到明确文种／底稿的草稿；字段更正覆盖对应字段并保留修订记录，不累积成矛盾要求。只读已采纳清单仅展示真正采纳内容；讨论性问句和系统默认规则分开。未开放文种需求可保留为讨论意图，不生成可执行草稿或收费任务。
- 同项目任务互斥、执行请求幂等。活动任务期间新材料／新要求进入下一任务草稿，不改固定快照、不自动排队；同范围术语澄清可作为原 run 附加事件保存答复，不重写输入 hash。新材料、报告期、品种、范围或成果变化须新快照并明确新执行。
- 编辑底稿、原募集书来源和讨论段落引用分别固定。显式继续改稿选择准确底稿，全文新版本按该底稿和完整要求执行。准确引用保留用于讨论；收到局部生成／改稿请求时说明 M5 尚未开放且不执行，不能把局部指令擅自转换为全文。用户另行明确全文新版本后，重新核对并固定全文范围。
- 跨业务请求可解释区别、保留意图并给出到现有更新／复核／材料工作区的显式入口。M4 不从当前助手自动创建其他业务草稿或启动对应 run；用户跳转后在目标工作区核对来源、目标、期间、范围、报价和授权，再明确执行。原更新／复核入口与已上线协议照常可用，不能把其他业务任务伪装成 QA 计费。
- 当前已上线 M1／M3 协议、历史任务、旧提示和旧账单保留原版兼容；新增行为采用本期范围门控。不得通过新 schema 重放历史调用或追补费用。
- 本轮按实际已开放的 Q 类型或 G 文种分类，继承第 14 章及对应公共账务适用契约，不新增价格。项目背景或上一轮高系数不决定本轮类型；平台纠错免费并记录 correction_of_run_id。已有回答保存／文本导出、预检／澄清、纯拒答、未执行／无结果查询和产品帮助按原免费边界处理。
- 未开放文种、组合、局部执行和跨业务自动执行的范围说明不建立文书 run、不冻结积分、不借已有生成预留执行。基础 QA 中的文字起草保留文本答复及免费已有文本导出；可编辑分析／起草 artifact 生命周期移至 M5，不由本 issue 提前引入。

## 验收标准

- [ ] 完整发送“请生成立项报告，保留待核事项，不要新增风险承诺。”正确启动 G01 并保留局部禁止项；“补充资料已经上传了，请开始生成立项报告。”同次启动，不误存为普通补充（U6）。
- [ ] “如何生成立项报告”“暂时不要生成”“先别生成”“不要复核”均不建执行任务；“请生成立项报告，如果缺资料请告诉我需要哪些材料”保持主请求，缺项精准追问，不退化为一般概念回答（U6）。
- [ ] 自由回答目标发行人、报告期和立项目的回填正确字段；切换到另一首发文种后指令定位对应草稿，更正覆盖旧值；仅答复缺项不执行，不重复追问已齐备材料（U2）。
- [ ] 三项“偿债能力重点、保留财务表格、不要新增风险承诺”进入草稿与固定输入；问“是否应该保留财务表格？”不冒称已采纳；系统默认内容不被标为用户要求（U2）。
- [ ] 工作区已上传募集书可用于准确 QA；随后“再用这份募集书生成立项报告”复用准确来源，仅追问特有缺项。多候选时澄清，不拿旧附件或其他话题数字代算（U1）。
- [ ] 制作中补一年内到期债务分析仅进入下一任务草稿；准备新任务、同版本重复继续改稿及切文种不丢限制、不跨文种传播；未绑定要求采纳有持久记录且只消费一次（U3）。
- [ ] v1 旧引用与显式 v2 全文改稿共存时采用 v2；讨论引用不改绑。续改先补禁止新增风险承诺，再发“精简全文，保留财务表格，生成新版本”，完整保留要求与准确底稿（U3/U4）。
- [ ] 带有效引用发“只压缩这段，保留数字并生成新版本”或“只改第二章”，说明精准范围改稿计划 M5，保留意图／引用且不建 run、不扩大为全文；随后明确全文新版本才执行，范围说明不产生生成账单（U5 的阶段边界）。
- [ ] 同 execution_request_id 重发只返回同一 run；跨话题同项目活动任务阻断另一执行，保留草稿、无隐式排队；旧任务结束或充值到账不自动执行旧请求。
- [ ] 复核页提出更新至2026年6月，解释与复核的区别、保留意图并提供显式目标入口；不自动创建更新草稿或 run。用户进入更新工作区核对来源、目标和对应有效报价并明确执行后，只由原公共入口创建一次真实任务，原复核记录不变。
- [ ] 材料与问答中“开始复核，重点看有息负债口径”提供复核入口而不启动隐藏任务；已选来源保留为可核对的意图上下文，用户在目标工作区明确执行；不得按短 QA 计价、复用旧任务费用或沿用旧 M3 免费断言。
- [ ] “生成法律意见书和核查意见”说明两个文种和组合计划 M5，不建立组合／子文书任务，不冻结费用，也不替换为立项报告；已有准确募集书保留，不重复索要。
- [ ] “下载在哪里”按免费产品帮助处理；本轮仅追问数值来源按实际定位类型，不沿用前轮高系数；成功回答再次导出不建立模型调用或新账单。
- [ ] 纯拒答、未执行／无结果查询、平台错误纠正按原免费边界；有证据的不确定分析与纯拒答区分。分类、预留、结算或释放、真实 usage 关联可核对，usage 缺失保持 unknown，不写零成本。

## 交付物与验证

- 公共意图／草稿修订／来源和范围契约在 packages/contracts/ 唯一定义，保存准确消息及版本、采纳依据、input hash 和执行请求身份；按原 schema／prompt 版本恢复，不重新路由历史消息或追加账单。
- CLI prompt／技能／协议版本、真实调用、工具事件及 usage 由独立 worker 宿主管理；不改为模型 API／SDK 后端，不以页面分类作为收费或执行权限依据。
- 用上述原句建立 U1–U4、U6 及 U5／跨业务阶段边界回归，记录“保存／澄清／实际启动／未开放”、目标文种、准确输入及账务预期；合成响应不冒充真实 CLI 意图能力验收。M5-08／M5-10 继承移出功能及原完整验收。
- PR 关联本 issue，列出自动化证据和最终统一验收待办；真实模型、专业判断和支付／结算证据按仓库当前口径分别登记。
