# [M4-08] 实现专业 QA 的检索、财务分析和公开查询

里程碑：M4 · 建议角色：AI 工程师 · 优先级：P0

前置任务：{{M1-10}}、{{M1-11}}、{{M3-04}}、{{M3-05}}。依赖是交付验收前提；资料研究、方案和单元开发可先并行。

## 目标与范围

- 覆盖债券问答、所选材料解读、财务分析、授权公开查询及轻量起草
- 基于当前会话/关联项目检索，确定性计算和有效来源引用
- 区分一般解释、适用法规结论、原始查询事实与推断

## 验收标准

- [ ] 财务回答给公式、输入、单位、期间和出处
- [ ] 法规结论给适用市场/版本/时点，不能虚构引用
- [ ] 未关联文件不可跨项目读取，数据源不可用说明实际限制

## 交付物与验证

- 对应实现或规则/模板版本，以及能复现上述边界用例的测试/样本记录。
- PR 关联本 issue；标明当前原型复用项、新增能力、配置迁移与尚未关闭的阻碍。
- 涉及生产短信、模型、支付、供应商或专业规则时，提供真实接入/审核证据；模拟通过不能替代上线验收。

## 规格与认领

- [13-QA与项目对话](https://github.com/ITSophiaXu/BondBuddy/blob/develop/product-prototype/product-specs/13-QA%E4%B8%8E%E9%A1%B9%E7%9B%AE%E5%AF%B9%E8%AF%9D.md)
- 认领时设置 assignee（权限不足请评论认领并请维护者分配），写明方案及依赖；完成后附 PR 与验收证据。
- 本 issue 不预设个人负责人或截止日期；多个成员可按组件协作，避免重复实现。
