# [M1-32] 建设后台募集书库、分类索引与首批可用参考数据

里程碑：M1 · 建议角色：数据接入工程师（商务/行业参与验收） · 优先级：P0

前置任务：{{M1-01}}、{{M1-08}}、{{M1-09}}、{{M1-14}}。依赖是交付验收前提；资料研究、方案和单元开发可先并行。

## 目标与范围

- 建立仅供授权运营和任务服务使用的募集书原件、正文、发行主体、不可变文书版本及业务收入画像；普通用户无库入口、列表、检索或下载权限，项目上传材料默认不入公共库
- 逐份索引上交所/深交所/交易商协会、发行方式、实际工具/债券品种标签、文书阶段、报告期与披露日期；DFI 仍为协会发行方式，注册安排与实际一期工具分字段
- 从库内募集书财务/业务章节或关联的发行人审计附注提取最近完整年度全部可比主营业务收入，按同一主体的合并报表口径排名，保存前三大业务名称/标准代码、顺位、金额、占比、年度、口径与逐项原页证据
- 建立审核过的业务分类与保守别名词典，生成不含顺序的三业务集合匹配键，保留原始顺位；同一行业标签、地区收入、合计行和重复业务不能冒充三业务
- 实现原文件及解析内容存储、内容哈希去重、同名发行人消歧、按市场/方式/品种过滤及三业务精确集合检索；向 M1-28 提供服务端内部查询契约
- 完成首次可用建库，提供来源可核验、允许处理的真实参考稿、审核记录及首发市场/方式/业务覆盖矩阵；索引可登记不完整条目，但只有来源、正文、分类与三业务证据均通过审核的版本可推荐

## 验收标准

- [ ] 目标与候选均按合并报表主营业务收入识别前三业务；营业收入、母公司/混合/未知口径或未区分主营业务不得自动匹配或锁定，不重标旧画像，细则见 LIB-01A
- [ ] 给定相同三业务且顺序不同的目标，返回集合匹配候选；只命中两项、宽行业相同、口径混杂、第三名并列或分类不明不能返回 exact
- [ ] 市场、发行方式、实际工具/品种可独立检索；DFI 注册稿与具体中票不混为一类，小/大公募不合并为未知公募
- [ ] 重复文件不重复建稿，同名不同主体不合并，新年度画像不覆盖旧年度；每项索引可追到材料版本和原文证据
- [ ] 不是仅交付空表、假数据或搜索页面：每个首发市场/方式至少有真实已审核参考稿，并有无用户相似稿的成功匹配编制样本；覆盖空白如实列出
- [ ] 普通账号不能枚举/下载库内原件，客户上传历史稿/相似稿/审计报告不会自动进入跨账号参考库
- [ ] 提交数据字典、导入清单、首批数据与权限证据、索引查询测试及运营使用说明

## 交付物与验证

- 对应实现或规则/模板版本，以及能复现上述边界用例的测试/样本记录。
- PR 关联本 issue；标明当前原型复用项、新增能力、配置迁移与尚未关闭的阻碍。
- 涉及生产短信、模型、支付、供应商或专业规则时，提供真实接入/审核证据；模拟通过不能替代上线验收。
