# 15 后台规则、模板及数据接入

2026-09-25 知识交付索引：用户提供的沪深通用法规及专家指南已整理为 [六种公司债范围的独立知识草稿](../../knowledge/exchange-bonds/README.md)（#20–#25）。原件、来源/版本/hash、段落页定位、章节映射、私募/小公募/大公募差异、冲突及未覆盖项均保留。使用既有 #19 RulePack/ChapterTemplate/CoverageManifest，未经现行效力核验及真实样本专业验收的条目保持研究状态，不随原型下拉选项自动发布。该知识库是法规与写作方法资产，与下文用于无历史稿编制的募集书参考库分别管理。

## 15.1 运营后台与权限

OPS-01：普通用户没有募集书库入口。后台仅对授权运营、行业审核、数据接入及账务人员开放，职责分离：内容维护人员不能直接修改钱包，账务人员默认不能查看项目正文。

后台必须管理能力开关、规则版本、平台模板、内部参考稿、供应商配置、模型/价格版本、失败任务诊断、支付对账及活动参数。生产密钥不可在普通列表或日志中明文展示。发布、回滚、调账、授权变更记录操作者、理由与时间。

规则/模板发布建议双人复核；维护草稿与已发布版本分离，已启动任务锁定旧版本不随后台更新漂移。

M1 上线前后台须具备任务日志检索：按用户、项目、job/trace、时间、类型、状态、模型和错误筛选，查看阶段时间线、调用/token、成果与失败原因，详见第 16.9 节。日志元数据、prompt 正文、账务和库运营权限分别控制；查看 prompt 需要专门内容权限及访问理由，查阅/导出行为本身也留日志。提供成功/失败/取消/拒绝、token 完整度、耗时、错误分布及日志积压告警，不能只查看服务器控制台或仅保存最终成功任务。

## 15.2 内部相似募集书匹配

LIB-01：目的为无本企业历史稿时获取结构与写法参考。参考企业事实不能进入发行人事实库，不能向用户披露内部候选、评分、文件名或“蓝图匹配”步骤。

LIB-01A（2026-09-25 用户确认，#77/#78/#33）：目标发行人和库内候选均按最近完整年度的**合并报表主营业务收入**排名，匹配其前三大业务集合。内部语义固定为 `accounting_scope=consolidated`、`revenue_basis=main_business_revenue`；仅双方口径相同仍不足以放行，例如双方都为营业收入也不能自动推荐。母公司、混合/未知口径、营业收入以及未区分主营/其他业务的收入不得自动替代。资料不足时进入补证据/审核，不通过改写口径标签生成命中；保留原始披露及来源供核对。此项是业务规则确认，不代表具体材料的收入排名已审核，也不变更测试材料的使用授权。

索引对象：文书 ID/哈希、来源与使用许可、发行人、发行市场、发行方式、实际工具/债券品种、资料时点、可读内容、前三大业务及原始收入证据、审核状态、替代关系和版本。M1-32 负责建库及首次可用数据，M1-33 负责持续扩库维护，M1-28 负责项目侧匹配与编制；三项为 M1 必要交付，不能把建立空索引表当作完整建库。

匹配流程：

1. 取得本发行人最近完整年度的合并报表主营业务收入明细。明确主体、年度、币种单位、原表和每项收入来源。
2. 统一收入统计口径，去除重复合计行，核对板块划分；“其他”不能被未经核实地解释成某具体业务。
3. 按收入排序，识别前三项。业务名称仅使用人工审核的保守别名映射，不把宽泛行业标签当同一业务。
4. 匹配库内同样有来源证据的前三项业务集合全部一致的候选；顺序可不同，不能只命中一两项就通过。
5. 多个有效候选先按目标市场/品种适用性，再按审核有效性与资料新旧排序；不是数字相似度最高就直接选用。
6. 复制只读结构参考到任务隔离区，记录 reference_id、匹配证据、规则版本、最终选择原因，供内部复核。

来源冲突、只有部分业务附注、第三名并列不能唯一确定前三项时不猜。企业确实只有一两类业务的特例不能凭空补第三类；首版严格匹配无法处理时进入内部专家确认/能力补齐，不以无关企业替代。后续若支持少于三类的特例，须有单独版本化规则和样本验收。

用户已上传可用相似稿时，可作为用户指定结构参考，不要求后台偷偷另选一份；仍检查可读性、目标结构适用性并隔离事实。未上传或上传参考不适用时自动走后台匹配，不将可选相似稿变成必填。无匹配且没有指定可用参考时，按当前能力不可执行/失败处理，记录运营补库缺口，不靠收费公式中的 none 档绕过匹配要求。

前台的可操作反馈是“需补充最近年度业务收入附注”“现有资料暂无法完成编制”等，避免暴露实现细节，也不能把内部覆盖不足说成用户资料必然错误。

### 15.2.1 建库与索引字段（M1-32）

LIB-02：募集书库是平台后台数据资产。管理界面或导入工具只对授权运营/审核人员开放，任务服务通过内部接口取用。普通账号不能枚举条目、搜索候选或下载库内原件；前台没有募集书库、蓝图选择或推荐清单。历史原型的库浏览页面及基于宽行业加分的排序不能作为本次上线需求。

| 字段组 | 必须保存的字段与校验 |
|---|---|
| 文书与主体 | reference_id、不可变 version、文件 hash、发行人法定全称、主体唯一标识（有证据时）、原文名称与消歧依据；同名主体不自动合并 |
| 来源与使用范围 | 来源机构、项目/文书编号、项目页与文件链接或授权来源记录、取得时间、披露日、使用/留存范围及状态；不能以可下载等同任意共享 |
| 发行市场 | sse / szse / nafmii 及原文依据；不确定值不得默认上交所 |
| 发行方式 | 沪深 private / public / public_all（普通私募/小公募/大公募）；协会 ppn / mtn / cp / scp / dfi；组合合法且有依据 |
| 工具与债券品种 | 实际工具 instrument、特殊品种标签 instrument_tags、DFI 覆盖工具和具体一期工具，未知可空；与发行方式分字段，不把分档“品种一/二”当发行工具 |
| 文书阶段与日期 | registration / issuance / unknown、申报/注册/发行稿版本、项目披露状态、财务报告期集合与最新截止日；发行日期不替代财务日期 |
| 业务收入画像 | issuer_id、文书/审计材料版本、完整年度、accounting_scope、revenue_basis、币种、单位、全部可比主营业务收入行、标准业务代码、原名称、金额、占比、顺位、逐行来源锚点及置信/审核记录；自动匹配必须满足 consolidated + main_business_revenue |
| 三业务检索键 | top3_business_codes、原顺位、与顺序无关的 top3_set_key、taxonomy_version、profile_version；缺项/歧义保留状态，不生成可完全匹配键 |
| 可用性与追溯 | 正文解析版本、结构/章节定位、OCR 缺口、审核状态与人/时间、validity、supersedes、索引版本、更新/撤回原因 |

库内收入画像优先读取该募集书对应最新完整年度的财务/业务分部披露；不足时由运营关联同一发行人的相应审计报告/附注。目标项目画像从用户提供的审计报告/附注提取。两个来源都须有完整合并口径主营业务收入排名依据，不能只截三行就认定是前三；营业收入、注册资本、总资产、毛利润、地域/客户分类不能替代分业务主营业务收入。母公司与合并、不同年度、不同业务分类层级不能混排，冲突进入审核。

业务名称映射到经过行业审核的同粒度分类代码；保留原始标签和映射依据。只允许有依据的同义归一，不用宽泛的“城投”“制造业”等标签代替具体三业务。候选与目标的年度可以不同，但各自必须为确定的完整年度、口径可比且来源有效，新旧程度参与排序。第三名并列、只披露两项、混合“其他”、分部重复或缺收入金额时不自动标 complete。用于本次匹配的收入占比以该主体同年度合并主营业务收入总额为分母，不能用前三项之和代替总额；原文其他分母的占比另行保留并标明。

最低索引能力为市场/发行方式/实际品种/文书阶段/可用状态过滤，以及分类版本下的三业务集合等值检索；原始收入顺位另存，不要求两个发行人三项收入排序相同。索引和来源数据库可用常规数据库实现，向量相似度仅可用于运营发现候选，不能替代完全一致的入选条件。业务代码、收入年度和分类词典升级均生成新画像/索引版本。

首次建库流程为：取得原件及来源 → 文件哈希/主体去重 → 正文解析及 OCR → 分类与全部业务收入抽取 → 人工核对证据 → 发布不可变版本 → 验证索引可查询。原文件、可读正文和元数据分别保存但以同一版本关联。允许只登记来源线索或不完整索引，但这些记录不能进入自动推荐。

建库交付包含真实首批参考稿、数据字典、导入清单、审核记录和覆盖矩阵；按首发的六类沪深公司债组合、PPN/MTN/CP/SCP 及 DFI 记录至少一个已审核可用版本，并取得可匹配业务样本验证无参考附件编制。披露不足、来源不可取得等真实空白必须显示为发布缺口，不能用演示条目或一份稿件冒充全覆盖。业务覆盖会持续扩大，不承诺首批覆盖所有企业的三业务组合。

项目上传的历史稿、相似稿、审计报告以及用户券商模板默认只在个人项目/授权范围内使用，不能自动沉淀为其他用户可用的库内容。项目匹配请求形成的业务画像也不是可分享的募集书库记录。

### 15.2.2 项目匹配契约与新稿质量（M1-28）

输入为目标主体、年度业务画像与证据、目标市场/方式/实际品种/阶段、规则版本和可选用户参考。先核验输入完整性，随后过滤已审核、可读、未替代且使用范围有效的库版本；三业务集合必须一致。适用性不是简单加分：没有已验收目标章节映射的跨市场/方式候选应排除，不能选中后套用不相干发行规则。

内部返回 exact / needs_evidence / needs_review / no_match / unavailable、候选命中/排除理由及选定版本；exact 只代表三业务匹配和参考可用，不代表本发行人合规或具有某项信用结论。同等适用候选优先目标市场/方式/品种/阶段一致，再比较来源有效性、审核质量和资料新旧，最后按稳定 ID 排序保证可复现。

执行时锁定 ReferenceSelection：项目输入、目标业务画像、文书/正文/画像版本、分类词典及索引版本、选择原因和哈希。正文按本发行人事实和目标规则生成，参考稿仅提供章节组织和表达示例；名称、业务事实、财务数字、授信、诉讼、风险、签章及信用结论必须重新取证，不能“改公司名后照抄”。编制说明只交付本项目事实来源、规则依据和待补事项，不含内部库名、候选清单或参考文件名。

若只有收入附注缺失则追问具体材料；内部三业务覆盖空白则进入后台补库/能力处理，不要求用户必须提供相似募集书，也不在找不到参考时伪造成功。已有历史稿分支直接在原文上更新，不依赖库命中。

### 15.2.3 持续增量维护（M1-33）

LIB-03：配置允许使用的公开披露/授权来源适配器，并保留人工或批量运营导入通道。后两者使用同一入库、审核和发布流程。来源配置记录获取方式、使用范围、更新周期、限流、增量游标和最近成功时间；实际来源访问及更新能力需验证，不承诺未经核验的接口或自动全网覆盖。

调度流程为发现新增/变更 → 保存来源元数据及原件指纹 → 幂等入库 → 解析/分类/重算业务收入 → 审核 → 原子发布正文、画像和索引。无变化跳过，抓取/解析失败按任务记录重试，断点续跑，死信/长期未更新告警。新募集书披露新的完整年度或修正业务收入时产生新画像，不能沿用旧前三项而不复算。

文书状态区分待处理、待审核、已发布、已替代、已撤回、失败；支持元数据纠正、补正文、替代、撤回与回滚。内容哈希及来源文书版本去重，不能把同一发行人不同年份或不同工具合并成一份。审核前不能出现在推荐集合，原子发布失败保留旧可用版本；迟到旧处理任务不得覆盖新版。

被替代、撤回或使用权失效的版本退出新的匹配并使缓存失效。普通资料更新不改写已运行任务和历史成果的版本快照；若发生授权撤回等禁止继续使用的情况，后续读取重新检查，按保留政策隔离/停止，而不是以已锁定为由继续分发。回滚也需重新核验使用范围，并原子恢复文书、业务画像与检索索引的一致版本。

运营页面提供待审、失败、陈旧条目、来源状态、各市场/方式/品种/三业务组合覆盖、未命中汇总及重跑/回滚入口，记录操作者和原因。未命中统计尽量只存标准业务代码及计数，项目名称、上传审计原件和公司敏感数据不得自动暴露给库运营。告警/维护任务均在后台，不让普通用户操作建库或更新索引。

## 15.3 行业规则包

RULE-01：十个具体首发市场×品种组合，以及 DFI 储架安排，均需有效规则和样本覆盖。现有主要知识集中在交易所尤其上交所私募；大公募不能直接复用小公募包，银行间不能用八条通用方法冒充正式规则库。

每条规则应具备：

| 字段组 | 最少字段 |
|---|---|
| 身份/来源 | rule_id、版本、发布机构、文件名、官方 URL/文件哈希、条号、准确原文 |
| 效力 | 发布/生效/失效日期、过渡条款、后继版本、验证人/时间 |
| 适用性 | 市场、品种、投资者范围、申报阶段、行业、特殊事项 |
| 执行 | 必要输入、公式/判定逻辑、例外、检查器版本、证据定位 |
| 输出 | 通过/不适用/问题/待补证/待判断/未覆盖，严重级建议 |
| 验收 | 正例、反例、边界、来源冲突处理与专家确认 |

法规、自律规则、参考模板、机构内部准入、专家方法、窗口指导、示例必须标明不同效力。来源含疑问、批注、机器转录或未核实阈值时只作研究线索，不直接启用硬拦截。

规则更新流程：发现官方变更 → 获取原文及指纹 → 判断差异和过渡期 → 专家复核 → 回归样本 → 发布签名包 → 通知受影响未执行项目。历史成果保留当时依据，不能后台改掉后假装一直使用新规则。

### DFI 适用包

DFI 随首发验收，但按“统一注册/储架安排 + 文书阶段 + 实际工具”选择规则。分别维护注册适用条件与文件、有效期及变更、覆盖工具、分期发行披露、承销商团、具体一期工具条款的来源和效力。不将统一注册一律理解为必须有固定注册额度；有无额度及其限制以适用规则和实际文件为准。

当前内部知识摘录 S019:1505 涉及统一注册与实际发行工具分离、注册阶段额度及分期确定条款；S019:1493 涉及承销商团。两者仅作为待核查线索，不替代协会现行原文；境外发行人规则不能直接推广给境内企业。正式规则、发布/生效时间、适用主体和样本均经专业确认后发布规则包。

内部参考库可保留 DFI 注册与实际工具元数据；仍需满足同一发行人审计口径下前三大业务匹配。参考稿出现多个工具不等于实际发行多个工具，也不放开未验收的复杂产品。

### 15.3.1 沪深规则收件、版本与适用边界（2026-09-26）

## 15.4 平台与私有模板库

## 15.6 授权、费用与复核覆盖

每项调用检查平台合同、账号可用权、地域/席位、用途、缓存/展示和再分发限制。授权不足返回 DATA_NOT_ENTITLED，余额再多也不能越权查询。

替代源用于容错时必须覆盖同一业务要求并符合授权，保留实际来源。检索失败不等同不存在；整类必需核验不可用时按第 06 章判定未完成。数据源接入尚未完成应在研发状态中公开标记，不能在产品中显示虚假供应商成功标识。
