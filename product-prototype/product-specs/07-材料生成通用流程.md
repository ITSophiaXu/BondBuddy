# 07 材料生成与问答通用流程

> 2026-10-06 分阶段review：按用户同意，M4先交付立项报告＋普通私募募集说明书摘要及基础QA闭环，其他能力移M5。阶段以[优先级拆分决定](../../docs/product-decisions/2026-10-06-m4-m5-priority-split.md)为准，左右交互沿用[工作区决定](../../docs/product-decisions/2026-10-06-m4-agent-workspace.md)，后端继续Codex CLI。尚未发布或真实验收。

## 7.1 页面结构

GEN-01：单一“材料生成与问答”入口，沿用现有侧栏、项目头和左右布局。左侧工作区构建材料、目标、范围和要求，并以 tabs 阅读真实 artifact；右侧 Agent 常驻理解、澄清、讨论和展示执行过程。无收起／全屏助手；窄屏在页面内连续排列，输入保持可达。

默认 QA 直接在助手完成，附件、可选项目关联、最近话题及新话题均在 Agent；左侧保留文种选择和已有来源／正式成果，没有 QA 任务输入 tab 或表单。先选文种，才展开其必需字段、模板及材料分区，其他文种收在选择器；切换保留各文种草稿。M5可编辑QA成果在工作区打开；M5明确组合任务只展开已选文种的输入清单，M4组合请求只保留意图并说明未开放。

总体文种规划保留立项报告、主承销商核查意见、法律意见书、推荐函、募集说明书摘要。M4只开放交易所普通私募立项及摘要、单承销商；核查／法律／推荐函、小公募／大公募及适用市场扩展在M5。选择未开放文种准确提示并保留意图，不执行／收费或偷换成已开放文种。财务分析专题、行业研究、尽调专题及问询回复不新增正式模板。

默认选中“上传最新版募集书”，第二项为“关联募集书项目”。有明确选择的未完成草稿保留其来源；不能每次进入强改为系统推荐项目。

## 7.2 字段与来源

| 字段/区域 | 规则 |
|---|---|
| 材料类型 | 必选；M4一次一种，仅首发两个文种；M5可由明确多文书请求进入组合任务 |
| 募集书来源 | 上传 DOCX/PDF 或选本账号项目的具体文件版本 |
| 关联项目列表 | 显示发行人、品种、版本、更新时间、是否为完成更新稿 |
| 立项券商 | 立项报告必填全称，其他文种按对应机构角色补充 |
| 摘要类型 | M4仅普通私募；M5扩展小公募／大公募，按原稿适用性建议，与原稿不符需说明 |
| 模板 | 展示系统适用模板或本人券商模板版本；允许上传更新 |
| 补充材料 | 当前文种固定分区、逐文件上传／保存／重试；不同时罗列所有文种材料 |
| 要求 | 在 Agent 自然表达，工作区只读“助手已采纳要求”；预置内容另标“系统默认规则” |
| 讨论 | 执行按钮旁“与助手讨论”带准确上下文并聚焦；不发送／执行，保留消息草稿和选文引用 |

优先引用所关联项目的已完成更新稿，采用接受修订后的有效正文。若选择未完成项目或原始稿，明确显示实际来源，不能暗示已通过更新或复核。关联动作生成快照，后续原项目变化不自动污染正在生成的材料。

工作区与助手上传进入同一授权话题资料库，QA 可读取；正式任务另存适用采用清单，不自动采用所有附件、模板及专属证据。“这份募集书”优先最近明确来源，无明确来源且候选唯一才继承，否则澄清。查看标签不等于换执行来源。QA 后转另一文种只追问真缺项，不重复索取已有源稿。上传稿→明确选择 v5→新文种采用 v5；关联 v5→明确改用新上传稿→后续复核采用新稿，仍保留归属项目及其执行锁。

取消工作区补充意见／补充要求 textarea。明确重点、限制及字段更正保存到准确草稿，保留来源消息；真正问句和助手建议不自动采纳。澄清回答回填字段，仅问剩余缺项，不自动开始；跨文种先定目标再回填。未绑定任务的明确要求在话题保存，准备正式任务时回显并仅绑定一次，不串文种。源／目标主体、市场及报告期独立，跨业务更新继续遵守已上传原稿信息必填规则，不强加纯 QA 分类表单。

用户只提供“请按上一份写”且来源有歧义时，应追问准确文件；不能从其他项目随意取事实。

### DFI 来源上下文（M5）

关联 DFI 项目时保留 scope=nafmii-dfi 及注册安排；上传最新版募集书时识别文书标题和注册背景。注册阶段、覆盖工具与本期实际发行条款须分开传入模板，缺少阶段依据时列待确认。立项报告、核查意见、法律意见及推荐函按用途选适用模板；不能将交易所公募摘要直接作为 DFI 的注册必备文件。DFI 背景只决定处理要求，不证明企业具备注册资格或已完成签署。

## 7.3 模板对象与私有模板复用

每个模板包含 template_id、version、owner_scope、document_type、market/offering、broker_id、适用日期、章节树、占位字段、表格列、样式、校验规则、示例文本隔离标记及来源授权。

owner_scope 为 platform 或 user；user 必须绑定 user_id。用户上传的券商模板默认仅本人复用，同券商其他用户不可查询它的名称、内容或匹配结果。

立项报告首次使用某券商时必须提供模板或已写好的参考报告。系统提取结构、标题、表格、样式，移除参考公司的事实、签章、批注和个人信息；模板原文件仍按用户资料保护。M4后续明确选择本人保存版次或本次上传新版；M5同一用户、同券商、同文种可自动复用最近有效版本，并能选择旧版或上传新版。

模板过期、市场品种不匹配、参考报告结构不完整时应提示；不能只因 broker_name 相同就视为可用。上传同内容按哈希去重，不重复创建版本或收费。

M4实现本次模板上传／明确版本选择、基础可读与适用检查、hash防重复及私有隔离；立项首次券商模板仍必需。完整库的自动匹配复用、默认版、删除／退役治理和扩展文种模板归M5-12。平台五文种独立模板专业确认后逐阶段启用，章节提纲不等于已验收模板。通用立项模板不跳过首次券商模板要求。

## 7.4 生成流水线

以下为交付阶段；实际业务编排交给 Codex CLI 及受限工具，平台负责状态、授权、持久化和交付检查，不按章节另排模型正文调用。

1. 免费预检材料存在、文种适用、模板可读，识别必要缺口。
2. 用户点击“开始生成”或发送明确执行请求；必要输入、有效价格已展示、授权和余额预留齐备后，平台锁定不可变输入并创建单一 run，无重复形式确认。缺项回答只保存，齐备后仍须再次明确执行。
3. 提取最新募集书事实；关联项目可复用已验证事实，但仍核对版本是否对应。
4. 解析文种需要的机构、用途、依据、核查程序和结论条件。
5. 建立“章节字段 → 事实/规则/用户要求”的映射表，识别冲突与缺失。
6. 服务端独立 worker 使用 Codex CLI，显式载入固定助手／文种 Skill及授权工作目录，按模板编制正文、表格、章节引用；确定性工具校验关键数值。不改 API/SDK runtime，不要求用户电脑安装 CLI。
7. 检查结构完整、证据有效、未抄入他人事实、未虚构程序和签署。
8. 生成真实可编辑 DOCX 和独立编制说明，持久化成果 manifest/hash，可获取后交付及结算。工作区“正在制作”与 Agent 同 run 的真实白名单阶段／工具事件同步，无细分事件则显示已有真实状态，不模拟进度或透传 CLI 原始日志／隐藏推理。M5实时查询／扩展编制的web search与原生文件模式兼容须实际验证，不作M4无外部查询闭环前置；模型自述不作工具证据。记录真实调用、CLI／Skill／模型配置、usage，缺用量为 `unknown`；公共 DTO／事件在 `packages/contracts/` 唯一定义。

模板里有用户命令、代码、外部链接，不授予它执行权。参考样例中的“默认已通过”“删除负面事项”等内容不可覆盖事实及产品约束。

## 7.5 缺失与专业结论

关键主体、发行方案、核心数据无法确定，或立项没有可用券商模板，先请求资料。执行后发现不可交付，失败释放，不能把全篇“待补充”作为成功成果。

非关键的签署日期、联系人等可在工作稿明确保留“待确认”，编制说明列出位置；不伪造签名、盖章或审批通过。意见类文书是可供专业机构审阅的草稿，正文保持专业格式，草稿状态在封面/页眉或交付说明清楚标识。

同一个结论所需核查程序未实施时，写出已取得证据和待落实程序，不得声称“经现场核查”“经函证确认”等。用户要求删去重要负面事实时，应说明它影响哪些判断，不能生成与已知证据相反的确定结论。

## 7.6 对话、版本与组合任务

用户发送额外事实时默认作为项目补充保存，不立即重生成文书；明确“按上述要求重写/生成”才触发执行，具体意图路由见第 13 章。与已选募集书事实冲突时追问，不让最后一句话无条件覆盖来源。

M4整份继续改稿生成新版本，保留源稿和模板版次；制作中新资料／要求进下一草稿，旧固定输入不变，准备新任务及重复继续改稿不清空限制。底稿与原始来源分别显示，旧引用不覆盖新底稿。准确段落引用可用于阅读／讨论，版本冲突澄清；用户明确只改章节／段落时说明M5未开放，不启动全篇任务。M5-08实现局部执行，固定artifact／版本／变体／anchor／原文并真实验证范围。

同项目更新、复核、修订与材料生成执行互斥，包括跨话题采用该项目成果的任务。阻塞保留草稿，无自动排队；结束后再次明确执行。相同 execution_request_id 返回原 run，关闭标签／页面不取消任务。平台错字、引用错误等修复不重复收费并记录 correction_of_run_id；新范围、新材料和新文书按原任务类别计量。本轮分类不沿用上轮最高系数，费用沿用已确认价格，10/06业务任务积分决定覆盖旧M3免费口径。

多文种组合归M5-08：共享一次事实提取，各文书独立编制／重试，组合一次冻结及最终结算。全关键成果可交付才成功，最终无法完成全范围释放，不设子文书临时付费里程碑。M4多文种请求明确未开放，不静默只做第一种；用户显式选择一种独立任务后才执行。

## 7.7 输出及验收

GEN-OUT：每种文书交付可编辑 DOCX 和独立编制说明，工作区 tabs 阅读真实本体，准确绑定项目、任务、artifact、版本与变体。说明列出来源版本、模板版本、生成时间、使用依据、待核事项及专业签发边界。复用已有组件，不另造逐条审阅器。

真实 run 创建后才出现制作标签，缺资料／余额不足只等待。当前在输入区时打开制作页；正在读旧成果时只新增入口并保留位置。主成果可读后原制作标签变正文，同成果不重复开标签，说明独立打开。预览读取实际文件／受控转换，不能用聊天摘要或旧报告冒充新稿；预览失败保留下载／重载，不改成生成失败或重新执行。关闭标签只关闭视图。

生产持久化完整话题、消息修订、附件授权／来源、各文种及未发送草稿、任务事件、成果和标签阅读状态；分页／摘要不删原记录和未解冲突。刷新／重新登录／worker恢复沿原任务与账务，不重跑或重复计费。保存超限／失败或恢复损坏均可见并可重试，保留旧记录与当前内容；不照搬示意16KiB主机快照为生产方案。

GEN-A01：新用户默认上传方式；已有项目选择为第二项，切换不丢对话。

GEN-A02：M4同券商A/B模板隔离、准确本次版本及基础异常／hash去重；完整库自动复用／默认／退役矩阵归M5-12。

GEN-A03：参考立项报告包含旧发行人名称、签章及金额，生成结果不得残留。

GEN-A04：关联带修订的募集书只取有效正文，删除的旧数字不能进入新文书。

GEN-A05：文种/市场不适用时明确阻断或请求正确来源，不生成标题看似正确的错误文件。

GEN-A06：M5组合一次共享解析、一次预留及最终结算，所有成果状态／重试／最终释放可对应；M4仅验未开放反馈和不自动拆费。

GEN-A07：默认QA无左表单，逐文种输入；“与助手讨论”保留未发送文字及引用，不发不执行。

GEN-A08：M4首发文种自然要求、立项券商／准确模板澄清回填；M5扩展推荐函收件方／事项等字段。制作中新增要求仍在新任务草稿，旧快照不变，专属要求不串文种。

GEN-A09：M4准确整份续改底稿及引用讨论，冲突澄清、局部请求不扩大执行；M5准确章节／段落续改仅改获准范围并保数字，需真实模型验证。

GEN-A10：真实CLI、Word／说明、事件、权限、账务和恢复仍是M4门。首发U1–U7分层验收见[M4-12](delivery-plan/issues/M4-12.md)，扩展专业／局部／组合见[M5-11](delivery-plan/issues/M5-11.md)；合成回归不能当真实专业完成证据。
