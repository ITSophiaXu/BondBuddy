# 07 材料生成通用流程

## 7.1 页面结构

GEN-01：左侧展示文种、募集书来源、模板和补充资料；右侧为“补充说明与写作要求”。对话窗口与更新募集书一致，支持多轮解释、追问及改稿；不把聊天输入变成另一套隐藏的必填表单。

首发五类文种：立项报告、主承销商核查意见、法律意见书、推荐函、募集说明书摘要。摘要含私募、公募变体，公募根据小公募/大公募路由。财务分析专题、行业研究、尽调专题、问询回复暂不作为独立模板上架；QA 的轻量分析仍可用。

默认选中“上传最新版募集书”，第二项为“关联募集书项目”。有明确选择的未完成草稿保留其来源；不能每次进入强改为系统推荐项目。

## 7.2 字段与来源

| 字段/区域 | 规则 |
|---|---|
| 材料类型 | 必选；设计默认一次一种，可由明确多文书请求进入组合任务 |
| 募集书来源 | 上传 DOCX/PDF 或选本账号项目的具体文件版本 |
| 关联项目列表 | 显示发行人、品种、版本、更新时间、是否为完成更新稿 |
| 立项券商 | 立项报告必填全称，其他文种按对应机构角色补充 |
| 摘要类型 | 私募/公募，优先按原稿建议；与原稿不符需说明 |
| 模板 | 展示系统适用模板或本人券商模板版本；允许上传更新 |
| 补充材料 | 固定分区；按文种提供建议，不使用材料类型下拉 |
| 对话 | 写作重点、读者、语气、篇幅、事实补充、核查线索 |

优先引用所关联项目的已完成更新稿，采用接受修订后的有效正文。若选择未完成项目或原始稿，明确显示实际来源，不能暗示已通过更新或复核。关联动作生成快照，后续原项目变化不自动污染正在生成的材料。

用户只提供“请按上一份写”但尚未选择来源时，应追问来源文件；不能从其他项目随意取事实。

### DFI 来源上下文

关联 DFI 项目时保留 scope=nafmii-dfi 及注册安排；上传最新版募集书时识别文书标题和注册背景。注册阶段、覆盖工具与本期实际发行条款须分开传入模板，缺少阶段依据时列待确认。立项报告、核查意见、法律意见及推荐函按用途选适用模板；不能将交易所公募摘要直接作为 DFI 的注册必备文件。DFI 背景只决定处理要求，不证明企业具备注册资格或已完成签署。

## 7.3 模板对象与私有模板复用

每个模板包含 template_id、version、owner_scope、document_type、market/offering、broker_id、适用日期、章节树、占位字段、表格列、样式、校验规则、示例文本隔离标记及来源授权。

owner_scope 为 platform 或 user；user 必须绑定 user_id。用户上传的券商模板默认仅本人复用，同券商其他用户不可查询它的名称、内容或匹配结果。

立项报告首次使用某券商时必须提供模板或已写好的参考报告。系统提取结构、标题、表格、样式，移除参考公司的事实、签章、批注和个人信息；模板原文件仍按用户资料保护。后续同一用户、同券商、同文种可自动复用最近有效版本，并能选择旧版或上传新版。

模板过期、市场品种不匹配、参考报告结构不完整时应提示；不能只因 broker_name 相同就视为可用。上传同内容按哈希去重，不重复创建版本或收费。

平台为五类文书建立独立的标准模板库。专业专家确认后的正式模板才能启用；章节提纲不等于已验收模板。平台通用立项模板用于数据结构和测试，不跳过首次提供券商模板这一用户要求。

## 7.4 生成流水线

1. 免费预检材料存在、文种适用、模板可读，识别必要缺口。
2. 用户点击“开始生成”，平台按实际请求锁定快照并冻结。
3. 提取最新募集书事实；关联项目可复用已验证事实，但仍核对版本是否对应。
4. 解析文种需要的机构、用途、依据、核查程序和结论条件。
5. 建立“章节字段 → 事实/规则/用户要求”的映射表，识别冲突与缺失。
6. 按模板逐节编制正文、表格、章节引用；生成前后都校验关键数值。
7. 检查结构完整、证据有效、未抄入他人事实、未虚构程序和签署。
8. 生成可编辑 DOCX、编制说明，核验可打开后交付并结算。

模板里有用户命令、代码、外部链接，不授予它执行权。参考样例中的“默认已通过”“删除负面事项”等内容不可覆盖事实及产品约束。

## 7.5 缺失与专业结论

关键主体、发行方案、核心数据无法确定，或立项没有可用券商模板，先请求资料。执行后发现不可交付，失败释放，不能把全篇“待补充”作为成功成果。

非关键的签署日期、联系人等可在工作稿明确保留“待确认”，编制说明列出位置；不伪造签名、盖章或审批通过。意见类文书是可供专业机构审阅的草稿，正文保持专业格式，草稿状态在封面/页眉或交付说明清楚标识。

同一个结论所需核查程序未实施时，写出已取得证据和待落实程序，不得声称“经现场核查”“经函证确认”等。用户要求删去重要负面事实时，应说明它影响哪些判断，不能生成与已知证据相反的确定结论。

## 7.6 对话、版本与组合任务

用户发送额外事实时默认作为项目补充保存，不立即重生成文书；明确“按上述要求重写/生成”才触发执行，具体意图路由见第 13 章。与已选募集书事实冲突时追问，不让最后一句话无条件覆盖来源。

改成果生成新版本，保留来源和模板版本。平台错字、引用错误等修复不重复收费；新范围、新材料和新文书按新任务计量。

明确一次要求多个材料时，同一事实提取只做一次，各文书分别编制；一个组合执行使用一次冻结和最终结算。普通组合默认全部关键成果可交付才成功，部分失败先重试；无法完成全范围则释放冻结，不把内部文书变成临时付费里程碑。若希望分开执行，由用户显式选择独立任务。

## 7.7 输出及验收

GEN-OUT：每种文书交付可编辑 DOCX 和编制说明。说明列出来源版本、模板版本、生成时间、使用依据、待核事项及专业签发边界。首页摘要只展关键内容，不需要逐条审阅器。

GEN-A01：新用户默认上传方式；已有项目选择为第二项，切换不丢对话。

GEN-A02：同券商用户 A、B 不能相互看到私有模板；A 后续生成可复用自己的版本。

GEN-A03：参考立项报告包含旧发行人名称、签章及金额，生成结果不得残留。

GEN-A04：关联带修订的募集书只取有效正文，删除的旧数字不能进入新文书。

GEN-A05：文种/市场不适用时明确阻断或请求正确来源，不生成标题看似正确的错误文件。

GEN-A06：组合生成只计一次共享解析；所有成果状态和最终账单可对应。
