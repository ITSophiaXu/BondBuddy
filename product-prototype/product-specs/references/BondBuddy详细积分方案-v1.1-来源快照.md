# BondBuddy 详细积分方案

版本：proposal-2026-09-22-v1.1（点击即执行）。适用对象：产品、运营、财务、研发及合同条款审阅人员。

**这是建议定价方案，尚未上线，也未以真实 API 成本样本校准。** 系数、积分兑换和赠送额度均为本次设计，不是 WorkBuddy、Kimi 的价格，也不是现有 BondBuddy 已实现的收费规则。金额均为人民币；用户端建议展示含税终价。

## 1. 推荐决策

采用“统一积分钱包 + 点击即执行 + 后台自动计价与冻结 + 按实际用量结算、多退不补”的模式。用户不需要看报价表、确认复杂度或再次授权任务费用。

- 注册赠送 **2,000 积分，30 天有效**。
- 邀请激活：邀请人 **1,000 积分**，新用户额外 **500 积分**；达成首次付费条件后再分别赠 **2,000 / 1,000 积分**。
- 每日有效使用累计消耗至少 **100 积分**，次日赠 **20 积分**；每月最多 **400 积分**。
- 基准 **100 积分 = 1 元购买标价**；这不是积分提现汇率。
- 充值档位 **50 / 500 / 2,000 / 10,000 元**；付费购入积分不设置使用有效期，活动积分单独到期。
- 用户指定的 **5 / 10 / 15 / 20** 用于“本企业完整历史稿、普通债券、同市场同品种、财务更新及全文数字同步”的业务阶段。
- **更新、复核、材料生成、QA 独立分类**。一次普通问答不按整份募集书系数收费；系统在后台识别实际任务，不因入口名称不同改变计价。
- 文件解析按首次实际处理在后台单独核算，汇入本次任务积分，之后复用；不按每次上传、每份文件或每次下载另收一遍费用。
- 对已经开放且材料可执行的任务，积分准入只有一条：**可用余额≥后台计算的本次所需冻结积分**。等于也能启动；不要求订阅、二次确认或逐项接受价格。

你前半段所述“依据历史募集书更新报告期”，本方案归入**募集书更新/编制**；“检查已写好的募集书”，归入**独立复核**。如果同一任务同时包含两项，后台分项计算并合并为一次余额校验，复用已经解析的资料。

## 2. 计量基础：保留 token 乘系数，但先统一成本口径

### 2.1 为什么不能把所有原始 token 直接相加

输入、输出、缓存命中、不同模型的价格可能不同。只用 `input_tokens + output_tokens` 会让相同积分对应悬殊成本，也会让缓存优惠无法传递给客户。

定义“标准 token”仅作为计量单位：**100 万标准 token 对应 10 元模型计量成本**。这 10 元是换算基准，不是对任何真实模型当前报价的声称。

对每次真实 API 调用：

```text
模型计量成本 C（元）
  = Σ（该类实际 token 数 × 任务启动时锁定的该模型单价〔元/百万 token〕）÷ 1,000,000

标准 token T* = C ÷ 10 × 1,000,000
基础用量积分 B = T* ÷ 1,000 = C × 100
业务积分 = B × 任务系数 K
```

这样，用户要求的“token × 5”对应 `标准 token ÷ 1,000 × 5 积分`。不同模型可以统一计量，并保留真实 token 明细。

**实际用量与单价来源必须可追溯：** 使用供应商 usage 和计量网关记录；输入、缓存、输出权重在内部计价快照中绑定模型及价格版本。供应商的折扣、赠款、税汇差异与客户计量单价的关系应在内部另行核算，不把未披露的费用塞进 token。任务启动后平台主动换用更贵模型、单价变化或用量超出内部估计，不追扣本次已冻结额度之外的积分，差额由平台承担。

示例，假设输入/缓存/输出单价分别为 10 / 1 / 30 元每百万 token：

| 分类 | 实际数量 | 假设单价 | 计量成本 |
|---|---:|---:|---:|
| 未缓存输入 | 100,000 | 10 元/百万 | 1.00 元 |
| 缓存命中输入 | 50,000 | 1 元/百万 | 0.05 元 |
| 输出 | 20,000 | 30 元/百万 | 0.60 元 |
| 合计 | 170,000 原始 token | 折为 165,000 标准 token | 1.65 元 |

K=5 时，业务扣 **825 积分**，标价等值 **8.25 元**。不能把同一个缓存输入既算普通输入又算缓存输入。供应商返回的推理 token 若已含在输出中，也不能再加一次。

### 2.2 总任务公式

```text
实际计量积分 A = 向上取整到 1 积分［
    Σ业务阶段（模型计量成本 × 100 × 业务系数）
  + Σ首次解析阶段（模型计量成本 × 100 × 解析系数）
  + Σ任务所需且在服务范围内的成功外部付费服务（采购成本 × 100 × 1.20）
］
```

其中模型计算费、OCR 服务费、外部数据费必须有不重叠的成本编号。同一笔费用只能属于一项；不能把 OCR 服务费既算模型成本又算外部服务费。

本公式先算后台实际计量积分 A。启动时已冻结内部估算额度 B，成功后的最终扣分为 **min(A,B)**；低于B释放差额，高于B不再补扣。原有token乘系数逻辑保留，B只提供余额校验和费用保护，不把预估数冒充实际消耗。

系统任务路由、计费查询、上传存储、普通本地解析、正常导出和下载不单独计积分。实际调用模型做材料解析才进入解析项。首次建索引若使用付费 embedding API，纳入解析项；复用既有索引不重复计费。

**系数针对对应阶段，不把所有系数无差别连乘整张账单。** 例如扫描 PDF 的难度主要影响提取与结构还原，不应让已经提取好的材料在后续 20 次 QA 中都再乘一次扫描系数。

### 2.3 费用边界

- 业务与解析阶段分开计量；同一 API 调用不得同时分配给两个收费阶段。
- 一个调用同时处理多个难度不同的工作项，优先拆分；无法拆分时采用版本化计费规则中的分配权重并留存依据。不能把全部 token 计入最高难度项。
- 平台长提示词、无效检索、系统重试、错误循环造成的浪费由平台承担。计费网关保留实际成本，同时标识 `billable=false`，不得从供应商总账中删除。
- 任务不设置不透明的固定起步价。实际计量积分汇总后取整，成功任务按min(A,B)一次结算；内部阶段不分别向上取整或分别扣款。普通任务失败或被取消，全部释放本次冻结积分。
- 产品篇幅、文件数量、普通表格数量会增加实际 token，**不再无条件追加“页数倍数”“文件数倍数”“字数倍数”**。

## 3. 募集书更新/编制：基础难度与报告期

### 3.1 报告期数 N 的判定

N 是**本次新纳入、替换或实质重述的不同报告截止期数量**，不是文件中出现了多少年份。

| 工作量 | N | 本企业完整历史稿基础系数 |
|---|---:|---:|
| 只更新一个年度，或只更新一期 | 1 | **5** |
| 一年 + 一期，或两个独立年度 | 2 | **10** |
| 两年 + 一期，或三个独立年度 | 3 | **15** |
| 三年 + 一期，或四个独立年度 | 4 | **20** |
| 更多实际报告期 | N≥5 | **5×N**，必须检查范围及预算 |

判定规则：

1. 历史稿已经正确披露、仅保留在目标窗口内的年度，不算新更新期。例如原稿有 2022—2024 年，新增 2025 年一季度，不能因为目标全文出现“四个期间”就按 20 收费，应按新增一期的 5 起算。
2. 年末没有独立中期报表时，不另加“一期”。
3. 同一报告期的资产负债表、利润表、现金流量表及附注只算一个报告期。合并/母公司不是两个报告期。
4. 季度报表中的上年同期比较数是该期任务的一部分；仅提取比较数不另算一个期间。若要实质更正原稿上年同期披露并重新核对，才作为独立变更期，并在内部计价依据中记录。
5. 已有年度发生追溯重述且需要改写，计入实际受影响的期数。对应口径桥接工作可另有特殊加成，但不能只因出现“重述”二字自动收费。
6. 一个文件包含多个年度，不按文件数；多份文件重复披露同一年度，不重复累计。
7. 纯发行条款、日期或措辞变更且 N=0，改走局部修改任务：基础 K=3，后续适用实际迁移与目标结构因素；不得伪造 N=1。无历史稿的完整编制不能走 N=0。

### 3.2 历史稿可用性 H：直接决定基础系数，不再额外重复乘 H

| 历史稿状态 | N=1 | N=2 | N=3 | N=4 | N>4 公式 |
|---|---:|---:|---:|---:|---|
| 本企业完整、可用历史稿 | 5 | 10 | 15 | 20 | 5N |
| 本企业历史稿不完整、需补建结构 | 8 | 13 | 19 | 25 | max(8,向上取整6.25N) |
| 只有其他企业参考稿或通用案例 | 25 | 30 | 45 | 60 | max(25,15N) |
| 无本企业历史稿，也无可用参考稿 | **35** | **40** | **55** | **70** | max(35,15N+10) |

“不完整”指实质章节或关键结构缺失，**不是**仅仅文件为 PDF；格式难度归解析。旧稿年份久但结构仍完整，不自动改判为“不完整”。

其他企业参考稿只能复用结构和写法，不能作为发行人的事实证据；免费获得平台内部模板，也不等于用户具备本企业历史稿。系统自动选用的结构参考在上述“其他企业参考稿”档自动计价，不额外收模板获取费。

这些基数确保在同一目标品种、报告期、范围及特殊事项条件下，无历史稿的完整编制比已知历史稿更新更贵。**不同范围之间不能绝对排序**：简单的从零起草可能仍比跨境重组复杂项目便宜。

### 3.3 更新范围 S

| 范围 | S | 包含工作 |
|---|---:|---|
| 财务更新及全文对应数字同步 | **1.00** | 表格、正文引用、期间、单位、受影响指标与一致性整理 |
| 全文事实更新 | **1.20** | 增加工商、债务、评级、业务、治理等有证据的新事实 |
| 重构编制 | **1.35** | 用户要求或目标结构需要整体章节重组、披露重新组织 |

三档互斥，只取一档。用户没有要求重构且只需正常章节映射时，不能因为发生市场迁移再自动套最高范围。无历史稿按实际交付范围选 S；基数已包含从零组织结构，不因“没有旧稿”强制追加 1.35。

### 3.4 业务阶段最终公式

```text
K更新 = min(200，历史状态及报告期基础系数 × M迁移 × J目标结构 × S更新范围 × C特殊事项)
```

原始乘积超过 **100**时进入后台高成本监控，不新增用户确认步骤。尚未验收的特殊产品先由平台完成能力验收再开放；开放后按相同的一键流程执行。200是系数保护上限，最终扣分另受本次启动时冻结额度B保护。不得通过人为拆任务绕过系数或费用保护。

## 4. 市场与债券品种转换

### 4.1 覆盖范围与边界

覆盖现有产品界面涉及的 14 类计费标签：上交所/深交所的私募、小公募、大公募；协会 PPN、MTN、CP、SCP、ABN、ABCP、项目收益票据、永续类票据。

这些是定价分类，不是对现行法规的核实结论。“永续类票据”中的 PN 沿用现有界面的内部标签；具体申报品种与永续属性应以正式规则和项目材料确认。DFI 等注册安排不能当作新增发行品种重复收费。绿色、科创等通常作为专项属性处理。

未覆盖的交易所 ABS、银行金融债、可转债、境外债、地方政府债、REITs 等均进入独立产品评估，不擅自套公司债矩阵。大公募、资产支持、项目收益及永续等结构先由业务人员确认可支持的范围；定价表存在不等于功能、规则库或发行路径已验收。

### 4.2 转换系数 M 的确定方法

```text
M = min(2.50，1 + 市场差异加成 + 基础结构差异加成 + 披露对象变化加成 + 同家族子品种差异)
```

同一层中的加成只取一次，**不用“市场1.5×品种1.6×投资者1.2”无限叠乘**。这也使每个转换可以解释。

| 市场变化 | 加成 |
|---|---:|
| 同一市场 | 0 |
| 上交所 ↔ 深交所 | 0.15 |
| 交易所 ↔ 交易商协会 | 0.50 |

| 基础结构变化（双向） | 加成 |
|---|---:|
| 普通债务 ↔ 短期工具 | 0.15 |
| 普通债务 ↔ 永续 | 0.25 |
| 普通债务 ↔ 项目收益 | 0.35 |
| 普通债务 ↔ 资产支持 | 0.60 |
| 短期工具 ↔ 永续 | 0.30 |
| 短期工具 ↔ 项目收益 | 0.40 |
| 短期工具 ↔ 资产支持 | 0.65 |
| 永续 ↔ 项目收益 | 0.35 |
| 永续 ↔ 资产支持 | 0.60 |
| 项目收益 ↔ 资产支持 | 0.45 |
| 同一基础结构 | 0 |

披露对象分类是计费分组，不替代投资者适当性法律分类。

| 变化方向 | 加成 |
|---|---:|
| 定向/私募 → 面向专业投资者的公开披露组 | 0.20 |
| 定向/私募 → 面向普通投资者组 | 0.40 |
| 专业投资者公开组 → 定向/私募 | 0.10 |
| 专业投资者公开组 → 普通投资者组 | 0.25 |
| 普通投资者组 → 专业投资者公开组 | 0.10 |
| 普通投资者组 → 定向/私募 | 0.15 |
| 同组 | 0 |

CP ↔ SCP 额外加 0.10；ABN ↔ ABCP 额外加 0.20；其他同组同结构子品种不另加。完整 196 格矩阵见附录。

常见结果：

| 从历史稿到目标稿 | M |
|---|---:|
| 上交所私募 → 上交所私募 | 1.00 |
| 上交所私募 → 深交所私募 | **1.15** |
| 上交所私募 → 上交所小公募 | **1.20** |
| 上交所小公募 → 上交所私募 | 1.10 |
| 上交所私募 → 协会 PPN | **1.50** |
| 上交所私募 → 协会 MTN | **1.70** |
| 上交所私募 → 协会 SCP | **1.85** |
| 上交所私募 → 协会 ABN | **2.30** |
| 协会 CP → SCP | 1.10 |
| 协会 MTN → 永续类票据 | 1.25 |

如果没有本企业历史稿，M 固定为 **1**；只依据目标产品计结构难度。不能把“无历史稿高基数”和“假设有一个源市场的转换费”同时收取。源品种无法判断时，先从材料补充识别；仍无法判断则提示补充必要项目信息，不能按最贵源品种推断。这里是资料完整性检查，不是收费确认。

### 4.3 目标产品本身的结构 J

| 目标产品 | J |
|---|---:|
| 普通私募/小公募、PPN、MTN、CP、SCP | **1.00** |
| 大公募 | 1.15 |
| 永续类票据 | 1.20 |
| 项目收益票据 | 1.30 |
| ABN | 1.50 |
| ABCP | 1.60 |

J 体现目标结构的工作难度，M 体现把原稿转换过去的工作。绿色等专题不改变普通债券的 J，按下一节受影响部分加成；永续、资产支持、项目收益已进入 J 的结构特征，不再在 C 中重复收费。

## 5. 特殊事项、材料质量与组合规则

### 5.1 业务特殊事项 C

```text
C = min(1.75，1 + 与本工作项直接相关的特殊事项加成之和)
```

| 特殊事项 | 加成 | 收费边界 |
|---|---:|---|
| 绿色、科创等单项专题披露 | +0.10 | 两个名称对应同一批披露，不重复累加 |
| 可持续发展挂钩目标、基准与条款 | +0.20 | 已取此项时不再对同一专题取绿色0.10 |
| 新增保证、抵质押、差额补足等事实核对 | +0.10 | 仅受影响保证及条款章节 |
| 项目建设、基金、股权用途专题 | +0.15 | 与项目收益结构J覆盖同一分析时不重复 |
| 有证据的重组、备考口径专题 | +0.25 | 不能把普通合并范围变动自动视为重大重组 |
| 跨境会计口径或双语实质对照 | +0.25 | 纯翻译或纯币种换算不自动取此项 |
| 非标准审计意见及其影响分析 | +0.15 | 只作用于实际承担该分析的工作项 |
| 经确认的追溯重述、口径桥接 | +0.15 | 期数计修改范围，本项只补偿口径桥接 |
| 可解决的实质证据冲突 | +0.10 | 不是扫描识别错误；严重未解决冲突先暂停 |
| 明确适用的新旧规则实质调整 | +0.10 | 单纯日期变新不收；须说明规则差异 |
| 多档品种的条款联动 | +0.10 | 同一事实重复叙述不算；只作用于条款联动部分 |

不同专题有不同受影响章节时分工作项核算。不要因为一页担保条款就对整份募集书 token 全部加 10%。无法准确拆分时，按版本化规则确定受影响比例、留存依据并按成本加权，不能事后默认 100%。

额外主体：确需处理不同发行人或独立担保人资料时，每新增一个独立主体对受影响工作项加 0.10，最多 +0.30。合并报表中的普通子公司列表不逐家收费；工作量已体现在 token 中的普通主体阅读不再加此项。该项也进入 C=1.75 的共同上限。

### 5.2 材料格式 F：只作用于首次解析阶段

```text
K解析 = min(6，2 × F格式 × Q可修复质量)
```

| 编号 | 真实材料形态 | F | 正常质量下 K解析 |
|---|---|---:|---:|
| F01 | 可读取 DOCX 正文、规范 XLSX/CSV 表格 | 1.00 | 2.00 |
| F02 | DOCX 复杂财务表、合并单元格较多的 Excel | 1.10 | 2.20 |
| F03 | 可复制文字的原生 PDF，表格与顺序清晰 | 1.20 | 2.40 |
| F04 | 原生审计 PDF，复杂附注、跨页财务表 | **1.30** | **2.60** |
| F05 | 清晰扫描 PDF，OCR 可稳定识别 | **1.60** | **3.20** |
| F06 | 图文混合 PDF、扫描表格或横纵混排 | 1.80 | 3.60 |
| F07 | 可校正且清晰可识别的照片、截图 | 2.00 | 4.00 |
| F08 | 低清但经抽样确认可识别的扫描、照片 | 2.50 | 5.00 |
| F09 | 可验证的文本、结构化数据接口结果 | 1.00 | 2.00 |

PDF 不天然意味着扫描件；Excel 不天然意味着结构化数据；Word 内嵌扫描图片按图片实际形态处理。文件扩展名只做预判，最终按内容识别。

Q 可修复质量互斥取一项：

| 质量 | Q | 例子 |
|---|---:|---|
| 正常 | 1.00 | 行列、单位、期间与主体可识别 |
| 轻度可修复 | 1.10 | 少量断行、表头错位，可可靠恢复 |
| 明显但仍可修复 | 1.25 | 多张表需拼接，仍有足够依据还原 |
| 密码未解、严重缺页、关键数字无法识别 | 暂不启动 | 要求补充材料或人工处理 |

F 已包含的“扫描、跨页、低清”等问题，不因同一事实再次加 Q。Q 只用于额外的结构修复问题。

### 5.3 混合材料、重复材料和缓存

1. **按片段/调用实际成本计费**：Word 按 Word 的 F，清晰 PDF 按该 PDF 的 F，不能取全部附件中的最高 F。
2. 同一次解析调用混合多种材料时，应拆分；无法拆分，按已确认的实际输入标准 token 占比计算 F、Q 的加权系数。估算时可暂按相关页/表比例，结算采用记录的分配依据。
3. 上传、改文件名、重复选择文件不扣积分。同账号同内容哈希、同解析版本、相同所需提取范围的成功解析可复用；跨项目复用也不重收解析费。
4. 新版本仅重新解析变化部分；无法可靠识别增量时，在用户提交该次新任务时自动计入必要重解析工作，不弹报价确认页。平台升级解析器造成的正常后台迁移费用不转嫁用户。
5. 已解析事实再次提供给模型仍可能消耗输入 token，该次业务成本可正常计量；这不等于重新收解析费。供应商缓存命中必须按低价权重计算。
6. 支持材料质量决定能做什么。缺少最新一期报表、关键附注或发行事实时，不能用高系数购买“自动补出事实”。

### 5.4 特别容易混淆的材料组合

| 上传组合 | 处理方法 |
|---|---|
| 历史 DOCX + 规范 Excel + Word 附注 | 分别按F01/F02解析；业务按报告期及市场系数 |
| 历史 DOCX + 原生审计 PDF | 仅审计解析按F04；后续业务不整单乘1.3 |
| 历史 DOCX + 清晰扫描审计 PDF | 审计解析按F05，并单列实际成功OCR外购费；不能同时重复计算同一OCR成本 |
| 历史 PDF + Excel | 后台检查能否生成所需可编辑底稿；已支持的重建工作计入本次任务，未支持则提示补充DOCX，不伪称能保留原Word修订 |
| 无历史稿 + Excel | 只有关键报表、缺少附注与业务事实时先补材料；充分时按无历史稿基数 |
| 无历史稿 + 完整审计 PDF + 业务等材料 | 按无历史稿业务系数，PDF首次解析在后台分项核算并合并到本次任务积分 |
| Word和PDF是同一报告的两种版本 | 选清晰可验证版本为主，另一版本仅必要时交叉确认，不无条件双重解析 |
| 同一数字在三份审计材料重复出现 | 事实去重；不能重复累计报告期 |
| 文件无数值或发行人主体不一致 | 不构成可用证据；先明确范围或更换材料 |

## 6. 独立复核募集书的系数

复核强度取决于**实际覆盖范围**。没有历史稿并不自动提高全文复核价格；需要历史对比却缺少旧稿时，该项不能执行。用户选择文内复核时，按文内范围执行；用户要求完整证据复核但缺少外部证据时，应在执行前提示补充材料，不能自动降为文内复核、照常收费并写“已通过”。材料补充提示不包含费用确认步骤。

### 6.1 复核类型 R：互斥选择套餐或独立专项

| 代码 | 内容 | 基础系数 |
|---|---|---:|
| R01 | 语言、格式、目录等表面检查 | 2 |
| R02 | 文内数字、日期、单位、表文与勾稽一致性 | 4 |
| R03 | 募集书对照财务报表、附注及审计证据 | 6 |
| R04 | 发行规则、披露与条款专项复核 | 6 |
| R05 | 完整复核：文内、财务证据、适用规则及约定公开信息 | **10** |
| R06 | 历史稿与更新稿的差异复核 | 5 |
| R07 | 明确问题清单的局部复核 | 3 |
| R08 | R05加独立第二轮质检 | 15 |

R05已包含其列示范围，不再叠加R01+R02+R03+R04。R08包含R05，不收10+15；实际二轮模型调用仍记录用量。第二轮是平台质检流程，不应向客户表述为注册会计师审计或律师正式法律服务。

### 6.2 复核期间、产品和历史差异

```text
K复核 = min(80，R类型 × P复核期间 × J目标结构 × D差异 × C特殊事项)
```

| 涉及需要逐期核对的期间数 | P |
|---|---:|
| 1 | 1.00 |
| 2 | 1.15 |
| 3 | 1.30 |
| 4 | 1.45 |
| 5及以上 | min(1.75，1+0.15×(N-1)) |

只有R03/R05/R06/R08实际核对多期财务内容时使用P；纯语法格式、单个法律条款或局部问题按P=1，不因全文含多年数据就加成。

D只用于R06中真实发生的跨市场/品种差异核验：`D=1+0.5×(M-1)`。其他复核D=1。历史对比没有发生市场转换时D=1。

例：普通公司债两年一期的完整复核，K=10×1.30=13；同产品三年一期为14.5。只检查一个明确的现金流指标则走R07，不按整份报告期再乘。

复核后修正错误：简短说明、引用补正、修复平台遗漏属于服务纠错；需要实质重写章节或更新新的报告期时另开变更任务，只计增量。不可在未确认的情况下把“复核”自动升级成整份重写。

### 7.2 模板 T 与证据准备 E

| 模板状态（互斥） | T |
|---|---:|
| 同券商/同机构、同文种、可用模板或既有项目结构 | 1.00 |

| 证据准备状态（互斥） | E |
|---|---:|
| 最新已确认募集书/项目事实库，可直接引用 | 1.00 |

| 关键事实缺失或主体/金额无法确认 | 不启动并提示补材料；用户另行选择较小范围并点击执行时，按新任务处理，不自动缩小范围 |

```text
K材料 = min(60，G文种 × T模板 × E证据 × J目标结构 × C特殊事项)
```

E=1.30已包含的多来源冲突整理，不再以同一事项叠加C的冲突0.10。材料生成不机械乘“5/10/15/20”；涉及多年会增加实际使用的材料和token，生成阶段不再对出现的年份额外倍乘。

例：本券商可用模板+最新已确认募集书，立项报告K=8；其他机构模板+完整原始材料，K=8×1.4×1.15=12.88；无模板且需多来源整理，K=8×1.7×1.3=17.68。

多文书订单先提取一次事实；各文书仅计自身生成token及系数。不把“摘要+推荐函+立项报告”收成三次整份募集书费用。相同内容的DOCX/PDF导出和再次下载免费。

## 8. QA对话的系数

| 代码 | 对话类型 | 基础系数 Q |
|---|---|---:|
| Q00 | 导航、余额、任务状态、产品计费说明 | **0**；优先规则回答，平台承担必要客服模型成本 |
| Q01 | 通用解释、单点摘录、简短改写 | **2** |
| Q02 | 项目事实查询、单份材料定位 | **2.5** |
| Q03 | 数据计算、单表分析 | **3** |
| Q04 | 多文档对照、证据综合 | **4** |
| Q05 | 财务分析、会计或发行规则判断 | **5** |
| Q06 | 联网/授权数据检索后的综合回答 | **6** |
| Q07 | 跨市场方案、多步骤深度研究 | **8** |

```text
K对话 = min(20，Q类型 × J相关目标结构 × C本问题特殊事项)
```

普通问答J=C=1。只有问题确实涉及特殊结构/事项，才对相关部分使用这些因素；不会因为用户关联了ABN项目，就让“下载按钮在哪里”变贵。QA不使用历史稿系数、报告期倍数或市场迁移系数。

- 连续追问按本轮实际工作定档；追问一个数在哪里不继承上轮深度研究的K=8。
- 上下文只发送相关片段；对话摘要可复用，平台不能故意重复发送整份文件提高消费。
- 后台实际检索失败、模型无法生成可用答复、纯拒答、要求用户补充必要信息的澄清，不扣任务积分。
- 普通QA点击发送即执行，后台计算本轮所需冻结积分。余额足够即自动启动，余额不足才显示充值入口；没有逐条价格弹窗或单独的限额授权设置。
- 对话里明确要求生成完整立项报告、全文更新等，系统自动识别对应任务并做同样的余额校验，足额就执行；没有价格二次确认。用户仅询问“如何更新”时仍按QA处理，不能自行触发完整编制。
- 客户要求同样事实换一种语气或缩短，按Q01增量处理；平台回答错误的修正由平台承担。

## 9. 注册、邀请、每日活跃

### 9.1 注册赠送

**实名归属可验证的手机登录完成后赠2,000积分，30天有效。** 不要求用户为了领积分额外提交身份证；现有演示验证码不能证明号码归属，正式赠送活动必须在生产短信/等效真实认证上线后启用。

同一实际用户仅一次，账号注销重开不重复领取。可用于QA、解析、材料生成、更新及复核的模型部分，也可支付已开放任务中包含的外部服务费用。后台合并计价，不因余额来自赠送还是充值再设置第二道支付门槛。按任务实际结算积分使用，不宣传“保证免费生成一整份募集书”。

到期前7天和1天提醒。用户主动充值不自动延长注册赠分有效期；平台服务中断导致无法使用的，按中断影响合理延期。

### 9.2 邀请奖励分两次

| 阶段 | 邀请人 | 被邀请人 | 生效条件 |
|---|---:|---:|---|
| 新用户有效激活 | **1,000** | **额外500** | 新用户真实验证；30天内完成有效任务，累计最终结算≥500积分 |
| 新用户首次有效付费 | **再2,000** | **再1,000** | 注册后30天内累计净实付≥100元、累计消耗≥1,000付费积分；达到条件后14天观察期内无相关退款/撤销/作弊 |

激活奖励30天有效；付费奖励90天有效。邀请人每自然月最多10个激活奖励、5个付费奖励；被邀请人只绑定一个邀请关系，首次有效归因锁定，不能事后替换。付费条件可以由两笔50元充值累计达到，不要求强推500元档。

激活仅要求有效使用，不强制上传敏感文件；结合项目内容与合法使用行为判定，不以文件数量代替真实激活。同单位共用网络不直接认定作弊，需要结合设备、支付、账号归属和行为证据；风控拒绝应给出可申诉状态。

奖励待确认期间不可消费。发现明确套利时撤销对应奖励；已消费奖励按事先披露的规则限制后续奖励/做人工处理，**不自动扣银行卡、不把赠分债务变成现金欠款**。用户正常申请退款不应被直接标记为作弊。

### 9.3 每日活跃

- 统一按北京时间自然日，不随用户设备时区切换重复领取。
- 当日完成至少一个有效任务，且当日最终结算的模型相关积分累计≥100，次日赠 **20积分**。
- 每个实际用户每天一次，每自然月最多 **400积分**。活动积分30天有效。
- 登录、上传但未处理、余额查询、失败任务、客服纠错、重复无意义请求不计。
- 实际用注册赠分完成有效任务也可计入；但每消耗至少100才返20，不能靠发送低价空消息实现净增长。
- 结算后退款冲回导致不满足条件时，未到账奖励取消；已到账按活动规则处理，不追扣现金。
- 奖励对普通用户与大客户一致。VIP如要额外奖励，须先单独测算，不能和充值折扣、邀请返利无限叠加。

建议注册、邀请、活跃作为90天首发活动。是否延续提前公告，已到账且未过期的合法奖励不因结束活动而提前作废。

## 10. 充值、钱包、有效期与退款

### 10.1 推荐充值档位

| 实付金额 | 购入积分 | 每1,000积分实际购入成本 | 相对基准购入量 |
|---|---:|---:|---:|
| **50元** | **5,000** | 10.00元 | 100% |
| **500元** | **52,500** | 9.52元 | 105% |
| **2,000元** | **220,000** | 9.09元 | 110% |
| **10,000元** | **1,150,000** | 8.70元 | 115% |

整档积分全部属于**付费购入积分，含批量优惠**，不是把多出的部分叫成“赠分”再附加短期清零规则。每笔订单保留实付金额、购入数量和精确单位成本，用于原路退款及收入核算。上表单位成本只作显示，底层不预先四舍五入。

支持正式接入后的微信/支付宝；机构采购可增加对公转账与发票。用户不配置模型密钥。充值不是承诺某任务固定价格，每次点击执行时自动锁定本次计费规则及所需冻结额度，成功后按实际计量积分与冻结额度孰低结算。

默认**不自动续费、不自动充值、不允许负余额透支**。不用“充值”按钮暗中开通连续包月。启动前余额不足则不执行，保留材料并提示充值；充值完成后用户再次点击执行。已成功冻结额度的任务不会因本次内部估计不足再要求充值。

### 10.2 一个钱包，两个积分性质

| 性质 | 有效期 | 支付范围 | 退款 |
|---|---|---|---|
| 付费购入积分 | 不设使用有效期 | 已开放任务中的模型、解析及外部服务费用 | 未使用部分可按原订单比例申请原路退款 |
| 注册/邀请/活跃等活动积分 | 30或90天，以活动批次为准 | 与购入积分相同，可用于已开放任务 | 不提现、不折现、不退款 |

付费积分不设有效期，并不意味着平台能承诺永久运营。拟停止服务时应提前通知，并提供未使用购入积分的清退安排。

商业数据库授权不是仅有余额就能突破的权限。特定机构授权、席位或授权范围不足时，先确认服务能否提供；不把供应商API调用额度与合法使用权混为一谈。

### 10.3 扣减顺序

所有已开放任务统一使用同一可用余额：未到期活动积分按最早到期先扣，同日到期先到账先扣，其后付费积分按购入时间先后扣。模型、解析和外部服务费在后台合并计价，赠送/充值来源不形成不同的任务支付权限。

点击执行后后台完成余额校验并原子冻结积分批次，不立即核销。活动积分在冻结后的正常执行中跨过到期点，允许本次已启动任务完成；新启动不再使用过期积分。未使用冻结积分释放时保留原有效期，若因平台故障释放时已过期，至少给予7天补偿期，防止用户因故障丢失奖励。

钱包必须显示：可用、冻结、已消费、近7天到期积分；可点开每笔任务查看扣减的批次。赠分与购买积分分开展示。

### 10.4 退款计算

对一笔购买积分：

```text
可退金额 = 原订单净实付金额 × 该订单未使用且未冻结积分 ÷ 原订单购入积分
```

例：500元购入52,500分，该批次已消费10,500分，其余42,000分可退400元。不能把优惠积分先按活动积分用掉后，允许全额退500元；本方案把整个52,500分视为同一有成本批次，因此没有这个漏洞。

原路退款，按订单累计分配并精确到分，最后一笔处理舍入尾差。退款、支付撤销、任务退积分分别记录，不能把同一剩余额度退两遍。正在冻结的额度先处理任务或释放，再退款。活动积分不折现；取消活动资格不影响已确认的法定退款权益。正式协议需经适用地区的法律与支付合规审阅。

## 11. 点击即执行、后台冻结与实际结算

### 11.1 用户看到的流程

```text
准备材料/输入需求 → 点击执行（QA为发送）
  ├─ 可用积分足够 → 自动执行 → 交付成果 → 显示本次扣分与剩余积分
  └─ 可用积分不足 → 不启动 → 提示余额不足及充值入口
```

**没有用户报价页、任务费用确认弹窗或追加预算确认。** 不要求用户逐项确认任务类型、历史稿状态、源/目标品种、实际更新期、材料格式、已覆盖范围、系数、预计区间、外部费用或最高可扣积分。这些信息由后台识别并保存，不构成前台执行门槛。

项目材料必须能处理、该功能必须已经开放、数据来源必须具备授权。这些是任务可执行条件；在满足这些条件后，积分准入仅判断可用余额是否足够，不另外要求月度订阅或某种积分来源。

执行中只显示正常进度；完成后在成果页显示本次扣分和剩余余额。账单明细可由用户主动查看，不作为执行前必读或确认流程。

### 11.2 启动前怎样判断余额够不够

真实总token只有运行后才能知道，因此不能声称在点击前已知精确的最终消耗。系统在后台根据材料、实际工作项、历史同类任务及模型单价计算本次所需预留积分B：

```text
E = 后台估计的业务积分 + 首次解析积分 + 任务内外部服务积分
B = ceil(E × 内部预留系数)
可用余额 = 未过期且未被其他任务冻结的活动积分 + 未被冻结的购入积分

若可用余额 >= B：原子冻结B并启动
若可用余额 < B：不启动、不扣分，只提示充值
```

初始内部预留系数可取普通任务1.20、复杂材料任务1.50，后续依据真实偏差分布校准。**该系数只用于预留，不乘到实际消费公式里收费，也不展示为用户确认项。** 预留过高会阻止原本可能负担得起的任务，应监控误拦截率并持续下调到足够可靠的水平，而不是无限放大预留。

免费本地预检、后台费用估计不计客户积分。估计结果可按材料哈希和规则版本短暂缓存5分钟；点击启动时再次检查材料版本，并以数据库原子事务完成余额校验和冻结，不能用前端旧余额直接执行。

### 11.3 成功后结算：多退不补

```text
A = 按真实有效API用量与原有任务系数计算的积分
P = min(A, B)
释放积分 = B - P
```

- A小于B：扣A，自动释放差额。
- A等于B：扣B。
- A大于B：最多扣B，超出部分由平台承担；不中途弹充值、追加授权或确认窗口，也不自动从余额再扣一笔。
- 同一用户还有其他可用积分，也不能仅因余额足够就把本任务超出B的部分自动扣走。
- 后台发现成本偏高可做缓存复用、检查点恢复和正常调度优化，不能减少用户请求范围或悄悄更换到不能满足质量要求的方案。
- 如果平台无法完成原任务，应按失败处理并释放本次冻结，不交付缺失关键范围的文件却标记成功。

例如用户可用积分1,000，本次B=1,000，可以直接执行；最终A=800则扣800、释放200；最终A=1,250仍只扣1,000。可用积分999时不启动。这是对“余额足够即执行”的可实现定义，不把事前估算冒充事后实际用量。

### 11.4 失败、取消、重试与改范围

| 情形 | 处理 |
|---|---|
| 模型不可用、超时、结构错误、关键成果不能交付 | 本次任务失败，全部释放冻结，平台承担已发生费用 |
| 只有占位符、关键引文不成立、导出损坏 | 不认定成功；修复或释放，不扣失败任务积分 |
| 用户取消普通任务 | 全部释放本次冻结；避免把内部步骤包装成付费里程碑 |
| 平台自动重试、服务重启恢复同一任务 | 复用同一任务ID和冻结，不重复冻结/扣费，不重新要求用户确认 |
| 用户修改目标报告期、补新材料或要求另一套成果 | 保存为新任务版本，待用户点击执行后重新自动计价；不因编辑或上传就直接扣分 |
| 已成功任务只下载、查看、重新导出 | 免费 |
| 因余额不足而未启动，之后充值到账 | 保留需求，由用户再次点击执行；默认不后台自动启动早先的请求 |

一个点击触发的普通任务只结算一次，内部解析、生成和校验不分别扣款。活动积分过期、冻结释放及支付退款仍按第10节处理。频繁恶意取消可按已公布的反滥用规则限制并发和服务，但不追扣未披露的现金或积分费用。

### 11.5 运行不变量

`任务总扣分 <= 启动时冻结积分B`；`可用余额永不为负`；同一任务只存在一条有效冻结及一次最终结算。并发任务共享钱包时，后发任务必须看到先发任务已冻结的余额。已接受并冻结的任务保留启动时的模型、价格与规则版本，平台重新估计成本不改变客户该次扣分上限。

## 12. 完整算例与价格敏感性

### 12.1 一年一期，沪私募转深私募，全文事实更新

条件：本企业完整历史稿；N=2；J=1；新增绿色专题只占本例业务范围，C=1.10；原生审计PDF首次解析F=1.30，Q=1。

```text
K业务 = 10 × 1.15 × 1 × 1.20 × 1.10 = 15.18
K解析 = 2 × 1.30 × 1 = 2.60

假设业务API计量成本10元：10 × 100 × 15.18 = 15,180积分
假设首次解析API计量成本0.20元：0.20 × 100 × 2.60 = 52积分
假设任务内已具备数据授权的成功外部查询采购成本2元：2 × 100 × 1.20 = 240积分

实际计量积分 A = 15,472积分，标价等值154.72元
假设启动时自动冻结 B = 18,000积分：最终扣15,472分，释放2,528分
若实际计量积分变为19,000分：仍最多扣18,000分，超出部分由平台承担
```

这是一组透明的假设成本，不是对真实募集书费用的预测。如果绿色专题只占业务计量成本的10%，则仅该部分使用1.10，其余90%不加；不能仍把全部10元模型成本乘1.10。

## 13. 商业测算与校准

这是成本加成模式，不能仅看“系数20很高”就认为一定赚到钱。客服、规则库维护、基础设施、失败任务、人力验收和税费均需覆盖；不同业务的交付价值也不同。

报告期系数是**商业难度加价**，不是对token数量的换算。若四个期间实际消耗恰为单期的4倍，基础系数又从5升为20，则总收费会达到单期的16倍。本方案按你的要求保留该梯度，但上线前必须检验用户接受度、可交付价值与内部冻结额度，不能把这种二次放大说成“完全按成本原价收费”。

在没有失败、取消及超出冻结额度的成本，且仅看成功任务模型采购成本的假设下，标准充值下的理论剩余率为 `1−1/K`：K=2为50%，K=5为80%，K=20为95%。这是扣除模型费用后的简化贡献，不是公司毛利率或利润率。

最高充值档每积分实际售价为基准的1/1.15；在上述同一假设下，模型任务的该项剩余率约为 `1−1.15/K`：K=2为42.5%，K=5为77%，K=20为94.25%。实际还应扣除失败、取消、超出冻结额度的成本，以及赠分兑换、支付、税费和人工费用。

如果一整笔2,000注册赠分全部用于K=2的任务，在没有失败、取消和超出冻结额度成本的情况下，对应模型采购成本约10元（2,000×0.01÷2），**这只是预算基准，不是实际成本上界，也未包括外部OCR等费用**。本版活动积分可用于已开放任务内的外部查询；若全部用于1.2倍计量的外采服务，在相同假设下对应采购成本约16.67元。平台仍需另计失败、取消、超出冻结额度的费用及客服成本，并据此控制活动预算与实际开放的查询能力。

外部采购按1.2倍计分，在最高充值档下的收入约为成本×1.2÷1.15=1.0435，利润空间很薄。本版不增加第三方服务的用户单独报价或付款步骤。首发只开放能以现有费率覆盖成本的查询；高成本服务先在后台核算采购费、赠分及充值优惠影响，必要时调整未来新任务的公开计费规则后再开放。平台不能在任务运行中追加人民币账单，也不能悄悄缩小用户请求的核验范围。

建议以首批30—50个获得授权的真实任务校准：每类至少涵盖低、中、高复杂度，不足样本不能声称验证。记录预估与实际偏差、有效交付率、系统重试率、退款率、每任务客服分钟数、渠道获客成本、赠分兑现率和各系数档客户接受度。

调整优先顺序：先修复重复上下文及失败重试，再校准token预估，最后调整商业系数或充值单价。价格变化只影响未来新启动的任务，保留已启动任务的计价快照。模型采购价大幅变化时也不能悄悄只改后台单位让用户无法对账。

> **任务范围。** 交付范围依据您提交的任务需求及适用产品功能。必要材料缺失或功能未开放时，平台先提示补充或无法执行；执行后发现不能交付原任务的，按失败规则释放冻结，不以缩小范围代替原任务成功。专业判断及签发权限不因支付积分而改变。

### 15.2 并发、幂等与预算不变量

- 客户端只提交任务ID/当前材料版本、用户需求及一次执行请求；后台自动计价。客户端不能提交最终系数、价格、积分数，也不必先取得报价ID再发确认请求。
- 多任务并发必须原子冻结可用余额，同一笔积分不能冻结两次。
- 支付回调、API用量事件、任务结算、邀请奖励均有不同用途的唯一幂等键；“同一提示词”不能作为已付款任务的通用幂等依据。
- 网关usage与CLI事件是同一请求的不同记录来源时，只选一个权威账源并对账，不能相加。
- 客户端断线、服务重启不应丢冻结、重复扣费或自动判成功。状态不明先对账，再恢复。
- 所有成功收费必须能追溯到已完成任务及内部用量；后台保留可解释依据，用户可主动查看明细，但不强制执行前确认。
- 冻结B、实际计量A、实际扣分P=min(A,B)、释放B-P及平台吸收的超出部分各自可核对。规则异常时停止新扣款，不自动修正为更高消费。

### 15.3 当前原型到本方案的迁移

已阅读现有 `bondbuddy` 的项目工作区说明、旧订阅说明、工作量评估及模型调用记录。现有文档存在版本差异：旧订阅说明仍写固定次数，新版项目流程已经改为评估点数后确认。迁移以实际订单及当前实现为准，不能照抄旧文案推算客户剩余额度。

当前关键差异：旧版个人499元、专业999元，分别管理QA次数、文件份数和任务点数；最新评估采用工作量加点，尚未把实际token用于正式结算。模型调用已有输入/输出/缓存用量汇总，是新计量的起点，但仍需网关级事件、价格快照及对账。

建议迁移规则：

1. 新用户使用统一积分钱包；基础材料任务不再因没有月度订阅而禁止使用。机构协作、权限及商业数据授权可以将来单独提供，不与消耗性积分混成一个无法核算的套餐。
2. 旧已付套餐按原条件保留至原权益到期；已启动的旧计费任务继续旧账本，不追溯重算token。新任务移除报价确认页，改为点击即后台计价和执行。
3. 旧“1点”不能自动换成新“1积分”。旧加购的未用独立点数可在用户选择迁移时，按原订单实付金额×未使用比例换算基准购入积分；旧订阅还含QA和文件权益，不能把全部订阅费只按任务点数拆分。
4. 原型是演示支付、演示验证码，不存在可直接上线真实收款的能力。正式启用前完成真实认证、商户支付、回调验签、退款、对账、数据权限与并发账本。
5. 先记录影子账单，与人工项目成本对比，不向客户扣新积分。校准并验证后，再对明确的新订单启用。

### 15.4 首发验收重点

采用能核对真实输入输出的样例，至少验证：

- 5/10/15/20锚点及N判定；同份文件重复年份不重复算期。
- 上交所转深交所、协会及反向转换的差异；无历史稿不额外套源品种M。
- 原生/扫描/混合PDF分类，缓存复用和增量材料计费。
- 财务复核期间加成、纯格式复核不加多年系数。
- 五类现有材料生成及QA路由，组合套餐不会重复收子项。
- 缓存输入不重复计量，推理token口径、模型切换、usage缺失处理。缺失可验证usage时暂停结算并对账，不估一个值直接收费。
- 同一支付回调、执行点击、取消及恢复重复触发，余额仍正确；余额等于B可启动，小于B不得启动。
- A低于B自动释放差额，A高于B不追扣或弹追加确认；失败/取消全部释放，平台重试不重复计费。
- 充值批次退款、活动积分到期/冻结/释放、跨月活跃与邀请条件。

**本次已验证的是方案算术与枚举一致性，未做生产支付、真实API任务或功能上线验收。** 后附矩阵及参数文件可作为研发定价配置的初稿。
