# 04 材料导入与证据处理

> 当前 M1 范围（2026-10-01）：统一编制入口；原募集书选填，上传时填写原稿市场／品种、与目标企业的关系及报告期；目标信息独立保存；现有对话区改为补充要求；材料和对应知识 MD 直接交 worker。保留修订版和清洁版，M2 复用输入计费。以[当前决定与统一验收](../../docs/product-decisions/2026-10-01-unified-prospectus-authoring.md)为准；下列旧日期工程记录不表示新流程已实现。

## 4.1 目标与固定分区

MAT-01：用户在明确的材料分区直接选择/拖入文件，不先选择“材料类型”下拉。Web 阶段是上传至账号隔离的服务端工作区；M5 桌面形态主要是导入本机工作区，只有真实发生网络传输时才称为上传。两种方式均需显示真实进度及保存状态。

| 功能/条件 | 分区 | 必需性与内容 |
|---|---|---|
| 编制／更新 | 历史／参考募集书 | 选填；可来自同企业、母公司、子公司或相似业务企业；上传时填写原稿信息 |
| 更新 | 审计报告 / 财务报表及附注 | 必需；覆盖任务所需期间，允许多文件组合 |
| 编制／更新 | 上述财务材料中的年度审计及分业务收入附注 | 按目标披露需要提供；局部缺项在任务内标注，不能以参考企业事实替代 |
| 更新 | 募投项目与权证材料 | 条件必需，按用途提示 |
| 更新 | 其他项目材料 | 可选，评级、债务、授信、决议等 |
| 复核 | 待复核募集书 | 必需 |
| 复核 | 审计报告 / 财务报表及附注 | 必需 |
| 复核 | 其他核验材料 | 可选，用于核对已知差异或补充证据 |
| 生成 | 最新版募集书 | 默认必需；可改选已存在的项目来源 |
| 生成立项报告 | 券商模板 / 参考立项报告 | 无本人已存可用模板时必需 |
| 生成 | 立项规则或其他支持资料 | 依文种提示，不强制所有材料共用同一清单 |

募投材料提示包含可研、项目备案、土地及建设许可、基金备案、子公司股权投资方案和批准文件等。提示只列实际相关项，不要求每种用途上传全部权证。

更新任务的材料清单用于识别所需证据，不要求每个分区齐全后才处理全文。按2026-09-25用户确认，已有可用发行人材料时，即使缺当期附注、审计意见页或部分发行条款资料，也按现有材料执行全文更新；在相关内容及结果摘要标记“材料缺失／待人工确认”，不编造缺失事实。原稿未上传不属于失败；已上传文件实际不可读或无法形成有实质内容的工作稿时说明具体原因，详见第05章 UPD-GAP-01。

## 4.2 文件格式与容量

MAT-02：设计目标，普通材料支持 DOCX、原生/扫描 PDF、XLSX、CSV、TXT、PNG、JPG/JPEG。文件名不能决定格式，以实际内容识别 MIME/文件签名。

历史和待复核募集书优先 DOCX，以保留编辑结构和可识别的字体信息。首发目标允许 PDF 作为基线，但需明确：

- PDF 历史稿先重建带原页锚点的可编辑 Word 基线，再输出相对此基线的修订版和清洁版；说明重建限制，不能承诺保留源文件所有版式或宣称是原生 Word 的既有修订轨迹。
- PDF 复核中无法可靠提取的字体、字号、Word 域等标记未覆盖；不能判为格式通过。
- 扫描 PDF/图片支持属于 OCR 要求，不能据此声称任意排版均可高保真还原。

当前原型历史/待复核仅 DOCX，PDF 基线扩展列为新增实现。旧二进制 DOC、XLS、加密文件、宏文档需先转换或提供可读副本；不给出改扩展名的假修复建议。

初始容量设计：每项目最多 60 份、合计 500 MB、单份 100 MB，扫描件允许分卷；这是相对当前 80 MB 总限额的扩容目标，须压测后发布。单文件页数阈值设计 1,500 页，超过给出拆分入口。限制由服务端/本地统一配置，不能浏览器接受而后台静默截断。模型上下文不足采用分块，不截断尾部后宣称全文完成。

## 4.3 导入进度与错误恢复

Web 文件状态：selected → uploading → persisted → prechecking → ready；支持单文件重试与中断恢复，服务端校验大小、签名与哈希。M5 文件状态：selected → copying → imported → prechecking → ready；发生网络传输另有 transfer 状态。执行后两端均可进入 parsing → needs_confirmation / parsed / failed，不能混淆本机复制和网络上传进度。

每行展示文件名、大小、分区、实际字节进度、状态、失败原因、重试/移除。上传或复制到 100% 后仍未保存成功时显示“正在保存”；未知总量的 OCR 显示已处理页数，不编造百分比。总进度应说明按字节还是按页计算。

支持逐文件重试、取消未完成导入、批量添加。一个文件失败不要求重传其他成功文件。新文件完成持久化及哈希后才进入项目 material_revision。用户删除引用时保留运行中快照所需文件；执行中的源文件不能被物理改写。

## 4.4 预检与收费边界

上传/导入、普通无外部付费调用的提取、文件校验、计价估计免费。Web 预检在服务端，M5 可在本机执行。预检识别：文件可读性、主体线索、期间线索、材料分类、重复文件、必要材料是否存在、明显缺页和扫描情况。

M1/M2 上传任一历史／参考募集书时，由用户填写原发行人、与目标企业的关系（同企业／母公司／子公司／相似业务企业）、原市场、品类、年度集合及一期。没有原稿时不要求这些源字段；目标信息始终独立收集。源信息与本次目标分开保存；具体字段见第 05 章 UPD-SOURCE-01。保存须绑定材料不可变版本，记录用户来源及修订版本，不要求先自动识别、确认画像或取得原文锚点。

由 worker 在任务内完成实际文件读取、财务核对和必要 OCR，保留事实不确定性；手填信息不代表财务已核验。旧识别记录可保留，不再作为上述三类字段的启动门槛。上传、保存、普通校验与内部估算不扣积分、不启动全文；既有平台承担的预检调用不可转成用户费用。

其余用户可计费的全文 OCR、模型解析或 embedding 建索引，仍属于用户点击执行后的内部阶段，并入该次任务计量；不得一上传就全量收费处理。执行前无法确定的非关键工作量可按文件页数/格式等估算预留；影响迁移定价的源市场/方式/期间尚未确定时，后台保留不确定工作量，不按猜测强行归档收费、不把未知 N 当零；M1 平台试用不以全文内容已审核为上传前置，M2 继续按第14章执行。执行时发现局部材料缺失，按第05章继续全文处理并标记受影响内容；只有实际无法形成可交付工作稿时，才按失败/澄清规则释放冻结、由平台承担该失败任务费用。不得把单个缺失项直接等同于整单失败，也不因有待确认项额外发起扣费。

“正在解析”必须区分免费预检解析与执行中的付费阶段；M1 成本由平台承担，不提前扣取尚未上线的积分。文件准备完成不等于财务数字已校验，不能在未读取时确认“资料齐全且准确”。

## 4.5 证据数据规范

每个证据锚点最少包含：

| 字段 | 定义 |
|---|---|
| material_id / content_hash | 原文件不可变身份 |
| locator_type / locator | PDF 页码及框坐标；DOCX 段落/表格/单元格；Excel 工作表/单元格 |
| literal_quote | 可回到原材料核验的原文，不只保存模型总结 |
| extraction_method / version | 原生解析、OCR、人工校正等方法 |
| confidence / uncertainty | 原始置信度、待确认原因、确认记录 |
| source_kind | 审计材料、用户补充、公开公告、商业数据、模板参考等 |
| observed_at / valid_as_of | 获取时间与该事实对应时点分开 |

DOCX 页码随字体、软件和打印设置变化，原生锚点采用段落/表格 ID，不编造静态页码。需要页码时使用带渲染版本的快照并标明来源。

事实键至少为：主体 + 合并/母公司/其他范围 + 指标/事项 + 期间起止或时点 + 币种 + 单位 + 会计/统计口径 + 数据版本。不同键的同名数字不能直接覆盖。

以下事实/锚点是 worker 可采用的内部记录，不要求在开始前全部生成或审核。事实状态：extracted、verified、user_asserted、conflicted、needs_confirmation、superseded。模板中的公司名、金额、签字和示例永远不得进入发行人事实集合。

## 4.6 worker 内部财务读取与 OCR 工具（非独立预处理服务）

OCR-01：保留原始图像、页序、方向校正信息、表格结构及坐标。处理跨页表头、合并单元格、负数括号、千分位、百分号、“—”与空白、小数点、人民币元/万元/亿元等。

1. 识别文件主体、审计机构、审计意见、报告日期、报表期间、合并/母公司范围。
2. 提取三大报表与附注，分开保存原字符串、标准化数值和单位转换。
3. 进行表内合计、报表平衡与跨表核对；勾稽通过不能反过来证明 OCR 每个数字正确。
4. 模糊数字、主体/列头错位、与其他材料冲突的值进入待确认队列。重要的发行规模、债务、收入、利润等不能用低可信值完成关键结论。
5. 上述财务/OCR 内容疑义在全文执行过程中处理：有依据的部分继续更新，存疑位置标记待人工确认并汇总摘要。用户可修改现有补充要求区或补充材料，再明确开始新一轮；上传阶段不新增必答清单、技术核对入口或要求逐项完成内容审核。
6. 保存校正者、时间、原值与新值；用户确认不能被记录为审计机构已经确认。

数值零、空值、不适用、未提供必须分开。负数不能因括号丢失变正；报表横向年度顺序改变时按列头识别，不按固定第几列。

## 4.7 冲突处理及缓存

同一事实有多个来源时，保留全部候选与来源日期。已更正审计报告可替代其明确更正范围内旧值；工商最新状态不能覆盖历史报表时点；用户口述不能静默覆盖审计事实。必要时追问究竟采用哪个有效版本。

缓存键至少包含账号、文件内容哈希、解析版本、OCR 版本、口径修正版本。相同文件改名或同账号跨项目引用，可复用成功提取结果；新增页或替换文件只处理增量。不同账号默认不共享私人内容缓存。

失败任务已产生的有效解析成果可缓存，但该失败任务成本由平台承担。以后复用这些成果不得倒补收失败费用。规则变更只重做受影响判断，不无故重复解析原文件。

## 4.8 验收

| ID | 输入/操作 | 预期 |
|---|---|---|
| MAT-A01 | 上传 3 份，1 份中断 | 2 份保留，失败文件单独重试；不扣分 |
| MAT-A02 | 同内容不同文件名再次导入 | 识别复用，无重复解析费 |
| MAT-A03 | 文件为旧 DOC 但扩展名 DOCX | 识别真实格式，提示转换 |
| OCR-A01 | 扫描表格中负数括号/小数点模糊 | 保留原页与不确定标记，不直接出确定结论 |
| OCR-A02 | 同期合并与母公司报表 | 建两套事实，不能混填 |
| OCR-A03 | 一页横排、跨页附注、年序倒置 | 还原页序/列头，无法还原明确阻断相关结论 |
| MAT-A04 | 引用中的页码或引文不存在 | 来源检查失败，不能当有效证据 |
| MAT-A05 | 超限/缺页/加密材料 | 预检说明具体问题，不静默丢失内容 |

## 4.9 Web 实现边界（2026-09-28，#384）

材料上传页保留文件名、大小、真实字节传输/保存和持久化任务状态，并在募集书上传区提供用户手填的原市场、品类、报告年度及最新一期。这些是普通业务字段，不是解析审核面板。等待/处理中不会伪装完成；任务 succeeded 显示“处理完成”，包括后台仍有 needs_confirmation 的情形，这不改变证据状态或声明财务已核验。失败展示简短原因和下一步；刷新状态只读取记录，不冒充重启解析，上传失败继续沿用逐文件重试。

普通材料页不渲染历史稿画像、原文、证据 ID、英文 warning、解析器类型、技术校正表单、OCR 核对链接或折叠事实审核面板，也不读取/写入 source-profile 来完成隐藏确认。后台既有识别记录继续保留；当前用户申报的原市场/方式/报告期另记为用户来源，不伪造机器已确认。本次目标只来自原有表单/补充要求，不能由历史稿自动覆盖。

状态按 project/material/version/hash 校验，刷新/重开从账号隔离的服务端恢复；旧请求与换号结果丢弃，文件选择器在状态刷新时保留。前端消除内容确认步骤不表示后台准入已经迁移：#76 的类型/难度依据和输入锁消费者、#31 的全文内容处理须协调验收；#18 改为补充要求区及旧用户要求迁移，不作为上传审核前置。合成浏览器证据与真实 API/模型/Word 结果分别记录，见 `apps/web/ux-evidence/issue-384/README.md`。

2026-09-29 #384 补充：预检 `blocked` 不逐条向用户展示规则、发行人绑定、材料候选、历史画像及难度诊断清单，也不以“继续提交并等待处理”暗示可出稿。只展示简短可操作的输入/文件问题或平台待核状态；重新检查精确已锁输入时不产生新 run。已有 run 暂停时先核对处理条件，仍阻断或恢复后再次停在同一条件的，提示联系支持，不引导循环点击“继续更新”。后台原始诊断、任务状态、版本与门禁保持不变；具体现场归因仍须按服务端记录复核。
