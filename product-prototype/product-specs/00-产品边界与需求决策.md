## 0.1 产品定位

BondBuddy 是服务券商从业人员的债券文书任务软件。用户个人注册、充值，提交项目材料，完成募集书全文更新、专业复核、配套材料生成及债券 QA。按最新要求先做网页版，最后做 Windows 下载应用；M1/M2 使用独立的目标／原稿信息与补充要求，持续维护项目事实和成果版本；后续专业问答按各自阶段交付。

本版“首发市场/品种”指募集书更新或复核各自首次上线时的覆盖范围，并不表示五个里程碑同时上线。M1 上线 Web 注册/登录与更新，M2 上线积分付费，M3 上线募集书复核及结果修订，M4 上线五类材料与独立问答，M5 上线 Windows。2026-10-02 用户决定本次 M3 不包含收费功能，不再以前置 M2 计费或支付验收作为上线条件；M2、M4 已有收费规则不变。详见[开发任务清单](delivery-plan/README.md)。

首发不以团队采购、机构审批流、协同编辑或在线 Word 审阅为前提。专业机构签发、投资决策、现场尽调和人工法律判断仍由有权主体实施；软件产出必须与实际取得的证据相符。

## 0.5 术语与责任

- 项目：长期保存的工作资料容器。创建、编辑、导入材料免费。
- 执行任务：用户一次明确执行请求对应一个 run 和不可变输入快照；只有已启用收费的任务才关联冻结与结算，本次 M3 不关联账务事件。
- 成果版本：成功输出及其来源快照；再次执行生成新版本，原成果保留。M3 执行开始即保留版本编号，停止或失败的编号不复用，工作台同时展示真实状态与最新可用成果。
- 事实：有主体、期间、口径、单位、来源和状态的信息；用户说法属于一类来源，不等于已审计事实。
- 规则包：特定市场、品种、有效期间的专业规则集合，经专业验证后发布。
- 模板：章节、字段、表格、样式与适用条件的版本集合，不包含可直接挪用的其他发行人事实。
- 平台内部参考库：无历史稿时后台获取结构参考的能力，普通用户不可浏览。
- “成功”：请求的成果通过交付检查且可供用户取得；不是模型返回了文本。

本文用要求 ID 连接功能与验收。供应商商品名称、精确字段、接口协议和法规有效版本未取得正式依据的部分列为接入条件，不以虚构接口或条号填补。

## 0.6 设计默认

M1 作为受控试用，平台承担成本并记录用量；这是为衔接 M1 与 M2 提出的排期默认，不是长期免费承诺。M2 开始真实钱包和收费，不追溯扣取试用任务费用。功能按已验收能力逐步开放，未上线功能不能用演示成果替代。

本次 M3 的复核、结果修订和项目助手调用由平台承担成本，不要求用户钱包已配置或余额大于零，不创建冻结／扣费／结算事件。真实用量、失败和重试仍可追溯；收费何时引入须另行确认，不把本次范围解释为长期免费承诺。

Web 项目及用户明确上传的材料按账号保存在平台工作区，保存期限、删除与备份清理必须在 M1 发布前落实；关闭浏览器不取消服务端任务，同一账号重新登录可继续查看。平台按账号限制并发，防止失控成本。

M5 本地项目不会自动跨设备同步。设计默认每设备同时运行一个大型文书任务，关闭窗口进入托盘，完全退出或系统关机保留检查点。用户可显式迁移 Web 项目或导出本地备份，不默认同步全文或删除云端副本。平台钱包始终支持跨端并发一致性。以上设计默认可经验证调整并记录变更。
