# 00 产品边界与需求决策

## 0.1 产品定位

BondBuddy 是服务券商从业人员的债券文书任务软件。用户个人注册、充值，在 Windows 客户端提交项目材料，完成募集书全文更新、专业复核、配套材料生成及债券 QA。产品将结构化项目信息与右侧多轮对话结合，持续维护项目事实和成果版本。

首发不以团队采购、机构审批流、协同编辑或在线 Word 审阅为前提。专业机构签发、投资决策、现场尽调和人工法律判断仍由有权主体实施；软件产出必须与实际取得的证据相符。

发行场所字段可以展示“发行市场”，选项仍为上交所、深交所、交易商协会。协会不是交易所，数据模型不得用 exchange 枚举强行等同机构性质。

超短融简称 SCP。DFI 中文名称使用“储架发行”（不是“储价发行”），纳入首发选择范围：前台在同一“发行方式”下拉框显示“DFI · 储架发行”，保存 scope=nafmii-dfi；不增加单独的“注册模式”选项。后台将 DFI 视为统一注册/储架安排，覆盖品种与各期实际发行品种分别记录，不将 DFI 自动改写为 MTN。ABN、ABCP、项目收益、永续及其他复杂结构分期实施；参数表存在这些产品不代表首发已开放。绿色、科创、含权、担保等作为额外特征识别，是否可处理由规则包和能力表决定。

大公募是用户明确的首发要求，不得悄悄降为后续版本。它的专属披露、发行对象、发行条件与适当性等要求必须补齐；如果未通过验收，应如实记录为首发阻碍。

五类生成材料按目标市场及用途匹配。摘要首发聚焦交易所私募、公募两类，公募按小公募/大公募分支；不把交易所“公募摘要”强套为银行间注册必备文件。银行间其他四类材料须有相应适用模板，不能仅替换文书标题。

## 0.4 体验决策与废弃项

| 保留的目标体验 | 应清除或迁移的旧行为 |
|---|---|
| 首页四个核心工作入口与项目列表 | 用户端募集书库入口及主动匹配推荐 |
| 历史稿只答有/没有 | “蓝图匹配信息”和实现原理说明 |
| 项目选填表单默认展开 | 把基本字段藏在对话主题卡或折叠面板 |
| 全文更新 | 手动更新范围、年度数量、注册模式选择 |
| 自由补充债券安排与机构分工 | 预建品种一/二、单承销商强填联席角色 |
| 六类资金用途下拉加金额与备注 | 重大重组、是否设置投资者保护条款问卷 |
| 固定材料分区和真实进度 | 材料类型下拉及模拟上传进度 |
| 复核三维范围可见 | 复核强填大量发行项目信息 |
| 生成默认上传最新版募集书 | 默认关联项目、模糊“自然语言补充”标题 |
| 点击执行后自动启动 | 报价确认页、固定任务点数、月度套餐限制 |

对话标题统一优先使用“补充说明与写作要求”；复核可用“补充说明与核验线索”。说明只列用户需要提供的事实和要求，不展示内部提示词或实现策略。

## 0.5 术语与责任

- 项目：长期保存的工作资料容器。创建、编辑、导入材料免费。
- 执行任务：用户一次明确执行请求对应的不可变输入快照、一次冻结和一个最终结算。
- 成果版本：成功输出及其来源快照；再次执行生成新版本，原成果保留。
- 事实：有主体、期间、口径、单位、来源和状态的信息；用户说法属于一类来源，不等于已审计事实。
- 规则包：特定市场、品种、有效期间的专业规则集合，经专业验证后发布。
- 模板：章节、字段、表格、样式与适用条件的版本集合，不包含可直接挪用的其他发行人事实。
- 平台内部参考库：无历史稿时后台获取结构参考的能力，普通用户不可浏览。
- “成功”：请求的成果通过交付检查且可供用户取得；不是模型返回了文本。

本文用要求 ID 连接功能与验收。供应商商品名称、精确字段、接口协议和法规有效版本未取得正式依据的部分列为接入条件，不以虚构接口或条号填补。

## 0.6 设计默认

首发单账号可在不同电脑登录，共用云端钱包；本地项目不会因此自动跨设备同步。默认一个设备同时运行一个大型文书任务；并发上限可按性能配置，云端钱包仍必须支持并发一致性。关闭主窗口默认进入托盘继续工作，完全退出或系统关机保留检查点。

用户可选择导出本地项目备份；不默认启用云端全文备份。以上默认与核心产品承诺不同，可由工程验证后调整并记录变更。
