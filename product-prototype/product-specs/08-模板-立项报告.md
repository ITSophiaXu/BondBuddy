# 08 模板规格：立项报告

标识：TPL-INIT｜计价 G01｜首发必需｜适用：券商内部立项工作稿

## 8.1 使用目标及输入

将最新募集书、发行安排及已完成尽调信息，组织成指定券商的立项报告，供项目组内部审核。系统不能替券商决定是否立项或虚构已通过内核/立项会议。

必需：最新版募集书或关联项目、立项券商全称、本人可用的该券商模板/参考报告。建议：该券商立项规则、尽调清单、业务部门要求、项目方案和新增风险资料。

可在右侧补充项目团队、拟申报节奏、重点风险、内部称谓、篇幅要求。项目人员名单、推荐立项意见及业务安排来自用户或正式文件；模型不能自行补出人名和审批日期。

## 8.2 章节与字段映射

券商模板决定实际顺序；以下语义模块必须映射到模板。确实不适用的项记录理由，不能强行新增与券商模板冲突的正文。

| 章节族 | 必须处理的事实/分析 | 输出形态与依据 |
|---|---|---|
| 封面与项目摘要 | 券商、发行人、项目名称、市场/品种、规模/期限、报告版本 | 封面及摘要表，拟定安排保留“拟/不超过” |
| 项目背景与承揽 | 项目目的、客户关系和推进节点 | 用户提供事实；未提供不写成长期合作 |
| 发行人基本情况 | 存续、股权控制、治理、资质、主要子公司 | 募集书与有效工商/公告对应时点 |
| 业务与行业 | 前三大业务、经营模式、区域/客户集中、变化 | 收入成本分板块表，行业判断附来源及日期 |
| 财务与偿债 | 三表摘要、债务、现金流、审计意见、授信及指标 | 各期同口径对照；计算列附公式及来源 |
| 发行方案与用途 | 申报/本期规模、各品种、增信、用途、偿债安排 | 条款及用途表，分清已确定和拟定 |
| 尽调情况 | 已收集材料、执行程序、发现和资料缺口 | 程序—证据—发现矩阵，不虚构访谈或实地核查 |
| 立项条件核对 | 券商内部准入条件、负面事项和例外 | 逐条规则、适用性、证据、结果和处理人 |
| 风险与措施 | 发行人、财务、结构、用途、信用及执行风险 | 风险描述、证据、拟措施、待落实事项 |
| 立项申请 | 建议方案、附带条件、未决事项 | 供项目组确认的申请措辞，不写成审批决定 |
| 附件及签署 | 材料清单、数据来源、必要内部表单 | 签署角色按模板保留，不填假签章 |

## 8.3 专用表格

项目基本情况表：发行人、统一社会信用代码（有来源时）、券商、市场、发行方式、规模、期限、评级对象、增信、用途、拟时间安排。

主要财务表：年度/中期、合并范围、资产/负债/权益、营业收入、利润、经营现金流、项目定义的债务和偿债指标。不能把中期直接当全年，年化需显式公式和说明。

立项条件核查表：

| 字段 | 要求 |
|---|---|
| rule_ref | 券商规则名称、版本、原条款 |
| applicability | 适用/不适用及理由 |
| evidence | 对应项目资料与定位 |
| assessment | 满足、存在差异、待补证、待人工判断 |
| action | 要补充的资料/拟采取的措施/负责人（仅用户提供） |

风险表应体现风险为何与该项目相关，不只复用通用套话。缓释措施未落实时用“拟”，不能写已完成。

## 8.4 规则缺失与模板差异

未上传券商立项规则时可以根据已取得模板和项目证据生成报告，但必须明确“未取得完整内部准入规则，内部条件核对待项目组确认”。不得用其他券商准入门槛代替。

如果模板本身含明确内部阈值，保存其版本与来源，标记为机构要求；不能升级为市场监管规定。模板中的历史案例是示例，不是本次项目事实。

财务、负面事项或必要发行方案缺失到无法形成有效报告时阻断；联系人/拟提交日期等可在编制说明列待确认。模板结构无法解析时要求可读副本，不自动换平台通用模板交付。

## 8.5 质量与验收

TPL-INIT-A01：同一发行人使用两家券商模板，结构和内部核查表正确变化，事实不变化。

TPL-INIT-A02：规则中明确门槛不满足，报告列差异及待落实事项，不输出“全部满足”。

TPL-INIT-A03：只有模板没有内部规则，仍能形成有用工作稿，明确规则核对限制。

TPL-INIT-A04：未提供现场尽调记录，不出现已访谈/已现场核查的陈述。

TPL-INIT-A05：首次上传自动保存本人模板；再次生成可选择原版或新版，不影响旧成果。

输出为“发行人_立项报告_券商_版本.docx”及编制说明；文件名应做安全字符处理。使用同券商有效模板对应 T=1，不因重复上传新文件名增加模板难度。
