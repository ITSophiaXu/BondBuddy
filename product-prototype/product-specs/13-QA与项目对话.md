## 13.2 业务控件与 Agent 的分工

本节M3问题／提议细则保留旧协议语义；本次新增Agent用最新决定的执行条件。工作区不再提供补充意见textarea。明确重点、限制、字段更正保存到准确草稿，在左侧只读“助手已采纳要求”；预置规则另标“系统默认规则”。真正问句、助手建议和普通分析不自动成为要求。未绑定要求保存到话题，准备任务时仅绑定一次；文种切换各自保存，不串要求。

执行按钮旁“与助手讨论”带任务、文种、来源、模板、报告期、范围及草稿上下文并聚焦，保留未发送文字与段落引用，不发送、不执行、不改范围。讨论目标随显式准备新任务／继续改稿更新；业务上下文与引用分别显示。

筛选问题、查看原文／依据／解释、补充文件、勾选修订、核对计划、执行和下载等常规流程通过页面按钮完成。“查看解释”打开问题内详情或弹窗，不创建虚构用户消息；加入修订和下载等局部操作使用页面反馈，不逐点击制造聊天日志。用户无需输入对话文本即可完成复核与结果处理，实际执行仍进入助手的同一任务时间线。

CHAT-TIMELINE-01：实际用户消息、真实助手回复、待确认范围提议和持久化任务卡按类型区分，统一保存在同一项目时间线，不另建任务面板。快捷与对话入口复用同一执行路径，任务卡通过稳定 run 身份去重，随真实事件更新状态、输入、发起来源、确认范围、来源报告、停止／失败原因和成果入口；不因轮询重复追加卡片，不为显示进度或完成额外调用模型。右卡定位准确左侧 report／finding，左侧结果能定位对应任务卡。公共字段、事件和版本在 `packages/contracts/` 唯一定义。

CHAT-PROGRESS-01（#547）：执行反馈按[当前动作与助手执行摘要](../../docs/product-decisions/2026-10-04-review-agent-progress.md)更新。左侧紧凑状态栏与右侧任务记录同步同一真实动作；右侧突出当前工作摘要，已完成动作默认折叠并保持用户展开状态。合并连续同类动作；无新事件时保留实际阶段，不按计时模拟工作。复核助手消息及任务记录不展示时间戳、心跳、用时、预计时间或百分比。保留审计时间；用户回看历史或选择文字时不抢滚动。

需要表达额外信息或继续讨论时，可从“继续讨论此项”“说明口径”“提出异议”带入上下文，窄屏同时展开助手。它承接以下场景：

| 场景 | 用户输入示例 | 行为与边界 |
|---|---|---|
| 业务口径 | “这段用母公司口径，偿债能力一节用合并口径。” | 关联具体章节与问题，显示适用范围；不默认统一全稿，不直接推翻原结论 |
| 异议与例外 | “旧名称属于历史沿革，不能全部替换成现名。” | 保存理由及原发现／来源报告，列待重新判断；不因用户异议将问题改为通过 |
| 补充材料解释 | “名称变更证明自 2025 年 8 月生效，区分前后表述。” | 关联文件、日期说明和问题；列待核验事项，上传或说明不启动任务 |
| 跨问题要求 | “债务金额和摘要一起改，先不处理 F-005，保留标题样式。” | 提议可核对的修订范围与限制，不自动改变现有勾选；明确执行后才生效 |
| 运行中新增信息 | “新收到的附注用于下一轮，当前任务继续。” | 将新材料与说明保存到下一版并显示适用范围；当前 run 快照不变 |

M3 公开查询复用 worker 的 Codex／所配置模型实际 web search，按第 06 章记录主体、时点、来源及覆盖；不依赖募集书库，不把商业数据接口或独立检索服务作为前置。

按[2026-10-03 CLI 架构决定](../../docs/product-decisions/2026-10-03-m3-cli-runtime.md)，M3 助手回复继续由 Codex CLI 生成，固定项目助手 Skill 由运行时显式载入。后台保存项目/报告/问题上下文、消息租约与真实调用记录；不依赖一个无限续接的 CLI 会话，也不因技能加载而扩大工具或执行权限。未提供的材料或外部查询不得在回复中声称已读取、已核验。

## 13.3 发送、保存和执行的语义

CHAT-02（历史M3提议协议）：已有消息、提议与run按原版恢复。旧协议发送只保存／讨论／提议，明确采纳绑定范围来源后执行；不默改已选问题或已有结果。完整复核锁定完整输入，讨论报告不能充当差异基线或缩小完整范围。下表是旧协议验收记录，不限制本次新增统一Agent在有效报价及明确授权齐备时承接一次发送的执行请求。

| M3 用户消息／动作 | 行为 |
|---|---|
| 补充事实、口径或异议 | 保存到适用的问题／报告或项目范围；区分用户提供与已验证证据；必要时澄清 |
| 请求解释某个问题 | 在带来源引用的讨论中回答；不启动文稿任务，不改变问题状态 |
| “把这些信息用于下一版” | 保存下一版要求，明确尚未执行 |
| “按这些问题修改／重新复核” | 提出待核对计划；既有勾选保持，用户明确选择／调整后点击对应执行按钮 |
| “继续” | 展示当前明确待办；含义不清先澄清，不启动未知范围的任务 |
| 页面点击执行 | 持久化已展示的输入、已采纳提议／发起来源、范围和精确来源，创建单一任务；助手时间线显示同一 run 的真实任务卡，左侧同步关联状态 |

同一项目的完整／差异复核与修订任务互斥；活跃任务期间可继续保存下一版说明，不能同时开始另一个冲突任务。相同 `execution_request_id` 返回原 run，空修订计划不执行。任务状态和错误在对应页面及同一任务卡显示，不以聊天中的一句回复替代已持久化任务。助手回复中断与业务 run 中断分别呈现，刷新或回复失败不自行取消已提交任务；恢复先补读持久任务／事件，不用重新执行代替恢复。

### 分阶段 Agent 的发送与执行规则

发送按整句区分回答、保存、澄清与执行，分类成本平台承担。M4已开放的单文种任务在准确输入、已展示有效价、授权及预留齐备时可同次启动，缺项先澄清，补齐只保存；已有授权不重复形式确认。请求M5未开放文种／组合／局部执行先说明阶段，不执行／收费或替换范围。M4跨业务提供解释／保存意图和显式前往目标工作区，在目标工作区核对输入／报价并明确执行；同会话跨业务自动执行归M5-10。

| 用户消息 | 行为 | 计费 |
|---|---|---|
| “补充：公司授信总额为……” | 保存为用户提供的事实，追问必要时点/单位，显示已记录 | 保存及纯澄清免费 |
| “请解释为什么这一项有差异” | 基于证据进行专业回答 | QA 对应档位；平台自身错误修正免费 |
| “把这些信息用于下一版” | 更新下一版需求，尚未要求生成时说明已保存 | 不因编辑资料直接收费 |
| “按这些信息重新生成立项报告” | M4整份续改，输入／有效价格／授权齐备后启动 | 原文书任务规则，无重复形式确认 |
| “怎么更新募集书” | 回答方法 | 普通 QA，不启动全文更新 |
| “请把这个项目全文更新到 2026 年 6 月” | M4保存意图并显式前往更新工作区重核执行；M5自动承接 | 真正执行按更新任务，不伪装短QA |
| “继续” | 结合当前明确待继续事项；有歧义则澄清 | 不自动启动未知范围 |

整句提取动作、对象及局部限制。M4用“请生成立项报告，保留待核事项，不要生成签署页”和“补充资料已经上传了，请开始生成立项报告”验主执行不被局部禁止吞掉；对应法律原句归M5。“如何生成”“暂时不要生成”“先别生成”“不要复核”不执行。条件缺项保留主请求并澄清，自由回答只回填；跨文种先定目标、更正覆盖值，未开放文种如实说明。

从复核页要求更新，始终区分固定报告修正与新期间更新，报告／来源／目标独立，新稿不等于复核通过。M4解释并保存准确意图，显式前往目标业务工作区重新核对及执行；M5-10扩展为原会话自动准备／执行。新规则不重发旧消息或更改历史账务。

M4 开始任务前的必要追问、无结果检索、纯拒答、客服问题不扣任务积分。问答有效答复中合理的不确定性与纯拒答不同：有证据的分析即使结论为“不能确定”，仍可能是完成了用户的分析请求。

2026-09-27 工程切片：项目页已增加独立的输入版本、预检及显式全文执行按钮；普通草稿补充不自动执行，改内容后保存新输入，旧 run 不变。这里只打通已有执行 API 的浏览器入口，未实现逐轮消息、真实助手回复、流式中断恢复或消息到 prompt/job 的持久关联，不能作为 CHAT-A01/连续三轮授信示例已通过的证据。

## 13.4 上下文与冲突管理

消息对象保留 role、content、attachments、project_id、artifact_version、intent、fact_refs、created_at 和修订关系。M3 问题级消息另含精确的 `report_id`／`report_version`、`finding_id` 和输入版本引用；项目级／跨问题要求标明适用范围及所含引用，不能只保存一个可变的“当前问题”。编辑／删除先前说明只改变后续上下文，不改写已运行任务快照；M4 已有账单同样不被历史消息编辑改写。

M3 的真实回复引用使用服务端保存并验证的版本化结构化元数据，不能从回复正文正则猜 report／finding。对话的报告引用与任务执行来源分开；已采纳提议、实际用户消息引用、任务输入及成果关系持久化，刷新后仍能回查真实来源。提议／回复 schema 与提示和调用版本一起固定，旧消息／提议保留原版验证与恢复，不因新 schema 重发旧调用。

未发送草稿与project／report／finding上下文一起持久化；切卡片、切文种／话题、标签和刷新保留原文及引用，不能静默覆盖／改绑。补证固定原归属，不跟随聊天焦点变化。生产保存完整消息修订、附件权限／来源、各文种草稿、任务事件、成果、标签和阅读位置；分页／摘要不删原记录。保存超限／失败及恢复损坏可见并可重试，保留旧记录及当前内容，不静默清空；不使用原型16KiB快照作生产历史机制。

来源优先最近明确选择；无明确来源且候选唯一才继承，否则澄清，不能拿旧附件或其他话题数字代算。M4整份继续改稿底稿优先旧引用并保留要求，原生成来源独立；准确选文讨论固定版本／位置，与底稿冲突澄清。局部实际修改归M5-08，未开放时不扩大为全篇执行。

2026-09-29 工程切片边界：`POST /api/v1/projects/{project_id}/messages` 只保存已提交用户消息和受控材料版本，显式返回未分类/仅保存，不产出助手回复或执行任务；`GET .../messages` 分页返回本人项目的最新修订，`GET .../messages/{message_id}/versions/{version}` 可回查原文与来源。旧版与新版本均保留受控正文和访问审计，消息集合 pin 的 version 在修订时递增、hash 改变、原会话顺序不变；后续 input revision 需锁住精确引用。该切片未接线真实模型多轮回复、意图提议、附件替换、流式中断或模型用量；M3 新能力由 #47 实现，账务不加入此次 M3 范围。

2026-09-29 浏览器切片：更新项目右侧已接上述 **user-only** 消息页，保存/原版本回查/冲突重读均保持用户输入可见；刷新和重新登录恢复已确认保存的消息。执行前读取当前完整消息集合 ref（包括未翻页的 ID），input revision 同时带全部 `requirement_message_ids` 和精确 ref；运行中补充产生后继输入，不改写已锁定 run。创建项目之前的 composer 尚未发送，临时失败用同一 request ID 重试。旧版 `supplementary_notes` 保留在原草稿并明确标记，未自动迁移为已提交消息。该切片不完成本节的助手追问、问题／报告上下文草稿恢复、消息附件替换或计划提议；不据此扩大 M1 范围或声称 M3 助手已实现。

新事实与结构化表单冲突时：

1. 先区分新安排与旧事实、不同期间与不同主体。
2. 如用户明确改变目标安排，记录下一版要求及差异；M3 涉及执行范围或修订选择时展示计划提议，等待页面明确选择与执行。
3. 如是对审计/公开事实的争议，保留两方证据，追问有效文件或口径。
4. 未核实用户补充以“用户提供”入库，不自动标为已验证。

会话摘要用于减少重复上下文，同时保留原消息、决策和来源引用。不能为了节省上下文丢弃尚未解决的冲突，或把“拟”总结为“已经”。

## 13.5 执行中追问与新增材料

M3 运行快照不可变：运行中新说明、新材料、事实更正、报告期或品种调整都保存到下一版输入，并显示它们尚未用于当前任务。可以解释当前状态或已有证据，但助手不能将新说明暗中注入正在执行的 run。要使用这些变化，由用户核对下一轮范围后明确执行。

停止任务不回收 run 或输入版本；新材料不得复用已停止任务占用的输入版本号。已完成的可靠解析可带来源复用。工作台保留每轮材料、要求、检查／修订范围、来源报告、状态及成果的快照，页面恢复准确关联版本。新结果通过任务卡关联左侧准确报告，区分本轮重核、沿用原报告及实际未完成；用户回看历史报告时不强制替换，提供准确的新结果入口，不给旧报告贴新版本标识。系统断线或 worker 恢复沿用原任务和锁定快照，不当作用户重新执行；关闭页面不取消任务。

M4运行中新材料、要求、期间、品种和成果范围保存到下一任务草稿，旧hash不变；“准备新任务”打开已有草稿，不清空。仅解释既有固定输入术语且不改证据／目标／范围的澄清可作为附加clarification事件继续原run。缺资料最终不可交付则失败释放，可靠解析可带版本复用；补资料只保存，明确继续生成建立新任务，不追补失败费用。

同项目更新、复核、修订和材料生成执行互斥，跨话题采用该项目成果继承项目锁。活跃任务期间保留请求／草稿，无自动排队；完成后再次明确执行。系统恢复使用原run／调用／账务，不以新任务替代恢复。

M1 `trial_limit` 是后台自动恢复的系统暂停：只在既有同页任务状态区提示实际原因，右侧补充位置保留；不把普通补充或刷新解释为再次执行，不因试用限制要求手动重建任务。此运行状态展示不代表消息/回复持久化及多轮语义已实现。

不要把运行恢复与用户更改范围都称为“重试”，接口必须区分。系统恢复沿用原任务及其账务规则；历史M3免费任务按原协议恢复，新业务任务依10/06积分决定预留及结算，不追补旧账。

## 13.6 回答和工具输出

专业回答优先结论或无法判断原因，再列依据。财务答案用确定性计算列公式、输入、单位、期间、主体／口径、结果和出处；规则答案列有效版本、生效日、适用市场／范围及官方原文。公开查询区分成功、无结果、未执行和失败，列主体匹配、目标截至日、覆盖及实际查询时间；未执行明确无实际查询时点，无结果不等于不存在风险。不存在来源时不编法条／URL／页码。

引用要能够定位，不以模型生成的 URL 或虚假页码冒充来源。官方原文、供应商返回、上传文件、用户补充、模型推断使用不同来源类型。模型的推断不可展示为数据库原始结论。

工具调用通过允许清单，界面只显示“读取材料/核对数据/查询公开信息”等业务进度，不展示隐藏推理、内部系统提示或供应商密钥。流式输出中断不标记成功，保存可恢复状态并避免重复模型调用；M4 同时遵循未交付不能按成功结算的既有要求。

统一任务时间线展示同run实际阶段与服务端白名单摘要；工作区“正在制作”显示固定输入，右侧显示执行过程。无细分事件显示真实状态，不模拟百分比或将模型自述当工具证据。原始CLI日志、prompt、隐藏推理、内部路径及未知字段不得透传。已完成任务／动作折叠摘要，执行中可见，输入框易达，回看不抢滚动。

制作标签在主artifact可读后原位成为正文；正读旧报告／文件时开始或完成不抢切。正文／说明／Word变体绑定不同真实artifact，同轮双Word同一版本。来源与结果在工作区打开，同成果定位原标签。预览失败保留下载及重载，不重跑或改成生成失败；关标签不取消任务。

QA 会话可以导出文本；正式 Word 文书遵循对应文种规范。M3 助手中的起草或说明不能代替经明确执行且通过交付检查的修订版／清洁版；保留原报告和修订来源，Word／WPS 检查按第 06 章。M4 已有回答另存／下载免费。

## 13.8 Codex CLI 与实施验收
