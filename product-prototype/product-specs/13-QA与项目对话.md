# 13 QA 问答与项目对话

> 当前 M1 范围（2026-10-01）：统一编制入口；原募集书选填，上传时填写原稿市场／品种、与目标企业的关系及报告期；目标信息独立保存；现有对话区改为补充要求；材料和对应知识 MD 直接交 worker。保留修订版和清洁版，M2 复用输入计费。以[当前决定与统一验收](../../docs/product-decisions/2026-10-01-unified-prospectus-authoring.md)为准；下列旧日期工程记录不表示新流程已实现。

交付阶段：M1 更新项目改为补充要求区一行“本次更新的补充要求”，无多轮聊天、发送按钮或助手追问；保存、输入锁和旧用户要求兼容见第 05 章。以下多轮行为适用于 M3 复核及 M4 独立 QA/材料生成，不是 M1/M2 更新的发布前置。积分结算自 M2 启用，共享上下文隔离与工具安全要求从 M1 执行。

## 13.1 两个入口、同一任务能力

CHAT-01：独立 QA 适合债券专业问题、材料解读、财务分析、公开查询和轻量起草；项目右侧对话服务当前项目的补充信息、解释、追问与改稿。两者复用身份、事实、证据、工具和积分服务，但各有明确上下文范围。

QA 首页展示输入框、附件、可选关联项目、最近会话和少量真实示例。Web 不默认读取全部云项目，M5 不默认读取全部本机文件；仅用户选择的附件与项目进入可用上下文。项目对话顶部显示当前项目、所用材料/成果版本和正在执行的任务。

用户不需要编写专业提示词。可直接说“授信总额 50 亿元，已用 20 亿元，截至 6 月末”或“把偿债分析写得更简洁”。系统追问年份、币种等必要信息，不把字段缺失隐藏起来。

## 13.2 支持范围

| 意图 | 能力与交付 |
|---|---|
| 专业知识问答 | 概念、发行规则、会计/财务解释；区分一般解释与适用法规结论 |
| 项目材料解读 | 定位原文、解释指标、列资料缺口，附文件与位置 |
| 财务分析 | 明确期间口径后计算，返回公式、输入来源、结果及限制 |
| 公开查询 | 按已授权供应商/官方信息查询，列主体、日期、来源与覆盖 |
| 轻量起草 | 段落、说明、短函、措辞调整，保持事实依据 |
| 文书执行 | 明确要求全文更新/复核/生成某文书时路由到对应执行任务 |
| 产品帮助 | 余额、状态、导航、规则说明，免费 |

首发不扩展为通用电脑自动化、Excel/PPT 全功能代理、自动发邮件或投资交易。超出任务范围给出准确能力说明，不以泛化“深度思考中”占用收费任务。

## 13.3 发送、保存和执行的语义

CHAT-02：对话中的“发送”是用户请求执行本轮意图，不是单纯按字数计费。系统分类成本由平台承担，收费依据是实际任务。

| 用户消息 | 行为 | 计费 |
|---|---|---|
| “补充：公司授信总额为……” | 保存为用户提供的事实，追问必要时点/单位，显示已记录 | 保存及纯澄清免费 |
| “请解释为什么这一项有差异” | 基于证据进行专业回答 | QA 对应档位；平台自身错误修正免费 |
| “把这些信息用于下一版” | 更新下一版需求，尚未要求生成时说明已保存 | 不因编辑资料直接收费 |
| “按这些信息重新生成报告” | 明确执行新文书版本，后台冻结后启动 | 对应文书任务；不再弹报价确认 |
| “怎么更新募集书” | 回答方法 | 普通 QA，不启动全文更新 |
| “请把这个项目全文更新到 2026 年 6 月” | 校验项目及材料，路由 update | 按更新任务，不伪装成廉价短问答 |
| “继续” | 结合当前明确待继续事项；有歧义则澄清 | 不自动启动未知范围 |

右侧区可有“保存补充”和主任务按钮；用户明确发送执行请求时不强迫再点第二个价格确认。响应中展示已创建的任务卡及状态，避免用户不知已开始执行。

开始任务前的必要追问、无结果检索、纯拒答、客服问题不扣任务积分。问答有效答复中合理的不确定性与纯拒答不同：有证据的分析即使结论为“不能确定”，仍可能是完成了用户的分析请求。

2026-09-27 工程切片：项目页已增加独立的输入版本、预检及显式全文执行按钮；普通草稿补充不自动执行，改内容后保存新输入，旧 run 不变。这里只打通已有执行 API 的浏览器入口，未实现逐轮消息、真实助手回复、流式中断恢复或消息到 prompt/job 的持久关联，不能作为 CHAT-A01/连续三轮授信示例已通过的证据。

## 13.4 上下文与冲突管理

消息对象保留 role、content、attachments、project_id、artifact_version、intent、fact_refs、created_at 和修订关系。编辑/删除先前说明只改变后续上下文，不改写已运行任务快照或账单。

2026-09-29 工程切片边界：`POST /api/v1/projects/{project_id}/messages` 只保存已提交用户消息和受控材料版本，显式返回未分类/仅保存，不产出助手回复或执行任务；`GET .../messages` 分页返回本人项目的最新修订，`GET .../messages/{message_id}/versions/{version}` 可回查原文与来源。旧版与新版本均保留受控正文和访问审计，消息集合 pin 的 version 在修订时递增、hash 改变、原会话顺序不变；后续 input revision 需锁住精确引用。右侧真实模型多轮回复、意图路由、附件替换操作、流式中断及账务/用量仍未接线。

2026-09-29 浏览器切片：更新项目右侧已接上述 **user-only** 消息页，保存/原版本回查/冲突重读均保持用户输入可见；刷新和重新登录恢复已确认保存的消息。执行前读取当前完整消息集合 ref（包括未翻页的 ID），input revision 同时带全部 `requirement_message_ids` 和精确 ref；运行中补充产生后继输入，不改写已锁定 run。创建项目之前的 composer 尚未发送，临时失败用同一 request ID 重试。旧版 `supplementary_notes` 保留在原草稿并明确标记，未自动迁移为已提交消息。该切片不完成本节的助手追问、消息附件替换和显式自然语言执行路由。

新事实与结构化表单冲突时：

1. 先区分新安排与旧事实、不同期间与不同主体。
2. 如用户明确改变目标安排，更新下一版草稿并记录差异。
3. 如是对审计/公开事实的争议，保留两方证据，追问有效文件或口径。
4. 未核实用户补充以“用户提供”入库，不自动标为已验证。

会话摘要用于减少重复上下文，同时保留原消息、决策和来源引用。不能为了节省上下文丢弃尚未解决的冲突，或把“拟”总结为“已经”。

## 13.5 执行中追问与新增材料

同一输入范围内的术语澄清可作为附加 clarification 事件继续原 run，冻结不变，并保存用户答复；不能重写原输入哈希。

用户上传新材料、变更报告期、改变目标品种或要求另一套成果时，创建新输入版本，需要用户明确再次执行。当前任务若因原资料缺失无法交付，应结束为缺材料失败并释放；已经完成的可靠解析可复用。界面可提示“资料已补齐，点击继续生成”，该点击建立新任务，不倒收失败成本。

M1 `trial_limit` 是后台自动恢复的系统暂停：只在既有同页任务状态区提示实际原因，右侧补充位置保留；不把普通补充或刷新解释为再次执行，不因试用限制要求手动重建任务。此运行状态展示不代表消息/回复持久化及多轮语义已实现。

纯系统暂停/断线恢复沿用同一任务和冻结。不要把运行恢复与用户更改范围都称为“重试”，接口必须区分。

## 13.6 回答和工具输出

专业回答优先给结论或无法判断的原因，再给简要依据。财务答案列数值、单位、期间、口径、计算和出处；规则答案列适用市场、版本、生效日期、条款与链接；查询答案列数据截至日及实际查询时间。

引用要能够定位，不以模型生成的 URL 或虚假页码冒充来源。官方原文、供应商返回、上传文件、用户补充、模型推断使用不同来源类型。模型的推断不可展示为数据库原始结论。

工具调用通过允许清单，界面只显示“读取材料/核对数据/查询公开信息”等业务进度，不展示隐藏推理、内部系统提示或供应商密钥。流式输出中断不标记成功，避免收费后只留下半段文本。

QA 会话可以导出文本；明确请求生成正式 Word 文书时遵循对应文种规范。已有回答另存/下载免费。

## 13.7 计费与验收

本轮按实际意图独立分类 Q00–Q07，不能继承上一轮最高系数。对话关联大公募项目不代表“下载在哪里”也应加大公募系数；特殊因素仅作用于实际相关工作。

| ID | 场景 | 预期 |
|---|---|---|
| CHAT-A01 | 补充授信但未要求生成 | 保存事实/追问，成果不自动被替换 |
| CHAT-A02 | 明确要求生成法律意见书 | 路由 G03，同一次发送启动，无报价页 |
| CHAT-A03 | 只是询问更新方法 | 不建立完整更新任务 |
| CHAT-A04 | 深度研究后追问一个数的来源 | 本轮按定位任务计价，不继承 Q07 |
| CHAT-A05 | 补新材料并要求继续 | 新快照和新任务，解析复用，旧失败不补收费 |
| CHAT-A06 | 其他项目文件含相关事实 | 未关联/授权时不能跨项目读取 |
| CHAT-A07 | 模型错误引用需修正 | 修复免费，记录 correction_of_run_id |
| CHAT-A08 | 文件内有指挥模型的文字 | 作为来源数据处理，不改变用户任务 |
