# 17 验收测试与实施路线

## 17.1 验收层次

验收分为交互、工程正确性、真实接入、专业成果四层。页面能点击和模拟模型通过，只覆盖前两层的部分内容。每个功能都要在实际部署的 Web 版本（M1–M4）或安装包（M5）、授权样本和真实服务上保留可复现结果。

本章数字为建议验收目标，不是已实现指标，也不是用户承诺的上线日期。正式验收由产品、工程和行业负责人签字记录。

- 完整旧稿、不完整旧稿、用户相似稿、自动匹配无旧稿、无匹配。

## 17.5 专业质量门槛

关键事实、主体、金额、期间、单位、发行对象和条款在金标准验收集上不得出现未提示的确定性错误。任何跨用户数据泄漏、虚构引用、无依据签发、漏掉已知重大负面事实、错误现金扣款均为发布阻断问题。

可程序验证的数值用确定性复算，而不是另一个模型“觉得正确”。所有结果中的关键数据与规则结论应有可回查来源；无法验证时以待确认/未覆盖处理，不能靠高置信度文字通过验收。

建议对专家一致标注的问题统计精确率、召回率、严重问题漏报率、误报率和来源有效率；先定义分母和争议项排除规则。初始建议目标：明确问题精确率及召回率各 ≥95%，关键 P1 不漏报；这些是测试门槛建议，不能替代每个细分品种的验收。

OCR 统计字段级正确率与“错误但未提示”的数量，不能仅看平均字符准确率。表格中关键数值错误未被提示为 0，允许通过待确认机制安全失败；同时监测过量待确认以防产品不可用。

Word 检查包括实际打开、表格可编辑、章节完整、字体回退、页面布局、页眉、目录、批注锚点、修订关系、长表跨页、图片、特殊符号。存在更新版式变化应在交付说明中反映。

## 17.6 性能与稳定性建议目标

Web 建议基准为当前稳定版 Edge/Chrome，记录浏览器版本、部署资源、工作进程并发与网络条件；至少覆盖桌面常用分辨率和窄屏。M5 建议基准环境为 Windows 11 x64、4 核以上、16 GB 内存、SSD；网络和供应商条件单独记录。

| 项目 | 初始目标 |
|---|---|
| 常用表单/列表交互 | P95 ≤200ms，长任务不得阻塞 UI；网络读取耗时另统计 |
| 自动保存 | 停止输入后约 1 秒发起保存，Web 服务端/M5 本地确认后才显示已保存 |
| 执行请求反馈 | 正常连接下 5 秒内显示准备/排队/失败状态，不要求此时已完成解析 |
| 长任务状态 | 至少每 30 秒有真实阶段/心跳，耗时长可显示等待，不伪造进度 |
| 任务恢复 | 重启后先在 10 秒内显示已保存状态，再异步对账恢复 |
| 余额/支付一致性 | 金额和积分错误为 0；重复事件压测保持不变量 |
| 大文件 | 按容量目标压测峰值内存、磁盘空间和取消，不能整文件多次驻留内存 |

全文任务耗时、OCR 每页速度、模型首 token 时间需基于真实服务测量后给出 P50/P95；在此之前不写“几分钟必完成”。成本校准记录 E、B、A、P、失败率、超预留平台损失、误拦截率和客服成本。
