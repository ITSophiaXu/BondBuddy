# 17 验收测试与实施路线

## 17.1 验收层次

验收分为交互、工程正确性、真实接入、专业成果四层。页面能点击和模拟模型通过，只覆盖前两层的部分内容。每个功能都要在实际安装包、授权样本和真实服务上保留可复现结果。

本章数字为建议验收目标，不是已实现指标，也不是用户承诺的上线日期。正式验收由产品、工程和行业负责人签字记录。

## 17.2 首发必须完成的范围

| 交付包 | 必须达到 | 负责人角色 |
|---|---|---|
| Windows 安装/更新/恢复 | 干净环境安装、文件隔离、进程恢复、升级回滚 | 客户端/测试 |
| 账号与钱包 | 真实短信、签名支付、并发账本、退款对账、活动幂等 | 服务端/支付/财务 |
| 材料与 OCR | 扫描表格、跨页、锚点、不确定数字与缓存 | 文档/AI/测试 |
| 首发更新/复核 | 沪深私募/小公募/大公募、PPN/MTN/CP/SCP，以及 DFI 储架安排的规则和样本 | 行业/AI |
| 五类模板 | 第 08–12 章的语义内容与相应市场适用性 | 行业/文档 |
| 多轮任务 | 补信息、追问、查询、执行、版本和免费纠错 | AI/前端/服务端 |
| 三家数据源 | 启信宝、Wind、企业预警通授权接入及真实能力验收 | 商务/数据接入 |
| 运营与支持 | 规则发布、模板版本、异常对账、数据删除与申诉 | 运营/服务端 |

大公募、DFI 储架发行和三家数据源均已明确要求，不因现有代码缺少就自动降为后续版本。若某供应商授权未完成，标为未关闭的发布条件；内部可先联调其他部分，但不能宣称全部首发范围完成。

## 17.3 测试数据集

建议首批取得授权的真实任务 30–50 个，用于端到端质量及成本校准；十个具体市场/品种组合每个至少有基础、材料复杂、边界情形样本；另须有 DFI 注册阶段与具体一期的对照样本，允许一个样本同时覆盖多个维度，但不能用一份上交所私募样本替代其他市场验收。

另建可公开或脱敏的合成测试集，覆盖：

- 完整旧稿、不完整旧稿、用户相似稿、自动匹配无旧稿、无匹配。
- N=0/1/2/3/4/更多期、保留旧年度、追溯重述、重复比较期。
- 原生 Word/PDF、清晰扫描、混合扫描、图片、跨页表、合并单元格。
- 合并/母公司、币种单位、负数、空值、不同截止日、非标准审计意见。
- 单承销商、多角色、多档品种、回拨、六类资金用途及混合用途。
- 数据源真实空记录、同名主体、授权不足、限流、中断、缓存、费用重放。
- 五类文书，摘要至少分别覆盖私募、小公募、大公募。

专业标注保留原文件哈希、期望事实/问题、来源锚点、适用规则、专家意见及争议。人工构造案例必须标 synthetic，不能宣传为真实客户验收。

## 17.4 跨模块验收用例

各功能章已给单模块验收；下表验证组合行为。

| ID | 操作/场景 | 必须观察到的结果 |
|---|---|---|
| E2E-01 | 新账号真实验证码注册 → QA → 钱包 | 赠分一次、实际结算对应回答、批次可追溯 |
| E2E-02 | 创建更新草稿 → 导入材料 → 退出重开 | 字段、文件和补充说明恢复，没有自动扣分 |
| E2E-03 | 有旧稿只新增一期 | 正确 N；正文、表格、风险及偿债数据一致 |
| E2E-04 | 同期跨市场/品种，N=0 | 改结构条款，财务保留，不虚增期数 |
| E2E-05 | 无历史稿并自动匹配 | 三业务匹配证据完整，无参考企业事实泄漏 |
| E2E-06 | 无历史且第三业务并列/无匹配 | 不随意回退；提示可处理缺口；不收费失败成果 |
| E2E-07 | 多档品种及混合资金用途 | 总额/分项、条款、风险与用途章节同步 |
| E2E-08 | 大公募更新及复核 | 独立规则命中，发行对象/条件不误用小公募 |
| E2E-09 | 同名企业的工商/债券结果 | 主体标识排除错配，来源时点可见 |
| E2E-10 | 复核发现大量明确问题 | 成功交付问题报告；不是因“有问题”失败 |
| E2E-11 | 公开核验必需接口全不可用 | 不显示完整复核已通过，不缩范围收费 |
| E2E-12 | 扫描关键数字无法辨认 | 原页位置、待确认、不确定项不直接入结论 |
| E2E-13 | 用户模板私有复用 | A 可复用；B 即使同券商也不可见 |
| E2E-14 | 生成意见类文书但无程序记录 | 不虚构现场、函证、律师签署 |
| E2E-15 | 募集书有修订删除旧数 | 生成材料只用有效正文 |
| E2E-16 | 对话补事实→明确生成新版 | 先保存，执行时创建新快照与成果 |
| E2E-17 | 用户只问“怎么更新” | 仅 QA，不启动全文任务 |
| E2E-18 | 输入与支付各重复点击 10 次 | 对应幂等域只形成一个有效执行/订单到账 |
| E2E-19 | 冻结后进程被杀/网络断开 | 对账恢复，不重收已计量请求 |
| E2E-20 | 取消与交付同时发生 | 原子终态明确，不能既释放又扣同笔 |
| E2E-21 | A 超过 B 且钱包还有余额 | 仍只扣 B，无追加确认或暗扣 |
| E2E-22 | 充值到账后旧请求仍存在 | 不自动启动，用户再次点击才执行 |
| E2E-23 | 退款申请与新任务竞争余额 | 不能重复消费同一批次 |
| E2E-24 | 结算 usage 缺失 | 成果可用、显示待对账，最终未能验证不估扣 |
| E2E-25 | 活动积分冻结跨过期与平台故障 | 本次可结算；故障释放补偿按规则 |
| E2E-26 | 账号切换、项目复制/删除、备份导入 | 资料隔离，账本不被本地导入覆盖 |
| E2E-27 | 材料中有越权命令/别家敏感信息 | 不执行命令，不复制别家事实进入交付 |
| E2E-28 | 更新包损坏、升级中断 | 校验拒绝/回滚，项目可恢复 |
| E2E-29 | 关键成果占位或 Word 损坏 | 交付检查失败，修复或释放 |
| E2E-30 | 同内容改名、跨项目复用、平台升级解析器 | 不重复向用户收既有解析费 |
| E2E-31 | 选择 DFI→保存→重开→上传→执行→关联生成 | DFI 安排贯穿上下文，计费可执行，无注册模式问卷 |
| E2E-32 | DFI 覆盖 MTN/CP/SCP，本期金额期限未定 | 注册阶段不造数、不重复收费；一期文件按实际工具核对 |
| E2E-33 | DFI 文书引用复杂工具/缺现行规则 | 不绕过复杂工具能力门槛，不把未覆盖写成合规通过 |

## 17.5 专业质量门槛

关键事实、主体、金额、期间、单位、发行对象和条款在金标准验收集上不得出现未提示的确定性错误。任何跨用户数据泄漏、虚构引用、无依据签发、漏掉已知重大负面事实、错误现金扣款均为发布阻断问题。

可程序验证的数值用确定性复算，而不是另一个模型“觉得正确”。所有结果中的关键数据与规则结论应有可回查来源；无法验证时以待确认/未覆盖处理，不能靠高置信度文字通过验收。

建议对专家一致标注的问题统计精确率、召回率、严重问题漏报率、误报率和来源有效率；先定义分母和争议项排除规则。初始建议目标：明确问题精确率及召回率各 ≥95%，关键 P1 不漏报；这些是测试门槛建议，不能替代每个细分品种的验收。

OCR 统计字段级正确率与“错误但未提示”的数量，不能仅看平均字符准确率。表格中关键数值错误未被提示为 0，允许通过待确认机制安全失败；同时监测过量待确认以防产品不可用。

Word 检查包括实际打开、表格可编辑、章节完整、字体回退、页面布局、页眉、目录、批注锚点、修订关系、长表跨页、图片、特殊符号。存在更新版式变化应在交付说明中反映。

## 17.6 性能与稳定性建议目标

建议基准环境：Windows 11 x64、4 核以上、16 GB 内存、SSD；网络和供应商条件单独记录。

| 项目 | 初始目标 |
|---|---|
| 常用表单/列表本地交互 | P95 ≤200ms，长任务不得阻塞 UI |
| 自动保存 | 停止输入后约 1 秒落盘，有明确保存/失败状态 |
| 执行请求反馈 | 正常连接下 5 秒内显示准备/排队/失败状态，不要求此时已完成解析 |
| 长任务状态 | 至少每 30 秒有真实阶段/心跳，耗时长可显示等待，不伪造进度 |
| 任务恢复 | 重启后先在 10 秒内显示已保存状态，再异步对账恢复 |
| 余额/支付一致性 | 金额和积分错误为 0；重复事件压测保持不变量 |
| 大文件 | 按容量目标压测峰值内存、磁盘空间和取消，不能整文件多次驻留内存 |

全文任务耗时、OCR 每页速度、模型首 token 时间需基于真实服务测量后给出 P50/P95；在此之前不写“几分钟必完成”。成本校准记录 E、B、A、P、失败率、超预留平台损失、误拦截率和客服成本。

## 17.7 开发顺序与依赖

| 阶段 | 工作包 | 退出条件 |
|---|---|---|
| M0 基线冻结 | 需求/接口、模型协议验证、供应商采购、规则清单与样本授权 | 模型与接入路径可行，缺口有负责人 |
| M1 通用底座 | Windows 壳、本地存储/恢复、真实账号、云钱包/支付、材料/OCR | 安全隔离与账务不变量通过 |
| M2 专业流水线 | 事实证据、规则引擎、全文更新、三维复核、十类具体品种及 DFI 适用包 | 每个品种有真实样本和专业验收 |
| M3 对话与材料 | 多轮路由、五模板、私有库、版本迭代 | 生成和对话用例通过，事实不跨版本污染 |
| M4 接入与商业校准 | 三家数据源真实联调、真实模型用量、影子账单、退款/活动 | 成本可核对，未将演示数据计为真款 |
| M5 发布 | 安装包、性能、灾难恢复、支持文案、规则与模板签署验收 | 发布阻断清零，协议与运营流程到位 |

阶段可并行推进工程，但不能先上线大公募再用小公募规则兜底。首发范围和商业收费开通应按实际验收状态控制。
