# v6 用户行为场景增补：从用户目标到恢复结果

设计修订：v6.1，2026-10-09。原[79组工程用例](test-plan.md)保持稳定，本文件把它们串成23张可执行用户任务卡；不是增加23个独立发布门，也不要求重复真实生成。本轮只设计，场景结果均not_run，U未批准。

**执行人怎么用：**Agent按用户路径点击真实页面，并独立核对run/输入/文件/账本。Human先只读“用户任务”和业务资料，自行尝试代表旅程；主持人用下面的步骤复现或必要时辅助，记录辅助次数，不能把照脚本点完当无辅导成功。Human判断理解、流畅、关键事实与真实Word/WPS；机械步骤不要求每卡由Human重复执行。

Agent场景执行可用浏览器自动化逐屏填写/点击，控制offline、丢某个响应、关闭整个browser context，再用新context登录回同项目；需要查真实服务端状态/账本，不能仅修改页面变量模拟任务继续。隔离环境的合成worker/模型用于可控竞争与恢复，证据标synthetic；真实业务闭环仍按U-B用授权材料、实际模型和真实成果，不能由合成回答代替。没有产品实测的场景继续not_run，本次没有新增自动化产品测试实现。

**源码边界：**场景核对参考为[develop 55941dc](https://github.com/ITSophiaXu/BondBuddy/tree/55941dc7f42aa3a87e2cae0ca933502f69e2aac3)；10月9日新增#618助手UI、#620固定QA价、#626项目链接取消后的材料恢复。#626只修复带导航参数的项目页面更新，不增加主动暂停/更换原任务输入的协议，也不改变积分政策；其定向回归纳入UX-A06。原v6源码/线上调查仍为历史参考，执行前冻结实际运行版/flags/price version。当前新专业QA在有效运营发布价下为60；旧已提交按量QA仍按原锁定价。v6旧“capped/成本配置/60未批准”断言只适用于对应历史协议，不能套给已启用的新固定价QA。见[固定问答价决定](https://github.com/ITSophiaXu/BondBuddy/blob/55941dc7f42aa3a87e2cae0ca933502f69e2aac3/docs/product-decisions/2026-10-09-fixed-qa-price.md)。迁移0101不自动发布生产价格，未核实线上配置不得声明已收费60。

在baseline/U报告的执行副本里填实际candidate、0101/有效价格receipt，并把本轮启用的新QA子例链接到UX-N06及59/60工程边界；旧BB-030/031/056/068及U-E的cap/成本配置断言标明legacy适用范围。不能只修改UI文字却继续拿旧按量oracle给新固定价判pass。

**暂停与中断不是同一回事：**

- 客户端断网/关页/关机：已由服务端接受的run继续，重新登录查看同run；未完成上传或未保存本地草稿不承诺自动恢复。
- 系统paused：按实际reason恢复同run、同输入；不是允许用户换掉原snapshot。
- 用户停止/cancel：终止本轮，不能把它叫可继续的pause；与成功竞争以实际唯一终态/结算为准。
- 用户主动暂停→新增材料→原任务继续：UX-A03业务目标已确认，当前缺入口/续做协议，积分尚缺设计。现有“下一草稿”或“停止后新任务”只能记替代路径，不能算该目标通过。

| 选择 | 应执行什么 |

## 中断点决定恢复预期

| 中断点 | 用户回来后的正确结果 | 钱和任务 |
|---|---|---|
| 本地草稿/上传途中 | 显示真实保存状态，必要时重选文件重传；已保存文件保留 | 未开始业务任务时无run/hold |
| 100%后complete回执未知 | 查原upload key/材料回执再完成或重试 | 不伪造保存，不另开业务run |
| execute响应丢失 | 查原key/服务端事实：已接受回原run，未接受同key合法重试 | 一个run/预留，不重已完成call |
| queued/running时客户端离开 | 服务端继续；重登后看同run实际进度/成果 | 原输入/价格固定，预留/结算按实际状态 |
| 系统paused/供应商待核 | 真实reason、按该reason恢复或支持处理 | 不盲重发、不靠新材料修改旧输入，不假释放待核账务 |
| 已交付但下载失败 | 同artifact重新授权下载 | 不重新生成或收费 |
| 用户cancel恰逢成功 | 唯一合法终态可追踪 | 一次合法finalize；成功与有效取消不能同时结算退款 |

same run不表示永远成功，新run不表示可以自动重新下单。记录实际状态、输入版本、完成调用、成果hash及账本；浏览器显示“卡住”不能代替服务端观察。

## 正常场景

### UX-N01 按流程更新已有募集书

**用户任务：**我是业务人员，需要用本期材料更新已有募集书，拿到可交付的修订版和清洁版。

**前置：**已授权原稿与本期报表/附注；源发行人、源市场/期间和目标确认独立；采用已核对的一期固定价环境时余额至少17,900，否则登记实际启用模式。

**用户动作与恢复：**

1. 登录→从工作台进入募集书编制/更新→创建或打开本人项目，填目标发行人、市场/品种、目标期间。
2. 上传原稿、本期报表和支持材料，逐份等“保存完成”，填写每份原稿必填源信息；选定本轮材料，保存补充要求。
3. 核对目标、材料清单与服务端报价；保存草稿不应启动。明确确认开始，记下进度页对应任务。
4. 等待任务；离开到工作台，再从当前项目的进行中入口返回。
5. 任务成功后下载修订版和清洁版；打开两份文件，再回项目查看本轮输入、成果与费用。

**Pass criteria / 设计缺口：**

- 本人项目/本轮输入/当前run相互对应，完整闭环没有死路；准备、等待、下载的可见状态准确。
- 原稿与目标事实不混用，下载为本轮两份非空Word；专业关键事实与真实客户端预检交Human。
- 仅一个run和一次合法预留；一期启用价为17,900时成功只扣17,900一次，试用模式按其实际协议核对。

**分工：**Agent独立；Human按代表旅程抽查体验。Human专业/真实客户端只按U-H或R适用范围签认，Agent机械通过不替代Human。

**关联：**BB-003 / BB-006 / BB-008 / BB-013 / BB-014 / BB-015 / BB-039 / BB-041 / BB-071 / BB-074；U-B / U-D / U-E / U-F。**选择：**U：开放M1更新时必选；复用既有M1真实代表run。**设计状态：**`current_contract`。

### UX-N02 没有历史稿也能新编

**用户任务：**我没有旧募集书，希望根据目标企业资料编制第一版。

**前置：**本轮开放无原稿新编；目标企业授权资料充分，固定价新编环境余额至少159,900。

**用户动作与恢复：**

1. 选择编制入口，填写目标发行人/市场/品种/报告期，不上传历史/参考募集书。
2. 上传目标企业报表和支持资料，等保存完成并说明编制要求。
3. 核对新编分类与实际报价，明确确认后查看进度。
4. 完成后下载修订版/清洁版并检查首稿说明，返回项目查看版本与费用。

**Pass criteria / 设计缺口：**

- 无原稿本身不阻断已开放的新编路径；企业事实必须来自目标资料。
- 新编不得伪造相对历史稿的修订；两份Word可用，事实预检由Human判断。
- 固定价启用时按新编159,900一次结算；不误套一期17,900。

**分工：**Agent独立；Human按代表旅程抽查体验。Human专业/真实客户端只按U-H或R适用范围签认，Agent机械通过不替代Human。

**关联：**BB-006 / BB-013 / BB-014 / BB-015 / BB-039 / BB-074；U-B / U-D / U-E。**选择：**U：新编在试用范围且与更新使用不同生产路径时补代表例，否则按scope登记。**设计状态：**`current_contract`。

### UX-N03 复核完成后补资料再核一轮

**用户任务：**我要复核一份募集书，读完报告后用补充资料核对未解决的问题。

**前置：**开放M3；授权募集书/支持资料；已核对收费flag与报告协议。

**用户动作与恢复：**

1. 创建本人复核项目，上传准确募集书和支持材料，保存本轮要求。
2. 明确开始复核，查看进度；从工作台回来仍进入同一任务。
3. 成功后下载本轮报告Word，记录版本，阅读待核事项。
4. 在同项目补充或更正资料，保存；确认此时旧报告仍可读取，未自动启动新任务。
5. 明确开始下一轮复核，完成后分别查看旧/新报告和对应输入。

**Pass criteria / 设计缺口：**

- 首轮真实报告可下载；每轮新run固定各自材料，旧报告及账务保留。
- 补料和保存不执行；新一轮必须明确开始并按实际M3开关/报价结算。
- 文件报告没有结构化finding时执行再次完整复核；仅实际存在finding入口时才选差异重核，不假设支持。

**分工：**Agent独立；Human按代表旅程抽查体验。Human专业/真实客户端只按U-H或R适用范围签认，Agent机械通过不替代Human。

**关联：**BB-016 / BB-018 / BB-039 / BB-041 / BB-071；U-B / U-D / U-E / U-F。**选择：**U：首轮复核必选；补料重核在试用确实提供该能力或相关diff时选，否则E/R。**设计状态：**`current_contract`。

### UX-N04 用材料表单生成一份业务文书

**用户任务：**我要生成指定业务文书，并拿到正文和编制说明。

**前置：**按开放文种参数执行：立项/核查/法律/私募摘要；每种一个授权市场；立项有本人券商模板，摘要有准确募集书源。已启用4,500固定价，余额足够。

**用户动作与恢复：**

1. 从材料生成创建本人项目，选择文种，再选择支持的交易所。
2. 选择准确来源和版本，上传本人模板（立项必备）及支持资料，等保存完成，填可选要求。
3. 核对页面当前文种/市场/来源；只点击一次生成，观察保存→提交→进度反馈。
4. 任务完成后下载正文Word和独立说明Word，检查文件名/内容属于选定文种。
5. 返回同项目查看输入、两份成果与积分明细。

**Pass criteria / 设计缺口：**

- 材料表单无需额外第二次报价确认；一个明确动作只启动一个run。
- 准确原件/知识/模板被固定到本轮；正文与说明不可混成M1修订/清洁稿。
- 两份真实Word存储/hash回读登记后才一次扣4,500；缺任一交付不按成功结算。
- 四文种都开放则各跑一次，共4个代表组合；U不要求沪深8组合，专业和客户端复用对应成果。

**分工：**Agent独立；Human按代表旅程抽查体验。Human专业/真实客户端只按U-H或R适用范围签认，Agent机械通过不替代Human。

**关联：**BB-025 / BB-027 / BB-028 / BB-029 / BB-033 / BB-035 / BB-036 / BB-037 / BB-039 / BB-052 / BB-056；U-B / U-D / U-E。**选择：**U：每个开放文种一个授权市场；共享成果供Human预检。**设计状态：**`current_contract`。

### UX-N05 选择准确成果继续修改

**用户任务：**我想基于刚完成的准确版本改内容，保留旧稿方便比较。

**前置：**已存在本人可下载成果；当前部署开放对应续改入口。M1助手续改需助手已部署；M4仅接受支持的全文新版本。

**用户动作与恢复：**

3. 通过对应入口明确确认执行；如有助手任务卡，先核对并确认任务卡。
4. 完成后下载新成果，同时再次打开旧版；确认二者来源和版本关系正确。

**Pass criteria / 设计缺口：**

- M1纯内容、不增年度的续改按interim17,900分类，不能误new159,900；M4全文新版本按4,500，精确局部改稿范围如实说明。
- 保存要求/聊天建议不自动执行；新run使用新输入，读取旧成果不再扣费。

**分工：**Agent独立；Human按代表旅程抽查体验。Human专业/真实客户端只按U-H或R适用范围签认，Agent机械通过不替代Human。

**关联：**BB-023 / BB-038 / BB-040 / BB-061 / BB-064 / BB-065 / BB-066 / BB-067；U-D / U-E。**选择：**U：仅续改/助手已部署并纳入scope时选；否则E/R。**设计状态：**`conditional_deployment`。

### UX-N06 先问产品帮助，再确认一个专业问题

**用户任务：**我先问如何使用，再提交一个独立业务问题，希望理解何时收费。

**前置：**助手已部署；先核对0101和可信运营发布的有效60积分price version。迁移本身不种生产价，不能据源码推定线上已启用。

**缺陷发现线索：**源码[QA分类](https://github.com/ITSophiaXu/BondBuddy/blob/55941dc7f42aa3a87e2cae0ca933502f69e2aac3/apps/api/src/m4-workspace.ts#L177)的免费帮助匹配可能漏掉自然说法“怎么下载已生成文件”，在空引用context下落入专业QA。保留该真实说法观察是否误收费；不要改成刚好命中关键词的句子来让测试通过。这是源码疑点，尚无运行复现；实际报价/账务错才记录对应缺陷。

**用户动作与恢复：**

2. 输入一个明确的独立专业问题，首次提交后核对费用与条款。
3. 确认本次问题固定60积分后再次明确发送；完成后回看持久保存的答案和费用。
4. 刷新/回看同一次答案，再提出一个新的专业问题并核对新的报价确认。

**Pass criteria / 设计缺口：**

- 产品帮助、必要任务澄清免费；不会因普通讨论启动文书任务。
- 采用已发布新固定价时确认前无付费run/预留，确认后预留60，答案持久交付成功后一次扣60；失败/有效取消全释放。
- 回看和同请求重试不重扣；新独立专业问题重新确认。unknown用量如实留审计，不阻固定价已交付答案合法结算。
- 未部署/未发布价时登记不适用或配置阻碍，验证实际禁用提示；旧已提交按量run保留原锁定价，不套新60。

**分工：**Agent独立；Human按代表旅程抽查体验。Human专业/真实客户端只按U-H或R适用范围签认，Agent机械通过不替代Human。

**关联：**BB-024 / BB-030 / BB-031 / BB-044 / BB-056 / BB-058 / BB-061 / BB-064 / BB-068；U-B / U-D / U-E。**选择：**U：可见免费帮助分支必选；固定60正例仅实际启用且纳入scope时选。**设计状态：**`conditional_deployment`。

## 异常场景

### UX-A01 漏填上传原稿的源信息

**用户任务：**我上传了参考募集书，但忘了填原企业或原报告期。

**前置：**提交前原稿源信息必填策略有效；故意漏一项，其他资料正确。

**用户动作与恢复：**

1. 上传原稿并等保存完成，保留一项必填源信息为空。
2. 尝试进入下一步或开始编制，阅读错误提示。
3. 补全所指字段，保留其他已填内容，重新核对并明确开始。

**Pass criteria / 设计缺口：**

- 指出具体文件和缺失字段，焦点/输入/已保存文件不丢；未补齐时不创建本次业务run、不预留。

- 未保存的纯本地草稿和未完成上传不等同持久化任务，不能要求从新设备自动恢复本地File。
- Agent证据标明“浏览器进程退出模拟”；不得写成真实电脑断电通过。Human真实关机/睡眠/换网络是目标用户环境的补充验证，不新增U全矩阵门。

**分工：**Agent独立；Human按代表旅程抽查体验。Human专业/真实客户端只按U-H或R适用范围签认，Agent机械通过不替代Human。

**关联：**BB-003 / BB-040 / BB-041 / BB-043 / BB-048 / BB-071；U-F。**选择：**U：重登恢复必选，Agent模拟足够；Human真实设备按用户环境风险触发。**设计状态：**`current_contract`。

### UX-C06 成功后预览或下载断网

**用户任务：**任务已经成功，但下载断了；我只想重新拿文件。

**前置：**同run已成功且完整成果可用；在预览或下载中断客户端网络。

**用户动作与恢复：**

1. 从已完成成果点击预览或下载，途中断网。
2. 恢复网络，回到该成果版本并重新下载，不点击生成/续改。
3. 打开完整文件，对照已登记artifact/version/hash，查看费用。

**Pass criteria / 设计缺口：**

- 预览/下载失败不把已成功任务改失败或新建run；重新下载使用同成果。
- 不会再次模型生成/预留/扣费，文件归属和hash一致；下载链接过期可重新授权获取。

**分工：**Agent独立；Human按代表旅程抽查体验。Human专业/真实客户端只按U-H或R适用范围签认，Agent机械通过不替代Human。

**关联：**BB-039 / BB-040 / BB-041 / BB-042 / BB-056；U-B / U-F。**选择：**U：下载恢复复用已有真实成果，零额外模型调用。**设计状态：**`current_contract`。

### UX-C07 后台卡住/恢复后用户继续看结果

**用户任务：**页面进度很久不变；我重新打开后能知道任务在等待什么、是否可以继续。

**前置：**隔离环境注入一处已完成call后的worker重启/检查点恢复；另选公开可见paused reason。禁止在生产崩worker。

**用户动作与恢复：**

1. 正常启动任务，在受控停滞/暂停时查看页面原因，不反复点开始。
2. 刷新或重新登录回同任务，按真实提示等待处理条件恢复或联系支持。
3. 仅当该reason有实际用户恢复入口且条件已解决时，点击对应重新检查/继续。
4. 后台恢复后看终态/下载/费用；如明确需要新输入则走支持的新任务流程。

**Pass criteria / 设计缺口：**

- 已有持久call/checkpoint不重复调用；不可判定供应商结果时先待核，不盲重发。
- 按现有系统paused/旧协议恢复同run须维持固定输入和原预留；resume不能使新上传材料进入旧snapshot，不能任意恢复terminal failed。该机械guard不限制UX-A03已确认的新暂停补料业务目标，后者必须设计版本化新协议。
- pending provider reconciliation/settlement_pending不接受普通公共resume；其他reason按实际guard及UI分别判断。
- 后台重启与客户端断网是不同故障，用户反馈/Agent内部证据分别保留。

**分工：**Agent独立；Human按代表旅程抽查体验。Human专业/真实客户端只按U-H或R适用范围签认，Agent机械通过不替代Human。

**关联：**BB-043 / BB-046 / BB-047 / BB-048 / BB-079；U-F。**选择：**U：关键checkpoint和暂停guard工程代表例；所有reason矩阵留E/R。**设计状态：**`current_contract`。

### UX-C08 两个标签页修改同一个项目

**用户任务：**我同时开着两个页面，旧页面不能覆盖新版资料或误用旧报价执行。

**前置：**两个同owner浏览器页，同项目当前草稿revision一致；未开始或有当前run分别按能力选择。

**用户动作与恢复：**

1. 页面A/B同时打开项目；在A更换材料/要求并保存。
2. 在B继续编辑或尝试用之前的报价/卡提交，阅读冲突反馈。
3. 在B核对本地与服务器版本，显式选择实际支持的同步/重新prepare动作。
4. 只有确认当前准确输入后执行；回看当前run和输入。

**Pass criteria / 设计缺口：**

- 旧页面保存冲突不静默覆盖，保留本地待核内容；stale quote/card不能执行。
- 已运行snapshot不因第二页修改而改变；每个有效key只一个run/hold。
- 多个标签只共享同项目授权数据，不能将旧卡切到其他项目继续执行。

**分工：**Agent独立；Human按代表旅程抽查体验。Human专业/真实客户端只按U-H或R适用范围签认，Agent机械通过不替代Human。

**关联：**BB-021 / BB-022 / BB-026 / BB-044 / BB-065 / BB-066 / BB-072；U-C / U-D。**选择：**U：输入/确认stale机制按实际入口选代表，其余多tab矩阵留E/R。**设计状态：**`current_contract`。

### UX-C09 会话过期或切换账号后回到任务

**用户任务：**任务处理中登录过期了，或我换了账号；重新登录要回正确的项目。

**前置：**两个授权隔离账号A/B；A有已接受run；控制session expiry/迟到读取响应，禁止真实外部越权。

**用户动作与恢复：**

1. A启动后令会话过期，观察登录/读取提示。
2. 同账号A重新登录，回同任务并读取实际进度或成果。
3. 另一个子例退出A后登录B，让A旧请求迟到；从B访问自己的工作台。

**Pass criteria / 设计缺口：**

- 会话失效不取消A后台任务；A重登恢复same run和输入，不重新下单。
- B不能看到A材料/进度/余额/成果，旧响应不污染B；恢复入口明确，不将认证失败报业务已失败。

**分工：**Agent独立；Human按代表旅程抽查体验。Human专业/真实客户端只按U-H或R适用范围签认，Agent机械通过不替代Human。

**关联：**BB-003 / BB-004 / BB-041 / BB-043 / BB-063 / BB-070；U-C / U-F。**选择：**U：退出/过期/迟到隔离必要机制；同一次代表run复用。**设计状态：**`current_contract`。

### UX-C10 最后4,500积分被两个项目同时使用

**用户任务：**我只有一份文书的钱，却在两个项目几乎同时点了生成。

**前置：**隔离账号available4,500，两个独立有效M4项目/不同执行key。

**用户动作与恢复：**

1. 两页分别准备项目A/B，核对均为4,500，几乎同时点击生成。
2. 查看两个项目的提交结果和主余额/预留。
3. 核对被拒项目草稿仍在；完成或有效取消已接受任务后再显式决定另一任务。

**Pass criteria / 设计缺口：**

- 仅一个请求可取得足额预留，另一请求拒绝且无新增run/hold/模型调用，不超支。
- available+reserved及ledger一致；被拒输入保留，余额变化/页面返回不自动启动另一项目。

**分工：**Agent独立；Human按需抽查提示理解。Human专业/真实客户端只按U-H或R适用范围签认，Agent机械通过不替代Human。

**关联：**BB-025 / BB-044 / BB-052 / BB-053 / BB-054 / BB-073；U-E。**选择：**U：钱包不同key竞争工程例，不要求两份真实生成。**设计状态：**`current_contract`。

## 探索式用户测试：主动发现缺功能与设计缺口

向Human只给业务目标和资料：例如“开始编制后，你发现遗漏一份关键附注，现在希望补上并把这次工作继续完成”。不告诉他当前只有停止，也不要求按现有按钮改写目标。观察他如何找入口、问费用、补料、理解是否采用和恢复进度；发生偏离脚本时跟随真实意图，记录期望/实际、最短轨迹、辅助次数和结果。Agent提供版本/网络/run/账务证据及可稳定重现，不替Human合理化绕路。

至少探索：漏材料后暂停补料、回来看不清哪个是当前版本、任务卡或费用难理解、下载后发现还需修改、异常后不知道下一步。新目标先记录，业务负责人确认后固化永久场景，不将所有临时愿望立即当既有合同要求。用户已确认的UX-A03不再待用户选择。

| 发现类型 | 如何记录和判断 |
|---|---|
| functional_gap 功能缺失 | 用户确认的目标没有入口/能力或只能放弃原任务绕路；不能仅因当前代码如此而pass。 |
| design_gap 设计缺口 | 暂停边界、输入/旧成果处理、收费/退款等没有可执行政策；预期未定义部分不能判pass，独立跟踪设计owner。 |
| usability_defect 体验问题 | 功能存在但入口难找、术语/提示误导、必须持续辅导；Human给原话与轨迹，Agent可复现UI部分。 |
| reliability_defect 可靠性问题 | 数据/任务在断网、关闭、恢复后丢失/倒退/重复；按run/input证据判断。 |
| billing_defect 积分问题 | 在已批准费用政策下实际金额、预留、消费、释放或重复收费错误；若政策尚不存在先记design_gap，不臆定金额。 |

## 执行记录与设计缺口

复制场景结果模板到受控证据目录，在原U执行报告中引用scenario_id/subcase/run/evidence。每步记录用户动作、预期/实际可见反馈、耗时、中断时点、run/input前后、费用变化与Agent证据；Human记录是否独立完成、困惑步骤、辅助次数、恢复/费用理解及反馈原话。初始数据不自动选择必跑或批准U。

证据复用须同运行版/配置、同fixture/run/artifact和适用断言；新网络/故障动作确实执行过才能记pass，不能只引用正常路径结果。环境或依赖步骤缺失记blocked，已确认目标的缺入口/能力记fail并关联functional_gap；设计不明确部分关联design_gap。功能未部署也可能是可用性缺口，只有明确批准的范围外目标才能N/A，不能据“尚未实现”自动缩小业务验收。P0/试用核心P1阻断U；其他缺口由owner按影响/处置与期限明确登记，不能因有替代路径就改pass。凭证、客户原件/成果和完整日志留受控位置，仓库只放脱敏摘要、hash和授权证据链接。
