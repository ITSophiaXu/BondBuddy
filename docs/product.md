# 募集书 Cowork 产品与实现说明

## 一、工作台的核心关系

左侧是项目、材料和章节目录；中间是可以审阅的募集书；右侧是 Agent 对话、修改依据和待办。用户从任何一个修改位置都可以找到证据，也能直接要求 Agent 重做该位置。

每个项目固定一份原稿、一个目标报告期和一种更新范围。新增项目用于新的原稿或报告期，避免把不同底稿的审核决定混在一起。

网页目前采用普通审阅预览，保留文字修订、表格底色、【】和来源定位。Word 导出独立处理：在上传的历史 Word 原文件中替换对应文字，沿用原字体、标题、段落及表格格式。普通预览的排版不作为导出模板。

“最终模式”只是显示当前内容的方式，不等于所有披露已被人工确认。所有未解决的【】在两种视图和导出文件中均保留。

## 二、两种更新范围

| 范围 | 主要材料 | 更新内容 | 需保留人工判断的内容 |
| --- | --- | --- | --- |
| 只更新财务数据 | 财务报表、附注、审计报告 | 各章财务数字、正文引用、表格、报告期间、材料支持的审计信息 | 缺失明细、会计口径差异、财务分析原因与判断 |
| 全文更新 | 上述材料，另加征信、工商、评级、其他说明和公开网页 | 材料能够支持的非财务事实及财务内容 | 缺少来源、时效不明、法律或经营判断、无法访问的外部数据 |

用户已经确认的边界：公司基本情况里的注册资本和实缴资本使用工商资料，不能拿审计报告中的实收资本直接替换。混合段落允许更新财务数值，但保护其中的工商资本条款。

## 三、一次更新怎样执行

1. 解析底稿与材料，给段落、表格单元格建立稳定的位置编号。PDF 记录实际页码；Word 不猜测页码。
2. 原稿中的【】立即进入待办。启动完整更新时，扫描潜在更新位置，以【待核对】提示尚未验证的值。
3. 默认更新只处理规则扫描得到的相关候选，不把目录、普通说明文字和明显无关位置交给 Agent。候选再按位置分组，结合章节、表格行名、列名和附近的单位说明查找相关材料。每组写入独立任务目录。
4. 启动本机 Codex CLI。要求对每个目标给出修改建议，或说明保留、不在范围、需要人工判断的理由。
5. 验证返回的位置和来源。来源文件不能是募集书本身；引用须匹配来源文字。没有有效引文的修改强制标记为需要确认。另检查新增数字是否出现于来源段落及表格上下文，或有明确说明的已支持换算/简单比率；不支持的数字单独加【待确认】。该检查不判定会计口径是否相符。
6. 逐组保存修改，向网页发送更新事件。每组任务输入、结果与事件日志可以在本机留档。
7. 记录逐项判断覆盖率。仍有未判断的位置时显示数量，任务结束不代表全文披露已经核验通过。

全文公开查询只在用户创建项目时启用。保存网页正文快照、URL 和取得时间后，再将其作为来源。禁止内网、本机地址、自定义端口和携带账号密码的链接；重定向也检查目标地址。

## 四、修改记录与审核

每处修改包括：原稿位置、原文、新文、修改原因、章节、引用列表、审核状态、版本和创建时间。

在形成修改之前，规则扫描候选单独列为“待 Agent 处理”，没有完成来源匹配就不能推断为“缺少资料”，也不能要求用户逐项填写。原文和扫描标记保留，但不展示为红绿修订，不计入人工待办。原稿已有的【】继续作为人工待办保留；Word 表格新增报告期列属于结构事项，单独统计，不混入数据人工待办。只有模型实际核对后的更新建议，才进入下列审核状态。

Agent 返回的新值如果没有通过来源校验，不写入当前预览或 Word 导出。系统保留原文并生成“缺少来源，建议未应用”待办；模型建议仅留在审核记录中。页面的“有来源修改”只统计带有效引文的 Agent 修改以及用户直接确认的内容。

| 状态 | 页面表现 | 后续操作 |
| --- | --- | --- |
| 待审核 | 显示修订和来源，表格更新值着色 | 接受、拒绝、编辑 |
| 需要确认 | 新文含【】，进入待办 | 补资料让 Agent 重做，或人工填写 |
| 已确认 | 显示人工确认标记 | 重新审核，或明确选择该处要求 Agent 重做 |
| 已拒绝 | 当前文档保留原文 | 重新审核 |

如果拒绝建议后原文仍含【】，该位置会继续保留为原文待办。人工编辑会清除当前修改的旧引文，防止旧证据被误当作用户新内容的依据；旧状态和引文仍保存在完整审核历史中。

服务端使用版本号阻止过时页面覆盖新编辑。Agent 运行期间可以浏览文档和来源，需停止任务后才能改文档或增加材料。停止、失败和服务重启均保留已经保存的结果。

## 五、技术结构

- `web/`：原生 JavaScript、CSS 和 HTML，无需前端构建。负责视图切换、正文/表格审阅、材料管理、来源定位和对话。
- `backend/server.py`：本机 HTTP 服务、上传下载、项目接口、任务事件、PDF 页渲染及导出。
- `backend/documents.py`：文件解析、稳定位置、表格上下文和按完整数值生成差异。
- `backend/docx_fidelity.py`：在原 Word 文件部件中定点替换文字、保留运行内字体样式、生成原生修订及列安排批注。
- `backend/word_preview.py`：保留原 Word 样式预览接口，供后续排版能力验证；当前普通预览不调用该接口。
- `backend/engine.py`：候选扫描、【】清单、来源匹配、工商保护、修改应用和人工审核。
- `backend/runner.py`：Codex CLI 参数、结构化输出约束、分组输入、任务进度与停止、失败处理、可选网页来源。
- `backend/store.py`：本地项目存储、原子保存、版本及审核历史。
- `outputs/上交所私募公司债财务数据更新规则_专家审阅版.md`：既有逐章知识，运行时写入每组任务目录供 Agent 参考。

文件保存在 `.local/data/files`；项目记录是 `.local/data/project_*.json`；任务输入和日志位于 `.local/data/runs`。`.local` 已加入忽略规则。

没有把网页应用状态直接当作模型输出使用。Agent 返回的 ID、引用和确定性都需要经过服务端校验；材料内容在提示中明确被视为数据，不具有指令权限。

## 六、后续模块如何接入

财务分析、行业研究、工商查询等模块应复用相同的“目标位置—修改建议—来源—人工审核”流程。模块只负责增加适用字段、来源获取方式与校验方法，不另建一套不可追溯的文本生成入口。

优先扩展项：

1. 结构化财务事实库：记录主体、合并/母公司、期间、单位、金额、审计状态、原文定位；对全文同一事实做独立一致性和公式校验。
2. 更完整的 PDF/OCR 表格解析，以及 Word 页面渲染引擎的视觉验收和复杂网页排版支持。
3. 专家确认后的逐章必查字段、指标计算口径和例外规则，转为可执行规则与真实脱敏样例评测。
4. 正式工商、征信及行业数据库连接器，明确账户授权、取得时间和可验证的来源页面。
5. 机构使用需要的权限、加密存储、多人协作和完整操作审计。

当前实现依赖模型进行字段映射和语义判断，尚未独立实现财务事实库与跨章节数值一致性引擎，因此不应把“引文已匹配”展示成“数据已审核正确”。
