# 模型执行的 90 分钟累计上限

每个用户运行任务及复核助手消息分别累计 worker 持有租约期间的执行时间。排队、已暂停及租约过期后的恢复等待不计入。达到 90 分钟后，系统在持久化**下一次模型调用意图**前拒绝该调用，错误码为 `TASK_EXECUTION_TIME_LIMIT`。检查发生在数据库事务内，涵盖普通调用、重试和格式重问。

每次新模型调用在取得执行槽位、准备好输入后读取剩余累计预算，并将模型进程截止时间限制在该预算内。因此已经运行的模型调用也会在累计 90 分钟时被中止，不再沿用五小时单次截止时间持续消耗 token。到点前已经完成的合格结果可复用，并可继续保存、生成 Word、执行质量检查、登记成果和结算。超时后的恢复点保存仍受独立的有界保存规则约束；未完成调用的最新工作不保证已形成可恢复快照。

编写调用仍有独立的单次／逻辑调用截止时间，但最长为 90 分钟；旧的五小时环境配置会被压到 90 分钟。模型进程取这个上限和任务剩余累计预算中较早的截止时间。累计预算先到时，任务报 `TASK_EXECUTION_TIME_LIMIT`；若提供方调用结果或用量仍不确定，则先进入核对状态，不能直接当作已安全结算。已完成调用后的交付不受模型截止时间拦截。

两个“执行时间”目前口径不同：90 分钟上限使用 `bb_jobs.active_execution_ms`（复核助手使用对应消息表），运行状态中的恢复点保存时间也会累计。用户可见的编写处理／计费时间使用独立计量逻辑；恢复点保存期间暂停该计量。因此两者可能不相等，不应以页面上的“已处理时间”推算 90 分钟剩余量。材料解析、OCR、Word 交付等无新模型调用的步骤仍受各自现有超时和质量规则约束。
