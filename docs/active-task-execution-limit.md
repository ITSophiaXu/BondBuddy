# 新模型调用的 90 分钟准入上限

每个用户运行任务及复核助手消息分别累计 worker 持有租约期间的执行时间。排队、已暂停及租约过期后的恢复等待不计入。达到 90 分钟后，系统在持久化**下一次模型调用意图**前拒绝该调用，错误码为 `TASK_EXECUTION_TIME_LIMIT`。检查发生在数据库事务内，涵盖普通调用、重试和格式重问。

90 分钟不是正在运行的模型调用的中断定时器。已发起的调用可按其自身截止时间结束；合格结果照常保存，已完成的模型结果可复用。保存恢复点、Word 生成、质量检查、成果登记和结算不再因 90 分钟而失败。若任务确需新的模型调用才能完成，才以该上限结束；失败时仅保证保留此前**已经持久化**的材料和阶段结果，不能保证未完成调用的最新工作已形成恢复点。

编写调用仍有独立的单次／逻辑调用截止时间，默认配置为五小时，可由运行配置调整。它限制已经发起的调用及其上下文恢复；90 分钟只决定是否允许发起下一次调用。当前调用触及自身截止时间时按原有模型超时或编写上下文截止错误处理；后续新调用触及累计上限时才报 `TASK_EXECUTION_TIME_LIMIT`。已完成调用后的交付不受两者拦截。

两个“执行时间”目前口径不同：90 分钟准入使用 `bb_jobs.active_execution_ms`（复核助手使用对应消息表），运行状态中的恢复点保存时间也会累计。用户可见的编写处理／计费时间使用独立计量逻辑；PR #1749 将在 `recovery_capture` 阶段暂停该计量。因此两者可能不相等，不应以页面上的“已处理时间”推算 90 分钟剩余量。后续可在统一计量来源时消除差异。材料解析、OCR、Word 交付等无新模型调用的步骤仍受各自现有超时和质量规则约束。
