# 复核原文修订与下载反馈修复

开发和定向自测完成，尚未部署，待统一集成、用户验收和发布。无数据库迁移，无新增运行依赖。

## 已确认原因

对 wql 2026-10-25 16:51 创建的复核任务进行了只读检查。持久化的 `report.md` 只有 41 字节，内容为 `BB_REVIEW_PROGRESS:read_materials:started`。三份 Word 的私有存储大小和 SHA-256 均符合交付记录，因此此次空修订并非文件丢失或字节损坏。

原 correction 收集器在报告文件缺失时直接采用最后一条模型消息，并无条件执行修订导出。进度消息被作为报告后，解析结果为零条问题，系统仍交付原文副本并将任务标成成功。结果中也丢失了已保存的最终消息引用。

下载异常尚未取得 wql 的具体浏览器错误，不能声称其网络或浏览器原因已经确认。原界面没有读取状态，错误提示位于整段正文预览之后，点击后的等待或失败不易察觉。已修复可见反馈和重试，并在浏览器及实际 API 上验证下载路径。

## 变更

- 复核任务必须提交真实报告文件；进度消息、文件保存通知及缺失文件不会生成成功的空修订。保留实际最终消息、模型 Word 和可用 Markdown 供诊断。只有 Word 报告时，从文件按顺序读取段落与字段表。
- 提示词以完成复核并保存报告为主任务；进度仅发往 commentary，完成后才 final。明确将有材料支持的修改直接落到原文，提供完整替换文本；待确认事项不阻止其他已确认修改。
- 修订解析支持不同标题级别、字段表和显式多行字段。仍要求原文唯一定位、依据和明确替换；不把普通报告说明推断成替换文本。无变化建议不计为已修订，也不阻塞同段真实修改。
- Word 继续使用原生插入/删除修订，打开时显示修订标记。无正文变化的旧结果显示“原文（未修订）”或“批注版（无正文修订）”，而非宣称正文已修订。
- 下载显示读取、校验、成功或错误状态；失败可重新授权后重试，重复点击去重，切换历史后不下载旧请求的结果。归属、版本和 SHA-256 校验保留。
