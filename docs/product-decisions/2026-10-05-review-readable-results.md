# 复核结果在页面阅读

用户下载真实报告后反馈可读性差，要求修复结果展示并设计内容。本决定覆盖同日“暂时只下载”的展示范围；直接文件交付、固定输入、无收费及执行边界继续有效。产品负责人已直接授权本次阅读体验设计。沿用材料与要求 / 复核结果和项目助手，不新增导航或整改工作流。

## 内容设计

| 内容 | 回答的问题 | 展示 |
| --- | --- | --- |
| 复核结论 | 主要发现、优先处理什么 | 首屏简短段落和重点文字；任务成功不等于合规通过 |
| 范围与依据 | 实际读取哪些材料、版本和检查范围 | 独立章节；不虚构覆盖率或通过数 |
| 复核发现 | 哪里有问题、为什么、怎么改 | 原报告编号卡片，展开显示原文位置、披露、依据与差异、影响、建议、待确认事项 |
| 待补充与未覆盖 | 哪些结论仍不确定 | 缺失材料、影响及下一步，未检索不等于无风险 |
| 建议处理顺序 | 用户下一步做什么 | 原文中的核实 / 补证 / 修改步骤，不声称已修订 |

顶部保留执行版本与 Word 下载。目录使用报告实际章节名，默认打开第一章；支持全文关键词搜索、逐项展开/收起及完整报告阅读。宽内容区左目录右正文，较窄内容区改为上方目录，保留原项目助手。手机无页面横向溢出，宽表格在表内滚动。

目录数字仅表示明确编号事项数量，不是可信度、覆盖率或通过数。无编号的旧报告保留原文排版，不编造问题对象；原文位置只显示已写信息，不提供未经验证的原稿跳转。此只读投影不自动生成可执行 ReviewFinding、逐项修订或差异执行依据。后续 CLI 建议按上述章节与分行字段写 Markdown；这是写作指引，不增加 JSON/schema 门禁或格式重问。未知标题、普通文字、未闭合代码块均可阅读。

## 读取与降级

`GET /api/v1/projects/{project_id}/review-executions/{run_id}/readable-report` 使用唯一公共 ReviewReadableReport 契约。核对账号、未删除项目、执行归属及成功可用的报告成果，验证私有结果与固定输入、正文路径/大小/hash及 UTF-8，仅读取 report.md。最终聊天说明、日志和 prompt 不能冒充报告。响应 private, no-store，不返回私有路径。

读取不写任务、不调用模型、不收费。缺失/格式/存储异常仅使正文提示“页面正文暂时无法读取，已生成的 Word 仍可下载”，提供重新读取；不能影响主工作区和下载。已有 Markdown 的成功项目直接可读，无需重跑。只有 Word 的旧结果仍可下载，不以简短文件说明冒充完整复核。

原文安全排版：不执行 HTML，不嵌入图片，显式来源链接只允许 HTTP(S)，新页打开且不带 referrer。搜索与展开只在内存保留，切换执行清空；不串账号/项目/旧版本。

## 验收与原型

原型 `product-prototype/public/review-v2.html?delivery=files`，新增阅读组件 `review-readable-preview.js/css`；示例均为 synthetic。迁移页面为 `apps/web/src/review-workspace.ts`。按 #55 / #56 交付，在 #361 登记原型 commit；#448 分别记录部署、用户成果读取和最终验收。

- 桌面/窄屏目录、编号事项、表格、列表、搜索、展开/收起、刷新及下载可用，未覆盖原文保留。
- 跨账号/项目404，跨run/错输入/篡改正文不展示；正文降级仍可下载，不重执行、不修改成功状态。
- HTML/链接注入不执行。无零发现=通过推断，不伪造来源定位。
- 自动化用合成 CLI 与真实 PG/Blob/Word，浏览器截图同尺寸对照；用户现存报告复测与内容验收单独记录。

本文件是实施决定，不声明已上线或真实结果已验收。
