# 诚信核查范围计价与旧报价退役

## 授权与性质

2026-11-11 用户要求执行积分计价、扣费与任务失败排查的合并修复计划，并退役旧计价和报价；随后明确授权“你来设计新的标准”。本决定据此定义新的商业价格，版本为 `bb-task-price-scope-20261111-v4`。

该价格不是测得的模型、浏览器或单站成本。诚信核查的 `C_plan` 仍为 unknown（代码中为 null），不能由下述积分倒推或伪造成成本数据。管理后台基于完整成本表发布价格的校验不因此放宽。其他任务 SKU 的积分沿用 v3。

## 新标准

一次核查最多 5 个主体。服务端锁定可执行的“主体 × 官方网站目录栏目”组合，每个不同组合计一个单位。

`预留积分 = min(22,738, 2,000 + 85 × 锁定的可执行组合数)`。

可执行组合为 0 时不受理收费核查。不适用的公司专属栏目、尚无法确定属地入口的栏目不计入收费范围，并保留未覆盖原因。一个栏目包含多个官方入口时仍按该栏目计一个单位。分页、实际打开的 URL 数量、跳转、截图数量、系统重试和原范围修复均不增加单位。

| 可执行组合数 | 预留积分 |
| --- | ---: |
| 1 | 2,085 |
| 10 | 2,850 |
| 49 | 6,165 |
| 100 | 10,500 |
| 244 | 22,738（达到上限） |
| 245 | 22,738 |

基础费覆盖本轮底稿整理与报告交付；组合费让较小查询范围获得较低价格；上限保持原整轮最高积分。以上均是商业设计的理由，不是供应商成本测量结果。

## 交付与结算

交付时，服务端根据原锁定范围内有持久化查询证据的不同成功组合，用同一公式计算实扣，并以原预留为上限。明确的官网零结果属于完成查询；HTTP 错误、验证码、仅访问首页、未执行检索或模型自行声称成功不构成收费证据。

部分成功时只按成功组合结算，剩余预留释放；全部失败时任务失败，全部释放，不收取基础费。底稿必须保留失败、未覆盖及待人工处理项，不能把未查到冒充“无风险”。证据、运行、主体、栏目均校验归属，并对重复记录去重。

同轮重新导出免费。同样输入再次明确发起新一轮核查，使用新 round ID，形成新报价与合同；重复提交同一请求返回原收据，不重复冻结。

## 历史条件与退役边界

- 已生效且未过期的旧报价、已接受的批次与付费合同，以及已付订阅周期的保价，继续读取原版本和条件。v2、v3 历史价表不删除。
- 新 HTTP 任务统一使用自动范围报价。旧开关不能恢复旧固定价、人工待报价或旧价表发布；旧报价 CLI 发布及分类入口、旧固定价 CLI 发布入口停止接收新操作。
- 本地预发 `api-legacy` 与 `legacy-billing` profile 退役，原 `/__legacy/api/v1/` 返回 410。历史收据、合同和余额通过当前 API 读取；不会自动删除旧容器、卷或业务数据。
- 历史执行与测试夹具保留显式兼容路径。生产 HTTP 不能通过测试夹具恢复旧规则；账本审计、退款和历史运行恢复按原合同处理。
- 不自动改写、补扣或退还历史资金；历史异常先形成只读盘点与纠正建议，实际财务纠正须单独按受控流程执行。

## 验收边界

必须覆盖范围变化、不可执行范围、部分成功与全部失败、重复证据、超范围证据、重放、历史合同、发布新价格后旧文件包报价的执行、长批次接受后报价过期以及钱包隔离恢复。合成回归不冒充真实官网、模型、支付供应商或用户验收。

代码完成后仍按统一发布流程推进。本决定和代码变更不代表已经部署或完成真实供应商验收。
