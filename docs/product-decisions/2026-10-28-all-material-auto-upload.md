# 所有材料入口选文件即上传

用户反馈：选完文件后仍要点击“上传并保存”，此前要求未覆盖所有页面。本次统一正常上传路径：选择有效文件或在支持拖放的区域放入文件后，立即上传保存，显示进度和结果。仅失败或结果未知时显示重试操作。

## 原因与覆盖范围

PR #772（95184462）只在 `ProspectusPanel.purpose === 'generation'` 时启动自动上传；更新和一致性检查继续使用手动保存。该改动已随 #775/#776 发布，截图反映的是遗漏的分支，不能解释成浏览器缓存或用户操作问题。

本次按生产入口审计了 `apps/web/src` 的十个含文件选择器模块：

| 模块及入口 | 正常上传行为 |
| --- | --- |
| `prospectus-panel.ts`：更新募集书、文件生成、项目文件、一致性检查中的募集书 | 统一选择或拖入一份有效文件后上传；保存成功保留版本，采用仍由用户明确选择 |
| `project-files.ts`：关联文件、各文种上传、某文件修改稿 | 先确定文件类型，选文件即保存新版本；未选类型时禁用选择器并给出提示；修改稿固定原文件类型及版本条件 |
| `review-workspace.ts`：复核材料区、上传弹窗、问题补证弹窗 | 材料区原已自动上传；弹窗统一在选择文件后上传，保留原补证对象；失败转到原上传记录 |
| `file-workspace.ts`：历史文件/模板、补充依据 | 模板选文件即上传并关联到本次文种；立项模板先填券商全称；补充依据原已自动上传 |
| `integrity-workspace.ts`：旧补证草稿恢复中的附件 | 仅对已保留旧草稿的选择器自动上传；不恢复已取消的新建人工补证入口；查询时间、说明和结论的业务记录仍需保存 |
| `main.ts`：更新募集书材料区 | 已自动上传，保持选择和拖放队列行为 |
| `material-workspace.ts`：材料生成的来源、模板、补料和附件 | 已自动上传，保持用途及原草稿范围 |
| `project-qa-workspace.ts`：问题清单和补充项目材料 | 已自动上传，保留免费识别和付费生成边界 |
| `workpaper-panel.ts`：Excel 底稿目录 | 已自动上传，保留目录解析及生成确认 |
| `project-assistant.ts`：助手附件及业务材料 | 已自动上传，保留发送消息与启动任务的独立操作 |

不是所有名为“保存”的操作都属于重复上传：采用当前募集书、填写实际查询结论、发送消息、确认生成范围和费用仍是独立的业务动作。刷新后的结果未知记录仍需核对原请求；重试继续复用上传编号、文件哈希、材料版本、原文种或补证对象，不另建重复上传。
