# M3：Codex CLI 统一业务执行与薄平台服务

## 2026-10-04 交互决定覆盖说明

当前交互与联动验收以[复核结果与项目助手组成同一个工作区](2026-10-04-review-assistant-linked-workspace.md)为准。桌面项目助手在右侧常驻，窄屏使用抽屉；真实消息、待确认提议和持久化任务卡使用同一时间线。快捷按钮与对话复用同一任务入口，真实执行过程与成果通过任务卡关联左侧结果，不伪造用户消息或输出原始 CLI 日志、隐藏推理。

对话产生的范围提议须可核对、可调整并经显式确认后执行；保存说明、异议或上传材料本身不建任务。用户回看历史报告时，新任务完成不强制替换当前查看对象，须提供准确的新结果入口。本决定覆盖下文及其引用中“默认收起／按需展开”、任务过程仅在页面反馈及被理解为与助手分离的“无需助手的按钮闭环”等旧交互要求。

下列原文完整保留，冲突的交互条款仅作历史记录；Codex CLI 统一业务执行、薄平台服务、无收费、真实用量与审计、不可变输入、幂等互斥、归属及恢复边界仍有效。旧工程证据保留，不能用于宣称新交互已实现或验收通过。

日期：2026-10-03。依据：用户同意“Codex CLI 是唯一业务执行与编排引擎，平台保留权限、任务状态和文件版本”的架构，并要求据此调整 M3。本决定将[2026-10-02 CLI 主导财务与合规复核](2026-10-02-m3-cli-led-review.md)扩展到公开比较、结果修订及项目助手；[M3 页面、明确执行与无收费范围](2026-10-02-m3-review-scope.md)保持。

本文确定实施边界和验收要求，不声明运行时已完成验证或已部署。代码接线、synthetic 测试、真实模型/专业成果及生产发布分别记录。

## 责任边界

Codex CLI 是 M3 业务理解、检查选择、来源比较、解释及修订决策的统一执行入口。页面按钮和按需项目助手提交明确任务与上下文；CLI 在锁定的任务中规划业务步骤并按需调用工具。平台不再维护另一套模型抽取后自动扫描规则、按固定记录批次逐段生成修订的业务流程。

| 部分 | 保留责任 |
|---|---|
| Codex CLI 与版本化 Skills | 理解任务和业务口径，选择读取与检查步骤，比较来源，形成复核结论、修订提案和助手回复 |
| API、PostgreSQL 队列及 worker 宿主 | 身份和项目归属、明确执行、不可变输入、幂等、互斥、租约、取消/恢复、调用审计、真实 usage、私有成果和授权下载 |
| 有界工具 | 文件/原文/知识读取、精确计算、真实格式属性、明确提案的 Word 写入；验证参数和允许范围后返回真实结果 |
| 通用成果处理 | 验证结构、引用、任务范围、文件/hash 与来源；将已形成的报告序列化成 DOCX/原生批注，登记成果及版本 |

“CLI 统一业务执行”不取消工具实现。已有 TypeScript/Python 计算、解析及 Word 脚本继续维护和测试，不把确定性算术交给模型猜算，也不为固定报告格式序列化增加一次只用于选择渲染器的模型调用。平台校验不能自行生成新的专业结论或替用户扩大修订范围。

## 各类任务

### 完整与差异复核

沿用 CLI 读取原文/知识及请求定向财务、合规、实际格式工具的路径。CLI 组织业务检查并形成发现、解释、引用和实际覆盖；宿主只验证证据和任务边界、规范化结果与生成成果。不恢复完整财务观察表作为前置，也不自动遍历整套规则。差异复核保留明确重核对象，沿用项仍引用原报告与原时点。

### 公开信息核验

保留数据边界明确的两次 CLI 执行：联网检索只接收允许的主体、日期和类别；随后一次材料比较执行获得真实搜索事件与来源，通过只读 `bb_materials` 工具按需读取本轮固定材料，在同一 CLI 执行内完成所需跨章比较。比较步骤不再由后台按文本批次创建多个模型调用，也不把内部材料交给联网搜索上下文。

真实工具事件、URL/标题、查询与事实时点、逐字来源及材料读取痕迹由宿主校验。未发生实际搜索或未能取得可信来源，仍如实列未覆盖/待核，不通过模型自述补齐能力。此调整不新增爬虫、搜索平台或商业数据前置。

### 基于已采纳计划的修订

一次 CLI 文件工作区执行获得锁定原件、源报告、已采纳计划、证据及允许目标。CLI 自行读取并安排局部修订，写出结构化提案，显式调用本轮提供的 Python Word 工具生成修订版、清洁版和逐问题处理记录。取消默认逐记录批次调用模型生成修改的流程。

只读原件与本轮可写目录隔离。宿主验证提案不越过已采纳范围，校验原件和成果 hash，并用同一提案重放确定性 Word 工具，拒绝提案之外的文件修改。该重放是成果核验，不替 CLI 增减修改。无法定位、证据不足或要扩大范围时保留原内容与具体未处理原因；不能以全稿重写替代已批准的局部修改。

### 项目助手

助手继续通过 CLI 生成解释、追问和计划提议，使用后台保存的准确项目/报告/问题上下文。回复、采纳与执行分开；不因换用 Skills 而获得直接修改勾选、改报告、写 Word 或创建 run 的权力。无需把项目中的所有用户交互串成一个无限续接的 CLI 会话；持久上下文及调用恢复由平台负责。

### 报告与版本

CLI 形成结构化报告后，现有通用 Word 渲染器生成报告和适用的原生批注；这里不虚构一个 CLI 已调用的渲染工具，也不额外调用模型决定固定格式输出。版本、源报告与成果映射仍保存在工作台。已生成、已修改、技术交付成功与专业复核通过分别表述。

## Skills 与恢复

运行时使用仓库内 `apps/worker/skills/` 的四个固定资产：`m3-review`、`m3-public-review`、`m3-review-revision`、`m3-project-assistant`。`m3-runtime-manifest.json` 固定版本、路径和原始字节 SHA-256，Git 属性固定 LF。宿主校验清单与内容后，将本任务对应技能显式放入受信提示；不依赖个人技能目录、用户配置或 CLI 的自动发现。

技能与知识的来源性质不同：受信技能规定获准任务的行为，知识 MD/材料/网页是待分析数据，不能授予工具或执行权限。技能 pin、方法/协议版本及固定输入参与提示和逻辑调用身份；新版本不得静默套用到已发送的旧提示或检查点。恢复优先复用已完成调用和成果，状态未知的调用先核对，不自动重发。原 `review_revision` 批次检查点与新文件执行检查点须明确区分，不用部署升级触发新业务任务。

## 验收要求与范围

- 验证技能确实被加载并以内容 hash 固定；缺失、篡改或不同版本不能恢复成同一调用。
- 验证 CLI 实际工具接线：财务/合规定向请求、公开比较的按需原文读取、修订中显式运行 Word 工具；没有工具事件不能凭回复冒充执行。
- 验证原件只读、目录隔离、修订允许范围、未申报 Word 修改拒绝、真实文件/hash、源报告和逐问题处理记录。
- 验证完整/差异覆盖、未搜索/未读取/缺证状态、未知 usage、中断恢复、项目互斥与取消；不静默降低专业证据标准。
- 保留无需助手的按钮闭环、助手不自动执行、工作台版本记录及全部无收费断言；不调整页面或新增账务。

工程验收记录见[本轮验收清单](../acceptance/m3-cli-runtime-2026-10-03.md)。使用 synthetic CLI 或材料的结果不冒充实际 Copilot 调用、公开搜索能力、专业样本、Word/WPS 客户端或生产验收。保持既有供应商配置，不因 CLI 架构调整宣称特定模型已生产可用。
