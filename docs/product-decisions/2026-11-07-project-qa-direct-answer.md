# 项目问答直接回应所问事项

依据：用户于 2026-11-07 提供券商用户修订稿，并明确要求“不要去和问题做反驳，如实解释和回答”“问什么就回答什么，不要引入无关的内容”。本决定补充 [募集说明书事实答复规则](2026-10-29-project-qa-prospectus-first.md)。修订原件和项目财务数据不进入代码仓库。

## 回复方法

1. 以项目组回复人的立场写正式答复。先识别问题要求的事项、期间和判断，按小问顺序组织相关事实、原因解释和对应结论；方法用于内部组织，不机械生成提纲。
2. 如实回应审核关注，不反驳提问者、不添加假想指控。不主动辩解“并非资质丧失或业务退出”，不将主要项目表的统计范围写成对“项目较少”的反驳。确实影响答案的口径错误应客观、简短说明，不能为顺从问题而重复错误事实。
3. 每段、表格、计算和限定均须回答具体小问。问收入下降及可持续性，就说明变动、相关原因、订单或项目支撑和可持续性结论；不自动扩展总收入降幅贡献、无关资质问题或“每年稳定增长”的额外命题。明确询问这些事项时则应作答。
4. 证据充分时直接给出相称的结论，不能用反复免责声明代替判断。证据不足时仅标出受影响的具体事项；保留相关不利事实和必要条件，不伪造凭证、核查、承诺或无风险结论。
5. 已披露且仅需说明的事实不要求另交原件重复证明。补件只针对本问的必要缺口；与本问无关的差异不形成补件义务或降低本题状态。提取范围不足仍须如实说明，不能将“未选入”写成“未披露”。
6. 表格完整性针对本问所需范围，保留单位、期间、明细、合计和必要附注；不因要求完整而堆入整份报表。复算在内部执行，只将回答所需的计算写入正文。
7. 历史案例只借鉴本问适用的方法，不照搬全部核查角度、项目事实或结论。问题明确要求风险、合规或文件核对时，在对应范围充分回答。
8. 输出前逐段检查：回答哪一问，是否必要，是否与问题争辩，结论是否与证据匹配，是否遗漏该问或添加无关内容。

9. 用直接陈述解释资金主体、金额、支付时点和原因，不先建立未被提出的“全部立即自筹”等命题再反驳。真实否定事实、是非问的直接回答及影响答案的错误口径仍应保留。
10. 区分事实、业务判断和申报合规判断的证据要求。关键规则适用或资产性质等前提缺失时，直接在相应判断处限定；不先给确定结论再尾注待确认。不得用资金用途或无政府偿债责任替代资产入账等不同条件的核验。

## 实现及适用范围

- `qaAnswerInstructions` 使用上述方法，prompt 版本为 `project-qa-direct-answer-v6`。
- Word 每题答复标签使用“回复：”。这只改变正文标签；schema 中的 `draft` / `missing` 状态、实际材料缺口和人工复核语义保持。
- 新模型输出只选择 evidence_refs，由程序逐字物化原文；200 条上限支持多小问及表格引用，旧任务沿用保存提示的协议。引文仍经原文定位验证并独立保存；本决定不关闭真实性检查，也不通过关键词替换或删句来强行修正生成结果。
- 不改原问题、计费、数据库、权限、固定输入、历史成果或已保存逐题回答；不自动重跑已有收费任务。
- 本次为开发变更，尚未部署，待统一集成与发布。

## 复验场景

使用合成材料或用户本地授权原件，不将客户文档提交仓库。逐项检查：

| 问题与材料 | 应有表现 | 不应出现 |
| --- | --- | --- |
| 收入下降原因及可持续性，材料已有结算原因及新增订单 | 解释变动及原因，用订单回答持续性 | 资质丧失、业务退出、反驳项目数量、每年稳定增长 |
| 仅问回款安排，材料有金额和具体期限 | 按期款项及回款安排直接回答 | 无端扩展信用评级、涉诉、全套尽调 |
| 明确要求判断回款风险，材料显示长账龄及逾期 | 正面解释风险与相关不利事实 | 因“避免反驳”而隐去逾期或直接认定无风险 |
| 同题含事实和未披露的销售计划 | 写足事实，仅标注具体计划缺口 | 整题拒答、要求重复提供已披露金额 |
| 问题金额与实际材料不同且影响结论 | 说明实际口径并继续作答 | 迎合错误数值，或长篇批评问题 |
| 其他业务存在与本问无关的报表差异 | 回答本问，不引入该差异 | 通用纠错清单、无关 missing 状态 |

工程回归与内容方法复核是不同证据。通过构建和既有测试不代表已经完成真实模型生成或用户验收，详见[本次验证记录](../acceptance/project-qa-direct-answer-20261107.md)。
