# 账号积分记录（#630，2026-10-09 用户反馈）

用户要求在“我的账号”查看积分消耗和充值记录，覆盖旧范围中不提供用户消费记录的限制。沿用 2026-10-08 账号页简化布局，在充值区下方增加“积分记录”，包含“积分消耗记录”“充值记录”两个可见标签及刷新按钮。

- 消耗记录按任务提交时间倒序，一条任务预留对应一条记录。正式消耗取不可变 settle 事件之和；预留 held 不显示为消耗；release 与 correction 分别显示释放、冲正返还。展示项目/业务名、任务编号、提交和结算时间，已删除项目如实标识。原始账本不改写，不补扣历史免费任务。
- 充值只读 bb_recharge_orders，显示订单号、渠道、创建时间、人民币金额、积分、到账时间和真实订单状态。pending 显示“待支付／确认中”，paid 显示“已到账”，expired 显示“已关闭／过期”，failed 显示“支付未完成”。不从时间或浏览器猜测支付成功，不把赠分、人工调整或存量权益伪装成支付订单。
- 两类记录每页默认 20 条，最多 50 条，使用账号与类别绑定的游标按 created_at/id 稳定分页；结算变化不移动分页键。刷新会保留用户已展开的页数；返回前台、积分变化及可见页面周期刷新同步记录和余额。失败时显示重试，不显示虚假空记录；离开页面/退出取消请求，跨账号不复用记录。

接口：GET /api/v1/credits/consumption-history、GET /api/v1/credits/recharge-history，limit/cursor 均按 query string 校验。公共 DTO 只在 packages/contracts。返回白名单，不暴露支付链接、商户交易 ID、操作员或内部计费理由；接口始终检查登录归属并禁用缓存。0102 仅增加查询索引，无账务数据迁移。

原型 account-credits.html，与 billing-page.ts、credit-history.ts 同步。样本明确为 synthetic，真实充值供应商/生产账本读回列入最终统一验收，不能以 UI 列表代替 #628 扣分链路修复。
