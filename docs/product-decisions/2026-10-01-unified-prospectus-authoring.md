# 2026-10-01：统一募集书编制入口、可选原稿及计费输入

依据：产品负责人在当前会话确认不设置有／无历史募集书两条 UX；原募集书可不上传，也可上传本企业、母公司、子公司或相似业务企业的稿件；上传时可补充原稿品种、企业关系和报告期（选填）；原稿与目标信息同时用于知识选择和 M2 计费。补充要求替代聊天。随后明确保留 Word 修订版和清洁版。

本文是当前 M1/M2 范围依据，替代 2026-09-30 决定中的“两类自带稿必需”“无稿只能保存草稿”和“补充要求必须移到表单末尾”。旧实现、评论和测试记录保留为历史证据，不构成要求继续建设旧流程的依据。本次文档变更不表示功能、部署或真实成果已验收。

## 1. 一个入口、一次明确执行

创建项目 → 填写本次募集书目标 → 上传发行人材料及可选原募集书 → 填写额外补充要求 → 开始编制 → 查看真实状态 → 下载 Word。

- 不要求先回答“有／没有历史募集书”，不按该答案切换页面、项目种类或必填材料分区。
- 同一“历史／参考募集书（选填）”区域接受原稿；没有原稿仍可用发行人材料和目标类型知识编制新稿，不依赖 M3 参考库。
- 现有对话区改为“募集书更新补充说明”，保留输入空间、保存及编辑能力；不提供助手聊天、追问或消息意图执行。示例不自动写入用户要求。
- 补充要求保存到项目，重开恢复；只有“开始编制”创建任务。运行中不显示补充说明编辑区；任务结束后点击“继续修改”再为下一轮补充，不改变当前任务输入。旧用户补充保留，助手回答不自动变成用户指令。
- 无原稿与没有发行人事实材料不同。缺少局部材料在成果对应位置标待确认；不能只输出空壳、复制原文或编造事实却标记编制完成。

## 2. 分开收集原稿与目标信息

| 对象 | 信息 | 规则 |
| --- | --- | --- |
| 本次目标 | 发行人、本次市场与品种、最新报告期（年份＋3月末／6月末／9月末／年末） | 根据目标品种自动整理报告期；原稿数据不自动覆盖目标；草稿可未填完 |
| 本次目标 | 发行／注册安排、规模、期限、用途等现有项目字段及额外要求 | 沿用已有表单，未知按未知保存，不以零代替 |
| 每份原募集书 | 原发行人名称；与目标发行人的关系 | 上传时填写关系：同企业、目标发行人的母公司、目标发行人的子公司、相似业务企业；方向以目标发行人为参照 |
| 每份原募集书 | 原市场与品种 | 市场联动；上交所／深交所普通私募、小公募、大公募，或协会 PPN、MTN、CP、SCP、DFI 安排 |
| 每份原募集书 | 原稿最新报告期（选填） | 年份＋3月末／6月末／9月末／年末，按原稿品种整理通常覆盖期间；旧实际期间不因无关编辑被重写；财务报告期与债券期次分开 |
| 没有原募集书 | 明确没有原稿引用 | 不要求填写不存在的原稿字段，不伪造默认同企业、原品种或原报告期 |

以上是产品数据语义，不在文档中新造一套 API 枚举。使用现有公共契约扩展和迁移。用户填写值保存为用户声明；记录材料版本、信息版本及填写来源。替换原稿时重新核对其信息，修改后重算尚未执行的比较／计费估计，已执行任务保持原输入。

如允许多份原稿，每份分别保存信息，不能合并成一个虚构的原企业或原报告期。worker 应记录实际采用的编辑基线；基线不明确时在任务内处理并说明，不能把多份原稿拼成伪造的历史版本。

## 3. 知识选择与 worker 输入

知识以本次目标市场、品种及文书阶段为主；原稿品种用于理解已有结构及迁移差异，不决定目标规则。例：母公司上交所私募稿用于目标子公司 MTN，主体是子公司，主要知识是 MTN／协会知识，原稿仅提供相应参考。

DFI 是注册安排。编制注册文件时使用 DFI 安排及覆盖工具的相关知识；编制具体一期文件时结合实际工具。覆盖列表不等于本期品种，不凭简称推定。

将保存的原始材料、原稿信息（可为空）、目标信息、补充要求、相应知识 MD 及其版本直接交同一 worker 任务（Codex CLI + AI）。文档读取、必要 OCR、分章读取、计算及 Word 生成是 worker 内部工具。无需独立财务提取服务、预先事实库、逐项业务审批或完整规则发布平台作为编制入口前置。

保留账号归属、私有材料、输入版本、防重复执行、任务及真实模型调用记录。知识 MD 是编制依据，不是“已出具合规意见”；资料、参考稿及知识内容中的指令不能取得额外工具权限。知识内容缺项应补充或说明，不能把错误品种当成兜底知识。

同企业旧稿可提供旧时点事实；母子公司和相似企业的财务、债务、评级及风险不得直接当作目标发行人的事实。企业关系是参考用途信息，不等于合并报表口径或事实核验结论。

## 4. M2 复用同一份信息

M1 现在就保存原稿是否提供、原／目标品种、原／目标报告期、企业关系、实际材料及补充要求版本，供 M2 判断更新／编制工作量、跨品种适配及期间差异。用户不另填计费期数，不再问一遍原稿信息。

- 同企业旧稿已有 2022—2024 年，仅新增 2025 年时，实际变更期间可为 1；保留年度不重复计数。
- 原稿与目标报告期相同而跨品种时，期间差异可为 0，结构调整工作单独有依据；不能捏造新增期间。
- 母公司、子公司或相似企业原稿中的年份，不视为目标发行人已经完成处理的年份；不能简单做年份相减。
- 没有原稿是明确输入状态，不是“原稿字段缺失”错误，也不等于工作量为零。
- 企业关系可以影响已有定价方案的适用判断，但本次没有新增或批准母／子／相似企业的固定收费系数。未明确的映射由 M2 业务确认，不能猜价或让 M1 等待收费规则。
- M2 最终扣分仍按批准方案及实际有效计量执行；避免重复扣分，失败／取消按既定规则释放。M1 不扣积分；余额现金退款和用户消费记录页仍不做。

## 5. 保留修订版与清洁版

有实际编辑基线时，输出真实修订版及对应清洁版，说明对照原稿的企业、材料版本或本项目成果版本。接受本轮修订应得到清洁版；原件保持不变。非同企业原稿即使作为编辑对照，也不能标为目标发行人的历史版本，更不能把参考企业事实残留到最终正文。PDF 重建要说明限制。

完全没有原稿的首次编制，交付可编辑新稿并说明没有旧文对照；不把凭空构造的“历史版本”作为修订基线。后续修改使用本项目上一版成果，交付修订版和清洁版。此区别只影响成果说明，不成为创建项目的分流步骤。

页面保留简短实际状态、实际修改／编制摘要、待确认事项和下载。复杂历史浏览器、逐条在线接受／拒绝修订及独立编制说明 DOCX 不作为新 M1 必须增加的功能。

| UNIFIED-A04 | 源、目标跨市场／品种及 DFI | 使用目标适用知识，原稿只提供迁移上下文；注册安排与实际工具分开 |

## 7. 同日 UX 修正：最新报告期与补充说明

用户截图验收否定目标年度文本框、一期 date picker、右侧上下文卡/快捷标签及“创建项目后可保存”。最新报告期放在项目基本信息中，用年份＋四个期末选择；不让用户另填年度集合。期中选择推导此前连续完整年度及当年累计一期，年末含当年且不重复一期。通常自然年度编制窗口：沪深普通私募、PPN 募集说明书两年；沪深公募、MTN/CP/SCP、DFI 通常公开注册编制三年。依据为现有 exchange 知识、NAFMII APPLICABILITY.md / NA041、OF007。此窗口是编制输入候选，scope 保持未知，status=needs_confirmation；PPN 协议路径、DFI 实际定向工具、非自然年度/豁免由 worker 结合对应知识与用户补充处理，不冒充已审核规则或新增问卷。旧项目不因修改无关信息重写已有期间；修改目标品种或期末重算，原稿元数据及旧任务锁不变。

右侧只保留额外更新说明输入、已保存内容及必要保存/编辑/失败反馈。新建说明（最多6000字）随项目创建请求的 supplementary_notes 一起持久化，避免创建后第二次保存、响应丢失导致补充说明丢失。已有项目的创建时说明在右侧修改，通过同一草稿版本保存；后续补充沿用版本化用户消息 API。两种已保存说明均随不可变输入直接交 worker，不生成助手回复或自动创建 run。新建无独立保存按钮，仅“随项目一起保存”；已有项目按钮“保存补充说明”。

## 8. 同日追加决定：原稿信息选填，补充说明只在材料末尾

用户最新截图及明确指示覆盖第7节旧的右侧布局：删除常驻右侧输入框。创建／项目信息页只收集项目字段；材料上传区末尾显示“募集书更新补充说明（选填）”、已保存说明和必要保存／编辑反馈。运行／暂停时不出现该编辑区；任务终止后明确点击“继续修改”才重新展示。旧 supplementary_notes 和版本化消息均保留，保存不启动，当前 run 锁不变。

每份原稿的信息均可留空，包括原发行人、关系、市场、品种和报告期。缺项不在 worker 输入阶段暂停，也不因仅上传原稿但没声明同企业而暂停。worker 结合上传材料、目标信息、对应知识继续编制，未知关系不默认同企业，无法确定的主体／期间／数值在成果中标待确认。归属、文件版本／hash、知识 hash、隔离、模型调用去重和 Word 交付检查保留。

原稿报告期也用年份＋四期末，无年度集合文本框或 date picker。原稿品种与目标品种分别推导通常自然年度窗口；推导项 scope=null、status=needs_confirmation。已存的特殊年度或非标准截止日只显示并保留，修改名称／关系不改变原期间；只有明确改期间／原市场品种时重算。期间早于品种填写时先保留已选最新一期，不丢输入；多份原稿独立。

新增验收：缺少全部／部分原稿信息且只上传原稿时，真实 API→解析→worker 能进入编制并交付通过检查的 Word（合成模型证据须单独标明）；未知关系在模型输入和成果待确认项保留。原任务恢复须核对准确输入与先前调用，不能盲目重放。
