# 参考募集书保留结构与格式，允许灵活改写文字

2026-11-11 用户明确要求修复原文保留规则：跨品种更新必然涉及大量局部改写，应保留模板章节及字体格式，具体文字按目标发行人、市场／品种和材料灵活更新。此决定覆盖 2026-10-31、2026-11-01 及后续说明中“标题文字不可变化”“章节内容阈值保持”“不得整段重写”等冲突要求，不取消可信服务端检查及统一发布验收。

- 全文和分节的原文片段相似度、逐章字数比例不再作为拒绝条件；正常局部精简不需要用旧文字补足。用户同日补充要求整篇长稿不能大幅缩成摘要，整体正文总量和实际渲染页数执行下述独立门禁。
- 章节与目录的数量、编号、层级及顺序继续保护；标题里的发行人、品种、期间和措辞可以更新。无编号标题中可识别的原标题换位仍报告结构变化。任意改写的语义归属无法靠结构比较证明，需内容验收。
- 整节清空、整表清空及大量非空段落消失仍拒绝。章节正文检查不含标题本身，不设最少原文字符门槛，按结构位置配对，避免标题改写后误判整节缺失。表格、行、列、分节、OOXML资源、修订一致性、锁定输入和可信操作重放继续检查。
- 字体、字号、段落、表格、页眉页脚、图片及页面格式继续由原包和受控编辑保护。PDF 到可编辑基线的重建仍须忠实于原件，重建后正文更新使用同一灵活规则。
- 仍须依据目标材料更新事实；不能为提高原文保留率强行保留母公司事实、旧交易场所条款或不适用结论。期间定义、已登记事实锚点、财务公式与真实历史比较口径的独立检查保持。

实现使用同一 `quality.verify` 供 worker 与模型预检调用，`format_diff` 同步采用允许标题改写的结构比较；原严格标题比较保留为诊断接口。报告继续使用 `word-quality-v1`，增加 `content_policy=template_structure_flexible_text_v1` 标明口径，无公共请求契约或数据库迁移。

Issue #987 的回归包括合成跨主体／跨市场／跨品种更新、简短局部改写、标题改写、PDF 忠实重建后更新，以及章节清空、重编号／换位、表格清空、字体与格式漂移、双稿不一致等反例。事故原稿及操作日志仅在私有本地目录回放，不提交客户原件。机械通过不证明事实、法规或页面视觉正确，不构成用户验收或生产发布授权。

## 同日补充：整篇长稿不能从300多页缩成100多页（#989）

文字灵活与整体披露规模分别检查。长稿正文总字符数（含表格，不含页眉页脚、空白）低于基线70%即拒绝。源稿在同一LibreOffice环境实际渲染为至少50页时，清洁稿页数低于源稿70%且减少至少20页，也拒绝。正常分页小幅变化及局部短段精简不会触发这些整篇下限；不恢复原句保留率或逐章字数阈值。

源稿满足以下任一信号即进入长稿检查：正文至少20,000个非空白字符、100个非空段落、49个显式分页、50个图形，或源稿缓存页数提示至少50页。正文或段落数量达到长稿信号时可直接执行正文总量下限；仅由布局或缓存触发时，先确认实际源稿至少50页才执行该下限，避免陈旧缓存误拦短稿。多个信号防止遗漏缓存缺失或图片较多的文档。缓存只用于触发更多检查，绝不充当实际页数。未满足长稿信号的文档仍执行章节、格式、清空与双稿一致性等既有检查。

`document_size.compare_size` 由同一 `quality.verify` 调用，预检和服务端都适用。比较原稿接受已有修订后的有效正文与清洁稿，避免删除修订或批注显示膨胀页数；页数来自私有临时区渲染的真实PDF，不读取模型声明。每次渲染使用独立配置目录、禁用低安全级宏、90秒超时和输出大小／页数上限，临时文件使用后清理。需核验页数但渲染缺失、超时或PDF无效时以 `WORD_PAGE_COUNT_UNAVAILABLE` 拒绝，不能退回缓存页数通过。

若正文总量已经骤减或其他质量检查已拒绝，允许跳过渲染以避免重复开销；报告明确 `not_run`，不会因此成为通过。规模下降以 `WORD_DOCUMENT_SIZE_REDUCED` 记录原值、新值及指标。质量报告沿用现有原稿／清洁稿SHA绑定，不接受输入里的关闭开关或自报页数。页面计数通过不代表已完成版面视觉或财务事实验收。

生产worker镜像已有LibreOffice Writer和中文字体，无新增数据库迁移或npm/Python依赖。新检查器、编写指引及必须执行的真实分页回归需随统一发布一起上线；新文件纳入发布验收工具指纹。未执行完整Linux发布门禁、真实模型与用户验收时，不能把本地开发测试当成发布凭据。

## 同日补充：篇幅拒绝先自动修复，不直接结束任务（#995）

用户明确要求篇幅门禁挡住后由worker重做。可信服务端确认 `WORD_DOCUMENT_SIZE_REDUCED` 后，在同一任务内最多追加两轮修复；同时存在可修复的章节、正文或格式缺失时一并反馈。原稿身份／输入冲突等完整性失败不授权模型重试。每轮将上一轮草稿或完整操作日志及可信质量报告交回模型，原始基线、材料、输入和修订时间保持不变；修复后的稿件仍独立通过全部交付检查才能登记成果。

每轮使用固定逻辑调用ID和独立提示快照，沿用已有持久化调用、结果、用量及未知调用对账。失败报告与候选绑定、每轮格式计划分别保存，worker重启后复用已完成调用，不能反复创建新任务或清空重试次数。每轮开始前和模型返回后检查暂停／取消。两轮后仍存在可修复篇幅失败，保留证据并以既有 `capability_not_ready` 暂停，原因 `word_size_repair_exhausted`；普通恢复不会重置预算或无限调用。页面沿用既有进度／暂停提示位置说明自动修复两轮后仍未通过，无新增页面或控件。

`WORD_PAGE_COUNT_UNAVAILABLE` 属于渲染基础设施异常，走已有有界检查重试，不额外调用模型改写；显式delivery-only恢复继续禁止模型调用。其他质量失败保持原有处置，不因修复轮次而绕过门禁。无公共状态枚举、数据库迁移或计费政策修改，真实模型用量继续如实登记。本次不重跑线上任务，开发完成后待统一验收与发布。
