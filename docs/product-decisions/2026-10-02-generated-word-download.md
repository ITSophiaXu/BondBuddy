# M1 双 Word 生成后直接下载

用户在 2026-10-02 明确调整交付标准：修订版、清洁版 Word 生成后返回页面供下载，不再以额外检查未通过让任务失败。本决定覆盖此前 M1 文档中将内容、修订一致性、包结构、基线或专业验收作为下载前置的要求。

- worker 仍按原始材料、锁定的项目输入与知识 MD 编制真实修订版和清洁版；不改成复制原稿、空模板或伪造修订。任务保持一次 Codex CLI 执行。
- 输出两份 Word 即进入私有存储与交付。取消应用的接受/拒绝修订一致性检查、完整 OOXML/XML 解析及基线文件先行交付。`baseline.docx` 和 `delivery.md` 为辅助资料，缺失不阻断双 Word。
- 保留文件存在、大小边界、声明文件为普通文件及 DOCX 容器标识、归属、不可变输入、私有存储、下载授权和 SHA-256 读回；不将空文件、其他账号文件或已丢失的 Blob 写成可下载。
- 新证据使用 `generated-word-download-v1`：`validation_scope=file_availability`、`content_review=not_performed`，旧检查项均为 `not_run`。为兼容既有存储/下载契约，`quality_status=passed` 仅表示**该 validator 规定的文件候选要求满足**，不表示内容、修订、排版或业务已验收。旧 `ooxml-docx-v1` 证据不修改，也不将旧失败改写为通过。无数据库迁移。
- `word_delivery` 新增 `delivery_policy=generated_pair_v1` 与 `content_review=not_performed`；基线成果 ID 可缺省；未测的修改/表格/待确认数量及哈希为 null。页面沿用当前成果/下载页面与两个下载按钮，文案为“修订版和清洁版已生成，可以下载”，不再显示检查通过或虚构 0 项。
- 对已完成模型调用、因 Word 交付失败的单个生产任务，运维命令 `reconcile-run deliver-generated-pair <run_id>` 显式恢复**交付**。核对原失败事件、唯一完整结果、计量用量及项目未删除；保留原事件、结果与失败证据，新增恢复审计。恢复分支只读取原有结果，绝不发起新模型调用。已取消或不存在可复用结果的任务不恢复。

验收：两份生成文件可经原账号页面下载；基线/XML 大小/旧一致性拒绝不再阻断；原失败和用量保留；恢复模型调用数不增加；缺文件、存储哈希不符、跨账号获取仍失败。页面成功表示文件已交付，不代表行业、内容或 Word/WPS 验收。

对应 #35、#361、#448。部署 commit、真实原项目下载与测试证据分别记录，不以本决定冒充已上线。
