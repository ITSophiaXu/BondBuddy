# 募集书更新的审计 PDF 清晰度检查与拦截

后续误拦修复：低 DPI 不再单独触发拦截，v2/v3 改为重测，详见[可读性风险判断](2026-11-18-audit-pdf-readability.md)。以下为该修复前的历史决定。

用户于2026-11-18明确要求：上传审计报告PDF后检测分辨率，低清时提示重新上传电子版，不能进入下一步。此决定覆盖同日早先“仅提醒、不拦截”的对应范围。关联 #1603、#1593。

- 适用 kind=update、role=audit、media_type=application/pdf。其他任务、其他角色与非PDF材料保持原规则；既有run与执行幂等重放保留原输入。
- 原件先核验归属、版本、哈希并保存，再通过独立持久化轻量作业检查。不恢复统一编制已取消的上传全文预解析或OCR，不调用模型、不计费。
- 默认沿用低于200 DPI且低清图片联合覆盖页面至少50%的规则；PDFium浮点矩阵的0.0001 DPI量化容差修复名义200 DPI误报，不放宽业务阈值。v1结果不直接用于拦截，v2重测。
- 材料行展示问题PDF页码、清晰度太低会影响财务数字识别，以及移除该文件并重新上传清晰电子版审计报告的动作。低分辨率不等于必然解析失败，不能据此声称失败根因已解决。
- 待检测/检查中暂不能继续；partial/unavailable不能冒充已通过，也不误称为低清。提供重试检查，重试保留旧终态回执并创建新检查作业。新版本/新字节重新检查。
- 页面下一步/开始与后端输入锁定、报价、新任务提交一致拦截。校验当前项目全部未删除审计PDF，直接请求省略低清附件不能绕过。删除问题文件后恢复检查其他文件；仍须满足审计报告必填规则。
- 原型在现有材料行与操作区表达，不增加新页面或导航：product-prototype/public/audit-pdf-quality-gate.html；实现apps/web/src/material-processing.ts、main.ts。截图与完整页面行为分别测试。
- 无数据库迁移、无新增生产依赖。开发自测、用户验收、统一发布分别记录。

同日性能补充：用户要求无需全页检查，见[快速抽查决定](2026-11-18-audit-pdf-quality-sampling.md)；原低清更换和异常拦截继续适用。
