# 固定单节点执行容量（2026-11-22）

用户决定：当前只使用一台腾讯云执行机器，不再自动扩容。主站和唯一业务 PostgreSQL 保持现状；执行任务继续使用既有持久队列、租约、模型额度、成果保存和节点安全协议。

## 运行行为

- 执行容量固定为一台已登记的常驻节点。该节点由现有的私有部署配置按准确实例 ID 绑定。
- 自动控制器不创建新实例、不启动已停止实例，也不因空闲自动排空/停止常驻实例。
- 单机槽位耗尽时，任务留在现有队列等待；不得丢弃任务、转成失败或重置模型调用。
- 唯一节点停止、失联、身份不匹配或未 ready 时，关闭新领取并记录可告警原因。运维人员核对运行状态、任务租约、模型调用和云端回执后，人工恢复同一节点；需要更换实例时沿受控维护流程执行，不自动补建。
- 原租约续租、checkpoint、模型未知结果保护、排空证明及云操作对账保留。固定容量不放宽全局/单节点并发、预算或授权限制。

## 切换要求

切换前需确认目标常驻实例、镜像/源码和服务 ready；将其它执行节点按既有安全排空流程完成停机；确认没有未决 Run/Start/Stop 云操作。随后将私有池配置和数据库策略都固定到同一个实例、`max_owned=1` / `max_nodes=1`、`min_running=1` 与 `phase=fixed_single_node`。不存在的实例、旧节点库存或策略版本不一致时，控制器 fail closed 并告警。不得在切换期间修改主站或数据库拓扑。

本决定覆盖 [腾讯按量执行池 runbook](../runbooks/tencent-execution-pool.md) 中“自动阶段停至零台”的当前策略。历史需求 #1361 和历史容量记录保留作背景；它们不再授权自动扩缩容。
