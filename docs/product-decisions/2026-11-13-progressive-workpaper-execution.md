# 底稿试生成、逐份交付与失败隔离

用户于 2026-11-13 要求依据五张 UX 截图缩短首份结果等待时间，并让单份失败不阻塞其余底稿。需求 [#1307](https://github.com/ITSophiaXu/BondBuddy/issues/1307)，下载冻结进度缺陷 [#1308](https://github.com/ITSophiaXu/BondBuddy/issues/1308)。界面说明见同目录 `2026-11-13-progressive-workpaper-ui.md`。

## 固定范围与确认

公共契约从原始目录的文件夹层级或编号派生章节；章节 ID 取完整目录中的稳定顺序。分组基于完整目录，勾选子集不重新编号。无章节信息的目录作为一个分组，不套用截图中的名称或数量。

提交时固化选择、章节顺序、原稿版本、要求、模板与报价。前八个已选章节各取首份选中文件作为试生成范围。其余项按章节及原目录顺序排列。文件数量来自本次目录。准备页和旧底稿入口使用同一公共 helper，服务端重新校验精确章节排列。

试生成结束且还有未开始项时，批次持久进入 `paused / awaiting_confirmation`。继续剩余使用带修订号及请求 ID 的独立动作；普通恢复不能绕过。重放确认只读取已有回执，不撤销其后的人工暂停。只有用户确认后，剩余项自动推进，不重复要求逐批确认。若试生成已覆盖全部选择，则直接结束。

重试仅纳入失败集合，成功文件及账务不重新执行。试生成失败重试结束回到质量确认；取消后重试不放行原本未开始的队列项。重新选择开启新一轮准备，原批次成果保留。

## 执行与质量

新系统模板、无补充材料的直接生成任务使用 `progressive_item_v1`。完整原稿、表格、附注、脚注和图片共享一次不可变提取，由持久顺序首项在既有队列租约内负责，其他项等待缓存时不长期占用数据库连接。试生成每份独立规划，首份不等待其他计划。确认后的非试生成项按固定章节拆成至多八项的小组，每组共享一次完整资料审阅；每份仍独立校验、缓存、Word 渲染及成果发布。末组只有一项时按单份处理，不把整章或整个文件包作为交付屏障。

组计划由可信程序投影到单份计划：保留原始排除说明、完整阅读记录、表格及上下文扩展、图片核对；仅将已明确归入同组其他项的事实列入当前项的额外排除记录。未映射的披露不能凭空补成“无关”。单份内容、计算等错误只记录该项失败，其他通过项原子保存。整组格式或覆盖不足使用显式内部 fallback 回执，然后逐份独立规划；该回执不是文件成果，供应商调用用量仍记入原持久日志。

计划表以 owner/batch/item 为键，组回执只存每项计划哈希或错误，关联不可变范围、完整来源和方法哈希。固定小组首项是唯一规划作者，崩溃后由同一运行的持久模型日志回放，其他项不接管模型调用。短事务按 run、job、小组锁的顺序提交缓存；重试和崩溃回放不能覆盖已接受的计划。失败项的显式重试重新规划该项，不永久重放组错误；其他已成功文件不重新收费。

每项都保留全源阅读与跨章节事实映射，保留原有内容与格式检查。解释文件继续区分业务不适用、资料不足及外部原始证据，不能因为未披露就推定不存在。已有成功文件立即进入授权预览、单份下载及 ZIP 清单。

同批最多两份并发；API 和数据库均校验持久化 manifest、owner、batch、item 及规范项目作用域。仅同批不同项获得例外，其他批次和业务仍受原互斥规则约束。按已有逐份报价、预留、结算和退款执行；试生成不预先收取整个文件包费用。

暂停、停止阻止新的调度，已开始的至多两份允许收尾，前端继续追踪并显示这些结果。停止后未开始文件属于未生成，不是假装失败或已完成。

## 错误边界与兼容

确定的单份模型输出、内容或渲染错误可单独失败。源字节/哈希、权限、模型能力、账务、存储、租约及供应商对账不明等公共阻断不得伪装成单份错误继续消耗整批。`stopped` 本身不证明失败，必须核对当前 item/run/job 的持久调用状态；取消、租约失效和待对账均不能凭回调推断安全重试。

公共故障已明确结算为终态失败时，等待该作者的已启动项安全失败，不重新调用整组模型；用户可显式重试失败文件并回到原阶段。试生成中断后先补完试生成，仍须质量确认。若子任务仍处于暂停或待对账，则通过“查看任务”处理，普通批次恢复不会跳过这些保护。

旧批次没有 progressive 字段，保留 `shared_batch_v1` 和原动作语义。自有模板、补充材料及既有评估模式沿原材料感知作者路径，但新批次仍遵循试生成关卡、独立文件与并发限制。迁移新增字段/表和精确的同批互斥例外，不重写历史输入、成果或计费记录。

## 性能证据与交付

本改动移除“全批计划完成后才能交付首份”的屏障，以最多两份并行降低独立文件的串行等待，并通过续跑小组复用审阅降低逐份模型重复读取开销。真实模型的整批总耗时仍需测量，不能仅凭合成测试承诺固定加速倍数。回归分别核验首份先于其他计划可下载、共享提取次数、小组模型调用次数、并发上限、失败后余项推进及确认等待；报告清楚区分合成模型与真实供应商调用。

本批新增迁移 `0175_workpaper_progressive_batches.sql`、`0176_workpaper_progressive_plans.sql`、`0177_workpaper_progressive_groups.sql`，无新增 npm 依赖。集成时须使用同一固定版本的 API、worker、Python helper、运行技能和网页；先完成迁移，再启用新入口，避免旧 worker 消费新执行模式。与前一轮界面 PR #1301 的前端重叠由集成工作区处理，不混入其他 chat 未提交文件。

开发和自测、统一本地集成、用户验收、生产部署分别记录。本任务只交付代码、迁移和测试证据，不执行生产发布。
