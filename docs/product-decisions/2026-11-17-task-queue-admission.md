# 任务提交与执行队列（2026-11-17）

用户确认：可以同时提交多项独立的募集书更新任务，系统先接收并排队，再按执行资源调度。本决定覆盖旧的每账户 2 项、全站 4 项活动任务提交限制。

- preparing、queued、running、validating、delivering 的任务数量不再作为拒绝新任务的原因。旧 BB_TRIAL_ACTIVE_RUNS_PER_USER、BB_TRIAL_GLOBAL_ACTIVE_RUNS 环境值和注入配置不再生效；管理员 DTO 保留兼容字段并返回 0，表示提交数量不限，不表示模型执行不限。
- 认证、材料与输入版本校验、报价、余额/预留、请求幂等、账户停用及模型紧急停止仍按原规则执行。队列接收不代表免费，也不取消已经认可的积分合同。排队不会触发模型调用或按运行时长收费；取消排队任务释放其原有预留。
- 使用现有持久队列，保留 queued/running/paused 等状态及逐任务暂停、恢复和取消接口。不增加第二套队列，不为每项任务创建模型进程。
- 节点任务租约与共享模型许可继续限制实际执行。生产当前全局模型并发为 8，但该数值属于执行池策略，本次不写死或修改执行容量。租约所有权、epoch/session、未知供应商结果及实际进程退出证明继续有效。
- 领取时优先考虑已占执行槽较少的账户，再按提交时间和 ID 排序。编制/复核任务与复核助手都计入账户占用；领取短事务串行化该选择，防止同时领取都使用旧计数。正在执行的长任务不被抢占，新账户在下一个可用槽参与调度。
- 来源项目关系保留用于归属和不可变材料追溯。不同目标项目共用同一来源材料，不再长时间互斥；一个来源任务暂停也不阻止其他目标。已有同一目标写入保护和同批次子任务身份/窗口保护保留。这不等于任意两个写入同一目标的请求都可以覆盖成果，也不改变诚信等业务共用目标输入指针的问题范围。
- 旧 TRIAL_QUOTA_EXCEEDED 拒绝记录保留审计；原请求在新政策下可重新提交，同一执行键不能换绑输入，重复提交只产生一个 run 和一份预留。
- 健康检查保留队列积压、心跳和错误率告警，不再把正常排队数量视作旧任务额度耗尽。旧错误码和前端解释保留兼容旧服务/历史记录。
