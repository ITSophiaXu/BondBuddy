## 页面与操作

左侧工作区构建 Agent 的完整任务输入，并阅读成果本体；右侧 Agent 始终可用，负责理解、澄清、讨论、执行过程和成果入口。取消收起及全屏助手。窄屏按既有组件风格连续排列工作区和助手，保持消息输入可达，不另设抽屉开关。

默认可直接在 Agent 问答、上传附件、选择项目、切换或新建话题。左侧保留文种选择和已有来源／分析成果，没有 QA 任务输入表单或 tab。简单回答不用创建空成果。选定文种，或明确准备正式更新／复核后，才展开对应任务输入；只显示该任务需要的来源、字段、模板和材料分区。切文种保存各自草稿，不一次罗列五套材料。

取消各业务工作区的补充意见／补充要求 textarea。用户自然语言中的明确重点、限制和字段更正保存到准确草稿；左侧只读展示“助手已采纳要求”，同时保留来源消息。预置要求标“系统默认规则”。问句、助手建议和普通分析不自动采纳。尚无正式任务的明确要求保存为话题待绑定要求，准备任务时显示适用对象并仅绑定一次；有歧义先澄清。

执行按钮旁提供“与助手讨论”，带入当前任务类型、文种、来源、模板、期间、范围及草稿引用，聚焦消息框。该动作不发送消息、不执行、不改变范围，保留已有未发送文字及段落引用；业务上下文与选文引用分别显示。切换任务／准备新任务／继续改稿后，讨论对象更新到准确草稿。

## 资料、草稿与固定输入

同话题的工作区和 Agent 上传进入同一授权资料库，QA 可访问；每个正式任务另存用户可核对的采用清单。模板、专属证据及其他文种要求不因同话题而自动采用；新话题不继承旧资料。

“这份募集书”优先解析到用户最近明确选择的来源；无明确来源且候选唯一才继承，否则列候选澄清。打开阅读标签不等于选择执行来源。关联版本后再上传并明确改用新稿，后续任务用新稿；保留原项目归属以校验执行互斥和权限。关联项目显示实际版本、发行人、品种、更新时间与是否完成，草稿／原始稿不冒充已完成更新稿。

任务提交固定输入版本及 hash、采用材料、源稿、模板、规则、目标、报告期、要求及实际范围。草稿、讨论引用和当前 run 快照为不同对象。制作中新增材料或要求保存到下一任务草稿，旧 run 不变；“准备新任务”打开已有草稿，不重置。仅解释固定输入中既有术语且不改变证据、目标或范围的运行澄清，可按原契约作为附加事件继续同一 run；改变任务内容必须新输入并再次明确执行。

“继续改稿”明确选定准确成果底稿，幂等复用该续改草稿，保留已存要求。编辑底稿与原始募集书生成来源分别记录，连续版本仍能追溯原来源。旧讨论引用不能覆盖新选底稿；若用户要求改“这段”而引用版本与底稿冲突，先澄清，不执行。局部修改固定 artifact、准确版本、变体、anchor 与引用原文，不能扩大为全篇；无法定位先追问。

## 发送、执行、互斥与费用

上传、选文种、补字段、保存要求和澄清只准备，不启动。用户明确按已展示的有效价格执行，必要输入和授权齐备且成功预留时，按钮与自然语言执行共用同一持久任务路径；无需重复形式确认。价格、执行对象或范围尚不明确时，先展示或澄清。缺项回答只回填，不因为资料终于齐备而自动执行；保留原请求，用户再次明确执行才开始。

意图判断针对整句：分别识别执行动作、对象和局部限制。“请生成法律意见书，保留待核事项，不要生成签署页”可以生成正文；“补充资料已经上传了，请开始生成法律意见书”是执行。“如何生成”“先别生成”“不要复核”不执行。跨文种指令先确定目标草稿再回填字段。“如果缺资料请告诉我”不能抹去句中主执行请求，但缺资料时仍只保存并澄清。

从任一入口提出其他业务需求，使用同一助手承接，在工作区显示目标业务的准确输入和报价；不偷偷复用当前页面旧任务。例如复核页要求更新：区分“根据准确报告修正原稿”与“更新到新报告期”，分别固定报告依据或目标期间、原稿及材料。已有完整执行授权可同次发送启动；缺报价、资料或含糊范围先展示／澄清。新稿不等于复核通过，原报告保留。本目标取代旧 M3 助手一律先提议再二次点击的新增交互口径，旧任务／协议仍按其原版恢复。

同项目的更新、复核、修订及材料生成执行互斥，包括跨话题从该项目成果继承的任务。活跃任务期间保留新请求及草稿，说明阻塞的任务，不创建第二任务、不自动排队；任务结束后须再次明确执行。相同 `execution_request_id` 返回同一 run。单纯 QA 与草稿保存仍可进行，不能借 QA 启动冲突文书执行。

费用继续沿用 M2、原 M4 的 Q00–Q07／文书类别和已确认价格配置；10 月 6 日业务任务积分决定覆盖旧 M3 免费口径。每轮依据本次实际任务分类，不继承上轮高系数。不新增费率，不把合成测试价格用于生产。执行前展示本轮价格与余额；运行／结果展示预留、扣费或释放。纯保存、必要澄清、产品帮助、纯拒答、无结果查询、平台纠错、已有回答导出／成果下载和内部恢复不另收费。有证据且回答分析请求的“不确定”不一概视为拒答。余额不足保留草稿，充值返回不自动启动。

组合文书保留 M4 原范围：一次共享事实提取，各文书独立编制、状态、交付和失败重试；整个组合一次预留和最终结算，全部关键成果可交付才成功。部分失败先重试，最终无法完成全范围释放预留，不把部分文件自动拆成付费里程碑。用户明确选择独立任务时才按独立任务执行。

## 正在制作、成果与恢复

真实 run 创建后工作区出现“正在制作”，显示任务及固定输入；右侧同 run 任务卡显示真实阶段和服务端白名单工具事件。无细分事件就显示已有真实阶段，不模拟百分比／预计时间，不透传 CLI 原始日志、内部路径、prompt、密钥或隐藏推理。已完成动作／任务默认折叠，执行中保持可见；输入框易达，用户回看不抢滚动。

当前正在输入时打开新制作标签；当前正在读旧文件、报告或来源时只增加入口，保留标签和阅读位置。完成且主成果可读时制作标签原位成为真实 artifact；不重复新建同成果标签。正文、编制说明、修订版和清洁版分别绑定真实文件和准确版本；同轮双 Word 使用同一交付版本，不冒充两个版本。预览读取实际 artifact，不能用旧报告或聊天摘要冒充新稿。预览失败保留下载和重新加载，不把已交付成果改成生成失败，不重跑。关闭标签只关闭视图。

生产持久化完整话题、消息与修订、资料授权／来源、文种草稿、未发送文字、任务与事件、成果引用、标签及阅读状态。服务端业务状态为权威，分页／摘要不删原文与未解决冲突。刷新、重新登录、worker 重启恢复原调用／任务／账务，不重跑、不重复费。保存超限／失败和恢复损坏均提供可见原因及重试，保留已有记录与当前内容，不静默清空。原型 16KiB 主机快照 codec 仅为示意限制，不作为生产方案。

## Codex CLI 边界及交付

M4 的 QA、对话理解和文书编制继续由服务端 worker 调用 Codex CLI。平台维护话题／草稿、上下文清单、不可变输入、执行幂等、租约、检查点、权限及账务；不要求用户电脑安装 CLI，不改成 Responses API／SDK 或浏览器直连模型。运行时显式载入固定助手及文种 Skill，记录其版本，技能不能扩大工具或文件权限。

模型只能在当前授权任务工作目录内读取已采用资料、写规定成果；确定性财务计算、解析和文件导出可作为受限工具。实际 web search 与原生文件编制是否能在当前 CLI 配置同时使用，须通过真实探针和完整调用记录核验；现有模式限制属于实施工作，不能用成功样例或模型自述代替已执行工具证据。复用实际已有适配器，公共 DTO、状态与事件在 `packages/contracts/` 唯一定义。

保留 prompt/input manifest、模型及调用配置、CLI／Skill／模板／规则版本、真实尝试、usage 和文件 hash，缺 usage 记 `unknown`。五文种仍交付真实可编辑 DOCX 与独立编制说明；私募／小公募／大公募摘要、DFI 阶段用途、多承销商职责、模板作用域与异常、专业 QA 全范围及组合执行不能因原型未覆盖而删除。
