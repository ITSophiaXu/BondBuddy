# 2026-09-30：M1 简化、M2 付费边界与更新成果展示

依据：产品负责人在当前会话中的明确要求，并进一步确认“M1 支持两类自带募集书”。第 1—4 节（含 4.1）为已确认范围，覆盖此前与之冲突的自动识别、多轮对话及 M1/M2 参考库要求。第 5 节将原有同项目进度、摘要与 Word 下载细化为**展示建议稿，布局待产品确认**。用户随后明确：原始材料直接交 worker（Codex + DeepSeek）处理，不建设独立财务数据提取服务，也不要求预先结构化财务数据。本文是需求，不是实现、部署或验收通过证明。

## 1. 阶段范围（已确认）

| 阶段 | 本次范围 | 不作为该阶段前置 |
| --- | --- | --- |
| M1 | 账号与项目；用户自带本企业历史募集书或相似企业募集书；手填原稿品类和报告期；表单末尾补充要求；全文更新、真实进度与 Word 交付；受控试用 | 原稿品类/报告期自动识别、多轮聊天、募集书库建库/推荐 |
| M2 | 为上述两条自带稿路径增加余额、充值、更新任务扣分及必要的支付/结算保障 | 募集书库推荐、余额现金退款、用户消费记录页面 |
| M3 | 增加无可用自带稿时的募集书库推荐/匹配、建库与持续维护；原定付费复核仍保留 | 不因本次调整取消原定 M3 复核，也不把库授权提前变成 M1/M2 阻碍 |

M2 保留最小后台账务记录、防重复发分/扣分、失败或取消释放冻结积分、支付差错纠正。取消“余额退款”不等于失败任务可以扣费。此次没有新批准积分单价、兑换比例、固定系数或活动排期。

M1/M2 完全没有可用自带稿时，保留草稿，简洁提示“请上传本企业历史募集书或一份相似募集书；募集书库推荐将在 M3 提供”。不展示虚假推荐，不静默调用库，也不以缺库阻挡已有自带稿的项目。

## 2. 上传募集书时填写什么（已确认）

保留原项目的目标市场、目标品种和目标报告截止日。以下是**上传的原募集书信息**，放在对应募集书上传区，不与“本次更新目标”混为一组：

| 字段 | 交互与规则 |
| --- | --- |
| 稿件用途 | 区分本企业历史稿与用户自带相似稿；沿用现有“有/没有本企业历史稿”及固定分区，不新增材料技术分类面板 |
| 原发行市场 | 上交所、深交所、交易商协会 |
| 原品类 | 随市场联动：沪深为普通私募、小公募、大公募；协会为 PPN、MTN、CP、SCP、DFI · 储架发行；不另造公共枚举 |
| 原报告年度 | 多选实际覆盖的完整年度，例如 2022、2023、2024；可增减，不固定要求三年 |
| 原最新一期 | “无中期”或年份＋一季度/半年度/前三季度，例如 2025 年一季度；这里是财务报告期，不是第几期债券，也不是签署/发行日期 |

填写示例为 synthetic，不代表任一客户原件。年度与一期须去重，保留用户选择的完整集合；原有最新目标截止日仍独立填写，不能由原稿信息覆盖。“原稿覆盖哪几年”不是让用户手工选择本次更新范围或计费期数。

保存原稿信息的填写人、时间、材料不可变版本及信息修订版本，语义为“用户提供”。不要求机器先识别同一字段或提供原文锚点，才允许保存/启动；也不得把手填信息写成机器已识别、财务已审核或审计机构已确认。

格式、字段组合、文件可读性、资源归属、输入一致性和实际执行能力仍校验。材料替换、原信息或目标修改使未执行的比较/估算失效；已执行输入及旧成果不覆盖。旧自动识别结果可作为历史记录保留，不能再成为这三个字段的强制准入前置。若旧项目缺手填信息，只提示补本处必要字段，不重跑旧识别/确认问卷。

不建设独立财务提取服务，不要求用户先等财务表、事实库或画像生成。原始 DOCX/PDF/Excel 等材料随版本化输入直接交 worker，由 Codex + DeepSeek 在更新任务中读取、核对并使用；必要的文件读取/OCR 是 worker 内部工具。技术上需要将文件转成模型可读内容时在任务内完成，不冒称模型 API 原生支持任意格式。实际不可读文件与缺少预提取结果分开处理。

## 3. 补充要求代替多轮对话（已确认）

在“提供项目信息”的最后增加一行选填输入框，标签为“本次更新的补充要求”。示例占位文案：“如：重点说明偿债安排，保留原有风险披露。”不预填内容，也不把示例存入项目。

- 输入随草稿保存；只有服务端保存成功才显示“已保存”。刷新、重开及重新登录可恢复；失败保留用户输入并给出重试。
- M1 移除右侧多轮聊天、发送按钮、助手回复/追问、消息驱动执行与聊天流式状态。输入框不是伪装成聊天的备注发送器。
- 唯一启动动作仍是“开始更新”。输入“开始”“继续”等文字不自动创建任务；不新增“添加到项目”或第二次报价确认步骤。
- 执行时将该要求的准确版本与项目、原稿信息及材料一起锁定。运行中编辑只影响下一次执行，不静默改写当前任务。
- 已保存的旧消息不删除、不丢失：旧 run 保留原消息引用；待执行旧项目只迁入用户要求，保留来源/顺序，不把助手输出当成用户确认。有无法合并的相互矛盾要求时保留待处理状态，由用户在这一个输入字段修改，不自动取最后一句为真。
- 完成后要改稿，回到同一项目的表单/材料修改，再明确开始新一轮；无需多轮问答。局部材料疑义在成果对应位置和摘要标记，不变回上传前必答问卷。

独立 QA、复核对话及其他后续多轮能力按各自阶段需求另行交付，不再依赖“先完成 M1 聊天”。

## 4. 两类自带稿的处理与交付（已确认）

| 路径 | 如何使用原稿 | 交付边界 |
| --- | --- | --- |
| 本企业历史募集书 | 作为本发行人的原文基线，结合新财务资料与目标更新全文 | 真实 Word 修订版＋清洁版；历史 PDF 重建边界继续披露 |
| 用户自带相似企业募集书 | 仅参考结构和写法；用本企业财务、业务材料及要求编制募集书 | 可编辑的新稿；不把参考企业信息、数字、风险、签章带入，也不制造相对参考企业的“本企业修订” |

相似稿不重标成本企业 historical，不自动变成商业参考库内容。使用用户指定相似稿不要求先取得“三大主营业务匹配”或库发布结果；可读性、目标适用性和发行人事实隔离仍须成立。具体行业内容不因选择了品类而自动被核验。

### 4.1 原始材料直达 worker（已确认）

执行链路：上传并保存原文件 → 用户填写源信息/目标及补充要求 → 明确开始并锁定原文件版本 → worker（Codex + DeepSeek）读取资料、完成全文更新与必要核对 → 检查并交付 Word。

- 上传前后只做真实格式/大小、可读性及归属/版本等必要校验；无需先完成独立财务数据提取、结构化三表/事实库或材料画像才开始。
- worker 可以调用文档读取、表格定位、OCR、确定性计算和 Word 工具；工具属于更新执行内部，不另建用户步骤、独立财务提取服务或第二次收费任务。
- worker 按完整文件/章节处理，不截断尾部后声称全文完成。保留所用材料版本、必要原文位置、真实调用和任务日志；不能用模型自述替代文件读取或数字核对证据。
- 财务数值、期间、主体、单位/口径的核对随更新完成；不确定内容在结果对应位置标记，不编造、不挪用相似企业数据。若实际无法读取必要原文，则说明具体材料问题。
- 已有解析结果或缓存可在版本、权限一致时复用，但缺少缓存/结构化事实不构成新的启动前置。原有 parser/OCR/事实模块可复用为 worker 工具，不以已有实现倒推要求另建服务。
- #13/#14/#15/#31/#33/#35 对齐这条执行链路；旧“财务提取未完成”门槛须迁移，不只是隐藏前端状态。交付检查和实际文件/权限/输入校验继续保留。

## 5. 更新过程和结果如何展示（展示建议稿）

沿用一个项目工作区：项目资料、更新中状态、结果和再次修改都可在同一项目恢复。原型 #85 中“同项目、真实进度、旧成果保留”的要求继续适用；常驻右侧聊天被第 3 节取代。#474 的新增历史卡、位置和第三个“下载有效基线”按钮并未因此自动获批。

### 5.1 更新过程中

| 状态 | 用户看到什么 | 可做什么 |
| --- | --- | --- |
| 准备/排队 | “准备更新”或“等待处理”，真实开始时间/排队状态 | 离开页面后回来查看；实际允许时取消 |
| 处理中 | 当前业务阶段：整理材料→更新正文→检查全文→生成 Word；当前章节/实际已完成数量仅在后端确有对应数据时显示 | 继续查看状态；不要求留在页面等待 |
| 需要处理 | 一个明确的短原因及对应动作，例如补清晰文件或调整项目信息 | 返回相应字段/材料；变更业务输入后开始新一轮 |
| 暂时不可用/失败 | 区分服务暂不可用、材料不可读、任务失败；保留原资料和旧成果 | 仅提供后台实际支持的重试/返回修改；同一未变化条件不反复显示无效“继续” |
| 已取消 | 明确本轮已取消，旧成果仍可查看 | 修改后重新开始；不暗中恢复已取消任务 |

不用模型日志、证据编号、英文 warning、内部检查点或聊天消息解释进度。没有真实总量时只显示阶段和已处理数量，不编造百分比/倒计时。正在生成 Word 仍是处理中，只有成果可取得后才显示完成。

### 5.2 更新完成后

按下面顺序展示，默认聚焦最近一次成功成果：

1. **完成状态**：完成时间、对应资料版本，以及“工作稿已生成”；有未解决内容时显示“含待人工确认事项”。输入版本不冒称项目统一文档版本。
2. **本次更新了什么**：原稿品类/报告期→本次目标；按实际改动简述财务期间、主要章节和条款，不列未经执行确认的修改或虚构统计。
3. **仍需确认什么**：简洁列出事项、所在章节/位置及所缺材料或信息；与 Word 内标记一致。展开后可查看完整清单，但不暴露后台技术诊断。
4. **下载与再次修改**：本企业历史稿提供“下载修订版”“下载清洁版”；相似稿路径提供“下载募集书”。已有编制说明通过说明入口取得。另保留“继续修改”，返回本项目资料与补充要求。
5. **已有成果**：既有入口可回看以前的成功成果及完成时间。新一轮更新中、失败或取消时，上一版成功成果仍能下载，状态明确区分“本轮失败”和“上一版成果”。下载不触发模型或再次扣分。

M1 不建设网页内逐条接受/拒绝修订的 Word 编辑器；细看增删在 Word/WPS 中完成。最终布局、摘要展开方式和旧版入口需补桌面/窄屏原型对照后确认；此表不批准 #474 现有偏离。
