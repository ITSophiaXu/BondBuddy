## 最小用户流程

1. 复用 M1 项目、材料和材料页末尾补充要求，保存不可变输入。
2. 在原开始区域展示任务类型、固定积分价、可用余额和差额；用户明确确认开始。
3. 积分不足：不冻结、不创建编制 run、不入编制队列，保留材料。免费上传处理不因此停用。
4. 从当前项目进入现有“积分与充值”页面，选档并在真实渠道付款；到账后返回原项目，由用户再次确认开始。支付回调不启动任务。
5. 余额足够且输入／价格仍有效时，一次事务冻结 P、持久化 run 与队列／outbox。并发和重复提交不可透支或重复冻结。
6. 清洁版与修订版 Word 已生成、私有文件交付可用后结算 P。沿用 2026-10-02 直接下载决定，不恢复内容、OOXML 或基线检查门槛。
7. 终态失败／有效取消释放；平台恢复复用同一任务和冻结。已释放任务的纯交付修复不重新扣费。

调价形成新版本，记录生效时间、操作者和理由。启动时锁价，旧任务不变；尚未开始的旧报价有变化时重新展示并确认。真实模型成本单独保留，unknown 不写零、不补扣固定价，也不因缺用量长期冻结一个已有确定成果的任务。

## 钱包、支付与运营边界

充值档位不变：50/500/2000/10000 元对应 5000/52500/220000/1150000 积分。整档购买积分长期有效。有效赠送批次先按到期时间使用，随后购买批次 FIFO。已冻结赠分跨过期可用于原任务；平台失败导致释放时已过期，追加至少七天补偿；自行取消不延长。

签名、商户、订单、币种、金额及真实支付成功必须核实；回调和主动查询共用幂等发分事务。付款已成功但数据库写入失败，可按同订单补发，不要求用户再次付款。不设置用户余额退款、消费历史、专门调价页面或新营销活动前置。发票仍人工处理。

M1 历史任务不追溯收费；真实旧权益按原来源凭证及有效期保留，演示 JSON 余额不作为真实权益。M3 本次不收费、不依赖 M2；M4 规则未由本决定修改。
