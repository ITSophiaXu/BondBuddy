# 2026-10-11：有积分即可开始，动态扣减与充值续跑

用户本次明确要求：余额大于 0 就可开始募集书更新，运行中扣减积分，余额归零弹出充值提示并暂停，到账后继续同一任务；AI 返回的中间工作状态展示在更新进度中。本决定覆盖 #684、#631 和《募集书实时进度与累计积分》中“开始前必须足额、预留整笔总价、运行金额仅为应结算额”的旧规则。复核、M4 文书、问答及既有任务不改费。

- 新编制/更新任务锁定原八档总价，`authoring_balance_v2` 不冻结整笔余额。0 积分不创建任务；1 积分也可创建。报价 shortage 继续表示与总价的差额，前端启动只判断真实可用余额，后端再次校验。
- 沿用既有有效租约时间与完成检查点的累计曲线及总价上限。每次服务端同步仅扣增量，最多扣至当前可用余额，钱包、任务回执和追加账本同步。同账号的扣款按账户锁串行，多个任务不能透支。排队、暂停和失效租约期间不计费。
- 归零立即冻结计费并持久化 `credit_pause_requested`，前端显示充值弹窗及持续可见的状态卡。已有模型调用需先保存其结果，期间如实显示“正在保存进度后暂停”；在持久检查点停下，不启动下一阶段。当前长调用可能尚未结束，不声称弹窗出现时供应商已经停止计算。
- 执行器扫描 `credits_exhausted`，确认服务端真实可用余额大于 0 且没有人工暂停后，自动重新入队同一 run，沿用不可变输入和模型/文件检查点。仅返回充值页、待支付订单、伪造回调均不恢复任务。任务取消后不自动恢复；用户明确暂停也不能被到账覆盖。
- 双 Word 已保存但尾款不足时，保存文件检查点并暂停。充值后直接完成剩余结算，不重新生成；未完成结算的文件仍受原有成功 run 下载约束。
- 主动结束保留已扣积分，无预留款可释放。平台失败/拒绝追加退款流水，保留原扣款历史；原赠送积分已到期时按原承诺延长七天。重复结算、回调和冲正不重复记账。
- AI 的 `BB_PROGRESS:类别 | 工作摘要` 投射为最多 240 字的明确用户可见摘要，随持久事件展示。思考文本、工具输出、材料全文、路径及密钥不作为进度转发。无新事件时保留真实“尚未返回新状态”提示，不生成虚假进度。
