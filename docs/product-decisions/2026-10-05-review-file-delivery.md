# 复核结果直接文件交付

用户于2026-10-05要求：“直接将codex cli的复核结果返回成可下载的文件即可，先不需要展示在UX上。”本决定覆盖 #56 / #55 中将结构化问题、引用与检查覆盖投影到页面作为复核交付前置的旧要求。

新复核：用户保存项目、材料与要求并明确开始；固定输入、知识MD和材料版本交给现有隔离Codex CLI，一次自主复核并生成报告。完整复核与针对旧报告的已选问题复核均可输出文件；不先要求CliReviewSchema JSON，不为格式重问整轮模型，不调用独立公开信息阶段后才交付。公开核验由本轮实际可用的CLI web search承担，未启用或未查到来源须在报告说明，不能伪造公开核验。

CLI可生成 `report.docx`；只有完整文字/Markdown时，由本地确定性导出器转为Word。页面仅显示任务状态及“下载复核报告（Word）”，不展示本轮问题列表、覆盖率、通过计数或逐问题修订操作。文件成功不表示专业结论全部通过。用户从下载文件阅读发现、依据、建议和未覆盖事项。

实际响应及声明的报告文件先存项目私有存储，报告缺失也保留已有响应以便诊断。保留项目归属、输入hash、只读原件、隔离目录、取消、租约、幂等、真实usage与私有文件回读/授权下载；不做正文内容、引用编号或JSON结构验收门。空结果、文件缺失或损坏的传输不能伪造成功。客户正文、报告与敏感日志不进入GitHub。

仅新提交的复核在输入中记录 `review.file_delivery.version=review-file-v1` 与知识原文/hash。旧运行、旧模型请求、旧结构化报告、旧修订流程及失败证据保持原协议；升级不自动重跑旧任务。新文件报告不伪造可供逐问题修订使用的结构化发现。

## 验收

- 原始上传材料与保存要求/知识准确进入隔离工作区，无需独立解析完成。
- 普通文字或CLI Word通过一次执行交付；不需要JSON，不虚构问题/引用和专业通过。
- Word生成后中断恢复复用持久结果，不再调用模型；重复提交同一请求仍为同一run。
- 下载内容及SHA与私有文件一致；跨账号/项目、旧输入hash、符号链接与字节篡改不能交付。
- 无结构化report记录时页面仍显示Word下载，桌面/窄屏可见、刷新保留，旧报告继续可读。
- 工程测试使用synthetic材料和CLI，与实际供应商调用、用户项目及Word/WPS专业验收分别记录。
