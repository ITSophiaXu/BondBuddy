# 模拟支付、充值与扣费链路

2026-11-05，用户明确当前没有付款 SDK，要求先开发模拟支付、充值、扣款整条链路。沿用 2026-10-30 的隔离本地测试决定，真实商户接入不作为本阶段开发与体验测试的前置。

在既有 `scripts/billing-functional` 中提供可操作的模拟收银台。产品账户创建真实订单后，测试者明确选择模拟支付成功、失败或关闭；未操作时保持待支付，查询与刷新不会付款。支持保存渠道结果后查单入账，以及 HMAC 认证回调入账。重复确认、回调与查单竞争必须只发放一批积分。

所有资金变化仍由产品实际 API、事务、锁价、任务及 PostgreSQL 账本处理。模拟渠道只保存渠道事实，不直接赠分、改余额或伪造任务成功。原路退款走既有退款申请、冻结、渠道提交、回调／查单及终态处理；处理中不显示已退款，失败释放冻结，成功只结算一次。未知响应重试保留原订单、退款申请及续费事件请求键。

当前商业订阅任务沿用 `outcome_cny_v1` 的实际预留与交付结算规则。另提供明确标注的按进度扣费专项，用独立的本地 API 配置和连接池执行既有 `authoring_balance_v2`：正余额启动、真实检查点扣费、归零暂停、充值后恢复同一任务、平台失败逐来源退款。专项使用标为 synthetic 的本地价格版本；不更改商业价格或线上任务策略。已存成果的尾款不足只恢复结算，不重新生成成果。

模拟入口仅由 loopback 测试启动器加载，要求专用数据库与实例标记、真实登录、Origin 与 CSRF。生产支付工厂、公共 provider 枚举、产品迁移和默认构建不加入模拟渠道。页面持续标注“模拟支付，不扣真钱”，合成成果不代表真实模型质量或真实商户验收。

使用步骤及验证命令见 [本地测试说明](../../scripts/billing-functional/README.md)。桌面验收采用 1440 和 1024 宽度；本次不扩展手机测试。
