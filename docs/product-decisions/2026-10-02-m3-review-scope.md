## 页面与常规操作

版本记录统一放在工作台项目卡内，查看复核/修订/停止/失败任务的状态、输入、材料、要求、范围和成果快照，进入准确的报告或成果版本。复核页只保留“材料与要求”“复核结果”，显示当前输入、来源报告和成果编号，不再设置版本历史标签或列表；必要的来源引用仍可查看。

常规流程可以完全不使用助手：上传/补充材料 → 开始复核 → 查看覆盖/问题/解释/依据 → 补证或选择修订项 → 核对范围 → 明确执行 → 下载成果。“查看解释”使用详情或弹窗；补证直接关联问题并展示重新核验范围。任务进度、加入/移出修订等使用页面反馈，不伪造用户消息，也不把点击日志灌入聊天。结果支持筛选和问题明细，不要求在线全文逐条接受/拒绝编辑器。

## 助手的五类场景

助手默认收起，用户主动打开或从问题“继续讨论”进入；桌面可并排、窄屏使用可收起抽屉。同一项目上下文贯穿准备、执行和结果，不要求转去独立问答页。

| 场景 | 示例与边界 |
|---|---|
| 业务口径 | “本节用母公司口径，偿债分析用合并口径”：关联章节/问题，明确范围和证据，不默认全稿统一 |
| 结论异议 | “旧名称是历史沿革，不能全替换”：保存理由与来源，保留原 finding，不直接改成通过 |
| 材料解释 | “变更证明从 2025 年 8 月生效”：绑定材料版本、问题、报告及日期说明，补充不执行 |
| 跨问题要求 | “债务金额和摘要一起改，F-005 先不处理，保留标题样式”：提出可核对计划，用户采纳才改变勾选，执行另行触发 |
| 运行中补充 | “新附注用于下一轮，本轮继续”：保存下一版并显示生效轮次，当前快照不变 |

普通发送仅保存/讨论或提出计划；即使表达执行意图，也先展示任务类型、范围及版本的执行入口，点击明确执行才建 run。助手不静默改动选择、结论或任务。问题级要求、草稿和补证动作同时绑定 project、report/version、finding 与相关材料版本；项目级/跨问题要求注明范围。切换问题、收起、刷新/重登不能丢草稿或改绑引用。

真实助手回复、追问与流式中断恢复由 #47 新交付，只复用 #18 已有的用户消息持久化/版本原语；不把 #18 当成现成多轮 agent，不依赖 M4 独立 QA。

## 执行与证据

- 执行前显示复核/修订/差异复核类型、范围、源稿/报告、输入版本及待补限制。修订包括被选问题的关联引用，关注重点不静默缩小完整复核范围；无可执行修改不建空任务。
- 同一项目同时只运行一个复核或修订任务；execution_request_id 保证重复点击、重试/恢复返回同一 run。保留归属、隔离、输入 hash、事务/outbox 和下载控制。
- run 锁定材料、规则、要求、来源报告/证据版本；新增只进入后继输入。停止/失败任务保留已占用版本，不能复用编号。关闭页面不取消任务。
- 严重性、结论、证据充分性、修订处理状态、任务状态和覆盖独立。异议已记录、已补材料、已修改均不等于复核通过；原报告/finding 不覆盖。
- 差异复核执行前列重核对象，结果区分本轮重核、沿用原报告、未覆盖/待补。沿用项保留来源版本，不能冒充本轮已核验或完整三维通过；完整再复核另行明确执行。
- 保留真实 DOCX 报告、原生批注、修订版/清洁版及 Word/WPS 检查；PDF 重建稿明确基线。发现严重问题与技术交付成功分别判断。
