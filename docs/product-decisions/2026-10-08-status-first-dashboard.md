# 2026-10-08 状态优先工作台

用户在本会话审阅可点击设计后明确选择“第一个推荐的状态优先”方案。此决定覆盖第 03 章旧工作台按业务入口重复铺卡的布局；不改变业务执行、计价或交付规则。

## 确认的布局与行为

- 顶部为待处理、进行中、已完成；按钮筛选同一列表。草稿和未完成任务归待处理，正在执行与排队归进行中，成功任务归已完成。内部测试稿不记为正式完成。
- 三个紧凑的开始入口分别新建更新、复核和材料任务，不与历史结果混用。
- 同一列表展示三类项目的当前／最近任务、类型、真实状态、最近更新时间和下一步操作；每个未归档项目一行。每次复核／修订的完整执行历史仍从版本记录查看。
- 草稿继续填写，运行任务查看进度，完成任务查看结果，失败查看原因。材料项目打开所选 run 的成果／进度，不回退到输入页或误展示旧成功文档。
- 从工作台进入项目后保持工作台导航，刷新和项目标签切换保留来源；返回恢复类型和状态筛选。原“全部项目”来源保持。
- 侧栏账号、积分及手机积分沿用现有实现；不增加聊天、QA 页面、确认审批或新的收费步骤。

## 数据边界

使用现有按账号隔离的项目分页接口，读完全部未归档项目元数据后才显示计数；去重、分页失败、退出／离页取消请求均有处理。只加载页面可见的运行任务阶段，取公开 Run DTO 已知阶段的安全文案，不显示原始日志，不推算百分比或 ETA。可见时每 30 秒刷新，回到页面同步。

首次读取失败时统计为“—”，不能将失败或部分页当成零／全部；后台刷新失败保留上次数据并明确提示。已完成计数反映服务端 succeeded，不新增交付判断。统计按当前项目任务计数，非累计执行次数；旧成功成果不会把新失败任务变成完成。
