# 2026-10-28 整批共享提取与编制

本决定落实用户本次对耗时和内容质量的要求，覆盖 2026-10-27 底稿决定中“每个条目完整重读募集书、各自编制”的执行方式。正文仍不写来源；这一点以用户最新纠正为准。

## 执行方式

新建直接生成批次在不可变 manifest 中固定 `execution: shared_batch_v1`。首个条目提取一次固定募集书，Codex 在一次文件工作区调用中读取完整文本、表格、附注、脚注和图片，形成全部已选目录项的编制计划。后续条目复用同一份材料快照和编制计划，由可信程序按各条目匹配的模板编制 Word，不再各自调用模型或重新全文提取。

逐项 run、暂停/继续/取消后续排队、失败项重试、归属校验、下载以及现有计费规则继续使用。文件仍逐项登记和交付；主要减少的是重复模型编制，不能把这个改动描述为无限并发。首份文件要等整批计划被接受；尚无真实项目的耗时基准，不承诺固定一小时完成。

共享提取或计划失败时暂停批次，避免把同一次编制失败自动重复到所有排队文件。已成功接受的模型结果先经持久日志保存，再写共享计划；中间崩溃重放日志，不重发已接受的模型调用。后续单个文件交付失败只重试该文件。输入、方法、模型、模板及共享资料的哈希变化会阻止错误复用。

## 内容与交付

- 只生成本次已选目录项，保留原编号、主体及目录内的实质要求。模板和旧项目样例不提供本项目事实。
- 已披露事实直接入稿；选中表格任一单元格时带入完整表格、邻接表名/单位/附注，以及脚注依赖。保留完整明细、合计、小计、合并关系和嵌套表，不以摘要代替明细。
- 宽表横向排版；超过十列时拆分列组并重复前两列关联字段。长表重复表头。空白单元格写“原文空白”，横线和零保留原样；合并单元格的延续部分不重复作为数据。
- 模型文字须有内部证据，数值必须存在于对应原文；计算由程序完成并带公式及基础数值，核对原文单位、期间和主体口径。业务差异和结论限制留在正文。
- 资料不足和需要原始证据的条目仍写足已有事实，逐项说明具体要求、原因、类别和资料名称。未披露不能推定事项不存在，不伪造证照、签章或实际执行记录。仅形成说明的条目净扣费为零，结果在后续计费步骤前登记。
- 来源位置、段落/表格映射、图片核对、覆盖及内部编制记录仅留在内部。正文和交付 ZIP 不包含来源栏、来源页码/章节、内部编号或编制过程；“资金来源”“定价依据”等业务内容保留。ZIP 仍只有“可生成文件”和“不适用说明”。

## 接口、迁移与兼容

公共契约增加可选执行版本和内部 `WorkpaperSharedPlanSchema`，不增加用户填写字段。迁移 `0121_workpaper_shared_plan.sql` 新建按 owner/batch 隔离的不可变材料快照和计划。文本/结构保存在 PostgreSQL；图片字节留在私有 Blob，数据库只保存地址和哈希。

旧 manifest 无执行版本时走原路径，不修改运行中的旧批次。统一集成时需先应用迁移，再将新 contracts、API、worker、Python 模块和固定 skill/hash 一起交付。不能让旧 worker 消费新批次，也不能在有新批次活动时直接回退到旧 worker；由发布负责人安全暂停/处理活动批次，保留新增表及账务记录。

## 验证边界

工程验收使用合成发行人材料和合成模型，真实执行 API、PostgreSQL 队列、模型持久日志、Python 提取/Word 编制、私有存储及 ZIP 下载。它验证复用与交付机制，不代表真实模型的语义覆盖、实际耗时或用户验收。

原生 PDF 提取表格几何结构并提供每页图像供模型核对。没有原生文字的扫描图片页要求先完成 OCR；无法核对的相关图片或表格不能标成“未披露”后交付。自动检查不能证明模型已识别所有语义相关内容；真实材料的全文覆盖、跨章节归集、复杂无边框/跨页表格以及全部成果页面仍需在本地集成验收中验证。
