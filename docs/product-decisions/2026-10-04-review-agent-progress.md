# M3 复核：当前动作与助手执行摘要

日期：2026-10-04。产品负责人确认在左侧展示紧凑状态栏，在右侧项目助手 response 区域显示任务进展；随后明确不展示心跳和时间，采用类似主流 agent 的工作过程反馈，并授权创建实施 Issue、修改 M3 和发布。

实施跟踪：[Issue #547](https://github.com/ITSophiaXu/BondBuddy/issues/547)。

## 生效行为

复核页保留“材料与要求”“复核结果”两个标签。当前任务的紧凑状态栏位于标签上方，显示真实状态与一句当前动作，例如“正在读取材料”“正在核对财务数据”“正在整理复核报告”。切换标签不隐藏状态栏；“查看进展”定位项目助手中同一个 run 的记录。桌面项目助手保持右侧常驻，窄屏沿用既有抽屉。

助手回复区域每项任务只有一条稳定记录。当前动作突出显示，必要时带一两句简短解释；真实已完成动作默认折叠，用户可展开回看。连续同类活动合并，重复轮询、重连及事件重放不增加重复聊天消息或任务记录。普通用户消息、真实助手回复和系统任务记录继续区分语义。

复核页运行反馈及助手消息不展示心跳、耗时、预计完成时间、任务/动作时间戳或百分比。时间字段继续用于持久化审计与排序；工作台既有历史版本管理及报告中的事实日期不受本决定影响。本条覆盖[同一工作区决定](2026-10-04-review-assistant-linked-workspace.md)中任务卡必须可见开始/完成时间的界面要求。

## 真实过程来源

执行摘要来自实际宿主阶段或通过校验的工具活动。公共动作的类别、状态和身份在 packages/contracts 唯一定义，消费端使用固定中文映射。模型推理原文、prompt、CLI 原始日志、原始参数/结果、内部路径及跨项目信息不进入公开任务事件。

无新事件时保留当前动作；宿主仅能确认模型正在执行时显示真实粗阶段。不得按计时轮播“正在检查下一章”等动作，不将工具开始描述为检查完成，不将某次查询完成描述为完整维度已通过。旧任务缺少细分事件时沿用真实状态与阶段，不生成回填的虚构历史。

动作写入只增加持久化进展，不改变原 run.state、run.stage、job checkpoint、固定输入、已有模型调用和结果登记。取消、终态或丢失租约后的迟到活动不能让任务回退为执行中。任务成功仍由已有交付与成果登记链路确认。

## 交互与异常

用户查看历史、选择文字或展开动作时保持其阅读位置；一般进度刷新不抢焦点。停止、失败、等待补充和连接中断显示具体状态与可执行操作，任务恢复不要求重复开始。助手回答中断与业务任务中断继续区分。

任务完成后，原任务记录展示结果入口并关联准确报告/成果。新任务形成新记录，保留原任务的来源、范围和成果关系；沿用、未覆盖、已修订和已重新核验继续分别呈现。

原型基准为 product-prototype/public/review-v2.html/css/js，实施同步更新原型说明及第 06/13/16/17 章相关执行反馈要求。实现 PR 登记最终原型身份与同尺寸对照；这份决定与示意本身不代表代码已发布。

验收包含当前动作持续可见、已完成动作可折叠并保持展开、真实活动持久化及重放、无时间/百分比、未知/原始字段不公开、暂停/终态准确、结果联动、桌面/窄屏浏览器核对及准确 master commit 发布。沿用 M3 无收费、真实用量、归属/隔离、幂等、输入锁定和 CLI 统一执行边界。
