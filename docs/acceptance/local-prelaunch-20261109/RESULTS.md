# 桌面上线前测试结果

本机验收入口为 <http://localhost:18087>。页面、API、数据库、文件存储、队列、
解析器和生成 worker 均执行实际产品代码，模型使用本次授权的服务。
支付渠道为模拟收银台；订单、充值到账、预留、扣费和退款执行实际账务逻辑。

本轮保留失败尝试和原任务，不靠改账本、替换生成文件或重复提交任务取得通过结果。
手机端不在范围内。

## 已核验的功能

| 用户场景 | 实际结果 |
| --- | --- |
| 输入错误、缺少原稿或原稿信息不完整 | 明确指出问题；纠正后能保存、刷新恢复并报价，未产生任务或扣费。 |
| 空文件、不支持的格式、超限声明、上传字节或哈希不匹配 | 拒绝错误输入；有效文件可以继续上传。 |
| 损坏、截断、加密或扩展名不符的文件 | 保留具体解析结果和可操作的纠正提示；替换为可读文件后恢复。 |
| 上传中断、服务端已保存但浏览器丢失响应 | 核对原上传记录并恢复，不重复保存材料。 |
| 两个窗口同时上传同一文件 | 两个上传请求完成后只保留一份材料；两个窗口刷新后均能找回并下载原字节。 |
| 来源版本切换、旧材料引用、跨项目和跨账号访问 | 拒绝无效引用或越权；合法纠正可继续，未产生任务和费用。 |
| 模拟支付待确认、失败、关闭、查询及回调重复 | 仅真实确认的模拟支付到账一次；失败和伪造回调不增加余额。 |
| 退款失败、重复退款、超额退款及越权退款 | 冻结、释放和退款结算保持幂等，不重复处理余额。 |
| 问答零余额开始、充值后恢复 | 使用原请求继续；实际生成、下载并结算一次。 |
| 当前募集书编制零余额开始、收银台查单到账后返回 | 自动恢复原请求和完整原报价；双 Word 下载，刷新及并发重放均只结算一次。 |
| 新旧计费规则同时存在 | 旧任务保留原输入、任务和报价；模型前后耗尽余额均可经当前充值流程恢复，已完成模型结果得到复用。 |
| 刷新、重复执行和终态重放 | 保留原任务与成果，不重复调用模型或扣费。 |
| 损坏原稿导致编制失败，再纠正原稿 | 失败在模型调用前释放预留；纠正后创建新的不可变轮次，旧失败证据保留。 |

已选定的 **42 个不同功能场景通过**：26 个输入／材料、8 个非模型支付、8 个真实
worker 场景。38 个场景在 `fc76c9c7` 上执行，合成长文档场景在 `76b8e3c1`
上执行，双窗口上传和错误材料版本恢复在 `50554262` 上执行，当前编制收银台恢复在
`fabf91c7` 上执行；不能将这些结果描述为
全部在后续版本上重跑。

输入和文件的逐项证据见[坏输入记录](../../../apps/web/tests/local-prelaunch-bad-cases.md)，
金额、账务和恢复身份核对见[支付计费记录](../../../apps/web/tests/local-prelaunch-billing.md)。

独立复核发现，当前募集书编制入口此前只验证到零余额拒绝；完整充值回跳链路由问答
及旧计费任务覆盖。补测发现任务账单读回丢失原报价有效期，已经修复；首次任务实际
生成成功，原失败断言及后续下载未验状态保留。修复后独立页面回归在 1.7 分钟内
通过，作为第 42 个场景；没有把失败尝试、重复观察或检查器测试算成新场景。

## 已修复的问题

- 可信解析器确认损坏的 DOCX 被当作基础设施错误重试：现在以
  `MATERIAL_UNREADABLE` 结束，在模型调用前释放预留，并引导上传可读副本。
- 恢复页出现两个开始入口：统一为一个“开始更新”，使用当前保存的输入。
- 旧输入冲突后仍反复使用旧报价：明确冲突后清理过期选择和报价；尚未确认执行结果时
  继续保留原请求，防止创建重复任务。
- 原稿必填、采用版本、已保存材料和项目状态的提示不准确：统一实际状态和操作含义。
- 任务锁定材料时上传控件仍显示：修复样式，使可见操作符合实际可用状态。
- 内部步骤出错被写成“本次处理未完成”：`c4be7c18` 区分步骤错误和整个任务失败；
  后续真实进度可继续更新，错误历史保留，不无依据宣称已经恢复。
- 运行和终态查看期间，参考募集书仍可上传或改用：`48669848` 将参考稿接入执行区的
  只读状态，覆盖点击、拖放、晚到文件选择、采用和删除；详情与下载保留，继续修改后
  恢复编辑。相关浏览器回归 123 项通过、1 项已有条件跳过，见
  [参考稿锁定对照](reference-material-lock/README.md)。实际充值回跳后的运行态和刷新后
  均已验证只读状态，详情与下载可用。
- 任务账单查询漏回原报价的有效期：`fabf91c7` 按原 owner、project、scope ID 补读
  不可变有效期，不改价格或结算。独立 Linux PostgreSQL 回归 14/14 通过，包括旧报价
  生命周期结束后仍保留原条款、跨账号拒绝及读操作不影响账务。

`50554262` 上的真实恢复流程复验通过：纠正原稿后只需一次开始操作，保存的输入与报价
一致；零余额时没有任务、预留、扣费或模型调用。详细截图和测试版本见
[界面验收记录](README.md)。

## 使用与结果边界

启动和停止命令见[本地环境说明](../../../scripts/local-prelaunch/README.md)。停止后保留
账号、文件和账务；有活动任务时启动器拒绝升级服务。原件、会话和模型成果留在本机
私有证据目录，不附入代码仓库。

本地模型使用 direct Enterprise transport，因此不证明生产 OAuth 换票可用。
本轮没有真实商户 SDK，模拟支付通过不代表真实收款、退款或未来订阅续费已通过。
LibreOffice 页图检查也不代替 Word／WPS 兼容性与财务专业签认。

GitHub Actions 因仓库付款／支出限制未启动；已执行的构建和相关测试有本地记录。
上述结果不表示已部署生产或已完成收费上线。
