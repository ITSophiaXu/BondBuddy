# 底稿目录导入修复（2026-10-29）

本文保留第一阶段修复证据。根据用户后续对任意表头/布局的要求，同一 PR 已补充灵活识别和原表核对；最新行为、契约、验证和发布交接以 [目录识别说明](../WORKPAPER-CATALOGUE-IMPORT.md) 为准。

## 问题与结果

无表头的“编号＋底稿名称”清单已通过文件上传检查，但目录解析器只接受名称表头，因此跳过全部条目并返回 422。界面将该阶段与上传恢复混在一起；每次重新选择同一文件又建立一个恢复记录，产生重复的“待确认上传”。

- 保留原有表头识别，补充明确的编号名称清单识别。至少两组编号和相邻名称，存在同等可能的多列时不猜测；标题行不作为条目。按原顺序保留编号、名称、行号及编号汇总行，不把层级编号自行改成文件夹。
- 分别显示“上传结果待确认”和“已上传，目录待识别”。文件已保存时直接继续识别；确实缺少字节时才要求重新选择原文件。
- 按账号、项目、用途、文件名、大小和 SHA-256 复用待办及原目录请求。相同名称而内容不同仍是独立上传。
- 识别成功后清理指向同一准确材料版本的旧重复待办。移除待办只清理本机记录；不删除服务器文件，不启动生成或扣积分。
