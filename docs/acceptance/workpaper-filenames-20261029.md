# 底稿括注命名与 Windows ZIP 兼容修复

用户反馈下载后的底稿 ZIP 被 Windows 判为无效，且目录括号内的核查说明仍进入文件名。旧实现会将“（包括……）”“（含……）”改成“及……”拼回标题，并按字符数限制名称；部分中文成员路径超过 Windows 压缩文件夹读取器的 UTF-8 字节限制。

## 实现与边界

- 名称去掉中英文及嵌套括注的完整内容，包括阈值、举例、适用条件、签字日期和操作提示。不再把“含/包括”内容拼回名称。保留法定名称中的必要限定，“批准（备案）”写成“批准或备案”。不完整的括注也不进入文件名。
- 原编号保留。过长标题先保留首句主体名称，仍超长时以省略号缩短并保留末尾文件类型。单文件名称最多 180 个 UTF-8 字节，归档子目录最多 40 字节，分类目录及说明后缀也计入完整 ZIP 路径；最终路径不超过 240 字节。中文和补充平面字符不被拆断。
- ZIP 按实际输出路径排重，移除括注或缩短后重名的文件追加序号，保留全部文件。新目录导入同样排重，原始标题、编制要求和目录条目身份保持完整。
- 历史批次下载从不可变输入中的原始 `entry.title` 和 `entry.code` 重新派生文件名，不沿用已将括注扁平化的旧 `entry.path`。批次列表、成果库、单份文件及说明下载、通用成果下载元数据/响应头和 ZIP 共用规则；成果库保存时采用服务端返回的名称。
- 不修改历史输入、任务、正文、Blob、原结果哈希或计费记录，不重跑模型。无需数据库迁移或新增依赖。API、web 及共享 contracts 需一起纳入集成；worker 仅调整对应回归断言。

## 验证

- 整仓 TypeScript 构建及 Vite 生产构建通过；更改后的 API 与 web 另行编译复验。
- contracts 检查：55 项测试、171 个普通合成样例、12 个内部库样例及 4 个生命周期样例通过。
- 定向 contracts/API/worker 回归：24 项通过，0 跳过。覆盖括注、法定名称、完整要求保留、长中文和补充平面字符、1,000 个重名文件、旧成果下载及既有追踪校验。
- 实际 Fastify 下载处理器和 ZIP 流测试：读取保留的 248 项合成批次，独立解析中央目录并逐项校验大小、CRC 和正文 SHA-256，验证分类数量、重名、说明响应头、批次/成果库元数据、跨账号拒绝及损坏内容拒绝。数据库和 Blob 为显式内存夹具；所有数据库调用断言为读取，不代表真实数据库集成或模型内容验收。
- Playwright：桌面和手机成果库、分页、预览、说明下载、原检查行为，以及旧路径下的单份下载名称和字节校验通过。界面沿用当前成果库，只有文件名文本改变，没有增加页面或操作步骤。
- 本地授权原下载包：248 份、两个分类目录完整保留，43 个名称修正，最长完整 ZIP 成员路径为 196 字节；全部文档字节与原包一致，Python ZIP CRC 检查通过。Windows Shell 压缩文件夹接口读取到 128 份说明和 120 份可生成文件。原包、修正版及逐项校验记录留在项目外层本地输出目录，不提交客户材料。

Windows 最小对照样本显示同一编码/压缩方式下，259 字节路径可读取，260/261 字节路径无法列出内容。该检查通过系统压缩文件夹接口完成，不冒称资源管理器 UI 点击成功或已在 Word 中审阅正文。

代码完成，尚未部署，待统一发布。本地集成版和用户验收仍由指定 chat 按既定流程承接；现有网站须纳入本次修复发布后才能使用新命名规则。
