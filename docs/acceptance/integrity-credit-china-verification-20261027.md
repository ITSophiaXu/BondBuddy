# 信用中国图形验证码自动识别与续查（2026-10-27）

代码完成，尚未部署，待统一发布。本批尚未完成统一本地集成验收和用户验收。

## 行为

信用中国已显示验证码时，采集器会识别已确认的官网弹窗，截取验证码小图，自动填写四位英文字母或数字并提交。图片识别期间会重新核对图片地址和像素摘要，已过期或已更换的答案不会填入新验证码；识别不清、验证码错误和过期刷新均有界处理。同一对象、网站和 run 最多使用两个识别调用槽位，浏览器重试和 worker 重启不重置预算。网站验证请求尚未返回时不重复提交。

弹窗消失只代表可以继续检查页面，不直接判定查询成功。仍需官网响应本次查询、查询条件可核对、结果发生变化且稳定、没有加载遮罩，并在截图后再次核对。识别等待不挤占后续查询结果的加载时间。已确认结构的单页企业主体名单也可识别为搜索返回结果；企业主体信息不等于失信、处罚或其他不利记录。

验证码未通过时显示“需要验证码”和“已尝试自动验证，仍未通过网站验证，本项未完成查询”。不要求补充信息或上传证据。明确无结果、加载超时、网站拒绝访问及查询有返回继续分开记录。页面、列表布局和已有状态展示不变，本批不新设用户上传或确认步骤。

## 验证码图片加载恢复

实测发现，官网验证码弹窗可以显示，但图片本身未能加载。原实现只等图片 5 秒，未加载便停止，并在取得图片前计入识别尝试，导致破图也被写成“已尝试自动验证”。本次修复如下：

- 图片每次最多等待 15 秒（不超过调用方的等待上限），确认加载完成且尺寸有效后才识别。图片加载失败不占用模型识别槽位，也不提交验证码。
- 在当前浏览器会话内通过官网“换一张”恢复一次；仍未恢复时复用采集器最多两次页面查询的上限重新打开查询。图片恢复次数在这两次查询间共享，避免反复刷新。
- 刷新会保留旧图时，等待来源、实际图片请求或像素摘要发生变化。识别后再次核对这三项，避免把旧答案填入新验证码；同一图片地址重新请求也能识别。
- 验证码图片的拒绝访问、访问频率限制（包括跳转后的响应）不继续刷新重试；内部保留实际响应状态。网页结果列表、查询详情和导出底稿共用中文说明：“验证码图片加载失败”“验证码图片加载超时”“验证码刷新未完成”“网站拒绝访问”或“网站限制访问频率”。不要求补充信息或上传证据。
- 沿用现有诊断 schema，在既有 detail 字段保存固定原因；旧记录不改写。查询结果、明确无结果与验证码验证仍独立校验。

本机第二次独立浏览器测试仍因验证码图片加载失败而停止，未填写或提交验证码，未取得查询结果。这是实际失败记录，不是自动验证成功证据。本次恢复策略的成功场景由真实 Chromium 与合成官网页面验证；不能据此认定真实官网或服务器访问已恢复。

## 模型与恢复

沿用部署配置中的 copilot_enterprise / gpt-6-sol，不更换供应商或模型；其他只支持文字的既有配置保留“需要验证码”，不发起不支持的图片调用。本批只自动处理信用中国已观察到的普通图形验证码；滑块验证、登录和其他网站的验证表单仍保留明确受阻状态。

只有验证码 PNG 小图进入模型，模型不接收完整客户页面，也不持有浏览器或官网操作工具。图片有尺寸、大小和摘要检查，通过私有存储读回校验；摘要与不可变 prompt 一起固定在任务检查点，模型实际使用固定文件名的短期隔离副本。仍使用现有调用意图、用量、结果保存和对账链路；取消、租约丢失、待对账不会被吞成网站核查结果。重启先处理此前调用，旧浏览器会话的答案不复用。命令行图片参数依据官方 Codex CLI exec --image 文档。

回归发现 Windows 的强制停止兜底等待过长，已缩短被拒绝工具调用的强制停止兜底；操作系统终止进程树的尝试及软停止流程保留。最终适配器套件通过。
