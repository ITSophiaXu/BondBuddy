## 根因及修复边界

| 失效点 | 证据和影响 | 处理 |

| 文件可用被当作充分交付条件 | 10 月 2 日旧决定、原 delivery 直接返回 deliver，旧测试甚至允许恢复 `WORD_QUALITY_REJECTED`；真实 V1 两个下载入口实为同一文件 | direct/controlled 两条路径均强制可信宿主检查；旧拒绝检查点不可绕过。 |
| 受控编辑没有交付前质量判定 | 原 finalize 使用 `--skip-report`，格式诊断在交付后非阻断；合法操作仍能删减或重写 | 独立检查整体/逐章保留、目录顺序、模板和修订一致性，失败保存私有报告与 failed checkpoint，不写 stage_completed。 |
| 原稿身份可降级或由模型构造 | 原 editingSource 优先级及非精确版本匹配；直接模式曾使用模型写出的 `output/baseline.docx` | 可信宿主锁定 ID、版本及 hash。DOCX 以真实输入原件核对；PDF 保留原 PDF 并独立比对重建底稿与输出，无法核验扫描页时失败。 |

## 当前交付检查

模型退出后，可信宿主读取不可变输入与精确原稿并运行 Python checker：接受修订等于清洁稿、清洁稿无修订、拒绝当前修订恢复基准、模板/样式/媒体/关系/表格/分节保留、目录和标题编号顺序、整体与逐章文字保留。失败不得标记成功，保留私有诊断，重新生成 Word 不重复调用模型。原稿和已有成果不覆盖。

保留率发现灾难删减和明显重写，不能证明每一句话正确。运行时明确记录 `factual_accuracy=not_verified`。`expected_text` 仅用于可信测试中的局部精确锚点，不是模型的自审声明。

## 发布门禁

固定清单包含构建、公共契约、门禁反例、数据库迁移、API 原稿选择/自动采用/格式绑定、worker 编制与交付、授权原稿固定编辑及双稿、强制 LibreOffice 渲染、部署脚本反例。任何失败、skip、TODO、空测试、缺样本或缺 renderer 都拒绝。机械 `validate` 不签发凭据。

完整 `run` 另要求当前 commit/tree、提示及工具 hash 对应的真实模型三季报金样和独立人审。验证器实际读取锁定 XLSX 原始单元格、DOCX 数值位置、全部原章节和三份 PDF 页数，检查主体/期间/合并与母公司口径、单位换算、模型用量及人审覆盖。已修复“历史比较数撞中本期预期值”的漏检；表格要求同行指标、同列期间及同表主体，拒绝日期、百分比、括号负数等碰撞。

凭据只绑定完整 commit/tree、Linux、干净源码和固定清单，正常发布有效期 24 小时；四个镜像必须带同一完整 OCI revision。回滚只能使用曾成功部署版本的原通过凭据，并核对部署记录内同一凭据 hash。凭据及 JSON 不提供人的身份或供应商数字签名认证，信任边界为受控发布者，模型不能写人审证据或发布者凭证。

说明与命令见 [质量与发布决定](../product-decisions/2026-11-01-prospectus-quality-gate.md)、[真实金样证据接口](../../scripts/prospectus-acceptance.md)、[受控发布者](../../scripts/prospectus-quality-publisher.md)。
