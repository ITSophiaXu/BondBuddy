# #31 内部测试工作稿的历史基线处理

## 问题与实现

预发 `fe2b668` 的真实授权样本在 `historical_baseline_needs_confirmation` 暂停：任丘九月历史稿有图片/页眉页脚，用户校正画像也只能保留 `user_asserted`。二者原来均导致全文修改清空。按用户已确认的 UPD-GAP-01，本切片允许已授权的非生产内部工作稿继续处理有依据的正文，同时保留具体待核项。

- `loadHistoricalGenerationInput` 先执行既有测试授权、样本、规则与身份检查，再由服务端选择 `non_production_working_draft`。客户端没有新开关，生产路径不采用此策略。
- `historical-baseline-warnings.ts` 仅消费 parser 1.0.7 完整、校验通过且 hash 一致的辅助对象清单。只处理 `DOCX_DRAWINGS` / `DOCX_AUXILIARY_PARTS`，保留对象 part/target hash、定位、关系与节范围；页眉页脚继承范围未知仍待核，图片不提取、不作事实、不改写。
- 缺清单、未知警告、解析失败、损坏/危险/外部关系、清单截断等继续阻断。正文记录自身存疑仍按原有逐块策略处理，不能成为画像依据或确定性修改来源。
- 画像必须对应同一材料/解析器，具备合法的市场/发行方式、期间、截止日与干净正文证据 refs。仅接受原生已识别字段，或正式校正函数生成的 `user_correction/user_asserted` 加“尚未人工核验”注记；缺锚点、其他疑义、跨市场和跨方式保持阻断。校正不是审核，不转为 ready/recognized，不用于确认 N、计费或合规。
- 内部 `PreparationPin` 保存 `baseline_policy=localized-auxiliary-user-asserted-v1`，模板使用 `historical-sse-private-test-v2`。恢复核对原固定画像/解析 hash/策略与模型 prompt 绑定。已有旧策略的准备检查点不能静默迁移或复用，返回 `UPDATE_BASELINE_POLICY_CHANGED`；没有准备检查点的原暂停任务可按正常恢复流程重验。生产模板仍为 v3。
- 完整辅助对象投影进入 plan hash；正文有锚点则附在对应段落，没有正文锚点则在首个正文段落放明确的“清单入口”，不伪称对象就在该段落。原对象的 XML 定位和未知节号写入待核清单。说明按现有规则完整分段，不能被已有模型待核说明覆盖；超限暂停，不截断。
- #34 消费同一 reviewNotes 输出 Word 批注及摘要。原稿信息待核、辅助对象待核与财务事实确认分开。无有效修改的纯占位结果仍拒绝。
