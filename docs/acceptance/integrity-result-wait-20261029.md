# 诚信查询结果加载与截图确认

本次修复针对搜索页先显示“0 条”、随后通过异步接口取得真实结果时，采集器可能提前保存零结果截图的问题。原复现中，合成接口在 6 秒后返回 1 条，旧采集器约 2 秒便将占位的 0 条记录为有效结果。关联范围：Issue #720 的官网截图采集。

## 最终行为

- 监听本次查询相关的文档、XHR、fetch，从提交查询持续到截图后的复核。收到 HTTP 响应头不算完成，必须等请求结束及响应体解析完成。新请求与响应变化都会重置稳定观察；已知统计请求、图片和脚本不作为搜索响应。
- 查询打开的页面以及已提交查询的同一页面中的后续数据请求，也纳入等待，覆盖依赖 token/cookie、不再次携带企业名的结果 API。只核对当前可见文档，旧文档与隐藏 iframe 不能证明当前结果。
- 页面查询词与本次条件一致、请求完成且成功、结果区无加载状态，连续稳定 2 秒后方可截图。零结果额外观察 5 秒，并核对可解析 JSON 中的明确总数或结果数组；错误、矛盾或未知 JSON 不能证明零结果。
- 脚本驱动的搜索文档没有取得可确认的数据响应时，初始 0 条不算完成，覆盖首次 API 尚未发起的延后初始化。无法证明零结果的站点保留“结果未确认”。无脚本的完整服务端结果文档仍支持明确零结果。
- 截图前后核对查询条件、结果区内容（包括同数量不同记录）与请求版本。期间变化则丢弃该图，在原等待期限内重新观察和截图。翻页也执行请求完成、稳定与截图复核。
- 每次尝试的结果等待上限继续为 90 秒，既有最多两次尝试与验证码暂停规则保留。超时/失败不转为零结果，短等待期限不会自动缩短稳定和零结果确认要求。

## 诊断与兼容

在内部采集批次的 `timing` 对象中保存查询开始、响应完成、有效截图时间、实际等待毫秒、观察配置与丢弃重截次数。没有完成请求或有效截图时不填相应时间。该对象随现有 `bb_integrity_browser_batches.payload` 一起持久化，不进入公开 DTO 或底稿正文。原有 `diagnostic.detail`、验证码原因精确匹配键和 attempts/elapsed_ms 保留。

无公共 DTO/schema、数据库迁移、包依赖、收费或任务入口变化。诊断时间不含查询词、响应原文或凭据；客户界面继续使用现有结果/失败/未确认文案。截图仍走既有原生桌面回调，成功复核后才进入批次和持久化存储，历史截图和历史轮次不修改。

## 验证范围

回归使用真实 Chromium 与全部拦截的合成网站；响应体分段传输使用隔离的本机 HTTP 代理夹具。不访问真实官网、不调用模型、不产生用户计费。专门用例使用正式的 2 秒 + 5 秒配置；历史场景显式使用较短测试观察窗口，其结果真实性断言保留。

覆盖 6 秒/30 秒延迟、HTTP 200 后响应体继续传输、真实零结果、token API、后续请求、延迟初始化、未知脚本页面、短期限、接口失败、持续请求、JSON 业务错误/数量矛盾、截图期间 0 变 1/同数量换记录/新请求，以及翻页等待。既有 iframe、弹窗、旧零结果、验证码、连接诊断、字体未完成和证据校验继续回归。

最终验证（Windows，Node 24.22.1，Playwright 1.63.0 / Chromium）：

- worker 官网采集、网络、页面就绪、验证码/图片/模型适配、compositor、证据与新增等待测试共 **179 passed / 0 failed / 0 skipped**，其中新增结果等待文件 21 项（含父测试），整组约 240 秒。
- contracts/domain/registry/applicability/API/worker/web TypeScript 构建与 Vite 构建通过；仅保留既有大 chunk 提示。
- 契约测试 **49 passed / 0 failed / 0 skipped**；171 个合成样例、12 个内部库样例与 4 个生命周期样例通过。
- `git diff --check` 通过。原生 Linux 桌面/任务栏实现未改动，本轮没有重跑 Linux 桌面实测，也没有重跑计费数据库或真实官网任务。

这是开发与自测交付；真实官网逐站兼容性、本地集成与用户验收由后续统一流程验证。脚本页面无法取得明确结果数据时，可能比旧版更多地显示“结果未确认”，不能将这类记录当作已查无结果。无生产部署。
