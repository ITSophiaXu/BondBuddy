# 统一底稿模板选择与生成入口

用户反馈：不选模板可以提交，主动选择光大模板反而报错，且目录和模板的关系不清楚。原来两个入口分别走系统模板和指定 Word 两条路径，指定 Word 入口选包后又清空逐项关联。本轮在同一个准备页明确模板来源，保留两种执行能力。

## 最终交互

- 新准备默认“系统模板 · 按文件类别自动匹配”。首次只加载目录，选好目录即可提交，无需先导入整套 Word。其他文件类型按需展开，目录与当前模板靠前展示。
- 目录与模板独立：更换光大或自有 Word 保留目录、勾选范围和编制要求。每种模板来源保留先前选择，返回后恢复手工关联。旧的指定 Word 准备清单保持原语义。
- 更换模板后自动采用经过包、文种和哈希校验的唯一候选；不覆盖手工指定，不新增未选项。剩余事项直接显示数量与列表，生成按钮会定位缺项，不调用报价。
- 支持 20 行分页、搜索、只看待处理项、按需加载下拉选项、请求取消/超时/重试。慢请求或晚返回不会覆盖后选模式。
- 系统模板提供真实资产的脱敏结构示例；光大/自有 Word 提供脱敏结构和版式预览。结构示例不是逐份生成结果，资料不足时采用说明样式。
- 普通旧底稿准备入口和“准备下一批”进入统一准备页；旧待确认提交继续原恢复路径，历史成果链接及受影响底稿重编入口保留。
- 批次模板来源从已保存的任务 manifest 推导，显示在历史进度中，不从当前页面选择推断历史批次。

## 接口、执行与集成

- 公共契约新增可选 `workpaper_template_mode: automatic | selected`。未传字段保持旧的逐项 Word pin 校验，只有新 UI 显式采用 automatic 时放行系统模板。
- 统一 `/file-generation/quote`、`/batches`。价格、混合批次钱包锁、事务回滚及原请求幂等保持不变。
- 系统模板无补充资料时复用现有 `shared_batch_v1`。共享提取当前只读取募集书，因此有补充资料的系统模板批次复用现有逐份生成链路，所有补充资料进入不可变输入。此类批次可能比共享提取慢；未改变费率。
- 新增只读、归属隔离的 `/file-generation/system-templates`。没有数据库迁移或新增依赖，需要 Web 与 API 一起集成。Worker 复用已有能力。
- 本分支包含 #848 的模板预览/加载修复（`8bca0c6adf6a998eb8c2441cf9ecabea8fbcc30d`），集成时无需再重复 cherry-pick 其文件。
