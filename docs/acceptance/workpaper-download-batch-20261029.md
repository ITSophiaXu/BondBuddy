# 批量底稿任务与下载反馈

用户反馈一次批量生成在“全部项目”被展开为几百项任务，点击 ZIP 下载长时间没有反馈。本次将项目任务列表和汇总统一为每个批次一项；文件数量、进度及下载仍在原批次详情中查看。

## 行为与兼容性

- 任务列表在数据库分页前排除批次子运行和历史重试，加入批次本身。尚未创建首个子运行的批次同样可见；状态来自批次，重试不新增任务。项目列表和项目文件页共用这一投影。
- `operation=workpaper_batch` 的任务使用稳定的批次 ID 作为列表标识。`workpaper_batch` 继续提供准确项目和批次路由，新增可选 `total`、`completed`；普通任务的运行标识不变。批次条目不用于调用运行操作。
- 下载点击后立即在下载按钮附近显示等待状态并禁用重复点击。ZIP 流式读取期间显示实际收到的 MB 数。读取完成后尝试自动保存，并保留 5 分钟的“保存文件”链接；点击该链接复用已读取字节。轮询重绘后保留原提示和链接。
- 单文件读取上限 2 分钟，整包读取上限 20 分钟（大型批次逐文件传输可能需要数分钟）；超时取消当前请求并恢复按钮，不触发生成或收费。失败和页面离开均保留原成果。
- 账号、来源项目和文件哈希校验不变；无数据库迁移、worker、模型调用或计费变更。API 和 web 一起纳入统一集成发布。

## 页面依据

沿用 `product-prototype/public/workpaper-batch.html`、现有项目任务列表和成果库布局，基准 `5ec099a2`。用户 2026-10-29 的要求确认了“一个批次一个任务”和下载必须有明确反馈的行为。新增的是任务名称/数量与现有下载位置的状态文字及保存链接，未增加页面或流程。

同尺寸对照沿用 `apps/web/test-evidence/workpaper-progress-routing/` 的原型；本次实现截图位于 `apps/web/test-evidence/workpaper-download-batch-20261029/`。截图和浏览器测试为合成数据，不能作为真实模型内容或用户验收证明。

## 验证

- `npm run build`：整仓构建通过；`npm run check:contracts`：11 项通过。
- 真实临时 PostgreSQL 16 + Azurite：相关 API 测试 5 项通过、0 跳过。覆盖 248 个条目、首个运行前的排队批次、失败重试、分页、暂停/部分完成/取消/完成、普通任务兼容、跨项目和跨账号隔离。
- 前端定向单元测试 31 项通过：完整/中断的 ZIP 流、接收进度、下载超时与取消、批次状态和路由。
- Playwright 12 项通过：桌面/手机任务只出现一项并打开原批次；下载等待与按钮锁定；浏览器抑制自动下载时仍能点击保存；轮询后保存链接保留；超时后在原批次重试；成果库单份下载。桌面/手机截图已检查，新增下载提示位于当前批次按钮附近。
