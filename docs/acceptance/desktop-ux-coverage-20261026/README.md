## 产品变化

成功任务卡的“继续修改”先核对原项目、原任务及唯一可下载 Word 成果的版本、哈希和交付状态，再打开准备。无法确认时保留完整旧草稿、已选底稿和未发送内容，并说明如何回到原任务核对；不会以先前选过的其他成果继续修改。

跨项目续改恢复原任务所属业务项目的原稿信息，避免后续确认与刷新仍使用另一项目；同项目已保存的原稿信息则完整保留，不被项目旧值覆盖。准备与明确执行仍分开，公共 API、计价和页面布局保持既有设计。

文件生成准备页还修复了一处异常草稿边界：`fields.market` 为 `constructor` 时，原代码会读取字典继承属性并在 `.filter()` 崩溃。现在只读取字典自身的市场项，保留原始草稿字段供核对，不改写或虚构市场。原有完整输入、冲突与明确保存断言均保留。

## 失败与证据采用

- 首轮从仓库根运行，但若干既有组件 fixture 按 `apps/web` 读取样式/原型；对应 `ENOENT` 由正确工作目录复跑验证。旧 UI 文案、过期上传会话、透明 radio 的测试点击位置和刷新后已恢复的准备状态仅修正测试前提，准确请求、材料/版本、执行次数及恢复断言保留。
- A 的冲突失败另有开发服务原因：构建产物热更新后，组件与 fixture 分别加载带时间戳和不带时间戳的 `ApiError`，`instanceof` 不同；真实 409 契约无误。最终构建完成后重启 Vite，保持 fixture 和冲突断言原样复验。
- 账号注销综合旅程两次在不同末尾动作耗尽整体 30 秒预算，隔离原样运行 10.5 秒通过。仅把这条双页、注销、退出、旧凭证拒绝登录旅程的整体预算设为 60 秒，各步骤断言保留原来的有限等待；整套账号在最终 C 复验。
- `M2 deferred charge prototype screenshots` 是可选静态原型采集器，最终配置明确排除，首轮失败保留，不记为已复测业务通过。手机专项和其他旧截图采集不计业务分母。
- 独立复审实际复现了同项目原稿信息丢失与异常市场字段崩溃；前者有失败/通过对照，后者保持原有 `constructor`、完整输入和保存断言。代码与测试修正均经独立复审。

首轮与 A/B/C 日志副本保存在 [checks](checks/)；提交副本仅统一换行并去除行尾空白，本机原始输出保留。最终 JSON 保留各阶段统计、失败原因和逐文件采用关系。[最终文件快照](checks/final-file-snapshots.json) 绑定实际源码、测试与配置；[C 运行前](checks/desktop-correction-c-source-before.json)和[运行后](checks/desktop-correction-c-source-after.json)两个产品文件哈希一致。全仓构建、契约检查及 883 条单元测试通过；最后两处产品修改再通过 [web 构建](checks/web-build-final.log)。仅有已有 Vite bundle 大小提示。

## 验收边界

本轮浏览器运行真实前端，HTTP 响应和交付文件为明确标注的合成数据。它证明用户操作、准确输入与成果身份、保存恢复和下载链路；不证明真实模型/worker、PG/Blob、真实支付账务、Word/WPS 实际排版或专业内容正确性，也未测得学习成本、完成率或留存改善。这些事项仍归最终统一验收。

暂停/恢复沿当前固定输入协议验收；暂停后把新材料纳入原任务的协议变化单独跟踪，不将新建后继轮描述为原任务续做。全历史分页、长期监控和逐字段三方合并不在本轮临时扩展。
