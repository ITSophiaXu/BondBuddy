## Recommended smallest connected slice

Add execution-scoped billing authority and lifecycle first, with synthetic internal acceptance before exposing a public continue action. Keep the existing B1 quote/confirmation APIs as immutable consent facts.

1. Introduce a segment keyed by the complete run execution identity `(owner, project, run, execution_version, input_revision, input_hash)`. Record original source reservation for V1; for rework, bind exactly one confirmed B1 quote and its exact supplement receipt/plan. Do not overwrite or increase the original quote or its existing charged allocations. A zero-work quote grants no extra debit authority and needs no zero-point reservation.
2. Give each payable segment its own cap, reservation/allocation identity, progress meter, and terminal/refund scope. The current reservation `run_id UNIQUE`, single run pointer, and meter PK require explicit compatibility changes. A practical bounded approach is a segment-to-reservation mapping plus execution-aware selectors, with original V1 consumers retained through compatibility wrappers. All progress event keys continue to identify the actual reservation/segment.
3. Route the existing debit/meter/finish/finalizer chain through the exact active execution segment. Keep account serialization and current delivery/readback checks. V2 work must not accrue to V1; V2 failure must not refund or recalculate V1 work automatically. Preserve each original policy rather than silently converting old on-delivery reservations to a new policy.
4. Add a separate production successor authorization that atomically binds the confirmed amount, exact verified preparation, billing segment, execution head and fresh queue/checkpoint state. Keep the 0135/0136 internal-test gates intact. The new authority must be recognized by artifact/call/result/Word delivery guards and production terminal delivery before paid execution can be opened.
5. Prove one complete paid M1/review/M4 path using synthetic provider results: original charged amount retained; accepted B1 amount capped independently; repeated adoption/debits do not double-charge; concurrent updates serialize; low balance pauses and resumes; cancel/failure/refund affect the right segment; stale input/quote cannot create authority; final output binds the exact active execution. Include a zero-work paid-source case that continues under its original fees without an extra charge. Re-run the existing credit audit over the resulting ledger.

This scope does not require redesigning recharge packages, all credit pricing, unrelated QA/integrity billing, or enabling an external supplier. The existing paid-successor rejection remains necessary until the connected lifecycle is complete.
