# 财务期间滚动更新：开发验证与集成交接

日期：2026-11-05。分支：`fix/financial-period-rollforward-20261105`，基线：`develop ab36573f`。

## 问题与改动

问题任务已提供同一发行人的历史募集说明书和新一期半年度报表，但保存窗口仍停留在上年。实际成果只增加新一期概览，没有滚动六张主表及重复分析表。任务读取了PPN写作框架，仍未落实全文财务更新。缺少另行上传的历史年度审计报告不是停止更新的理由。

受控编辑接口此前不支持增列，同时要求所有正式编辑通过操作日志进行。本次补齐普通矩形表的`insert_column`，支持全行数据、相邻列样式、稳定节点引用及真实单元格／列宽修订，保持表格总宽度。模型对错误期间的具体决策原因与工具能力缺口是不同证据；不能证明工具限制是问题任务的唯一原因。

`task.md`明确按同企业历史比较数与最新报表更新，覆盖六张主表、相关分析、指标、风险和重复披露。保存窗口落后时，通常全文更新采用材料确认的最新一期并如实说明差异；明确的截止日或局部修改要求仍优先。原输入保持不可变。详见[产品决定](../product-decisions/2026-11-05-latest-financial-window.md)。

唯一自动化用例合计47项。Windows使用bundled Python，设置`PYTHONPATH=python;python/tests`、`PYTHONIOENCODING=utf-8`后执行：

```text
python -m unittest -v test_fixed_edit test_file_authoring test_source_outline test_word_delivery test_revision_cli
```

首次未设置UTF-8时，已有CLI测试受Windows默认编码影响失败；按worker实际设置UTF-8后完整固定编辑套件通过。实际原稿回归最初把清洁版所有XML字节也要求不变，遇到页脚重新序列化失败；修正为修订版未改部件字节一致、清洁版文字部件等价于接受原有修订后的原件、非文字部件字节一致，复验通过。这是测试比较方式修正，没有改写原稿。

问题原稿回归只使用显式标注的合成值，未调用模型，不能算真实财务生成验收。客户输入、诊断证据和生成文件仅保存在本机私有目录，没有提交仓库。未做页面渲染、Word/WPS兼容性或财务内容验收。新固定编辑测试与目录回归已加入现有`M3 CLI review integration`工作流。

无数据库迁移、无新依赖、无公共API或计费变更、无新增下载阻断检查。模型工作目录继续由worker复制`task.md`和`fixed-edit.md`；Python工具必须与说明一起更新。
