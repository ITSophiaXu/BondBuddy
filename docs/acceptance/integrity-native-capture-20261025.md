# 官网首张整屏截图就绪修复

对 `ffd637fa` 进行发布前集成验证时，复现了 Chromium 窗口已经最大化、但首帧尚未绘制的情况：第一张原生整屏图只有空白浏览器区域，稍后的截图才包含页面。仅等待窗口管理器 200 ms 不足以证明浏览器已绘制。

采集器现在先等待 Chromium 完成一次 compositor 截图；仅对首次绘制阶段的 `Unable to capture screenshot` 协议错误在 10 秒内重试，其他错误或超时仍向上传递。该同步图不持久化；最终证据继续由 scrot 原样截取整屏，包含浏览器与原生任务栏时间，不拼接、不注入时间、不关闭浏览器 sandbox。

真实 Linux 桌面测试增加首张整屏图含浏览器网址的断言。时钟使用测试专用的局部副本进行 OCR，避免整页分区导致日期识别不稳定；原始证据字节不变。日期、时分秒、后续时钟变化、1440×1000 尺寸、凭据隔离和 X socket 清理检查继续保留。

验证：完整构建和公共契约检查通过；修复后 worker 编译通过。非 root、read-only、cap-drop、no-new-privileges、仓库专用 seccomp、1536 MiB 的本地 Linux 容器中，桌面测试连续三次通过；官网浏览器/代理/策略回归 13 项通过，0 失败、0 跳过；Word 模板测试 2 项通过。依赖复用经比对的本地 Linux 镜像，其 151 项已安装包版本和 integrity 与候选锁文件一致。

本批其他 API/数据库/账务/worker/Word 场景先前已在独立 PostgreSQL、Azurite 及合成模型环境通过。初轮还有一项沙箱策略测试因测试容器漏挂策略文件失败，补挂后已由上述 13 项回归复验。真实官网、模型质量和生产宿主 AppArmor 不属于这些合成测试的结论。本修复无迁移、无新增运行依赖，发布需重建 worker 镜像。用户验收及生产发布仍待完成。
