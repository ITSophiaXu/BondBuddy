# #15 issuer identity source record handoff

Migration `0035_m1_issuer_identity_source.sql` adds owner/project/material-version scoped identity observations, append-only review decisions and a dedicated reviewer-grant ledger. Each observation binds to one immutable `bb_parse_evidence` row and stores its parser snapshot, record/content hashes, locator and literal quote. The API repository resolves these anchor fields from PostgreSQL; callers provide an evidence record ID, issuer display name and service-resolved `entityId` only.

`appendIssuerIdentitySourceRecord` assigns a monotonically increasing version within that material version, enforces request replay consistency and writes its `needs_review` row with the outbox event in one transaction. Conflicting observations remain as separate rows. `reviewIssuerIdentitySourceRecord` accepts a runtime-branded reviewer context returned by `authorizeIssuerIdentityReviewer`; arbitrary actor/grant objects are rejected, and the referenced database grant must still be active while the review transaction runs. The reviewer-grant table has no API or repository grant-creation function and requires out-of-band privileged provisioning.

`loadVerifiedIssuerIdentitySourceRecord` is the internal #17 handoff. It returns `null` when there are no observations, any observation lacks an active-grant review, a conflict decision exists, or verified observations name more than one `entityId`. When the result is unambiguous it returns the selected row's `recordId`, `version`, `contentHash`, and `entityId`, alongside the exact material and evidence references. The API recalculates `contentHash` from the immutable stored fields before returning it. No route is registered by this slice; the caller must pass `request.principal.userId` into `authorizeIssuerIdentityReviewer`, never a body-supplied reviewer identity.

Verification performed with synthetic records on a disposable PostgreSQL 16 database migrated through `0035`: append/replay/versioning, owner and source-anchor isolation, no-grant rejection, exact review replay, quote/content-hash mismatch triggers, append-only enforcement, pending-observation gate, conflicting verified-entity gate, recomputed hash, and outbox rollback. API TypeScript build and full workspace build passed. These tests validate storage and authorization boundaries, not industry review of a real issuer or its source documents. No production reviewer grant has been inserted.
