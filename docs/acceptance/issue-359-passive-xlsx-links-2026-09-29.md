# #359 被动 XLSX 外部工作簿引用兼容

上传检查曾将 `externalLink` 中的 `alternateUrls`、`relativeUrl` 和同一外链部件的多条 `externalLinkPath` 关系判为结构错误。Excel/WPS 可以把备用地址保存在这些被动元数据中。检查器现在允许这些 XML 形态；外链目标只作为不透明元数据，上传、解析均不打开、执行或请求目标。

仍验证上传字节大小及 SHA-256、ZIP 结构和 CRC、解压资源上限、XML 良构及深度、外链关系类型与长度，并拒绝宏、DDE、OLE、脚本和主动外部内容。公式不会执行，缓存值和业务事实仍须按解析结果待核。

针对原报告的 411637 字节文件（SHA-256 前缀 `e98dfa51fa21`），隔离测试中的公开 API 返回创建上传 201、传输 204、完成 200；私有存储读回与版本记录的 SHA-256 均相同。持久解析任务完成，解析快照为 `needs_confirmation`，记录 22014 条。此结果证明代码路径可处理相同字节，不代替部署后的原项目浏览器重试、重新登录与页面提示验收。

合成的双路径外链样本覆盖备用地址与多条外部关系的内存、文件及 API 上传路径。主动 OLE 关系、DDE/OLE 节点、宏、坏 ZIP、压缩炸弹和 XML 限额继续拒绝。原报告文件和详细运行证据仅在受控测试目录保存，不进入仓库。

部署此修复并核对原文件成功后，将预发布环境的 `BB_UPLOAD_EXCEPTION_ENABLED` 设为 `0`，移除 `BB_UPLOAD_EXCEPTION_SCOPE`，重建 API 容器并确认配置未生效；随后用同一原文件复验。此例外默认关闭，仍保留代码供过渡期回滚。若部署后浏览器仍显示笼统损坏提示，页面错误接线由 #361 处理；本改动不改变页面结构或公共响应契约。
