# 底稿目录灵活识别（2026-10-29，PR #806）

客户的 Excel 已经上传并保存，旧解析器因没有名称表头而返回 422，界面却重复显示上传待确认。用户进一步明确：不能要求客户遵循固定表头、列顺序或内容样式。本次同时改进识别和核对体验。

## 行为

- 根据表头和单元格值推测结构，支持不同表头、无表头、非相邻编号/名称列、编号名称合在一格、纯名称清单、多个工作表、重复表头和同表不同区域。编号按原值保留，不自动补造。
- 明确的目录自动进入文件选择；含歧义、未用内容列、未纳入行、混合编号或无法确定结构时，展示原表样例、识别结果和提示。用户可调整名称/编号列、行范围、多个分类/要求列、类型列、拆分编号及工作表区域，再更新预览并确认。
- 默认优先“1 尽职调查文件”，可查看全部工作表。保留原条目、编号、行号及编制要求；仅明确的类型列将行标为文件夹，不因编号层级丢弃汇总底稿。
- 上传和识别分开。原文件已保存时直接重试或修改识别范围，不重复传字节。相同文件名、大小和 SHA-256 复用待办；同名不同内容保持独立。
- 预览不创建目录、任务或积分事件。用户确认目录后持久化；生成仍在下一步单独确认。确认请求先保存在本机，响应丢失时使用同一完整请求重放；条件写入防止另一标签页的旧预览覆盖已确认请求。
- 清理当前成功的待办及引用同一材料版本的旧无上下文重复待办。移除待办只影响本机，不删除服务器文件。

## 契约与边界

新增只读 `POST /projects/:project_id/workpapers/catalogue-preview`；请求含原材料 pin、可选 scope 和 mapping。响应含 entries、mapping、工作表/列样例、warnings、needs_review、未纳入行总数及前 100 行样例。

现有目录导入请求增加可选 mapping。旧的明确目录请求仍可用；有歧义但没有明确 mapping 的新导入返回可恢复的 422。已入库请求优先走原幂等返回，不重新解释历史目录。映射定义在 contracts；请求哈希包含映射，结果哈希包含最终条目/提示。每次预览和入库均校验归属、材料版本和 SHA-256。

当前输入仍为 XLSX（10 MB、30 个工作表、10,000 行、前 100 列、1,000 份文件）。这是基于单元格的结构识别和人工修正，未接入付费模型，不宣称任意文件/布局均可自动理解。公式不执行、不以缓存值充当事实；隐藏工作表继续跳过并提示。原表与未纳入行样例有明确显示上限，原件完整保留；条目超过字段容量时提示调整。不会执行文件中的指令、宏或外部关系。
