## 实现与兼容

1. `#update` 显示主新建卡片、次级折叠选择器。搜索/浏览不写入项目；明确继续时创建或复用更新工作区。新项目复用现有创建表单、原稿必填信息、材料、补充要求和执行页面；创建请求幂等。
2. 原有 update 项目使用原 ID。其他项目保持原 kind，以 `bb_update_workspaces` 关联唯一 update 工作区，在项目列表仍只显示原项目。目标信息复制到更新草稿；材料按确切版本复制到独立私有 Blob，记录源 ID/version/hash，原稿信息映射到新材料 ID。复用 execution scope 互斥，原任务与新任务不混用输入。
3. `bb_prospectus_versions` 只追加版本；`bb_prospectus_selection` 用 revision 乐观锁选当前版本，带 request_id 回执。旧原件不能单独删除，删除整个项目沿用原保留/清除政策。原项目删除、归档会覆盖所属更新工作区。
4. 输入锁定 current selection revision/id、材料版本/hash。当前生成稿作为准确 clean artifact 基准，上传新稿则清除旧生成基准。旧输入不受后续切换影响。
5. 成功交付时归档修订版/清洁版指针；只有当前选择仍等于任务输入时才自动设为当前。用户运行中上传或切换时，任务成果仍进历史，但不能覆盖其选择。重复完成不重复增版。
6. 保留现有队列、积分、模型调用、暂停/恢复、不可变输入和授权下载。旧任务未固定完整报告期时，续更沿其当时已存的截止日使用原规则推导，避免空报告期造成报价失败。
7. 成功后刷新版本历史，只在项目字段完全未变化时接收新 draft revision，避免继续修改错误地覆盖另一个页面的编辑。

新增公共契约位于 `packages/contracts/src/prospectus-versions.ts`：

- POST `/api/v1/projects/:project_id/update-workspace`
- GET / POST `/api/v1/projects/:project_id/prospectus-versions`
- POST `/api/v1/projects/:project_id/prospectus-versions/current`

## 验收步骤

1. 进入更新募集书，新建项目，填写发行人/市场/品种/目标报告期，上传历史或相关募集书及材料，填写原稿信息和补充说明。
2. 上传募集书新版本：核对当前版本变化、旧版仍可下载，积分和任务数不变。切回旧版，核对其原稿信息恢复。
3. 明确点击开始更新；刷新或重新打开页面，核对持久化任务进度。完成后下载修订版、清洁版，并查看版本历史。
4. 从次级选择器选择已有 update、review 或 generation 项目；核对原材料复用、原项目保留、新更新任务归属。
5. 任务运行中上传新版本，完成后核对新上传仍是当前版本、生成结果保留在历史中（自动化集成测试覆盖）。
