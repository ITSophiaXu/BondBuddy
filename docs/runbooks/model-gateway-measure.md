# 模型请求测量与预算（Refs #994）

网关统计每次模型 HTTP 请求的实际大小和组成，并在转发前执行字节预算。文件编制路径强制使用 `enforce`，未显式填写预算时采用 2 MiB（2,097,152 B）的本地策略；这不是供应商实测上限。其他调用路径仍由 `BB_MODEL_GATEWAY_MODE` 控制，默认 `off`。记录只包含大小、计数、图片尺寸、状态码、请求编号和用量，不包含客户正文或图片内容。

这是 #994 的部分修复，当前候选同时整合按页读取/OCR 缓存、受限看图与 [#1302](https://github.com/ITSophiaXu/BondBuddy/pull/1302) 的自动工作区恢复核心。限制请求和恢复进度不等于扫描 PDF 已处理完成，也不代表真实 Word 交付通过；没有引入手动重试页面或从原材料重新开始的接口。

当前候选的固定 CLI 请求字节、本地 74 MB 扫描件按页读取及恢复测试，见[本轮验证记录](../verification/large-pdf-request-budget-20261116.md)。


本手册中的强制保护与自动续跑指更新募集书的 `file-authoring-v1` 和 `file-authoring-size-repair-*` 路径。复核及 M4 文件路线仍使用单图 128 KiB 的受控 JPEG，但不使用只有快照续跑路线才能处理的 512 KiB 累计轮换额度，不把本地图片额度信号记为供应商 413；其 HTTP 网关模式仍由既有配置控制。

## 模式与配置

下表描述全局模式对其他调用路径的影响。文件编制始终开启 `enforce`，`off` 或 `measure` 不会关闭该路径的预算保护；显式预算会替代其 2 MiB 默认值。

| `BB_MODEL_GATEWAY_MODE` | 行为 |
| --- | --- |
| `off`（默认） | 保持原来的供应商连接方式，不启动网关。 |
| `measure` | 原样转发并记录请求大小，不使用配置的执行预算；保留既有 256 MiB 请求缓存保护。网关启动失败时允许回退直连，并记录 `event: start_failed`。 |
| `enforce` | 启动网关并执行显式请求预算。启动失败即停止本次调用，不能回退直连。首次本地拒绝或上游 413 后锁存停止，后续请求不再转发。 |

其他模式值会使 worker 配置校验失败。`enforce` 必须同时设置 `BB_MODEL_MAX_REQUEST_BYTES`：仅接受 `1` 至 `268435456` 的十进制正整数字符串，不带单位、小数、空格或科学计数法。全局 `enforce` 的空值会在 worker 配置加载时被拒绝。全局 `off`/`measure` 可以留空，此时文件编制使用自己的 2 MiB 默认值；任何模式下填写了非空预算时，都必须满足同一格式与范围。

`268435456`（256 MiB）只是本地配置允许的最大值，不是 DeepSeek 或其他供应商的限制，也不是推荐预算。没有预设的“DeepSeek 10 MB / 20 MB”阈值。应先使用实际 CLI、模型、出口和供应商测量，再选取并验证预算及余量。仓库环境示例将全局预算留空；文件编制的 2 MiB 是明确的本地保护策略，需要通过真实任务验证完成率和供应商余量。

## 开启和关闭

对于文件编制之外的路径，可先在执行端的私有环境文件中开启测量；文件编制依然执行自己的预算：

```text
BB_MODEL_GATEWAY_MODE=measure
BB_MODEL_MAX_REQUEST_BYTES=
```

取得实际请求大小和组成后，选择经过验证的正整数字节预算，设置 `BB_MODEL_GATEWAY_MODE=enforce` 和 `BB_MODEL_MAX_REQUEST_BYTES`。两项必须一起核对；只切换模式而留空预算不能启动 worker。

按 [拆分部署手册](m1-split-deployment.md) 的正常流程重建 `worker` 和 `worker-review`。基础 Compose 通过共享 worker 环境同时传递模式与预算，复核 worker 继承这两项。保留现有供应商、认证、代理、业务输入和账务配置，核对实际镜像及最终环境，不以示例文件或源码变更代替已生效证据。

腾讯弹性执行池需在实际节点 enrollment 的 `service_environments.authoring` 和 `service_environments.review` 中设置相同策略，并使用包含该实现的镜像。现存节点、暖机持久配置和未来节点启动模板分别核对，不能只修改主站配置。预算可以按经过验证的供应商/执行环境选择，不要把一个供应商的结果套用于另一个供应商。

其他路径回退到仅观察时改为 `measure`，关闭时改为 `off` 或删除模式项。文件编制不会随全局模式关闭保护；需要回滚其行为时必须回滚应用版本。按同一部署流程重建两个 worker，保留前像与变更回执，不能把回退当作超限已修复。

## 预算和失败行为

- 每次 Codex 调用单独启动一个只监听 `127.0.0.1` 随机端口的网关，Codex 的 `base_url` 指向它；调用结束后网关关闭。
- 网关仅允许原始路径 `/responses` 和 `/responses/compact`，解析后再次核对配置的供应商 origin 和 base path，保留合法查询参数。含反斜杠、路径穿越、绝对地址或其他路径的请求在读取/转发 body 和鉴权前返回 `PATH_INVALID`，不会把鉴权头带到其他地址。
- 预算针对每条实际 HTTP 请求体，包括提示、历史、工具结果和图片。它不是原始 PDF 大小、token 上限或整个任务历次请求字节数之和。
- `enforce` 在转发前分别限制收到的请求体字节和解码后的请求体字节。压缩请求不能利用较小的传输体绕过解码后限制。支持 `gzip` / `x-gzip`、`deflate`、`br`；`zstd` 仅在运行时具备解码器时可用。不支持、叠加或损坏的编码以 415 拒绝，不能绕过检查。请求超额以本地 413 拒绝，不向供应商转发该请求。
- 适配器在所有模式下看到明确 HTTP 413 诊断后都会立即停止本次 CLI；其他路径的 `off` 和 `measure` 仍没有配置的请求预算。`enforce` 另通过网关事件和锁存实现边界，不依赖 CLI 是否及时打印错误。
- `enforce` 首次本地预算/编码拒绝，或首次收到上游 HTTP 413 后，本次调用进入停止状态；Codex 后续重连不能再次转发。上游 413 说明该请求已经到达供应商，和本地拦截的“未转发”分开记录。停止前已经发出的请求不能被当成从未调用。
- 明确 HTTP 413 或本地请求字节超限使用 `MODEL_PROVIDER_PAYLOAD_TOO_LARGE`，编码拒绝使用 `MODEL_PROVIDER_REQUEST_REJECTED`；`enforce` 网关启动失败使用 `MODEL_ADAPTER_CONFIG_INVALID`。不会把本次调用此前未知的用量改为零，也不会因为最后一条请求被本地拦截就认定整场没有消耗。
- 文件编制优先使用 `pdf_pages.py` 按页分段读取原生文本或本地 OCR，缓存绑定原件哈希、页码和 OCR 引擎。受控 `view_image` 单图最多 128 KiB，每个上下文累计图片 base64 和 data-URL 前缀最多 512 KiB；达到限额后返回宿主可识别的明确标记，停止当前上下文，在完整快照核验后按下述正常轮换次数限制换新上下文接续；已有 OCR 缓存和工作记录随快照保留，不把未查看区域当成已核验。
- 累计图片预算耗尽是宿主的 `MODEL_CONTEXT_ROTATION_REQUIRED` 正常轮换，不冒充供应商 413。只有进程退出、不可变观测匹配、完整工作区快照及捕获元数据均核验通过，才在原任务内继续；整个任务最多正常轮换 32 次。明确 413、本地输出上限或超时仍共用每个逻辑调用最多 2 次、整个任务最多 6 次的故障恢复预算，正常轮换不占用该预算。
- 同一逻辑调用在首次宿主准备阶段按既有编制超时配置产生绝对 `deadline_at`，在首次调用 intent 的捕获元数据中绑定；快照、恢复审计、自动恢复和运维 retry 都必须保留同值，不能删除或延期。后续上下文只使用剩余时间，截止后不再启动模型并正常失败；缺少截止时间的历史快照不能授权正常轮换。配置默认编制时限仍为 5 小时，未扩大默认值。
- 每次轮换继续使用原输入、run、积分预留、调用准入和并发许可；逐次保存供应商用量，未知仍为 unknown，不把部分 HTTP 响应计量冒充完整调用用量。现有 token 汇总是报告，不是硬额度；执行范围由轮换次数和绝对时间约束。用户暂停、积分暂停、钱包隔离和取消请求继续生效。
- 工作区快照统一限制为 4096 文件、单文件 100 MiB、总计 512 MiB，完整保存 `input.json` 及 scratch/output；恢复前重新核对私有对象归属、路径、大小和哈希。现代调用的捕获失败、不完整或冲突时保持暂停，不静默从原材料重新开始。
- 未被拦截的请求原样转发到配置的供应商地址，经过与 Codex 相同的出口代理（`HTTPS_PROXY` / `NO_PROXY`）；供应商流式内容交回 Codex。鉴权头仅用于转发，不写入诊断记录。

## 查看结果

**按调用查。** 团队诊断入口执行：

```text
exec-log ATTEMPT_ID --tail 400
```

执行日志末尾的 `[bondbuddy-model-gateway]` 段，第一行是本次调用的汇总，后面每次 HTTP 请求一行。该段最多 512 KiB；请求很多时保留前 10 条和最近的请求，中间用一行 `omitted` 说明省略条数。汇总行始终保留。

**实时查。** 在 `logs worker` 或 `logs review` 中搜索 `"kind":"model_gateway"`：

- `event: summary`：每次 Codex 调用结束一条，带 `run_id`、`call_id`、`logical_call_id`、`attempt_no`。
- `event: request`：请求被拒绝、失败（如 413）、网关或上游出错，或单次请求达到 4 MiB 时实时输出。4 MiB 是日志提示条件，不是默认请求预算。
- `event: start_failed`：网关启动失败。`measure` 可回退直连；`enforce` 必须终止本次调用，不能继续直连。

容器日志在容器重建后会丢失；执行日志随调用持久保存。

## 主要字段

| 字段 | 含义 |
| --- | --- |
| `request_bytes` | 网关从 Codex 接收的请求体字节数；本地拒绝或连接失败不代表供应商收到这些字节。 |
| `request.items` | 按类型（如 `message:user`、`function_call_output`）统计的条数和字节。 |
| `request.largest_item` | 本次请求中最大的一条输入及其字节数。 |
| `request.image_count` / `image_data_url_bytes` | 请求中内联图片数量，以及它们在请求体中占用的字节。 |
| `request.images[]` | 每张图片的位置、格式、宽高、请求内字节和解码后字节（最多列 16 张）。 |
| `response.status` / `upstream_request_id` | 响应状态码和上游请求编号；本地拒绝响应不是供应商 413，也没有供应商请求编号。 |
| `response.usage` | 流式响应结束时供应商报告的 token 用量；缺失不等于零。 |
| `max_request_bytes` / `max_request_seq` | 本次调用中最大的请求及其序号。 |
| `first_413_seq` / `first_413_request_bytes` | 首次上游响应 413 的请求序号和大小；本地拒绝没有上游响应，不计入这两个字段。 |
| `mode`（汇总） | 本次网关使用 `measure` 还是 `enforce`。 |
| `outcome` / `gateway_error` | 本地拒绝为 `gateway_rejected`，错误码区分预算超额 `MODEL_REQUEST_BUDGET_EXCEEDED` 与编码无法校验 `MODEL_REQUEST_ENCODING_INVALID`；上游 413 标记 `MODEL_PROVIDER_PAYLOAD_TOO_LARGE`。 |

## 内容边界与限制

记录中只有模型 ID、输入类型名、计数、字节数、图片尺寸、状态码、供应商响应编号和用量。不记录提示词、工具命令或输出、模型文字、图片字节、图片地址、请求头或密钥。

- 网关到供应商使用 HTTP/1.1；直连时 Codex 可能使用 HTTP/2。每次转发多一次本机处理，代理隧道会被复用。
- `measure` 保留既有 **256 MiB** 请求缓存保护；超过上限时本地返回 413 / `GATEWAY_REQUEST_LIMIT`，记录为 `outcome=gateway_rejected`、`response=null`，没有转发给供应商。该保护不是测得的供应商上限，也不计入 `first_413_*`。`enforce` 则使用上文显式请求预算和错误分类。
- 请求会在内存中缓存并解析，峰值可能高于原请求体大小；`request.items` 是重新序列化后的分项大小，不能用其总和替代原始 `request_bytes`。压缩请求的原始大小和解码后的 `request.json_bytes` 也须分别看。
- 供应商响应如果被压缩，只记录状态码和字节数，不解析用量。
- 网关需要读取并检查请求体，预算与实际 worker 并发、容器内存须共同验证；256 MiB 配置上限不保证所有执行环境都有足够余量。
- 本地预算低于真实任务需要时会提前终止；高于供应商实际限制时仍可能收到一次上游 413。拦截只提供边界与诊断，不保证任务完成。
- 单图压缩不能替代累计请求预算；多张小图及历史仍可累积。请求大小通过也不能证明 OCR 数字、财务表格或最终文档正确。

## 发布验收

固定应用版本、实际镜像、CLI 和供应商，保留以下证据后再判断部署效果：

1. 文件编制在全局 `off`/`measure` 下仍强制 `enforce`，空全局预算使用 2 MiB；其他路径 `off` 保持直连方式且没有请求预算；所有模式均停止明确 413；`measure` 启动失败允许直连；`enforce` 缺失/非法预算及网关启动失败均不能绕过保护。
2. 边界字节、压缩后较小但解码超额、单图合规但多图累计超额均被正确处理；每次本地拦截记录未转发，上游 413 与本地拒绝分开。
3. 首次拒绝后没有同体上游重连；终态明确、未知用量仍未知，暂停/取消及账务行为保持一致。
4. 生产固定 CLI 0.169.0 的 DeepSeek 与 Copilot 路径分别验证。真实 CLI 0.167 的合成测试不能替代这两条路径的验收。
5. 同一锁定大 PDF 的真实业务完成、财务明细完整、正式 Word 可下载另行验收；没有正式成果时不能因拦截生效就关闭 #994。

本文描述配置与待验收行为，不提供本次未执行的测试通过声明，也不代表功能已部署。

## 背景

Codex 执行日志不会记录 `view_image` 看图事件。此前用 Codex 0.167 做的合成测试中，一张 1542×2184 的灰度扫描页被缩放为 1333×1888 的 PNG 后，在下一次请求中占 2.56 MB；第一次请求只有 27.7 KB。该图片会随后续每次请求重复发送。生产中的实际比例需要测量。

[#1302 的固定版本合成接线记录](https://github.com/ITSophiaXu/BondBuddy/blob/9fbd5b59200cbd2b4ca17d947d33e324f41318b5/docs/verification/file-authoring-payload-recovery-20261113.md#L47)中，四次受控裁剪使请求从 33,346 B 逐次增至 613,554 B，说明单图有界仍会累计。该测试不是 DeepSeek 上限实测，也不是财务识别或真实成果验收。
