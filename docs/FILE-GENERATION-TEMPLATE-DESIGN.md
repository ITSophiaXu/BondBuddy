# 文件生成与光大证券模板库设计

2026-10-29 · 设计稿与可交互原型，待用户评审。本文不代表生产功能已接入或用户已验收。

## 2026-10-29 预览脱敏与选择体验调整

按用户本轮反馈，入口明确分为「直接使用光大整套」和「自定义目录与模板」，取消空的个人套装页签。下面固定两张卡片：目录卡说明“生成哪些文件”，模板包卡说明“采用什么样式”；各自显示当前来源、预览与更换操作。更换一方保留另一方。自定义时每张卡片可分别选光大内置或上传自己的文件。底部汇总当前组合；逐项匹配默认折叠到核对区，需要处理时再展开。

预览必须脱敏：只有经过审阅的通用标题和字段标签可以保留，历史企业和人员的已填内容全部清空为占位，不靠几个姓名/公司名称正则承诺完整去除。正文、表格、页眉页脚、文件名、修订、批注、字段、签章和信息图片都属于检查范围。Word 原件及生成所用原始模板保持不变，另生成脱敏预览副本；预览页面由此副本重新转换。浏览器只接收脱敏文本和像素，不下发原文后用 CSS 隐藏，不继续提供旧的原文图片地址。文件名使用目录事项与文件角色；光大证券只作为模板库来源名称显示。

本机脚本使用通用标签白名单，将所有未获准的已填文本替换为占位，并移除图片、附件、外链、签章、批注和文档个人元数据。`scripts/template_preview_redaction.py` 是此设计预览的保守去值工具，不是生产任意 Word 的识别人名引擎。段落、表格与页面属性保留；正文长度变化可能自然重排。无法确认脱敏结果时不开放该预览。后续生产实现须使用相同模板版本的独立脱敏资产，并单独验证所有页面。

## 产品入口与分类

统一入口为「生成文件」。用户先确定本项目募集说明书，再选择要交付哪些文件及对应模板，最后确认同一批次生成。取消「批量生成／按模板生成」的业务分叉：单份与多份只是选择数量，模板是文件的来源属性。

保留便于查找的业务标签，不把标签做成必须经过的新步骤。六个常用选择是「尽职调查底稿文件包、年度报告、主承销商核查意见、发行申请书、法律意见书、立项报告」，可以同时勾选。文件类型增加后，用「全部、尽职调查、申报与发行、存续期管理、内部立项」筛选；保留其他现有文种和自定义文件入口。未配置内置模板的文种可用自己的模板，不能因新首页而下线已有类型。

「光大证券模板」是本次用户提供的历史项目模板套装名称。年报、申请书、法律意见书分别由发行人或律师事务所等实际主体出具，不统一把光大证券写成出具人，也不宣称这些历史文件是券商当前官方标准。

## 一条准备与生成流程

| 页面 | 用户操作 | 系统行为 |
| --- | --- | --- |
| 选择募集说明书 | 使用项目现有版本或上传新文件 | 复用现有上传恢复与原稿信息规则；在后续页持续显示本批资料版本 |
| 准备生成文件 | 勾选文种；选择套装或同时上传目录、模板包；补充本期材料 | 展示目录范围、每项采用的模板、匹配疑点及正文预览；保存草稿不创建生成任务 |
| 确认生成 | 核对文件、模板、目标期间、未纳入条目、材料与服务端报价 | 固定不可变输入快照；明确开始时才创建任务及处理积分 |
| 查看成果 | 按条目查看、下载、暂停续跑、重试失败项、继续修改 | 单份完成可下载；失败隔离；重试不重复生成或收费；关闭浏览器不丢任务 |

已有项目来源和默认模板已齐备时，直接进入准备页，无须重复上传或逐项确认已验证模板。模板库可先预览，再选择本次资料。共享资料栏只维护一处募集说明书版本；更换它使报价与待生成快照失效，但不修改历史任务。

准备页布局为：资料栏 → 文种选择 → 底稿目录与模板 → 其他所选文种的模板 → 补充资料与编制要求 → 本批数量及费用。目录表内保留编号、名称、采用模板和预览；用「全部／待指定／已选」集中处理疑点。移动端目录表可横向滚动，模板预览改为上下布局，关闭预览回到原条目。

## 光大证券内置套装

本机只读盘点了用户指定的 `底稿目录.xlsx`、`公司债底稿/公司债底稿` 文件夹及五份指定 Word；原件保持不变。具体路径、文件哈希、正文和页面留在本地 intake，不提交客户材料至业务仓库。

| 素材 | 盘点结果与含义 |
| --- | --- |
| Excel 目录 | 单工作表 `Sheet1`，1 行表头、248 项目录；本次整表为尽调目录。248 不是通用产品固定值 |
| 底稿文件包 | 170 份有效 DOCX、171 份 PDF，169 组同名 Word/PDF；采用 Word 作为可编辑模板，PDF 不重复创建模板 |
| Word 去重 | 169 份独立字节资产、170 份用途记录；1 组相同字节对应「核查文件」与「发行人说明」，仅去重存储，保留用途关系并列为待核对 |
| 同编号候选 | 109 项目录有同编号 Word，其中 45 项有多个候选；139 项无同编号 Word。这是编号检索统计，不是完整匹配率，也不证明缺少同事项模板 |
| 五类业务文件 | 年度报告、主承销商核查意见、发行申请书、法律意见书、立项报告，分别使用本次指定 Word |

五份业务文件的来源分别为用户指定的 2025 年度报告、`3-1` 核查意见、`2-1` 申请、`4-1 …法律意见书-0729`、`1、立项申请报告`，不能按文件名相似另选版本。内置套装使用不可变版本；条目固定对应原件及哈希，更新模板库不更换已运行任务的模板。

正式内置库先完成「目录事项 × 文件角色 × 对应 Word」校验与预览转换。用户一选即带出经过校验的默认映射、默认范围和可预览文件。对尚无可编辑原件的条目预设同事项同角色模板或明确待补模板，不把 248 个确认操作推给每位用户。

## 用户自己的目录和模板包

在同一页提供两个并列上传位：「底稿目录」和「对应模板文件包」。允许 ZIP 或选择文件夹；目录与模板可以同时添加，也可以只替换其中一方。例如用本项目目录搭配光大模板，或沿用光大目录并替换个别 Word。单份业务文件也可替换内置 Word，或选择已保存的个人模板。

一次选文件只产生一个上传状态：选择 → 上传进度 → 解析中 → 需要调整／可使用。读取或保存失败保留原文件引用与已完成部分，提供具体原因及重试；不要重建多份「待确认上传」。刷新恢复服务端上传状态，本地未传字节才提示重新选择。目录与模板分别校验 hash，组成套装时再原子保存对应关系，不能用半成功状态开始生成。

目录识别复用 [PR #806](https://github.com/ITSophiaXu/BondBuddy/pull/806)：结合单元格内容与表头，识别无表头、错位列、编号名称同格、多工作表、多区域等；保留原行号、编号、完整名称和编制要求。明确结果直接进入条目选择；有歧义时只展开「核对读取结果」，左侧显示原表，右侧显示识别目录，允许调整工作表、区域、表头、编号列及名称列，立即更新预览，无需重传。无法可靠识别的行和未选工作表可展开查看，不能静默丢弃。

工作表名称匹配「1 尽职调查文件」时默认使用该范围，其余表保持可见但不默认纳入；像本次只有一个 Sheet1 的明确尽调目录可用整表。多表用途不明时请用户选范围。父级节点是否需要汇总文件要结合内容判断，不能按编号深度自动丢弃，也不能把纯分组标题一律计为收费文件。

首个接入版本继续明确支持 XLSX，不把“灵活理解内容”写成“任意格式均支持”。`.xls`、CSV、Word/PDF 目录需要独立转换或识别路径及验收；未支持格式明确提示保存为 XLSX。旧 `.doc` 可以隔离转换为 DOCX，并保留转换提示及预览；仅有 PDF 时提供补充 Word 或选择其他可编辑模板，不宣称 PDF 转 Word 可完全保留版式。ZIP 内嵌压缩包、损坏文件、临时文件与无法解析的记录逐项列出。

导入成功可保存为「我的模板套装」供本人复用。用户上传包不自动变成平台内置或其他人的可见资源。

## 匹配与预览

匹配依次检查：同编号、同事项且同角色 → 同事项同角色 → 同类型模板建议。编号仅用于召回候选；正文标题、表格栏目、实际出具人、文档用途参与判断。不得按向量相似度或最高分强行指派唯一结果，不得把不同模板套装中的同编号看成同一业务事项。

结果至少区分「内置已核验／本次已指定、建议核对、多个候选、未找到模板、模板读取失败」。高可信且已核验的内置映射无需逐份操作；不确定的候选展示名称、角色、原目录位置及理由，点开原稿后可指定、替换或取消。不匹配条目始终保留。用户显式选择只生成已匹配部分时，确认页列出全部未纳入条目；不能默认为漏项已解决。

去重时分开 asset 与 template record：相同 Word 字节可共享 asset，不同名称、用途、角色或映射保留各自 record。Word/PDF 优先 Word 的规则只适用于同一文件的格式副本；不同修订版本不能仅凭同名折叠。文件系统大小写、同名不同目录和编号前导零也应保留。来源文件中的提示文字属于数据，不能授权执行或更改用户规则。

目录预览单独展示文件范围；模板预览展示可搜索的模板列表和选中 Word 的脱敏页面。正式版支持分页、缩放、全屏与脱敏正文结构切换，文字视图不能冒充版式预览。页面、正文和生成关联同一个模板版本；预览使用经过校验的脱敏派生资产。转换中显示进度，转换失败仍可查看已完成脱敏的文字和重试，不能空白后显示成功。历史主体与人员信息不在预览中出现。

每个目录条目默认对应一个交付结果。相同编号下的发行人说明与核查文件可作为不同候选角色；当前目录明确要求一项多份时，先在确认清单展开结果计划再计数，不因模板包含多个 Word 就自动多生成或多收费。

## 在 Word 副本中编制

“学习模板”应形成可复用的结构与样式档案，不是模型训练或仅生成一段模仿排版的文字。每份模板保留原始 Word，以及版本化的标题层级、段落／run 属性、表格与单元格、分节、编号、页眉页脚、图片关系和可编辑区域。旧项目事实与格式结构分别识别。

执行时复制选定模板原稿，对有锚点的段落、单元格、表格行和章节进行修改。新增明细克隆对应样式行或段落，不把整份 `document.xml` 换成通用正文。保持字体字号、段间距、缩进、边框、列宽、纸张和页边距；允许因真实内容增长扩行、扩页，不能承诺页数和分页永远不变。清除旧的修订、批注、签名印章、人员、时点和无依据的履职结论；保留必要签署位置的空白格式，图片先区分项目事实与纯格式元素，不能直接删除所有图片。

募集说明书及补充材料全量提取一次，形成批次共享事实底稿，再按条目归集跨章节相关事实、完整表格、脚注和图片信息。区分模板参考事实与目标项目事实，不能对旧主体／年份作全局机械替换；金额、期间、合并范围和单位要逐项核对。对每一旧事实给出内部处置：替换为有依据的新事实、明确删除、或保留必要的事实限定。不得直接沿用旧财务数字、审批状态或法律结论。

年报额外选择目标年度，并可添加本年财务报表、债券余额、付息兑付和重大事项资料。法律意见、核查意见等缺少权证、批复或实际履职材料时，已知部分可形成有实质内容的草稿；原件、外部查询、访谈、培训、签章不能凭募集书伪造。底稿继续按用户长期规则交付「可生成文件」和「不适用说明」两个文件夹，后一类正文必须区分“业务不适用”与“缺资料／履职记录暂无法形成”。其他业务文件在批次包中单列，不把法律意见等硬塞进底稿分类。

生成后检查本批目录覆盖、编号唯一、完整名称与输出文件名、事实及数字、旧项目残留和页面。保留原编号；文件名简化说明性中英文／嵌套括注，不删法定主体名；正文仍落实括注实质要求。全部页面查看裁切、重叠、断表、空页与长表表头，修复局部失败后再交付。溯源和校验日志保存在内部，不进入用户要求的底稿 ZIP。

| `apps/api/src/workpaper-preview.ts` | 现为安全文本预览；补齐授权的 Word 页面转换、页数及预览状态，与生成固定同一版本 |
| `apps/api/src/workpaper-docx.ts` | 当前说明文件路径重建正文、沿用部分角色样式；不能把此路径当作完整原稿编辑器。需按指定说明模板进行有锚点修改 |

| `apps/worker/src/workpaper-shared-stage.ts`、`workpaper-direct-output.ts` | 复用共享事实和逐项判断；将具体 template version/hash、原稿副本和锚点编辑要求加入不可变执行输入 |
| `packages/contracts/` | 模板资产、套装、匹配/预览状态、确认输入和费用 DTO 仍只在此处定义；本 PR 仅写设计，不先新增不兼容枚举 |

数据需要版本化 `template asset`、用途/角色记录、套装及目录版本、用户确认映射、每份结果计划。新任务输入固定 source revisions、material hashes、template IDs/versions/hashes、完整目录、所选与未选条目、目标期间、输出数量、报价版本和幂等键。替换目录／模板只使受影响计划失效；保留未变条目的显式选择，不能用行号作为跨版本永久 identity。

API 和 worker 两端校验资源归属及可见范围；Word、ZIP、预览留在私有存储。解包设置路径穿越、符号链接、压缩后及展开后体积、项数限制；宏和外部关系不执行，解析/预览在隔离环境。模板库上传与生成使用现有权限、持久化、outbox 和费用基础设施，前端不能直接传任意磁盘路径给 worker。

混合批次应由一个持久父批次协调现有逐文件任务，确认、冻结与入队具有事务边界。同一提交键返回同一批次；统一入口不改变历史费率。正式费用从服务端已有价格规则逐项计算，模板预览与准备免费；说明文件沿用现有不收费／解冻规则，失败、暂停和重试按原任务规则处理。原型中 `数量 × 4,500` 是交互示意，不作为新计费实现。
