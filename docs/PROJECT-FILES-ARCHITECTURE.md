生成继续沿用每份 4,500 积分的现有动态扣费规则。检查和接受修改暂按不新增用户扣费实现，记录模型实际用量；此收费方案尚未获用户确认，发布前需产品确认。模板跨项目复用按最新设计实现，未新增共享给其他用户的权限。

## 内容关联与检查

`bb_project_files` 是稳定文件身份和当前版本指针；`bb_project_file_versions` 是不可改的历史记录。来源募集书、模板和成果均带版本与 SHA-256。生成模型同时提出 paragraph/table 引用，host 对照真实字节核实源与目标原文是否在指定段落中唯一出现；没有有效关联的成果不标为一致。

检查冻结当前募集书以及各类关联文件当前版本，通过现有 Codex 调用日志逐份检查。财务期间、单位、主体/合并口径、发行安排、募集资金等共同披露分别核对；不会因缺少材料而自动认定一致。PDF 转为文字/表格进行比较，排版及文字提取限制保留为人工确认。空白/不可读文件、不完整段落覆盖、虚构定位、重叠修改均不能自动更新。

结果包含原文位置、关联文件原文、募集书证据、建议和理由。项目文件显示未检查、检查中、不一致、需人工确认、已更新或版本变化待重查。全部项目、更新/复核成果页和项目文件均可进入检查。

## 接受与版本保留

用户逐项、按文件或批量接受确认冲突。服务端重新核实检查哈希、所有者、当前募集书选择修订号及文件版本；请求幂等。持久化更新包逐份执行。Python 仅替换被接受且不重叠的准确原文，不再调用模型；生成带 Word 修订/批注的修订版和清洁版，旧版继续可下载。

部分接受后再次接受剩余项，以检查时原稿累积所有已接受修改，避免丢失前一次修改。成果和引用关联原子持久化后再写阶段检查点，中断恢复复用原字节。发布当前文件指针采用比较后更新：运行期间用户上传文件或更换募集书时，完成的成果保留为历史，不覆盖用户选择。原募集书不会被关联文件更新替换。

## 接口与存储

公共 DTO/Schema/OpenAPI 在 `packages/contracts/src/project-file-workspace.ts`。

`/api/v1/projects/:project_id/project-files` 下提供：读取版本、workspace、source、imports、batches 与 retry/cancel、checks、checks/:run_id/accept、updates 与 cancel。使用现有认证、CSRF、项目归属、私有 Blob、run actions 和授权下载。冻结操作在 `bb_project_file_operations`，检查结果写入后不可更改；接受记录和文件历史不可变。

迁移 `0111_project_file_workspace.sql` 创建上述注册表、批次和关联记录，回填已有成功 M4 文件；扩展十二类型及模板品种约束，沿用并扩展 M4 费用结算任务列表。历史成果不伪造内容关联，初始为未检查。发布需协调 API、worker、web 和此迁移；不支持用删除历史表方式回滚。旧版代码不能处理新类型，回滚前先停止新入口、处理在途任务并由发布负责人评估兼容性。
