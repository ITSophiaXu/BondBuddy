## 开发者如何使用

1. 先阅读所选案例 README；优先用任丘九月或章丘年末进行电子材料联调，再用杞县验证 OCR/多年更新，任丘六月验证日期冲突提示。此顺序是测试建议，任何一组都还没有验收结论。
2. 在测试环境新建独立项目，选择“有历史募集书”。历史稿放入 `historical`；年度报表放入 `financial`，中期报表放入 `interimFinancial`，附注放入 `notes`，审计包放入 `audit`。按清单逐份上传，保留材料 ID、版本和 hash。
3. 以系统识别结果对照原文证据。不要将本目录标签直接写入识别结果，也不要因为清单标了发行方式或期间就跳过 #76 的证据抽取、冲突处理和难度比较。
4. 真实执行后记录运行版本、输入快照、job/run、日志与用量、修订版/清洁版成果及专业核对意见。使用[验收记录模板](ACCEPTANCE-TEMPLATE.md)；记录应链接受控成果，不向样本目录提交运行缓存、凭证或生成稿。
5. 在 Windows WPS/Word 中验证修订、批注、接受/拒绝、保存重开；结构检查或其他渲染器不能代替 #146 的客户端验收。

校验原件（只用 Python 3 标准库，不调用模型或上传文件）：

```shell
python tests/samples/verify.py
```
