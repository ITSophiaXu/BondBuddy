# BondBuddy 真实项目回归与 bug bash 样本

本批按用户 2026-11-05 的明确要求整理指定账号下七个项目的原始材料和输入。用途为私有仓库内部功能验收、回归测试和 daily bug bash。材料准备与校验不代表业务功能已经通过验收。

**当前为部分交付：16 份去重原件，62,328,265 字节；登记17个案例，其中15个可准备，2个更新案例尚未齐备。** 中捷、邹平的9份财务/评级附件及完整业务输入仍未读取，具体见 [SOURCE-CAPTURE-GAPS.md](SOURCE-CAPTURE-GAPS.md)。离线校验通过只表示已收录文件完整，不表示全部来源已取得。

`manifest.json` 固定已收录原件的 SHA-256、字节数、来源绑定及缺失清单。相同字节只保存一份，各案例通过文件 ID 引用；同名但字节不同的版本分别保留。原件不转换、不清理日期、不修改财务数值。

## 离线准备

在仓库根目录执行，Python 3.11 或以上即可，不需要数据库、模型或登录凭据：

```shell
python tests/samples/verify.py
python tests/samples/regression_pack.py list
python tests/samples/regression_pack.py prepare --case update-xinjin --output work/bug-bash/update-xinjin-run-01
python tests/samples/regression_pack.py prepare --case qa-dongying --output work/bug-bash/qa-dongying-run-01
```

准备命令生成 `materials/`、`input.json`、`preparation.json`、`RUN-RECORD.md`，以及适用的 `source-inputs.json`。它只复制本地样本、核验哈希，不提交任务或扣费；输出目录必须是新目录，避免覆盖前次结果。`list` 标明 READY / INCOMPLETE，`prepare` 拒绝未齐备案例。

使用时在独立测试环境新建项目和测试账号，按文件绑定重新上传，在界面填入业务字段及原要求，再按当前规则报价和执行。**原生产项目 ID、任务 ID、材料 ID、冻结 hash、报价和账务引用只用于来源追踪，不能直接作为新请求重放。** 新环境生成的新 ID 记录到运行记录中。

有多版本原稿时，按已记录输入的绑定选择正确版本；其他版本留作切换、续改和历史兼容测试，不能全部自动当作事实证据。删除标记仍保留用于解释历史上传，但不将已删除项默认重新选中。

## 验收方式

按 [BUG-BASH.md](BUG-BASH.md) 分配案例和记录结果。每次固定候选 commit、镜像、模型/提示词/规则版本以及本批清单 hash；区分真实模型、合成模型和仅页面模拟。

募集书更新须逐项核对最终 Word 中的目标财务数据及对应正文；复核须检查完整报告与实际问题；问答须检查全部问题块及其子问、资料缺口、引文和回填 Word。文件可下载或任务显示成功不等于内容正确。

本批没有将历史生成稿、恢复稿或任务 `succeeded` 状态认定为标准正确答案。专业基准、未覆盖类型和建议补充材料见 [COVERAGE-GAPS.md](COVERAGE-GAPS.md)。

## 数据边界

- 仅用于 `ITSophiaXu/BondBuddy` 私有仓库内的团队测试；未授权公开再分发或自动加入生产参考库。
- 原始客户文件和新编测试要求分别标注。不会修改原生产项目、任务、积分或历史结果。
- 不包含账号密码、Cookie、访问令牌、存储密钥或临时下载链接。
- 原件结构/哈希检查不等于逐页排版或专业核验；文件中原有异常也可能正是需要保留的测试条件。

清单版本 2 将全局原件与案例引用分开，避免五类任务重复存储同一募集书。旧的 2026-09-25 批次保持原版本 1；总校验脚本同时验证两种格式。
