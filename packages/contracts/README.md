# M1 public contract (Issue #6)

## Current #11 addition

The original #6 skeleton description below is historical. For current persistent endpoints and auth see `apps/api/README.md`; the integrated Vite client is documented in `apps/web/README.md`. `src/update-project.ts` is the single public definition of `UpdateDetailsSchema`, money units/precision, purpose codes/material hints, field limits and semantic date/amount validation. `MARKET_LABELS`/`OFFERING_LABELS` sit beside the existing enums in `src/index.ts`. UI imports these; it does not maintain a second market dictionary.

`ProjectCreateRequest`, `ProjectPatchRequest` and `ProjectResponse` add optional `update_details` for old client/example compatibility. New server responses always fill its canonical shape. Its members are all required when the object is present; fields use null for unknown and an empty list for no entered funding rows. PATCH omission retains it; present object replaces it completely, including explicit nulls. Amounts are decimal strings (nonnegative, up to six decimal places), with `yuan` / `ten_thousand` / `hundred_million` unit codes. DFI remains `market=nafmii, offering=dfi`; there is no registration-mode field. `examples/update-project.json` contains clearly synthetic examples and is checked together with existing examples. New input manifests include these user-provided details; source recognition and confirmed facts remain independent. See #11 migration/round-trip tests before relying on persistence in other modules.

This is the importable source for public values, DTOs, JSON Schema and OpenAPI. All `/api/v1` operations are **contract only** in this slice. The API skeleton implements only `/health` and `/openapi.json`; it has no login, database, object storage, queue, model calls or artifact delivery. Synthetic examples do not demonstrate deployed behavior.

## Fresh checkout

Use Node.js 22 and npm 10 or newer at repository root:

```bash
npm ci
npm run build
npm run check:contracts
npm run test:api
npm run start:api
```

Open `http://127.0.0.1:3000/health` and `http://127.0.0.1:3000/openapi.json`. `PORT` and `HOST` can change the local listener. It binds to `127.0.0.1` by default. The root `package.json` introduces npm workspaces only for `packages/contracts` and `apps/api`; `product-prototype/` remains an independent existing package. Do not use the old Python `backend/server.py` for M1 routes.

Consumer code imports values and inferred types from one package:

```ts
import { MARKETS, MARKET_OFFERINGS, M1_MATERIAL_PARTITIONS, M1_UPLOAD_MIME_TYPES, RUN_STATES, schemas, type Project, type RunEvent, type Recognition, type InternalObservabilityEvent } from '@bondbuddy/contracts';
```

Use `npm run build` before importing compiled package output. `schemas` are runtime JSON Schema objects; `openApiDocument()` exposes the public schemas and operation catalog, while internal observability schemas remain importable from the package but are omitted from public OpenAPI. The synthetic examples in `examples/synthetic.json` are validated with AJV by `npm run check:contracts`. The checker also verifies revision/idempotency conflict envelopes, owner-safe 404, recovery of the *same* run after a new session, ordered event cursors, OCR uncertainty, and missing usage represented as `null` rather than inferred zero. The runnable API test verifies advertised routes remain contract only.

## Contract conventions and handoffs

- Public HTTP prefix is `/api/v1`. Spec 16's `/platform/v1` is an older prefix; the newer M1 architecture and `AGENTS.md` set `/api/v1`. CTO technical verification of this contract is the #8 handoff gate.
- All times are UTC ISO-8601 with trailing `Z`. `null` means unavailable, unknown or not yet determined as described by the field; `0` means a measured zero. SHA-256 hashes use 64 lowercase hexadecimal characters. Cursor pagination is opaque; `next_cursor: null` ends a page. Run event `seq` is a per-run increasing integer and clients deduplicate `event_id`.
- `ProjectPatchRequest` requires `If-Match` with current `draft_revision`; stale revisions return `INPUT_REVISION_CONFLICT` (409). Its fields are partial, so the service must merge them with the stored project and then validate the resulting market/offering pair with `isMarketOffering()`. A JSON Schema check of the patch alone cannot reject an invalid pair made from one old and one new field. After upload completion, `POST /projects/{project_id}/input-revisions` binds the current draft, verified owner material versions and submitted requirement messages into an immutable snapshot. The server computes `input_hash`; the browser cannot choose it. This explicit route is the #6 server-owned snapshot boundary for #8 implementation and integration tests. `execution_request_id` is unique per user action: same key and same immutable input returns the same run; same key with changed input returns `IDEMPOTENCY_CONFLICT` (409).
- Unknown and foreign personal resource IDs share `NOT_FOUND` (404). The service must derive `user_id` from the session, check ownership at every read, association and download, and never accept caller-supplied `user_id` as authority. The browser must not receive supplier credentials, private Blob keys, internal reference candidates or raw model request bodies.
- Upload is created with a scoped, short lived URL. `UploadCreateRequest.media_type` and filename are untrusted declarations. The service must verify actual bytes, container/magic signature, safe content, size and hash before recording a canonical `MaterialResponse.media_type`. Supported ordinary formats are DOCX, PDF, XLSX, CSV, TXT, PNG and JPEG (`M1_UPLOAD_MIME_TYPES`). Legacy DOC/XLS and macro formats such as DOCM/XLSM return `MATERIAL_FORMAT_UNSUPPORTED` (415); encrypted input returns `MATERIAL_ENCRYPTED` (422); a declared/verified type or hash mismatch returns `MATERIAL_CONTENT_MISMATCH` (422). Do not advise renaming the extension. These are contract errors; the skeleton does not inspect files. `persisted` means an immutable server copy exists; parsing and source recognition are asynchronous.
- M1 update uploads use the fixed `M1_MATERIAL_PARTITIONS` and `M1_UPLOAD_MATERIAL_ROLES` taken from the current `product-prototype/public/project-fields.js` values: historical or user supplied similar prospectus, plus financial/audit, issuance/fund use, corporate/credit, debt/security, and business/governance support materials. `reference` means a **user uploaded** similar prospectus, never an internal library item or permission to access one. The service also checks format by role: a historical prospectus baseline requires DOCX or PDF, even though ordinary support materials allow all seven listed formats. Review (`updated`) and generation roles are outside the M1 update upload schema until their capabilities are released; server capability/owner checks still apply. The example checker compares the shared role codes and labels with the prototype to detect drift while Chris migrates its UI imports.
- `RecognitionResponse` contains separately sourced market, offering, reporting periods and latest cutoff. Each field or period carries raw text, material version, extraction/correction method, evidence anchors, uncertainty and status. Annual/interim and consolidated/parent scopes stay distinct. Ambiguous source values and an unproved latest cutoff remain `null`; signing/issuance dates do not substitute for reporting dates. Xuefeng must derive the cutoff from supported periods and preserve correction history; Chris can render uncertainty and evidence without inventing values. `MARKET_OFFERINGS` and `isMarketOffering()` express approved target combinations from spec 00; source recognition does not overwrite target fields.
- Runs belong to the server. Closing a tab causes no cancel request. A reauthenticated user calls `GET /api/v1/runs/{run_id}` and `GET /api/v1/runs/{run_id}/events?after=<last_seq>` to recover the same run; the examples show the intended contract, **not a live recovery test**. Explicit cancel is its own operation. Worker recovery must reconcile provider attempts before retry. Only a checked, authorized, retrievable Word artifact permits `succeeded`.
- Public `RunEvent` is an ordered, owner filtered run progress event with a fixed safe payload field list and `schema_version=1`; it is returned by `RunEventsResponse`. Upload/parse/recognition can happen before a run exists, so `ProjectEvent` carries those project scoped event types and has its own cursor at `GET /projects/{project_id}/events`. Consumers deduplicate both by `event_id`; sequence is ordered within its own run or project stream, not globally. `InternalObservabilityEvent` is a separate versioned #79 handoff for trusted services: operation/request/trace/span, job/run/work item/call attempt, job kind/stage/status, prompt reference, structured error and usage observation. It must stay on an internal transport and never be copied wholesale to the browser. These event schemas have no prompt body, secret or arbitrary payload field; prompt content belongs in encrypted, access controlled snapshots. #79 will implement durable operation/job/prompt/call/outbox records, retention, querying and access controls; this slice does not persist logs. Missing usage is `pending` or `unavailable` with `null` unknown counts, distinct from a measured zero. #16 will validate actual provider model IDs and protocol behavior; the synthetic model ID is not a real provider selection.

# #12 completion reuse semantics

`M1_UPLOAD_LIMITS` is the shared single-file/saved-project capacity definition. No JSON DTO shape or role changes. Completing a renamed equal-content upload may return an existing `MaterialResponse`: the canonical filename, upload ID and exact material version may predate the current upload session. Clients must use that returned material identity for recovery and downstream work, not infer a new material from transfer completion. Reuse is scoped to owner, project, role, verified hash, size and MIME; it does not authorize cross-owner/private cache reuse. See `apps/web/UPLOAD-ACCEPTANCE.md`.
