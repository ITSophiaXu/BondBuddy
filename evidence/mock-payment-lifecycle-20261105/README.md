# 模拟支付、充值与扣费验收

2026-11-05，按用户“没有付款 SDK，先开发模拟支付、充值、扣款链路”的要求完成。实现基于 `develop` 的 `ca6171205093acdd52d70728285a4d27c709fe73`，独立分支 `feat/mock-payment-lifecycle-20261105`。

模拟收银台接到产品真实订单，明确选择付款成功、失败、保持待付或关单。查单只读取渠道事实；认证回调和查单均由实际产品事务入账。充值、任务扣款、退款冻结与结算使用真实 PostgreSQL 账本，测试端没有直接改余额或赠分。

默认商业模式保持现有 `outcome_cny_v1` 的预留和交付结算。按进度专项显式选择独立配置及连接池，通过真实 `authoring_balance_v2` 执行；本地 synthetic legacy 价表不覆盖商业价表。没有修改产品 API、公共 provider 枚举或生产迁移。

原始失败均保留在本地 `.runtime/` 和 `.local/`：首次低余额补款后直接继续需要额外状态刷新，随后已在领取工作前核对真实恢复条件；退款金额 wire 格式、失败回执 `CLOSED`、双配置共用 Pool 的问题均由真实联调发现并修复。旧年付脚本进入管理页及停止续费确认也按当前实际 UI 修正，未放宽业务断言。最后完整生命周期及续费在最终服务重启后再次通过。未重写历史 2026-10-30 的证据文件。

## 复现

从仓库根执行 [本地测试说明](../../scripts/billing-functional/README.md) 中的启动命令，再运行：

```powershell
npm run test:billing:mock
npm run test:billing:mock:flow
node scripts/billing-functional/cashier-browser-verify.mjs
node scripts/billing-functional/product-recovery-verify.mjs
```

涉及任务队列的脚本顺序执行。原始报告写在 `scripts/billing-functional/.runtime/`；新浏览器报告各用独立随机账号子目录。生产服务默认不加载任何模拟入口。真实商户及真实模型成果仍分别验收，不再阻断本阶段模拟链路开发。
