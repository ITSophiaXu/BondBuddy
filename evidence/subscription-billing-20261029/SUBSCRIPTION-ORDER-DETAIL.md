# 原支付订单与订阅周期核对

2026-10-29。本记录为本地开发与合成数据验证，未发起真实支付、退款或生产发布。

## 修复

此前账户 API 仅返回最近 50 期，页面把列表中找不到的历史订单显示为永久充值，并使用充值部分退款表单。现在页面通过 `GET /api/v1/subscriptions/orders/:order_id/period` 读取所选原订单，账户列表继续只承担最近记录展示。

- API 先认证本人，再核对原支付订单归属；未知订单、他人订阅单及他人充值单均 404。
- 仅经核实的充值单返回 `period: null`；订阅单按原 order_id 与 owner 读取唯一原周期、原积分有效期与冻结分项。
- 原周期缺失、订阅订单与周期原对价不符，或者已付款订阅缺有效 lot 和日期时返回 503。数据库读采用同一只读可重复读事务，响应为 `private, no-store`。
- 新 DTO 的金额与积分直接使用公共 `Int64Schema` 十进制字符串；不增加旧数字 wire 层。
- 前端只有明确的周期或明确 `null` 时展示对应订阅/充值规则；404（包括旧部署未提供接口）、503、无效 schema 或错订单回执均显示“订单类型待核实／有效期待核实”。读取失败时暂停现金退款入口，并关闭已打开的原退款弹窗。刷新核实后恢复正确规则。
