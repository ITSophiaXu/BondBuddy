# 支付宝规范化交易账单与原账核对

2026-10-30。本轮为本地 PostgreSQL 与 synthetic 完整 CSV/已认证接口边界测试；没有商户网络请求、真实付款、退款或生产数据。

## 行为与证据边界

- 仅接受 `alipay-trade-cn-v1` 规范化结果，重新验证条目唯一性、日期、int64 金额及汇总。未识别配置保持原 unresolved 下载证据和 unknown 重试状态。
- 一个 PID 的账单可能含多个应用。行中不生成 APPID；按本库原订单号、支付宝交易号、商户归属共同匹配。退款另匹配原 `out_request_no` 及本库记录的渠道复合身份。未登记行记为未归属覆盖差异。
- 交易金额与本地订单名义金额核对；退款金额与本次原退款金额核对，使用明确业务类型对应的金额幅值并保存源值符号。
- 商家实收、商家优惠由明细算式和可用尾汇总核对。服务费保留原符号和按类型聚合金额；本地没有独立应付手续费台账，本轮没有核准商户费率或验证手续费的独立预期值。可选字段缺失留下 coverage。
- 买家现金证据仍来自原验签接口，不使用商家实收填充买家实付。原付款现金凭证、原积分发行、退款现金事件和分配后的积分退回分别核对。
- 完成时间按系统既定 `Asia/Shanghai` 解释，与本地已认证付款/退款成功时间比较。公开 CSV 字段说明未显式给出时区；此项是部署解释约定，待商户代表性样本核验。不会用本地 `created_at`、`completed_at` 或微信退款受理时间代替。
- 已认证完成日发生的漏单，以及名义金额/身份/时间冲突生成差异与告警；计算完成为 complete。格式未识别或关键认证时间缺失为 unknown 并退避，不声称对账通过。
- 同一 ZIP 的旧 unresolved 证据不可改写。规范化证据使用 `sha256:alipay-trade-cn-v1` 新键，保留旧记录、检查与原空条目状态。
- 首次取得支付宝认证付款日或退款成功日，会在同一数据库事务中重开该日交易账单任务，保留旧检查。已结算退款只查询原号补时间，不重发退款或重复财务事件。支付宝不要求微信式申请时间。
- 本轮保持已有 90 日检索窗口。超过窗口的迟到日期可排入 pending，但不会自动下载；尚未增加跨窗的额外覆盖清单。正常逐日与窗口内迟到日期已经验证。
- 核对任务只写账单、检查、差异和告警；不会修复付款、退款、钱包、积分或订阅记录。

新 8 项覆盖：

1. 完整付款/退款 CSV、负退款源值，以及商家实收不等于买家现金的正确场景。
2. 错误金额、错误订单/退款身份、未登记 PID 行和本地漏单。
3. 跨午夜退款完成日、漏单及更正账单。
4. 缺付款/退款认证时间保持 unknown，不从 CSV 或本地时间补造。
5. 重复行 unresolved，以及同一 ZIP 的旧证据与新规范化证据并存。
6. 超过 `2^53` 的相邻分值精确比较和持久化。
7. 20 天前账单因迟到认证付款/退款日期重新检查，旧检查保留且不重复结算。
8. 支付宝已完成退款的归属检查、后台退避、原号 query-only 日期补证和现金不重复移动。

每项检查对相关财务表进行原始 JSON 文本快照比较，包含付款、现金凭证、钱包、积分事件、退款、订阅、任务退款及 outbox；日期补证用例仅排除明确允许新增的证明日期和调度字段。新测试使用真实数据库约束；31 秒后台年龄门按实际时间经过，不关闭触发器或修改终态完成时间。

CSV/ZIP 解析、RSA2 下载协议和真实商户字段配置是不同验证层。本文件不替代各适配器证据或真实商户验收。总体统一 TypeScript 编译与最终源码版本由集成交付记录补充。
