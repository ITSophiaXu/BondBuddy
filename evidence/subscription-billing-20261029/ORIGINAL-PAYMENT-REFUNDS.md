# 原支付现金退款：历史加赠包与质量返分

2026-10-29。实现与本地合成验证记录，非真实商户退款或上线验收。

## 实现口径

- 1:1 充值保留 `{request_id, amount_fen}`；订阅仍仅支持到账后 7 天内、整期从未消费且未冻结的原单全额退款。
- 历史加赠充值按 `{request_id, points, expected_amount_fen?}` 申请。`amount_fen` 上限仍为 1,000,000 分（人民币 10,000 元），`points` 上限为 1,150,000，覆盖原历史套餐。两种请求单位互斥，金额、积分及可选预期现金均严格验证安全整数。
- 原始认证现金 A、原积分 Q、此前成功退款积分 R/现金 F 不变。服务端用 BigInt 计算 `floor(A*(R+q)/Q)-F`；数据库使用 numeric 再校验，累计 q 不超过 Q、现金不超过 A。消费后的最后一笔剩余权益不会领取已消费部分对应现金。
- 示例：原付人民币 500 元获得 52,500 积分，消费 10,500 积分后，退余下 42,000 积分只退 400 元。若该消费经质量纠正恢复 10,500 积分，可再退 100 元；原单累计仍以 500 元为限。
- 质量纠正产生新 lot。新表 `bb_payment_refund_allocations` 记录本次实际冻结、核销的原单同源 lot；退款主记录始终绑定认证原支付。仅同原单、同 A/Q、同 cash_origin、未过期且未冻结的购买权益可以分配。现金流水和各 lot 的积分流水分别记录，审计使用实际分配。
- 同一原支付只允许一笔未决退款。账户锁后按稳定 lot 顺序分配，先持久化冻结和派发标记，再调用渠道。未知结果保留冻结；仅认证成功核销，认证 CLOSED 释放；相同请求恢复不重复退现金。
- 不足人民币 1 分的请求不建退款、不冻结或销毁积分。已认证实付证据缺失、外部补贴导致实付与原单金额不等额的订单继续拒绝自动现金退款。原单现金证据须来自可信回调或查单，不从名义积分推断。

## 前后端协议

Eligibility 提供 `request_unit`、`original_points`、`paid_amount_fen`、`refundable_points`、`refundable_fen`、`refunded_points`、`refunded_fen`。回执同时提供 `amount_fen` 和 `credit_points`。

新版 UI 可按相同公式展示现金，提交 `expected_amount_fen`。服务端锁定原单成功游标后若预期不符，返回 HTTP 409 / `QUOTE_CHANGED`；该分支在退款 INSERT 和冻结之前，事务回滚，可刷新后重新申请。不能把一般 `PAYMENT_INVALID` 当作确定未受理：渠道回执冲突也可能在冻结之后返回该错误。未知请求应保留原 request_id。

0142 扩展原始证据和累计对价守卫；0143 增加退款分配及提交时完整/冻结校验，已有退款仅派生回填其原有 credit_points 分配，不改写原金额或终态。

## 验证

使用完整迁移至 0143 的空白本地 PostgreSQL 模板，测试自行克隆隔离数据库；支付/退款使用合成认证渠道证据，没有发送真实退款。

运行：

```text
node --test apps/api/dist/payment-refund-calculation.test.js apps/api/dist/payment-refunds.pg.test.js apps/api/dist/subscriptions.pg.test.js
```

结果：17 passed，0 failed，0 skipped，约 41.8 秒。包括：

1. BigInt 精度、非法/超界数值与不一致累计游标；逐笔一分钱累计到全部 Q 后恰好退全 A。
2. 500 元/52,500 分消费后只退 400 元；质量返分再退 100 元且原单累计封顶。
3. 一笔退款同时分配原 lot 的 42,000 分与质量返分 lot 的 10,500 分，礼赠等其他资金不能混入。
4. 预览变化明确拒绝，断言该 request_id 无退款行、冻结为零、渠道请求为零；不足 1 分保留积分。
5. 未知状态维持冻结、同号恢复、回调/查单并发、任务消费与退款竞态、回滚前不能调用渠道、不可变证据及账本审计。
6. 订阅整期退款、曾消费后拒退、超过 7 天拒退、返分原对价及到期恢复、延期旧周期退款不撤销新周期权益等回归。

Contracts/API 构建由主任务串行统一完成。上述测试使用该构建产物；此记录不替代真实渠道商户验收。

后续独立审查发现日账单曾只读取原 lot 的退款积分事件，漏掉质量返分 lot 的事件。支付模块已按退款分配表精确汇总。追加混合来源对账断言并定向运行 `--test-name-pattern 'cash refunds allocate'`：1 passed，0 failed，0 skipped，约 13.4 秒。该用例确认同一退款现金为 50,000 分、积分为 52,500，日账单差异为零；对账前后钱包和积分事件数完全相同。
