# 募集说明书复核材料 UX 修复

状态：开发和自测完成。代码完成，尚未部署，待统一发布；用户尚未验收。

## 本次范围

用户于 2026-10-28 提供两张复核页截图，要求排除项目问答的问题清单和文件生成的任务材料，将待复核募集书的两种提供方式明确为二选一，并处理用途不明、展开无有效反馈的“按细分类别补充材料”。

- 复核 API 按已保存的业务引用排除问答问题清单、底稿目录、生成模板和文件生成中导入的文件。沿 `bb_update_material_copies` 追踪关联工作区副本；不按文件名、后缀或笼统的 `other` 分类猜测，不排除同名的事实核验材料。
- 复核材料清单和可编辑草稿采用同一排除规则，保存入口拒绝重新加入上述文件；新复核任务固定的输入也经过校验。清理旧浏览器草稿中的不可用材料引用。原件、文件生成/问答记录及已开始任务的不可变输入保持原状。
- “上传新募集说明书”和“选择项目已有募集说明书”使用单选卡，只展示当前方式的控件。当前选定的本次待复核稿持续可见；切换方式本身不替换稿件。上传并保存一份新稿，或明确选择其他版本后，才替换本次待复核稿。
- 新稿上传采用有持久记录的单文件替换策略；上传失败、回执丢失和刷新仍核对原文件、原草稿版本及完整输入，不重复上传或覆盖并发修改。旧上传恢复记录沿用旧策略。
- 移除复核页通用的细分类别折叠入口。财务材料和其他核验材料直接说明用途、选填属性和上传操作；原财务报表/附注等细分角色的已保存文件仍显示在所属分区。
