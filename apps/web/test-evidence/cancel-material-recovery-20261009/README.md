# 取消任务后补充材料恢复（2026-10-09）

关联 #361。用户报告停止更新募集书后材料区一直读取，新上传没有反馈。

## 原因与修复

从全部项目进入的路径带 `?from=projects`，刷新步骤页还带 `step`。材料区使用完整路由与无参数项目路径比较，错误丢弃当前项目的材料读取、上传进度、已保存列表及执行条件同步。取消接口成功也无法解除这一显示问题。现在五处材料状态更新共用按路径校验的函数，仍保留完整导航上下文、项目归属和异步过期保护。

沿用原有「停止本次任务 → 继续修改 → 补充材料 → 生成新版」流程，旧任务输入不改变，补传本身不会执行新任务。回归时还发现悬浮助手挡住开始按钮；准备编制时将收起的助手移到操作栏上方，展开面板的位置不变。

## 验证

Windows / Node 22.14 / Edge，独立 Vite 端口 5619。所有浏览器 API、账号、文件和扣费为 **synthetic**，未将测试文件上传到真实用户项目。

- 修改前新增场景重现失败：停止并继续修改后，材料恢复提示为空、执行区停留在读取材料。
- 新增 3 个场景：项目列表入口、手机刷新材料步骤、不同参数顺序及任务链接。均实际选择并上传补充文件，确认列表/数量/执行按钮同步，重进页面保留文件，上传一次、不重新执行、原不可变输入保持相同。
- `project-execution.spec.ts` + `upload.spec.ts` 68 个不同场景全部获得通过结果：最终整组 67 通过；剩余 1 项为账号页标题变更后的旧断言，将「积分与充值」更新为当前「按需充值」后单独复测通过。
- `npm run build`、`npm run check:contracts` 通过；最终助手样式调整后再次 web build 通过。契约包含 167 公共样例、12 内部样例、4 生命周期样例、29 OCR 用例和 11 发行人绑定用例。
- 助手遮挡曾让真实鼠标点击失败；最终新测试使用正常点击及 `trial` 可点击性检查，没有强制点击或隐藏助手。
