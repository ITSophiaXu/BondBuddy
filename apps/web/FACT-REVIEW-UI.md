# #15 事实候选审核界面首片

项目页的“事实候选与冲突决定”按需读取 #200 已发布的 owner/project 限权 API。浏览器逐页读取完整候选集合后，才按 `fact_key_hash` 和完整 FactIdentity 分组开放提交；重复候选、跨页游标循环、超出 100 页或同组身份/最新决定不一致均不展示部分集合为可审核结果。

审核人能查看全部竞争候选的值、来源、材料版本、原文锚点、OCR/用户陈述疑点及最新决定。选择候选或暂不解决时需要说明原因；提交带上当前看到的 `expected_version`（无决定时为 0），同一次提交失败后的显式重试沿用 `request_id`/`decision_id` 和原预期版本，修改输入会生成新 ID。服务端 409 保留本地输入并要求刷新后再次核对。退出项目或账号时中止读取，候选和请求 ID 不进入浏览器存储。

此界面只记录 `selected|unresolved` 冲突决定，**不升级来源核验状态**，不从项目名称猜发行人 `entityId`，不管理专业 reviewer grant，也不替代 #76 源稿识别校正或 #14 OCR 原页核验。发行人身份来源记录尚无浏览器审核契约，#17 的 input lock 应只消费服务端已签认的记录。

`develop` 已增加服务端预期版本比对；本界面只发送完整候选集合中观察到的版本，不能用本地数据代替服务端并发检查。真实候选入库、专业审核、预发浏览器与发行人身份签认仍需分别验收。

验证：全仓 `npm run build`、`npm run test:unit -w @bondbuddy/web`，以及从 `apps/web` 执行 `npx playwright test tests/fact-review.spec.ts`。浏览器用合成 owner/project API，覆盖跨页完整读取、失败重试同 ID、409 保留输入、缺游标失败关闭、桌面/手机布局与无相关脚本异常；不代表真实 PG/Blob 或专业验收。
