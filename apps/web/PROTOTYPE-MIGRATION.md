## 可操作流程

1. 登录或注册后进入工作台；`#dashboard`、`#update`、`#tasks` 可直接访问，原有 `#/new`、`#/projects/{id}`、`#/artifacts/{id}` 继续支持。
2. 创建页填写项目与展开的选填信息；财务截止日为年份＋3月末/6月末/9月末/年末，右侧可填写特殊覆盖或补充说明。目标期间逐行编辑器已删除。一次创建保存后进入材料步骤；编辑/材料阶段写入 URL 的 `step` 参数，刷新能恢复位置，不把个人草稿存入 localStorage。
3. 材料页分为历史/相似稿、审计报表附注、募投权证、其他项目材料。细分类别是可选展开项，角色仍保留原契约；默认接收角色分别为 historical/reference、audit、fundUse、other。完整审计报告无需拆分上传。文件选择/拖入复用原上传队列、真实字节进度、保存核验、去重及单文件重试。刷新恢复的细分类材料会展开一次，不因轮询覆盖用户后续折叠。
4. “开始更新”在原型材料步骤的页脚，与“上一步”同层；没有独立启动卡片、目标摘要、文书用途/法规日输入、材料重选或常驻确认框。点击后页面串行保存草稿/不可变输入、预检、提交。新增输入省略可选 target_confirmation，不把隐藏的旧期间当作本次重新确认。ready 或 needs_confirmation 直接按用户本次点击提交执行，不额外索要内容确认；blocked 仅显示简短操作提示并可重新检查同一输入，不提交注定被拒绝的 run，不把后台诊断清单当作用户任务。
5. input revision 保存没有幂等键，响应丢失后要求读回并选用已有记录，不盲目重传。execute 继续使用由 project/revision/hash 生成的稳定键；响应丢失重试返回同一任务。编辑或新材料使旧预检失效，已提交请求保持原输入。
6. 启动后进度移到左侧顶部，材料改为可展开回查；暂停/取消/恢复用实际 run API，不模拟百分比。结束后同页显示授权成果摘要、待确认项和修订/清洁/基线下载，沿用服务端检查与浏览器 SHA-256 校验；“继续修改”明确准备下一轮。旧成功成果链接保留。

## #384 上传评估与全文内容处理分阶段（2026-09-28）

以原型 `94e38fba9fcfd4c957fc8c352b69f72bb817c118` 的材料分区、文件行、右侧补充区和页脚主操作为布局基线，按 [最新用户决定](https://github.com/ITSophiaXu/BondBuddy/issues/384#issuecomment-5865771819) 移除上传技术审核。删除历史稿详情/原文/证据/英文 warning、source correction 表单与事件、每行 OCR 核对链接及页底折叠事实审核组件；没有把它们移到新页面。只保留真实处理状态、上传进度、错误及恢复操作。后台画像/证据与既有校正 API 不变，当前视图不读取/调用校正接口。

预检的内容 uncertainty 不再渲染为上传待办或二次确认；一次开始操作可提交 needs_confirmation。blocked 提示仅展示服务端阻断的简短可操作部分或平台待核状态，条件未变时不再引导“继续提交并等待处理”。已暂停的任务不默认提供“继续更新”：材料等待和试用限制由后台恢复，能力等待可按同一 run 的锁定输入重新预检；若预检仍阻断或恢复后再次停在同一条件，则提示联系支持，避免无限循环。服务端权限/版本与执行门禁不变；真实现场原因及是否可恢复由 #35/#76 复核，不能从合成测试推断。#31 负责全文模型处理与 Word/摘要待核；#18 补充迭代对话独立交付。这里没有真实模型/部署/成果验收声明。对照、连续操作及联调依赖见 [#384 证据](ux-evidence/issue-384/README.md)。
