# 订阅与自动计费升级

本文件描述发布准备，不代表已经执行生产操作。保持 `BB_SUBSCRIPTION_BILLING_ENABLED=0`，直到发布环境的迁移、API/worker版本、商户配置与验收一致。现有已经受理订单继续沿用原请求号、原对价和原周期，不重新建单。

## 版本与迁移

1. 备份数据库并记录当前代码与镜像版本，停止旧worker继续受理/完成任务，等待或核实原在途支付意图；不能删除原订单消除未知状态。
2. 使用本次代码执行 `node db/migrate.mjs`。本轮累计迁移至0155：0145独立权限、0146/0148成本和价格版本、0147/0149原条目售后、0150/0151/0154资金隔离与SQL写入保护、0152普通文件逐份检查、0153隔离告警、0155零价同版本检查复用原成果。更早0131—0144必须按序存在。
3. API、所有worker组及网页使用同一可核对版本。新网页使用 `int64-decimal-v1`；旧 `number-v1` 只允许原记录读取/重放，不开放新购买。不得将新wire直接套在历史manifest上重算hash。
4. 核验配置仍关闭新收费，账户、原订单及已交付成果可读取，原付款回调/查询和退款恢复正常，后台隔离扫描与原补单调度就绪。未配置渠道也应运行钱包审计。
5. 发布机器执行现有支付部署检查、镜像代理探针和商户验收。用正式安全配置位置，不把密钥写进日志、聊天或仓库。Windows主环境没有Docker CLI；后续已发现本地BondBuddyM3 WSL内的隔离Docker，可用于合成配置与镜像验证。其验证不等于生产容器、真实商户或发布网络验收，具体完成范围以验收记录为准。

本地已经从空库执行全部迁移；日志在 `evidence/subscription-billing-20261029/completion/clean-migration-final.log`。全部支付和修复证据均为synthetic。

## 权限与价格

通过 `billing-permissions` 可信CLI授权有效账号，分别授予 `price_draft`、`price_publish`、`task_refund_approve`、`billing_repair` 或 `credit_adjust_approve`；网页不自助授权。缺少任一SKU精确标准成本及来源时，新成本版本不能发布。已批准的冻结价表仍可按原版本执行，不从售价反推成本冒充证据。

价格管理保存成本原稿、12项结果、校验和和未来生效日。先校验再发布；回滚创建未来版本，不改旧报价、已受理任务或已付周期。历史订阅期按原订单独立查询，不依赖“最近50期”列表。

## 异常处理

`node apps/api/dist/billing-ops.js audit` 只读核验；`audit FILE` 可用仅含 `owner` 的JSON选择具体钱包，返回该范围的 `audit_hash`，供审阅后修复使用。`safety-scan` 独立提交确证的隔离事件。每60秒调度也执行该扫描。`billing_safety_isolated` 告警引用不可变incident；隔离不阻止原订单读取、取消订阅和已核实的非资金关单结果。

投影修复只接受原钱包、独立授权操作者、理由、请求号和 `billingAuditHash`，由原账本推导余额。使用 `repair-wallet-projection FILE`；不能传目标余额或SQL，不能修改原分录、价格、对价或期限。修复成功仍隔离，再用 `safety-resume FILE` 重新核验。

CLI不接受虚构渠道证据。渠道恢复必须由可信 `ChannelSafetyVerifier` 在当前已提交状态上验证认证证据；缺失时明确为unverified，保持隔离。先前账单的无差异结论不能当作新核实。纯网络超时或未知渠道响应也不能被当作资金不变量破坏。

## 回退

停止新购买和新任务入口，保留原订单查询与受控恢复；先核对正在派发的原资金意图。选择与0155及已保存新数据兼容的应用版本，不逆向删除新表或改写历史。普通多文件批次产生的子任务各自结算，不得用旧聚合执行器再执行父批次。零价复用项只引用原成果，不得为其补建执行任务。若旧镜像不理解新协议/批次/隔离/复用引用，保持相关写入暂停并前向修复，不强行启动旧worker。

价格版本回退、应用版本回退和资金纠错是三种不同操作。上线验收也不能代替经营验证：当前认可预算下的基准24个月预测仍未达到60%税后公司净利。
