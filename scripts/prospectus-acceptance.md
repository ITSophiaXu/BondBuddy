# Real-model prospectus acceptance evidence

`BB_PROSPECTUS_ACCEPTANCE_FILE` points to private JSON supplied by a controlled CI job or release operator after a real model run and independent human review. Keep it and its artifacts outside Git, for example in `.local/acceptance/`. The verifier never generates a passing record. Missing, synthetic or incomplete evidence blocks a release; mechanical tests alone do not authorize release.

The operator and CI access controls are the trust boundary. This verifier checks file bytes, source bindings, numerical comparisons and review completeness. It does **not** authenticate a natural person, verify a provider's digital signature, or replace professional financial/legal judgement. Do not copy model-authored claims into human-review fields. Do not upload client documents as CI artifacts.

Hosted CI runs only `prospectus-quality-mechanical` via `validate` and never receives private acceptance or signs a release receipt. A controlled Linux publisher runs the full gate and exact-SHA verification, then emits the independent required `prospectus-release-acceptance` status; see [publisher procedure](prospectus-quality-publisher.md).

Run with the same Python environment as the document tests:

```sh
BB_PROSPECTUS_ACCEPTANCE_FILE=/private/acceptance/evidence.json \
  node scripts/verify-prospectus-acceptance.mjs
```

The only successful output is `PROSPECTUS_ACCEPTANCE_RESULT=` followed by hashes and a compact summary. Failures print a fixed code without private text. Evidence must bind the current clean `HEAD` commit, complete Git tree, and `pipelineFingerprint()` exported by the verifier. **Any source-tree change, including documentation, requires a new run and review.** Store evidence externally so adding it does not change that tree. Review must follow the model run and be no more than seven days old.

The required JSON shape is described below. These are field definitions, not an approved record or a runnable passing example.

| Object | Required fields |
| --- | --- |
| Root | `schema_version: prospectus-acceptance-v1`, `synthetic: false`, `status: passed`, `commit`, `tree`, `prompt_tools_sha256`, `reviewer`, `findings`, `cases` |
| `reviewer` | `actor_type: human`, real `id` and `name`, `independent_from_model: true`, `generated_by_model: false`, ISO `reviewed_at` |
| `findings[]` | `severity: minor/major/critical`, `status: open/resolved`, `description`; every major/critical finding must be resolved |
| `cases[0]` | Exactly the authorized `case_id: rq-202509`, `task_kind: full_update`, actual `run_id`, `input_hash`, `source_cutoff: 2025-06-30`, `target_cutoff: 2025-09-30`, `materials`, `artifacts`, `chapters`, `financial_checks` |
| `materials[]` | All three files in `tests/samples/2026-09-25/manifest.json` for this case: `file_id`, local `path`, registered `sha256` |
| `artifacts` | References named `input`, `provider_record`, `source`, `tracked`, `clean`, `quality_report`, `source_pdf`, `tracked_pdf`, `clean_pdf`, `render_report`, `review_record`; each has local `path` and `sha256` |

Local artifact paths are resolved relative to the evidence file. Each must be a readable regular file with matching bytes; symlinks are rejected. The source must match the authorized historical DOCX. `input` is the actual locked `codex-file-input-v1` input JSON with the same input hash, source hash, issuer, target period and material hashes. Do not recreate input from a later project revision.

`provider_record` is an operator export of the actual durable execution record, containing the same commit/tree/tool fingerprint plus `synthetic: false`, `real_call: true`, `provider: codex`, actual `request_id` (provider request or captured CLI thread/call ID), machine `actor_id`, `run_id`, configured `model`, `input_hash`, `tracked_sha256`, `clean_sha256`, ISO `started_at`/`finished_at`, and `usage`. Usage requires `status: measured` and positive integer `input_tokens`, `output_tokens`, `total_tokens`, with total equal to input plus output. Preserve original runtime evidence behind that export. An unavailable real identifier or usage measurement is a missing prerequisite, not permission to invent one.

`quality_report` is the independent `word-quality-v1` report: `status: passed`, empty `issues`, and matching `baseline_sha256`, `tracked_sha256`, `clean_sha256`.

`chapters[]` must cover `preamble` and every actual source level-zero heading exactly once. A heading ID is `p:<zero-based paragraph index>:<SHA256 of UTF-8 heading text>`, using `bondbuddy_file_authoring.source_outline.outline`. Each row includes `chapter_id`, the human `reviewer_id`, `status: passed`, `disposition: updated/retained`, `content_retention: passed`, `tables: passed`, `required_updates: passed`, a concrete `note`, and nonempty `output_locators`. Review required updates even for retained chapters; absence of changes needs a substantive reason.

`financial_checks[]` covers exactly 21 explicit scope/metric keys in [the fixed policy](prospectus-financial-policy.json), version `rq-202509-financial-v3`: 20 monetary bindings and one derived ratio. The original `total_assets`, `total_liabilities`, `net_assets`, `net_profit`, `operating_cash_flow`, and `nonoperating_expenses` retain both `consolidated` and `parent`. Six additional metrics require only `consolidated`: `deferred_income`, `sales_expenses`, `administrative_expenses`, `finance_expenses`, `investment_income`, and `profit_attributable_to_parent`. `bonds_payable` requires both scopes; `bonds_payable_noncurrent_liabilities_ratio` requires only `consolidated`. This is not a Cartesian product; the source parent profit statement has no corresponding attributed-profit row. Each row has `metric`, `scope`, human `reviewer_id`, and `status`, `amount`, `unit`, `reporting_period`, `entity_scope`, `repeated_values`, all `passed`. It also contains:

- `source`: `file_id: rq-202509-02`, matching registered `sha256`, the exact policy-bound Excel `locator`, decimal-string `value` equal to the original XML numeric cache, `unit: CNY`, `scope`, `start`, `end`.
- `output`: decimal-string `value`, `unit`, `decimal_places` from 0 to 6, `scope`, `start`, `end`, all distinct precise location objects in `locators` where that value occurs.
- `expected_occurrences`: the number of independently identified output occurrences, equal to the locator count. At least three consolidated metrics need two or more checked occurrences.

These operator-supplied counts are not the fixed-case coverage test. Policy `rq-202509-occurrences-v3` requires **28 table amounts, 14 narrative amounts and one narrative ratio**. All previous 39 roles remain. The four new roles are the consolidated and parent primary-statement bonds-payable amounts in original tables44/47, and the bonds-payable amount and percentage of noncurrent liabilities in original paragraph7403. Each actual role must have exactly one unambiguous output location and be covered by an already validated amount cell or target-period span for the same scope and metric. Omitting a stale narrative while checking correct tables, repeating one location, or citing equal numbers elsewhere cannot satisfy this check. Old 27/39-role evidence and invented role names are rejected.

Original coordinates identify the registered source roles, not clean-document positions. The reader locates actual output captions, structured ancestors and complete metric-list clauses again, so inserted body paragraphs or table rows can shift their indices. Missing/ambiguous roles or unsupported changes fail closed. A retained same-metric monetary list with an unsupported connector, period expression or shared unit also blocks coverage; an inserted correctly worded copy cannot substitute for it. No submitted role names, count assertions or model self-report determine this result. The 43 required occurrences are a minimum; independent review must still identify other financial values and narrative updates throughout the document.

Output units are `CNY`, `CNY_10K`, or `CNY_100M`. Exact decimal arithmetic applies half-away-from-zero rounding at the declared output precision of0–6 places. Source values accept bounded plain finite decimal strings, including all digits of the original XML cache; scientific notation, non-finite values and truncation to an old eight-decimal limit are rejected. The workbook is never recalculated or saved. Floating-point tails in stored caches remain provenance, not newly asserted accounting precision. Output values retain the six-decimal maximum.

The derived bonds-payable ratio instead requires output `unit: PERCENT` and `decimal_places: 2`. Its `source` binds consolidated balance-sheet `D116` as numerator and contains `denominator` with its own complete `file_id`, `sha256`, `locator` (the policy-bound `D127`), original cached `value`, `unit: CNY`, `scope`, `start`, and `end`. Both source cells and their visible context are independently validated. The denominator must be positive; exact rational arithmetic computes numerator / denominator × 100 with half-away-from-zero rounding. A correct displayed ratio derived from an unsupported denominator fails. Each output locator requires `narrative_ratio: true` and no `narrative_list`; its complete quote preserves the bonds-payable three-period amount and percentage clause, and its offsets select the entire target-period percentage token. Period-definition and scope anchors are required as applicable. Historical amounts, percentages and their noncurrent-liability denominator wording remain checked against the authorized source. Other ratios still require independent business review.

The fixed source reader independently validates the XLSX SHA, exact scope/metric cell, visible statement title, issuer, reporting date, current-column heading, unit and full metric label. An equal number in another cell or hidden/helper sheet cannot substitute. Missing or nonnumeric caches never become zero. Stock metrics, including `deferred_income`, use start/end `2025-09-30`; flow metrics use `2025-01-01` through `2025-09-30`. Human review still confirms the business meaning of the source and output.

DOCX locator strings use `word/document.xml//w:p[N]` for the one-based paragraph index across the complete story, including table paragraphs, or `word/document.xml#table=T,row=R,cell=C` with one-based physical table/row/cell indices. Header/footer/footnote/endnote story filenames are also supported. Financial output `locators` cannot be bare strings or merely contain an equal number somewhere in the paragraph.

For narrative text, each location object requires `locator`, a unique exact `quote` copied from that location, and `start`/`end` Unicode-code-point offsets selecting the **whole numeric token within that quote** (start inclusive, end exclusive). By default the quote must contain exactly one actual target reporting period, a recognized label for the selected metric, and exactly one amount outside the reporting date. The selected span must be that amount, never the year/month/date digits. Percentages and parenthesized accounting amounts are unsupported and fail; signed negative amounts must use an explicit minus sign. Multiple metrics require a narrower unambiguous quote. Each location also needs `scope_anchor: {locator, quote}` identifying actual unique text containing `合并` or `母公司` for the reviewed scope.

A preserved single-metric clause such as ordered annual/quarterly figures may instead set `narrative_list: true`. Its exact quote must contain the complete period expression, one exact metric label and `分别为`, followed by the complete amount list; one trailing sentence/semicolon terminator is allowed. Both quote edges must be actual paragraph or sentence/semicolon boundaries, so neither the period list nor the amount list can be cropped. Periods must be unique and chronological, and their count must equal the amount count. The independent reader selects the target amount by its period's position, and the declared span must select that token even if a historical figure has the same value. Every amount must explicitly carry the same unit and displayed precision as `output`; shared trailing units, mixed units/precision, extra metrics, ambiguous dates, competing entities/scopes and hypothetical figures fail. This fixed case does not support per-location amount/unit overrides.

For `nonoperating_expenses`, the main profit-statement label `减：营业外支出` is an exact supported label, and the original narrative's complete trailing `，明细如下：` is supported. It must remain inside the quoted clause; cropping it fails. The required roles are original tables 45 row 22 and 48 row 21, plus paragraph 7931. The source metric is `D41` in each of `02合并利润表` and `02母公司利润表`; a generic detail-table `合计` is not an alias for this metric.

The six added metrics use a shared finite clause parser for role discovery and numeric-span checking. Deferred income retains its complete three-amount clause and the following three percentages of noncurrent liabilities. Sales, administrative and finance expenses retain the three amounts, three percentages of total operating costs and the `主要为…` explanation. Investment income retains `，明细如下：`. Percentages remain visible context and cannot be selected as monetary tokens; parsing them does not approve their formulas or arithmetic.

For every metric with a required narrative role (including the existing net-profit, asset and cash-flow roles), an unsupported assertion with even one currency amount in the same actual heading context blocks coverage. Amounts following the metric, and amounts directly assigned to it before the label (such as `100万元为发行人销售费用`), are checked. Amounts of a different metric followed by a ratio-denominator mention, such as noncurrent assets as a percentage of total assets, do not assert that denominator's monetary value. Adding a correct three-period copy cannot conceal an unsupported amount assertion. Explanations without currency amounts remain allowed. A single-amount historical event or explicit other-entity clause is excluded only when its complete text, amount and unit exactly match an eligible clause in the SHA-bound original under the same heading context; an inserted old date, changed historical amount or stray guarantor word is insufficient. New or ambiguous monetary prose requires review rather than silently disappearing from coverage.

Attributed profit is a distinct metric from net profit. Its source clause uses `归属母公司所有者的净利润为…；` and inherits its period only from the immediately preceding complete issuer consolidated net-profit clause in the same actual paragraph. Missing, foreign-entity, parent-scope, hypothetical, unknown-period or intervening clauses fail. Only the exact attribution metric is exempted from the competing `母公司` word check; parent statements elsewhere in context remain disallowed.

For all six added metrics, the 2023/2024 narrative dates, units and amounts must match the authorized source; the third slot is selected from the actual target-period definition. Corresponding primary-table historical headers, currency units and values must also remain, including original blanks. A blank historical cell cannot be normalized into zero. This preserves the fixed case's comparators without asserting that their original accounting has been professionally reaudited.

For lists using `最近两年及一期` (flow) or `最近两年及一期末` (stock), add `reporting_period_definition` with three `{locator, quote}` anchors: `section_anchor`, `term_anchor`, and `definition_anchor`. The reader verifies the real level-zero `释义` heading and its actual declaration, then the complete actual glossary term and its period definition in the same table row, with the definition to its right. Other cells may only be blank or `指`; arbitrary date paragraphs, another glossary row, merges and tables outside that bounded glossary section fail. The authorized source really contains these two terms; it has no glossary row named `报告期`.

`报告期内` is supported only for a flow list and additionally requires `period_context: {section_anchor, introduction_anchor}`, each `{locator, quote}`. The actual first substantive management-analysis introduction must explicitly use the same defined `最近两年及一期` term and issuer scope. The narrative must lie within that real heading's section, before any same/higher heading or competing scope boundary. An intervening explicit local redefinition such as `本节报告期为…` is unsupported and fails. Input target dates and distant dates cannot substitute for either the glossary definition or this section context.

For the source's default consolidated scope outside its financial chapter, a list may cite the exact complete clause `本募集说明书其他章节中若无特殊说明，则财务数据及财务指标均为合并口径。` as its `scope_anchor.quote`. That clause must occur uniquely in a main-body paragraph of the actual clean document, and the narrative must not explicitly name a competing scope, another entity or hypothetical figures. This narrowly recognizes an actual document statement; carving out `合并` from a mixed-scope paragraph remains insufficient. Independent entity and occurrence review is still required.

For a pure numeric table cell, omit `quote`/offsets and supply `locator` in canonical `#table=T,row=R,cell=C` form. The **entire cell** must equal the reviewed decimal value. Supply `period_anchor`, `scope_anchor`, and `metric_anchor`, each `{locator, quote}`. Table anchors quote the whole actual cell or paragraph, allowing only whitespace normalization; a convenient substring cannot hide another period, scope or metric. The period and metric anchors must be within the same physical table as the amount. The metric label must be in the same row to its left and match a complete recognized total label, including standard `资产总计`; `非流动资产合计`, `归属于母公司所有者权益合计` and attributed/subdivision net profit are not the corresponding totals.

Physical locator indices stay unchanged for horizontally merged tables. The independent reader maps `tblGrid`, `gridBefore`, `gridAfter` and `gridSpan` to logical column intervals. A preceding period header must cover the amount's single logical column, and a lower period header cannot be ignored. A header such as `2025年1-9月/9月末` explicitly identifies both flow and stock periods; both parts must identify the same target year/month. A stock-only header cannot establish a flow period. Amounts under a `比例`/`占比`/percentage subheader fail even when the merged period covers that column. Vertical merges on the selected amount, period or metric anchor and invalid/inconsistent grids are unsupported and fail.

Table scope has three supported, independently checked forms:

- An explicit `合并` or `母公司` title in an earlier row of the same table, whose other cells are empty. Attributed ownership labels are not scope headers.
- The table's nearest preceding caption paragraph, identified by `scope_anchor`. Only blank paragraphs, recognized currency-unit paragraphs and bookmark/proofing markers may intervene (at most 16 nodes); another substantive paragraph, heading or table breaks adjacency. The whole caption must explicitly identify exactly the reviewed scope and a compatible statement type. Conflicting scopes, `备考`, `模拟`, `假设`, `发行后` and `预测` cannot establish actual financial scope.
- An explicit management-analysis section introduction when the adjacent caption omits scope. Supply `scope_section_anchor: {locator, quote}` for the real section heading and `table_caption: {locator, quote}` for the adjacent caption, with `scope_anchor` identifying the section's first substantive paragraph. The heading needs an actual outline level or inherited heading style; text resembling a heading is insufficient. The introduction must explicitly say management is analysing the selected scope's financial statements. All three paragraphs and the table must share their story and parent. Inheritance ends at the next actual heading at the same or higher level and at a competing scope/hypothetical heading or explicit scope switch. Subsections may inherit, but arbitrary distant scope text cannot authorize a table. Both additional anchors are required together.

External scope captions and section introductions must identify `发行人` or the full locked issuer, and explicit other-entity contexts fail. The authorized `rq-202509` source has one existing caption typo (`行人` in original table 54). Compatibility is limited to that registered historical DOCX SHA, its verified exact original caption, the same exact and unique output caption under the same actual structured heading ancestors, and its locked issuer. Actual output table indices may shift when an unrelated table is inserted. `行人` is never a general alias; a changed source, duplicate caption in that context or foreign/unknown issuer does not receive this compatibility.

The authorized template exercises these forms without adding scope rows or changing its layout: financial statement captions precede a units paragraph; the management-analysis introduction establishes scope for subordinate analysis tables; one summary table has separate stock and flow header rows; an asset-analysis table has merged amount/percentage headers. The fixed-edit fixture tests exercise the reader's structure only and do not supply financial, model-run or human-review acceptance. Entity identity and whether every actual occurrence was checked still require the independent reviewer; other-company or hypothetical values cannot stand in for the issuer's actual figures.

`render_report` contains `status: passed`, actual `renderer`, human `reviewer_id`, and `template_fidelity`, `headers_footers`, `tables`, `no_clipping`, `no_missing_glyphs`, all `passed`, plus a concrete `pagination_note`. Its `documents` array has exactly `source`, `tracked`, and `clean` variants, each with matching PDF `sha256`, corresponding original `docx_sha256`, actual `pages`, and ordered `inspected_pages: [1, ..., pages]`. The verifier independently counts PDF pages. A clean PDF below 80% of original pages blocks this fixed regression case; this does not prove pagination or visual quality without the human inspection record.

`review_record` is a separate private JSON record with `reviewer_id`, `generated_by_model: false`, `facts_verified_by_human: true`, the same `reviewed_at`, source/tracked/clean hashes, `render_report_sha256`, exact ordered `chapter_ids`, all `financial_check_keys` in `scope:metric` form, and at least 64 characters of substantive `notes`. It preserves the independent review behind the summary. Never substitute a model response or mechanical report for it.
