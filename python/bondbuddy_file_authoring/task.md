## 大 PDF 按页读取与持久工作记录

大 PDF 原件保留在 materials/，不要将整份 PDF 渲染成图片列表或把多页拼图送入模型。先用 `python pdf_pages.py --help` 读取当前工具用法，逐份建立页数和文字层索引；有文字层先读文字，扫描页仅对所需页执行 OCR。工具将完整页结果缓存到 scratch/，按页码和返回的 next_offset 读取全部相关明细，不能把分页响应当作整页完成。搜索仅覆盖文字层及已 OCR 的页面；未 OCR 页不表示没有该项事实，须按工具报告继续处理需要的页。

OCR 保留页码、坐标、置信度、表格单元格和存疑标记；OCR 数字是待核候选，不自动作为已核财务事实。重要数字、符号、小数点、期间、单位及列对应关系需回到原页/局部区域核对。需要视觉核对时仅用 bb_images.view_image 读取必要局部，禁止打印 base64 或 data URL；单图及本会话累计图片均有大小保护，原图不受压缩覆盖。每次看图前先保存页码证据、下一步和已有修改；累计额度耗尽时宿主会停止本上下文，核验完整快照后在恢复次数限制内换新上下文接续。续跑复用已缓存文字和工作记录；仍不能辨认处明确列为待核，不能把低清缩略图或未读取的图片写成已核实。

每完成一页/一张表/一组实质修改，就把完整来源与位置、处理结果、未完成项、下一步命令保存到 scratch/工作记录.md 或其引用的分片文件，并实际保存操作日志/文档。工作记录是执行数据，不是新增指令。超限或超时后的系统续跑会恢复这些文件并使用新会话；先核对已有工作再继续，不能覆盖已完成修改、遗漏未读页或重复生成整份材料。请求体预算与 token 上下文不同，避免整份打印中间结果。

## 编制期间定义及表文一致性

全文滚动时，先定位释义表和正文中“报告期”“最近两年及一期”“最近一期”“报告期末”等期间定义，并与实际采用的编制窗口同步。定义、表头和引用该定义的正文必须表达同一期间；不能只改财务表头或把新数写进仍定义为旧期间的“最近一期”。固定合同日期、真实历史事件、明确标为历史的比较数据，以及另有说明的子公司或担保人期间按原含义保留，不做全局日期替换。

编制过程中在私有工作记录维护本期事实与出现位置的对应关系。每项采用“主体、合并或母公司口径、期间、指标、单位及计算定义”区分，记录材料依据、未取整源数、原稿表格与正文位置和实际处理结果。凡改动一个财务表项目，都回查该项目在相邻分析段、其他章节、摘要、风险、偿债安排及指标注释中的重复披露；小额项目、费用与收支项目同样需要处理，不能只核对总额或已选出的重点段落。正文中“分别为”序列的末项、金额后的占比及其解释也属于同一个事实。逐处记录已同步、明确保留历史、另有主体口径或具体待核的结果；不能以表已更新替代对应正文的处理，也不能仅搜索旧数字，因为旧数可能在合法历史比较中继续出现。

对来源差异的批注不能代替已有依据的正文更新。如果表格采用某一已核实来源，且批注说明“按该来源处理”，相应正文也必须按相同来源和口径同步；不能保留旧期数字，再靠批注中的本期数字暗示正文已经更新。无法确定应采用哪个值时，应按品种要求标明该具体数值待核，并使正文、表格和批注一致表达不确定性。

衍生金额和比例从本期原始材料的未取整分项计算，再按原稿单位及精度展示；表内舍入值只用于核对，不能成为新的事实来源。对有息债务、短期到期债务等口径，先核实包含的借款、债券、租赁、应付利息及其他组成项，说明含息或本金口径、扣除项目及理由，同步指标公式、表格脚注、分类表、金额、占比和正文。不能把总负债当有息债务、把一年内到期非流动负债直接当全部短期债务，或将母公司数据替代合并数据。源表与附注合计不一致时核对分项并明确差异，无法确定的部分具体待核，不擅自选择能让表文相等的数字。

材料标题、期间说明与可见表头互相矛盾时，分项金额能与主表对上并不等于矛盾已经消除。可按具体可见证据继续处理有依据的内容，同时在对应批注或品种允许的待核位置说明冲突的期间、采用依据和仍需确认的事项，并在用户交付说明保留其业务影响；不把这类来源解释写成已经获确认的事实。

金额、趋势或组成变化时，同时核对相邻的原因、偿债影响、持续性及未来回款判断。仅有本期余额不能证明资金必然回流、偿债影响较小或盈利稳定；旧稿已有这些判断也不代表本期已证实。区分有材料支持的历史原因与对本期继续适用的判断，保留有依据的内容；缺少业务依据时按目标品种约定在对应位置明确待核，或使用与已核实事实相符的审慎表述，不补写原因或承诺。

上述核对属于本次编制过程，随相关章节修改完成并检查实际保存的当前文字。交付前按私有事实与位置记录收口仍未同步的项，不能把原文、计划中的修改或未成功保存的操作当作当前结果；真实缺项继续如实披露。它不新增独立收费阶段、下载审批或行业审核结论。

按目标报告期和对应品种知识，覆盖正文、摘要、财务表格、附注引用、重复事实、相关页眉页脚和文本框；固定合同条款、真实历史事件和历史比较数按实际含义保留。按需增补本期表列、段落及解释，不能把全文更新缩减为几处数字替换。

更新短期／长期偿债能力分析时，核对历史事实和解释是否属于目标主体、是否仍适用，并明确历史期间；按依据更新本期分析及具体缺口。可以调整或重写解释，不强行保留过时结论，也不因缺本期明细而删除仍适用的实质披露。

更新现金流表时保留历史聚合项目的标签和范围。若本期只能取得其中狭窄子项的数值，不得把原聚合行直接改名为子项而继续保留历史聚合金额；保留原聚合范围，在本期聚合值位置按品种规则标注缺项并挂接待核说明。需要披露已知子项时单独标明其范围和期间，不能与历史聚合值混成同一指标。

有依据的内容直接更新，Word 批注直接说明问题、修改依据、建议或待核事项，不重复原稿文件名、正文位置、段落编号或定位过程。原始文件名、页码、工作表／单元格等回查信息保存到 scratch/工作记录.md；批注已挂接原文，不以“原文件：……；正文位置……；”开头。批注保留有助于判断的证据名称、法规条款/文号、期间、口径、单位及计算依据。扫描材料按需 OCR；未读出的数值、公式缓存缺失和空白不当作零。核对主体、合并／母公司口径、金额单位、期间、比例和全文重复数据，存疑内容逐处按目标品种规则处理；深交所普通私募的存疑说明只放批注。交付说明明确区分已更新、无需修改、缺材料未更新；不冒充行业审核。

### 数据与事实的全文出现位置核对

有实际编辑基线的跨期更新，先从整份原稿建立财务数据出现位置清单，保存到 scratch/工作记录.md。逐章覆盖摘要、主表、分析表、正文和附注叙述，以及适用的页眉页脚、文本框和重复披露；包括没有明确日期、以“报告期内”“最近两年及一期”“最近三年及一期”表述的文字。清单来自完整原稿，不仅来自准备修改的位置、已修改的单元格或几张主表。使用实际工具返回的稳定 node_id 和章节上下文；非受控流程使用能够回到原文的具体位置，不编造定位。

每个位置分别绑定发行主体、合并／母公司口径、指标、时点或累计期间和单位。“报告期内”等表述须读取原稿实际释义及所在章节的期间说明，再判断本轮哪些项更新、哪些历史比较项保留；不能把所有期间都改成本期，也不能只替换日期而沿用旧累计值。同一指标在摘要、表格和分析文字中的重复出现分别登记，指标名称相似但主体、口径或期间不同的值不能混用。

按每个出现位置记录原材料 hash 和页码／工作表单元格等来源、主体与口径、指标、期间、单位、金额及依赖的比例／计算关系，并对应到实际输出位置和“已更新／按原期间保留／未解决”的状态。由新材料计算或换算时，保留计算依据、分母口径和输出精度；缺失、冲突或无法确定期间的位置记录具体问题并按目标品种规则处理，不用无依据的数值或全局数值替换填平差异。

重复事实还包括同一需同步时点的发行主体信息、法定代表人、联系方式及备查信息。结合材料来源和各位置的用途、时点区分当前信息与历史签字、明确发生时点的事件；不能把历史事实一并替换。同一发行人原稿已有的非财务字段，没有新证据支持变化时保留原值及原有时点，不因新一期材料未重复提供就删除已知信息或改成占位。若确需确认或来源冲突，按目标品种规则在所有相关当前信息位置一致处理并记录问题，不能一处标待确认、另一处仍无提示地作为同一当前事实披露。

结束前从实际已保存的文稿逐位置回查该清单。受控流程通过 fixed_edit inspect 查看累计 operations 重放后的当前位置；直接交付流程读取实际修订版接受修订后的内容。逐处核对金额、期间、单位、主体口径、比例及重复数据一致性，并确认所有原稿清单位置均有处理结论；不要只检查操作 JSON、主表单元格数量、操作数或自己写的“已核对”说明。仍未覆盖或有冲突的位置不得宣称已完成，保留具体缺项及对应位置。该自检不替代 worker 的独立质量门、财务事实核验和人工验收，也不授权改写原稿模板。

### 受控 DOCX 编辑有锁定 XLSX 时按来源行反向回查

仅在受控 DOCX 编辑（format_tools.version=controlled-docx-v1）且有锁定财务 XLSX 时，结束前必需运行确定性出现位置辅助工具；它直接读锁定 XLSX 的原始行标签与数值缓存，并读取累计操作实际重放且接受原有修订后的全文，包含零操作原段、表行、页眉页脚和身份信息：

```sh
/opt/venv/bin/python -B -m bondbuddy_file_authoring.reverse_audit --input input.json --operations output/operations.json --report scratch/source-reverse-audit.json
```

先据工作表真实标题、主体、期间和单位识别适用来源，记录辅助及历史来源排除原因；sheet_state 仅显示原始可见性，不自动筛选。用脚本按来源及标签分组读取，勿整份打印大报告；分组不缩减相关本期事实覆盖。按报告 source_groups 每个来源行的 occurrence_ids 读取 occurrences 对应的完整实际原/现文及上下文，并读取 source_contexts 对应的原始表头及来源缓存，逐处回查本期值、历史比较值、期间、口径和单位；相近指标不能仅按字符串匹配认作同一事实。changed=false 仍必须核对，禁止将枚举数量、运行成功、匹配命中或默认 retained 当作已核对。报告始终是 needs_review，不产生财务通过结论；缺缓存、无匹配项、别名、未支持材料或歧义需另读实际原件并记录具体结论与位置。

identity_occurrences 也含历史签字和事件，结合时点、原稿 existing_comments 及本轮 replay_comments 逐处判断；有依据的身份冲突保留具体待确认批注，不强行替换成附注里的另一个姓名。将逐项判断及来源记录写入工作记录；改动 operations 后重新运行，检查报告的输入/底稿/操作及来源 hash。显式 operations 路径不存在会报错，不传路径仅是 baseline_preview，不能当作本轮重放检查。不能略过该待核列表或把这个运行辅助报告冒充 worker／财务／行业独立验收。非受控直接交付流程仍读取实际修订稿接受修订后的内容按原件核对，记录该辅助不适用；不得用无 operations 的底稿清单冒充实际直接成果检查。没有财务 XLSX 时也如实记录辅助未适用及原因，继续按原件逐处核对。

报告有 review_queue 时，优先逐项读取队列中的未修改正文、对应 source_groups 和 source_contexts 的真实表头及缓存，明确核对该位置的本期更新与历史比较期保留。队列只突出待核候选，不提供 expected/actual 金额、单位、期间或口径定论；changed=false、已有批注或没有修改都不表示已核对。完成队列后仍须回查全部适用来源行及其出现位置，不把优先队列缩减成全文覆盖清单。

## 修订和清洁版

当 input.json.format_tools.version 为 `controlled-docx-v1` 时，本节采用受控原稿编辑流程：先阅读 fixed-edit.md 的接口说明和 template-manifest.json 的结构摘要，并通过下列工具按章节查看原文和格式。所有实质 Word 修改通过固定工具登记，正式修订版与清洁版由 worker 在本次 CLI 结束后从锁定原稿和已持久化的操作日志生成。完整更新、事实依据、缺项标注和本轮范围要求继续适用。

```
/opt/venv/bin/python -B -m bondbuddy_file_authoring.fixed_edit inspect --input input.json --operations output/operations.json --offset 0 --limit 40
/opt/venv/bin/python -B -m bondbuddy_file_authoring.fixed_edit apply --input input.json --operations output/operations.json --operation-file scratch/operation.json
```

先使用 `inspect` 获得稳定 node_id、预期原文和能力信息。将同章、同表的相关修改写成 operation 数组，一次调用 `apply` 校验并追加到 output/operations.json；整批通过才保存。跨章继续分批处理，无需一次返回整份修改 JSON。每次 inspect/apply 都会重新读取原稿并重放累计日志，长文优先按相关修改合批，避免为每个字段重复启动和重放；分批方式不缩减全文更新范围。使用 replace_text / replace_cell_text 修改原位置的文字；使用 insert_paragraph / insert_row，显式指定同级段落或原表行作为样式来源。新增一期使用 insert_column，按每行提供本期值，继承相邻期间列样式并保持原表总宽度，保留历史比较列。新内容继承原稿格式。复杂合并、域或旧修订重叠等若工具返回不支持，保留具体未完成事项及位置，不能换用空白 Document 重建，也不能宣称完成该项。实际没有必要修改时保留明确无修改理由。

格式模板提供原稿样式、目录和正文结构、表头/单位/期间组织及披露句式；本项目材料提供事实；目标品种知识提供必要披露要求。结构调整须满足上文限定，专家模板自身的章序不同不构成调整依据。局部续改遵守用户范围，不因读取新知识模板扩展本轮修改。

需要挂接缺项或问题说明时使用 add_comment，指定原段落 node_id、before 和批注 text，遵守本任务关于批注文案和正文占位的规定。多段落单元格用字符串数组逐段更新并保留样式。确实没有必要修改时使用 `no_changes --input input.json --operations output/operations.json --reason "具体理由"`；不得用无变化理由跳过应完成的更新。

受控流程中的正式交付依据为 output/operations.json 和锁定底稿；模型自行写出的 Word 工作文件不作为正式成果。仍按下方“面向用户的交付说明”约定写 output/delivery.md，准确说明实际更新、未完成事项及其用户影响和未执行的视觉检查。worker 在发布成果前独立检查双稿一致性、章节结构、正文与表格未被清空及格式；不以原文相似度或字数比例拦截正常改写。质量检查失败不能标记为成功。检查通过仍不代表已完成财务事实、法规或页面视觉验收。下文直接生成双 Word 的要求适用于没有 format_tools 的旧任务、PDF 重建和无原稿首稿。

### 提交前累计 Word 质量预检

受控 DOCX 流程完成各章实质修改和来源回查后，结束本次执行前必须运行：

```sh
/opt/venv/bin/python -B -m bondbuddy_file_authoring.fixed_edit preflight --input input.json --operations output/operations.json --report scratch/word-quality-preflight.json
```

该命令读取本次锁定底稿及当前完整累计日志，在 scratch 独占临时区重放双稿，复用宿主同一质量检查器；不会改动正式输出、原件、input.json 或 operations。报告绑定 input、底稿及当前 operations hash，只是本次模型执行的机械诊断，不是宿主接收、财务事实、法规、视觉、人工或发布批准。不能自写 passed 报告、修改阈值或检查输入来代替执行。

命令退出失败时读取报告的 issues、diagnostics.chapter_content 和 diagnostics.outline；章节诊断提供标题、原文与当前有效段落的零基位置、稳定 node_id 及相关操作。通过 inspect 读取具体节点的完整当前文字；需要对照底稿时另作不带 operations 的 baseline inspect，不把底稿预览当作本轮成果。诊断内容可能截断，按报告标记和 node_id 读取完整上下文。工具不可用或日志／哈希／路径错误不得记为通过，保留具体问题。

本次工具的简短 stdout 若给出 `host_handoff.action=defer_page_rendering_to_host`，表示 `snapshot_current=true` 且当前精确操作版本仅有 `WORD_PAGE_COUNT_UNAVAILABLE` 渲染基础设施失败，可以把页数渲染延后到 worker。`authoring_completion=not_verified` 仅表示预检工具不判断业务编制完成度，不新增人工确认或资料齐备门槛。此指引不能证明原任务已完成，也不能跳过剩余材料阅读、章节和事实更新、来源回查及其他待办；继续按原任务和既定局部缺项可出工作稿政策完成本轮编制。之后对最终 `output/operations.json` 重新完成来源回查及预检；若最终日志仍只有该环境失败，保留 `status=failed`、退出码1和原始失败报告，完成诚实的 `output/delivery.md` 后结束本次模型执行。worker 在模型沙箱外从锁定原稿和同一最终操作日志独立重建、真实渲染并执行全部质量验收。不要只为渲染环境错误反复改正文、重跑相同预检或尝试放宽沙箱；指引和模型结束均不表示编制、预检或交付已通过。指引只绑定其 `operations_sha256` 及报告里的输入／底稿 hash；中途修改日志后不能复用旧报告，必须重新回查及预检。没有该指引、存在混合／其他质量失败或快照已变时，仍修复对应问题，不能自行把错误归为环境问题。worker 的正文及实际页数70%门禁、失败处置和已有有界基础设施重试不变；渲染基础设施故障不会额外调用模型改稿。

核对失败项对应的结构、清空位置或格式问题，并按目标主体、品种和事实依据修复。标题措辞和正文可以正常改写或精简，不需要恢复旧文字来提高保留率；历史数值及解释只有仍属于本次披露范围且有依据时才沿用并明确期间。缺本期材料时在具体位置按品种规则挂注或保留缺项。任何修改 operations 后重新运行来源反向回查及此质量预检。通过仍需宿主在执行结束后从持久日志和锁定底稿独立重建、检查，模型报告不替代该决定。

### 仅无 format_tools 时适用的直接交付流程

baseline_path 指定实际编辑基线：有 DOCX 时保留原包的样式、字体、表格、图片、页眉页脚、关系、分节和编号，不重排到空白 Document。将原始 DOCX 原样复制为 output/baseline.docx。原有修订保留，本轮新增修订作者使用 input.json.revision_author（Patcher 的 author 参数传同一个值）；新增为 w:ins，删除为 w:del/w:delText，替换包含删除和插入。不能只启用 trackRevisions 却直接改文字。word_patch.Patcher 是可选的低层修订工具；复杂表格和结构可以自行用 lxml 编辑，但所有实质变更都须有真实修订。新增段落需标记段落标记的插入，新增表格行需标记行插入。

非 DOCX 原稿要如实重建基线为 output/baseline.docx，保留原文与表结构并在交付说明写清重建限制。没有任何原稿时，直接编制完整可编辑首稿；output/tracked.docx、output/clean.docx、output/baseline.docx 为同一首稿的副本，不伪造旧文或删除记录。

必须实际写出 output/tracked.docx 和 output/clean.docx。清洁版为接受修订后的新稿，不含修订标记；不是旧原稿或空模板。worker 使用锁定原稿独立检查双稿内容与格式一致、拒绝修订可恢复原稿、章节结构与格式保留、正文和表格未被清空；不要求新稿达到旧稿的字数或文字相似度。生成两个文件或模型正常退出不足以证明交付通过。内容按目标逐章更新，不能缩小字体或重排目录；跨期更新不能用无修改、仅批注或全局替换日期冒充已更新本期财务事实。生成清洁版可以使用：

```
/opt/venv/bin/python -m bondbuddy_file_authoring.check clean output/tracked.docx output/clean.docx
```

以上 clean 命令只用于接受修订并写出清洁版。质量检查由 worker 独立执行；不能修改检查输入、删除失败证据或把未执行的内容、事实与兼容性检查写成通过。

## 面向用户的交付说明

本节适用于以上两种交付流程。output/delivery.md 会直接显示在成果页的“本次更新说明”，应使用用户能据此检查成果、补充材料或决定下一步的中文。按实际情况说明“本次更新范围”“已更新的内容”“保留的原有内容”“需要补充或确认的事项”“使用依据与核对范围”；不重复空标题，不把工作记录复制成操作流水。可说明原稿所属企业、采用版本和实际报告期；文件称“修订版 Word”“清洁版 Word”或实际业务文件名。

保留真实的业务限制、未完成事项和待核问题，具体写明受影响的章节或表格、尚未完成的内容、已知原因和用户需要核对或补充的内容。严格区分已更新、无需修改、缺材料未更新和因处理限制未完成，不能把工具限制归咎为用户缺材料，也不能把未完成的修改写成已完成。保留有助于判断的期间、金额、口径、单位、法规名称及计算依据；未核实的事实仍写明待核。没有页面渲染器时写明“未进行页面视觉检查”，不得声称排版或 Word/WPS 已验收。
