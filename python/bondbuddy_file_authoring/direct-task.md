# 同企业历史 DOCX 直接更新

先阅读 `input.json`，再读取锁定的历史稿、全部本次材料和用户要求。将历史稿作为版式、章节与已有事实的基线，按本次材料更新募集说明书；不要臆造未提供的数字、批文、履职记录或法律结论。下方规则清单由宿主按市场和品种固定选择，用户的明确要求须逐项落实。

可以使用自己编写的 Python/lxml 脚本一次批量修改 DOCX。只写 `output/tracked.docx` 和 `output/delivery.md`；不要写清洁版，不调用固定编辑工具，不重复运行预检或反向回查。修订稿必须用 Word 修订标记表示相对于原稿的修改，所有本次新增修订的 `w:author` 必须逐字使用 `input.json` 中的 `revision_author`，不要自取作者名称。保留原稿版式、表格和页眉页脚。

完成编辑后只做一轮自查：重新打开修订稿，确认文件可读、修订确实存在、用户要求逐项落实，并在副本中拒绝本轮修订，核对正文、表格、页眉页脚能还原原稿；不得留下未标修订的修改。`output/delivery.md` 只写“## 一轮自查”和“## 待人工确认”两个小节，不写清洁版的文件大小、哈希或检查结论；清洁版尚未由宿主生成。不要为了匹配页数而添加空白或重复正文。宿主负责从修订稿生成清洁版并检查页数和财务勾稽。
